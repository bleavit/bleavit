**F2 landed the generation pipeline**: `app/.papi/polkadot-api.json` + `packages/papi-descriptors` (both live-capable `spec_version`s, committed, drift-gated), so what remains here is the app-facing work — the `@bleavit/descriptors` wrapper exporting the `spec_version` → descriptor map, the **Asset Hub** set (D-12; a whitelist is right there and wrong for the Bleavit set — Decision log D7), and 10 §5.2's three-mode compat classifier. **The "bootstrap from the committed `keeper/.../runtime-metadata.scale` — no node boot needed" note stays withdrawn** (V-75): that blob is B16-era metadata **v14** declaring contract **v9** with 42 pallets, and v14 has no runtime-APIs section at all. The *no-node* property survives and is now exercised per commit — PAPI generates from the committed metadata file offline (V-76). **Started 2026-08-03; 15 tests, 11 mutations all caught.** Three of the four pieces are in. **(a) `CRITICAL_SURFACE` is generated** from `tools/release/surface-manifest.json` (app-code rule 7) into a committed, byte-compared `critical-surface.ts` — 220 probed entries, and the 2 unprobeable ones are excluded *deliberately*: 02 §12's fixed-layout `ReleaseChannel` key has no metadata entry by design (that is what makes the newer-release pointer readable from `ReadOnlyIncompatible`), and chain properties are identity, verified by the spec pin. **(b) `SUPPORTED_RUNTIMES`** is compared in both directions against `app/fixtures/chain-feed/`, so a stale metadata hash or half a primary/recovery pair is a build failure — it caught a placeholder hash on its first run. **(c) The three-mode classifier** is a pure function over probe results, which is the point rather than a convenience: it decides whether the app may sign, so it has to be exercisable on the probe outcomes a healthy chain never produces. Two rules it gets right and that are easy to invert — `read-only-incompatible` is about the **`spec_version`**, not about how much broke (collapsing heavy breakage into it would take the app offline for a partial upgrade it could have survived), and an **unprobed** surface is refused rather than counted as passing (a classifier that ignored what nobody asked about would report `full` for a runtime it never examined — F2's whitelist defect one layer up). The PAPI probe adapter is structural, informed by **V-87**. **SQ-577 found here:** 10 §5.2 names calls as part of `CRITICAL_SURFACE` and §3.2 makes `restricted` signing per-surface, but doc 02 freezes no calls at all and the manifest has 0 call entries — so `callIsProven()` is fail-closed outside `full` mode (INV-FE-12: an unproven capability is absent), and its own test asserts the manifest still has no `call` kind, so closing the question fails that test rather than leaving the placeholder. **Remaining: the Asset Hub descriptor set (D-12)**, which is not a small addition — 10 §5.1 requires descriptors be generated from **built runtime artifacts, never a live node**, so it needs the pinned system-chain runtime wasm put through the same `tools/release/` extraction as the Bleavit feed, plus the pin itself. **SQ-587 ruled that pin on 2026-08-04 and it is no longer a decision**: 08 §2.5 and 09 §6.3 already phase the Asset Hub connection — Paseo's at Phase 2, Polkadot's at Phase 3 — so a release pins the Asset Hub of the relay it targets, a per-release property exactly like the relay. 02 **§7.7** now freezes the three AH surfaces the deposit leg touches, and §13 **rule 8** puts them outside `INTEGRATION_CONTRACT_VERSION` deliberately (a Bleavit runtime constant cannot attest a chain it cannot observe), pinned instead in the release feed by AH genesis hash / `spec_version` / metadata hash and probed as a **separate** §5.2 verdict — never folded into the local one. Fetching it from a public RPC would be the exact discipline F2 exists to prevent. **(d) That separate verdict landed 2026-08-04** (`packages/descriptors/src/foreign.ts`, 32 tests, 6 mutations all caught): the two verdicts are different types with **disjoint mode vocabularies**, so folding one into the other is a type error rather than a convention — a merged `mode` would let a healthy Bleavit runtime vouch for a chain it cannot observe, which is what rule 8 exists to prevent. A **genesis mismatch is `wrong-chain`, not `unsupported`**, and identity is checked **before** compatibility (the same ruling `packages/verify` carries, for the same reason: an unsupported `spec_version` is this chain further along and a user can wait it out, while a different genesis is a different chain where every balance shown belongs to someone else). `withdrawIsBlockedBy` returns a constant `false` with a test over **every** mode, because the tempting shape is one `funding` verdict across both legs and it takes withdraw offline exactly when AH is unreachable. **`FOREIGN_CHAIN_PINS` ships empty and the suite asserts the emptiness** — the verdict is then `unreachable` and the deposit leg blocked with a named reason, which is the honest state until the artifacts exist. **What still remains is only the artifacts**: the pinned AH runtime wasm through `tools/release/` extraction, the descriptor set generated from it, and the two `[VERIFY]` tags (asset index, exact AH extrinsic) that R-2 forbids resolving by assumption. **(e) The artifacts landed 2026-08-04, and both tags are discharged** (V-105/V-106/V-107). The pin is `paseo-network/runtimes` **v2.4.2** — Paseo, because 08 §2.5 phases the AH connection and a release pins the Asset Hub of the relay it targets — verified through a closed chain: the published wasm's sha256 matches its srtool digest, and that digest's `core_version` matches what two independent live operators report, so the artifact descriptors are generated from and the chain the surfaces were verified on are the same runtime. **The scope of the asset-index tag was wider than it looked**: V-17 had verified 1337 on *Polkadot* AH, and Paseo's registry is its own — `Assets.Metadata(1337)` there decodes to `USD Coin`/`USDC`/6 decimals from both operators, with `Assets` at pallet 50 confirming §8's `PalletInstance(50)`. **`limited_reserve_transfer_assets` is present and not deprecated**, which is the check that mattered: the same runtime marks `teleport_assets` and `reserve_transfer_assets` deprecated in favour of the limited forms, so the row is correct today and one upstream release from citing a call that is gone — hence the gate *reports* a deprecation rather than failing on it. **Three pieces of machinery, not just data:** `tools/release/pin-foreign-runtime.py` (refuses a wasm whose hash disagrees with its srtool digest, and a pin recording fewer than two distinct genesis sources), `app/fixtures/foreign-chain-feed/` (a separate feed because `check-chain-feed.py` compares against *runtime source* and there is none for a chain somebody else builds — 02 §13 rule 8 makes the same split normative), and `pnpm -C app run foreign:check`, the one surface gate that **cannot** be Python: PAPI reads **v16** from the wasm and `scale_metadata.py` stops at v15, so presence is checked over the decoder the client itself uses. Eight mutations, all caught (deprecated call → warns and passes; absent call, wrong genesis, unpinned spec_version, wrong metadata hash, one genesis source, directory/spec_version mismatch, missing descriptor entry → all fail). **V-107 killed this file's own stated design**: `.papi/README.md` promised an Asset Hub whitelist, and a per-chain whitelist silently guts every chain it does not name (`bleavit.ts` 458,662 → 43,258 bytes, measured, with `papi generate` reporting nothing) because PAPI hardcodes the generated package name and `[]` is truthy. No whitelist anywhere is the shipped answer. **The assignability binding landed 2026-08-04, and the blocker was a false premise.** It had been recorded as waiting on a `createClient` that nothing wires — but **assignability is a compile-time relation**: `TypedApi<typeof bleavit>` is a *type*, `getStaticApis()`'s return is a *type*, and `compat` is a property of it, so the binding needs no client, no node and no running anything. It lives in `app/tests/descriptors/types/papi-shapes.ts`, which is the right home for the reason the row already gave: `descriptors` names no PAPI type by design and `chain-client` is the only package the firewall lets import the SDK — a **test** may import both. `light-client.ts`'s ruling on `createClient` stands untouched and is still correct; it was simply never this item's dependency. **The binding shipped vacuous first, and the witness is what caught it.** The member union was spelled `G[keyof G][keyof G[keyof G]]`, whose inner `keyof` is taken across the *union* of pallet objects and so yields only their common keys — `never`, since pallets share no member names. Indexing by `never` gives `never`, **`never` is assignable to everything**, and the positive control compiled while comparing nothing. Fixed to a mapped form computing `keyof Group[P]` per pallet. The witness itself then failed to notice the repair because it carried **its own copy** of the broken definition — V-86's shape one layer up — so it now imports `RealCompat` and `EveryMemberOf` from the file it witnesses. Both directions are gated in `compat.test.js`: the positive must compile, the witness must fail with a `level`-type error. The subtlety pinned along the way: `CompatHelperLike.isCompatible` is declared with **method syntax**, whose bivariant parameters are what make PAPI's `(from?: CompatibilityLevel) => boolean` property assignable to it — rewriting it as a property for consistency would break the binding, and the file says so
