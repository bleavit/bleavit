**The application shipped with no stylesheet at all, and nothing said so.** 119 `className` occurrences across 25 `.tsx` files named 92 distinct BEM-shaped classes and five interpolated families, and not one of them had a rule — no `.css` in the repository, no Tailwind, no PostCSS, no CSS-in-JS, zero bytes of CSS in `dist/`. Every suite passed throughout, because an unstyled element still contains its text: `renderToStaticMarkup` sees the same string either way. **Tailwind v4.3.3 via `@tailwindcss/vite`** (peer range `^5.2.0 || ^6 || ^7 || ^8` admits the pinned Vite 8.1.4), exact-pinned like every other dependency here. **The markup is untouched** — the class vocabulary is styled where it stands, because the suites assert on `renderToStaticMarkup` output with quote-anchored `class="…"` regexes: converting to utilities breaks 19 assertions and silently voids 3 more, which are negative assertions that would go vacuous rather than red. The stylesheet is linked from `index.html` rather than imported from TypeScript, which avoids `noUncheckedSideEffectImports` and stops a `.css` specifier reaching a package's emitted `dist/*.js`, where Node would refuse it and take the whole screens suite with it. **The one design constraint that is not taste:** 10 §2.1 requires provenance labelling to be *"mandatory, non-suppressible"* and INV-FE-9 admits *"no unlabeled rendering path"*, so no rule may hide a badge, a `data-status` treatment, a refusal or a notice — not by `display:none`, not by `opacity:0`, not behind `:hover`. Provenance is quiet here and never absent: the marker always renders, the three risky statuses (`provider`, `stale-cache`, `external-proposal`) additionally mark the **value** rather than only the badge beside it, and it is the detail that expands on hover. **Three integration defects were found and fixed rather than shipped:** the CSS entry was missing from `RECIPE_INPUTS`, so two builds with different Tailwind configuration would have published the same `buildRecipeDigest`; the `@source` scan was wide enough to reach `dist` and the pnpm virtual store, making the emitted sheet a function of the install shape; and the dev server was unusable, since a `<meta>` CSP applies to the *source* document and both `style-src 'self'` and the unsubstituted `connect-src __CONNECT_SRC__` block it — a `serve`-only plugin now relaxes exactly those two, and `pipeline.test.ts` asserts the built tree still carries `style-src 'self'` with no `unsafe-inline` and no dev marker. **New gate:** `check:style-coverage` (+ witness), binding markup and stylesheet in both directions, with the five interpolated families **declared** rather than inferred — its first version reported 100 % coverage and zero dynamic families on a tree that had five, because its pattern could not parse `className={`…${…}`}`. **R-6 review ran on the first cut and returned 0 blockers, 5 majors, 12 minors; all five majors and five minors are fixed here.** Two of the majors falsified claims this row made. (1) **`@source` does not narrow — it *adds* to auto-detection**, so the scan I described as scoped was still reading every non-ignored file under `app/`: `.ordinal`, `.row-4`, `.start-3` and `.end-2` reached the published stylesheet from test *prose*, and the emitted CSS was a function of any scratch file present in one build environment and not the other. `source(none)` fixes it; the sheet lost 4,356 raw bytes and all four utilities. (2) **Five colour pairs sat under 3:1 in dark mode**, three of them provenance badges, because the `-600` state steps are tuned against white and were reused verbatim on a dark ground — the labelling obligation met nominally, which is the exact failure this row claims to avoid. State text now indirects through theme-flipping tokens like the surfaces already did: the five measured pairs move from 2.21–2.60 to **4.48–9.31**, and the light theme's faint labels from 3.16–3.50 to **4.78–5.29**. Also fixed: `.button:disabled` used `opacity`, which composites label and ground together and produced 2.41:1 on the primary — the fade its own comment disclaimed; `.shell`'s `grid-template-rows: auto 1fr` named two rows for a three-or-four-child shell, so with the §11.10 banner present the **header** absorbed the slack and the page body was pushed to the bottom edge (now a column flex with the growing child named on itself); `.disclosure`'s `overflow: hidden` clipped the focus ring off the control that opens a decoded payload; the dev-only CSP marker `/* --dev-only */` parsed as the host-source `*` with path `/`, widening the dev policy to every host rather than annotating it; and the witness leg asserted only that its collectors returned something, which is the weaker half of the very control this gate argues for — it now runs the same `analyse` over a fixture carrying one of each defect and requires all four to be reported. **Verification:** 43/43 App CI commands, stylesheet byte-identical across repeated builds, the gate mutation-tested three ways and the witness mutation-tested itself, all exit codes checked directly. **Open:** the system font stack is a placeholder for a self-hosted face, `check:render-budget` needs a Chrome this workstation lacks (CI has one), SQ-1040 records that no byte budget measures the stylesheet, SQ-1041 asks whether the client has a stated contrast target at all, and the badge detail is reachable on hover but not by keyboard
