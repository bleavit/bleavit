INV-FE-2/5/14. Phase 1 adapters: injected, QR, mock. **Started 2026-08-03; 13 tests, and two vacuous controls found and closed.** The structural core is in. **11 §11.4 rule 1 — *"the tx machine has no bypass edge"* — is now a property of the state space rather than a review note**: `AwaitingSignature` has exactly **one** inbound edge, from `Refreshing`, and it requires a `GatePassed` carrying a non-exported `unique symbol` brand, so a hand-written proof that the gate ran does not typecheck (the same device as `Finalized<T>`, for the same reason). The lifecycle is parsed **out of 11 §11.3's own text** and compared against the reducer's reachable states. Three rulings the machine encodes: `FE-TX-007` is checked **before** the preconditions, because a runtime that changed invalidates the *encoding* — every row could pass and the bytes still be wrong; a blocked gate returns to **Draft with the preparation preserved** (rule 5), since a blocked transaction is a normal outcome of a moving chain and losing the user's work over one is how people learn to click through warnings; and a **declined** signature drops the signing window, so re-submitting re-runs the gate rather than reusing an old pin. Preconditions take 11 §11.4 rule 2's three sources and **only** those, and rule 4 (*"provider/local-index data never satisfies any precondition"*) is enforced by `evaluate`'s signature — `Finalized<T>` is the only input it accepts — so a provider read is *untypeable* rather than filtered. Signers: capabilities are a fail-closed lattice (INV-FE-12), and `metadata-hash` is deliberately **not** declared for the raw-payload adapter because FE-P6 is unresolved — declaring it would let a surface tell the user their device verified the call when nothing has established it can. The mock signer sits behind `@bleavit/signing/testing` with **three independent controls** (exports map, firewall rule, runtime refusal in `SignerRegistry`), each blind to a different mistake. **Two vacuous controls found while building it: V-91** (the negative-compilation corpus could not tell a rejected import from a missing file — both new fixtures passed while failing with `TS2307`) and **V-92** (the new test-signer firewall rule could not fire, because a workspace *subpath* export is recorded as a bare specifier just as an external package is). **SQ-552 ruled 2026-08-03, so the tables are unblocked** — four corrections, the sharpest of which is that the diff test both 09 §1.2 and 11 §11.5 credited to doc 15 **did not exist there**, which is why a frontend `execute` precondition on `DescriptorLeadTime` — whose clock does not start until `execute` itself succeeds — survived since X-11i. The obligation now lives in 15 §4.8 and must fail on a frontend row with no backend check behind it. **Remaining:** writing the precondition *tables* P-1…P-15 (11 §11.5–§11.9) and the 15 §4.8 mirror test itself, plus the fee-currency selector binding to `fee.vit_usdc_rate`, the mortality/nonce rules, and the real injected/QR adapters (the descriptors and the boundary are in; the PJS export names are FE-P1's remaining slice). **Multisig/proxy landed 2026-08-04 once SQ-580 froze `Multisig.Multisigs`** (`packages/transaction-builder/src/wrappers.ts`, 67 tx tests). The part worth stating is not the encoding: **a wrapper splits identity in two.** `Proxy.proxy` executes the inner call as `real` and `Multisig.as_multi` as the derived multisig account, while the **signer** still pays the fee and owns the nonce — so a precondition row that resolves one account for both questions checks the wrong one, and it fails *green*: the signer's healthy balance turns every row green while the runtime rejects the inner call because the proxied account is short. Every clause in P-1…P-15 therefore now carries a **`subject`** (`chain` / `acting` / `signer` / `recipient`), and 11 §11.5's own P-3 text — "USDC balance ≥ amount + fee headroom", one clause, correct only while signer and origin coincide — is **split** where the two reads actually happen. `recipient` is a third subject rather than a special case: P-9's `MaxPositionsPerAccount` clauses are about the *destination*, and folding it into either other subject would check the sender's position count against the recipient's bound. Approval state is a pure function over the frozen `Multisig.Multisigs` read, because the states that matter — a second approval, an already-approved signer, the threshold-reaching call — are ones a healthy local chain will not produce on demand. Four mutations run, all caught. **F6 stays 🔨, and the reason changed on 2026-08-04.** SQ-588's ruling closed the P-9 blocker (the clause now binds `api.is_reserved_protocol_destination` at contract v25 and is mutation-proven), so the *old* reason is gone. What replaced it is an **adversarial Codex review** (`gpt-5.6-luna`, `max`, read-only) that returned **20 findings — 3 blockers, 16 major, 1 minor**. **One blocker is fixed:** `gate()` returned `proceed` over an **empty result set**. Every check in it is a filter over `results`, and every filter over an empty array is empty — so *"every precondition holds"* and *"nobody read one"* were **the same value**, on the only edge that reaches a signer. `txTransitionEdges()` minted its passing gate exactly that way, which is how the hole was normalized: the enumerator that exists to prove there is no bypass was itself using one. `TxPreparation` now declares `requires` (non-empty), the gate refuses any declared row with no result, and five tests that had been passing *through* the hole were given real coverage. Four tests die when the check is reverted. It is the same *passes-by-shrinking* defect `classifyForeign` and `classify` already refuse — present in the most safety-critical place in the client and absent from the two that copied the pattern. **Two blockers stand, and both are real work rather than one-line fixes.** (a) *Gate-to-signature staleness*: `signed` transitions unconditionally, mortality accepts any block number, and the nonce is not tied to the gate's pin — so state that moves between B′ and the wallet prompt is signed against. (b) *P-12 carries 7 clauses where 11 §11.5 states 13*, and `rows.test.js` asserts `rowsFor('P-12').length < 13`, which passes for a trivial reason. The delegation to `check-dispatch-mirror.py` does **not** cover this: that gate parses the two **documents** and never reads `rows.ts`, so nothing verifies the client implements the 13 checks — a queued execution can reach signing and be refused on preimage, resource locks or freeze. **The 16 major findings are unaddressed** and cluster in three places: wrong `subject` or wrong storage item on several P-rows (`PositionTotals` is a per-position supply, not a per-account count; `PhaseFlags` does not prove `Market::FrozenUntil`; `IntakeQueue` is not the per-funder count `Epoch.Proposals` keys on), self-declared signer capabilities the registry trusts without establishing, and `estimateFee` accepting an unadmitted rate. **They are recorded rather than fixed, and F6 must not close until they are triaged** — each was cited with a file:line and a pallet cross-reference, but I have verified only the three blockers myself, so the majors are credible-not-confirmed **Closed 2026-08-04 after an adversarial Codex review (gpt-5.6-luna, max effort) found 20 defects — 3 blockers, 16 majors, 1 minor — every one of which is now fixed.** The review is the reason this row is ✅ rather than the reason it slipped: the suite that existed passed throughout, and in two places **asserted the defect** (`rowsFor('P-12').length < 13`, and a test requiring `decoded-payload` on a descriptor with no decode channel). Verification against the enforcing pallet preceded every fix, and it paid: finding #8 was **refuted** for the `execute` path (`Constitution.PhaseFlags` genuinely is what the guard reads), while four others needed no contract bump because the surfaces already existed and the rows cited the wrong ones. **Two findings were defects in 11 §11.5 itself** (P-10 keyed the intake cap to the caller and hardcoded an amendable 4; P-11 admitted only the proposer where `epoch-core:823` admits the funder too), repaired under R-1 — a client written to that text refuses lawful withdrawals, which no test of the client against its own table can see.
