**10 §5.2's three-mode classifier had never run on either chain.** `probeCriticalSurface` was defined once and called **zero** times, and `createClient` was constructed nowhere — so the compat lattice that `check-client-surface-obligations.py` exists to protect had no consumer at all. **Nobody owned it** (SQ-1010): `probe.ts` waits on F6, whose row never mentions it; the 2026-08-04 log assigned the placement to F7, whose row never mentions it; PLAN called it *an F3/F7 boot-sequence decision* — and F3, F4, F6 and F7 are all ✅, so it was handed forward three times and every recipient closed without taking it. Not a defect in F4, whose row correctly calls the classifier *a pure function over probe results, which is the point rather than a convenience*: until F18 there was no light client, so no client could be constructed. **The sharpest find is the foreign half.** `CompatSurface` declared four of PAPI's six groups and `FOREIGN_SURFACE`'s frozen 02 §7.7 entry is a **call**, which lives in `compat.tx` — so `PolkadotXcm.limited_reserve_transfer_assets`, the deposit leg itself, was the one Asset Hub surface the check structurally could not examine; skipping it would have been F4's own named failure. `tx` added, `view` correctly not, since nothing frozen is a view fn. Built above the read layer per the recorded constraint, so an incompatible runtime stays a boot state rather than a failure to construct. **An R-6 review returned 2 blockers, both reproduced and both fixed.** `#unpin` evicted `#runtimeAt` on window trim, so an upgrade that did not finalize inside the window was dropped and the client kept the **pre-upgrade** `spec_version` forever — classifying it `full` against a live post-upgrade runtime with signing enabled, and FE-TX-007's mitigation re-reads the same poisoned value so it could not fire. Fixed by **lifetime rather than window size**, the cap failing closed rather than evicting. The branch's own new test had demonstrated that eviction and read it as boundedness — the bound was right, the eviction of an un-promoted upgrade was what it hid. The second: PAPI defers compat work to property access, so the probe sat in a `try/finally` with no `catch` and threw instead of returning a verdict, taking `openDepositLeg` down rather than blocking it with diagnostics. Three majors and seven minors closed with them. **Verification:** full `app/` gate list plus twelve root checkers, suites 41/175/575, `surface:check` 288 probed, **21 mutants across two rounds all killed** — one survivor was M11, which asserted through a local copy of `levelOf`, so a mutant returning `identical` for every flat helper passed the whole suite. **Why not ✅:** the classifier cannot be exercised against a real chain — `releaseChainSpecs()` is `unpinned` — and `compat.ts` is untestable without a node, the same seam as `light-client.ts`. Raises SQ-1011, SQ-1012, SQ-1013. **2026-08-08 — the first blocker is retired and the three questions are ruled, but the milestone stays 🔨 on three majors.** **The stated blocker is gone**: F27's drill exercises this classifier against a real chain and reports `compatMode: "full"` at `specVersion 2`, so *"cannot be exercised against a real chain"* is no longer true. **The rulings ratified the implementation rather than replacing it** — 10 §5.2 keeps three modes and 10 §3.1 gains a state, `CompatUnavailable`, under a new `FE-COMPAT-003`; `ForeignMode` keeps five arms because 02 §7.7 already froze the distinction as *"unavailable **or unprobed**"*; and SQ-1013's answer inverted its own question, since smoldot de-duplicates identical chains and **instructs callers not to hand-roll it**, so the cost is CPU share and §9.4's silent row was the mobile-CPU one rather than the memory line (V-365, V-366). **The R-6 review returned 1 blocker, 6 majors and 11 minors, and the sharpest major was found by the normative text written the same hour.** §4.1's new obligation 2 — *"releasing a probe stops **every** chain it added"* — was violated by the code it describes: `getSmProvider` re-invokes its chain factory on every halt (131 calls measured in 300 ms), each call adds a relay **and** a parachain, and `compatProvider().release()` remembered only the newest pair. Two chains leaked per retry, on a path §3.2 re-runs on every `CodeUpdated`. **Closed**: the blocker (both VERBATIM design-kit copies had drifted at exactly the two edited lines, so the `docs` job was red), the leak, `FE-COMPAT-003` stamped on a session that never reached `CompatCheck` (an unpinned release is `FE-BOOT-001/002/004` and no retry can satisfy it — it is now `not-attempted`, carrying no code at all), and the drill recording `ForeignVerdict.kind` instead of the foreign lattice, which reported `"classified"` for a `wrong-chain` Asset Hub — the identical wrapper-not-lattice defect `compatMode` had already fixed for the local leg, left standing beside its own written explanation.
