INV-FE-1. **Done 2026-08-03; 52 tests, 21 mutations all caught, plus 5 firewall-rule injections.** Six parts. **(a) The brand F0 shipped did not hold** — `isFinalized` was a type predicate, which *asserts* the phantom field it cannot check, so any package could launder a forged `Verified<T>` literal into the transaction path (**V-81**, fixed; the negative corpus and the cast gate both extended to see the mechanism they were blind to, and `readmitFromLeader` now serves 10 §4.4's real re-entry need as an explicit trust decision). **(b) The 10 §11 two-domain layer** (`src/domain.ts`): domain is a total function of the id and of nothing else; the boundary is taken as an argument read from the `ConditionalLedger::ServiceIdBase` metadata constant with **no default**, so a caller that has not read metadata cannot obtain a domain and a missing constant fails closed — assuming `2^63` would label every hosted position as governance participation, the one error 11 §11.2a exists to prevent; `totalWithinDomain` **refuses** a mixed input, because I-4 solvency is per instance and a merged figure asserts a backing pool that does not exist while looking on screen like a larger correct number; the FE-P2 cross-check returns view and storage prefix **together**, so one domain's view can never be satisfied with the other's keys. **(c) The §3.1 boot machine** (`src/boot.ts`): a pure reducer, no chain and no timers, which matters because its states are the ones that only occur when something is broken. The suite **parses the mermaid diagram out of doc 10 §3.1** and asserts the reducer's reachable edge set equals it in both directions — the diagram is not documentation of the code and the code is not an interpretation of the diagram, they are one artifact with two renderings (same method as `reference-model/lifecycle.py`). Also pinned: all three non-terminal error codes reach a recoverable state, `WrongChain` is terminal against every event, the compat classifier is a **lattice** (a partial pass boots into `ReadyRestricted` rather than claiming `Ready` and failing lazily), `MemoryOnly` is a flag that survives boot and never disables signing, an out-of-order event is a no-op rather than a crash **or** an undrawn edge, and no non-terminal state is stranded from a rendering surface. **(d) The finalized-only read layer** (`src/reads.ts`): a `FinalizedReader` bound to **one** block, because a reader that re-pinned per call would produce a set of values no block ever held simultaneously — each individually verified, the combination fictional (INV-FE-2); it refuses every read after the transport re-pins, refuses a malformed pin at construction, and refuses to attach a domain to a value from another block. The transport is **injected**, and not merely for testability: folding the smoldot connection together with the finalized-only rule is how a fallback path acquires the ability to mint verified values, so with it as a parameter an RPC transport changes nothing about what the module will hand back — 10 §2.2's never-promote rule expressed as a type. `crossCheckedCall` is the transaction path's entry point rather than `call`, because FE-P2 makes the conservative cross-check the *default*, not the fallback. There is no archive-depth read and a test asserts none appears: smoldot exposes the chainHead group only, so a depth-taking API would have to fall back to a provider to honour it, which is precisely the promotion path §2.2 deleted. Driven by F2's `packages/mock-runtime`, so it runs per commit with no chain — which matters because everything asserted here is a *refusal*, and refusals rot unnoticed in a suite that runs rarely. **(e) The hash-pinned chain specs and the two-chain topology** (`src/chain-spec.ts`, `src/topology.ts`): a chain spec is trusted input to smoldot — it carries the genesis the light client anchors on and the bootnodes it dials — so the app ships a *pin* and refuses bytes that miss it, which matters because the bundle is fetched through an Arweave gateway and a substituted spec makes every later read honestly "verified" against the wrong chain. The hash pin authenticates the **file**; the §3.1 genesis check authenticates the **chain smoldot ended up on**; neither subsumes the other, and `WrongChain` is terminal with no override. Both specs are verified before **either** chain is added; the relay is added first and the parachain is linked to that exact `Chain` object, because smoldot resolves relay candidates by `WeakMap` identity and the `[]` default re-opens the near-miss-`id` ambiguity its own docs warn about; a failed identity check **removes both chains** rather than leaving a client dialling a chain we just decided we cannot trust; and expert bootnodes (§4.3) are unioned **after** verification, so an override can neither replace the release dial set nor smuggle a modified spec past the pin. **(f) The chainHead-v1 transport** (`src/transport.ts`) speaks the wire directly rather than through PAPI's typed client, because `crossCheckedCall`'s two legs are only a cross-check if the pin is *ours*, and because typed decoding under the read layer would put metadata failures where 10 §5.2's classifier cannot see them. It is driven per commit at the **wire level** by F2's recorded transcripts through a provider shaped exactly like `getSmProvider`'s, so the production request/operation code runs with no node; block numbers are decoded from real recorded SCALE headers in all four compact modes, since chainHead reports finalized blocks by hash only. `src/light-client.ts` is the **only** module naming PAPI or smoldot, and it *binds* the structural interfaces to the real ones by assignability, so a drift in smoldot 3.x or PAPI 2.x breaks the build instead of rotting a fiction the tests still pass against. **Four defects, all found by building the transport rather than reasoning about the interface** — V-83 (the interface shipped synchronous and no worker transport can implement it), V-84 (the transport chose the block a value was labelled with; the guard ran before the read), V-85 (an operation event arriving before its `started` response was dropped and the read hung forever), V-86 (three CI-fatal firewall rules could never fire, including D-21's no-network-primitive-in-handoff). **Honest limit:** that smoldot syncs, that browser-WSS peers are reachable, and that a real node's follow subscription behaves as specified are *not* verified here — that is FE-P4 and the B7 drills. The failure branches are injected, because the recorder only ever met a healthy node. Two prototype gates bound here and are F1's: **FE-P2** (routing half answered by V-82; the conservative per-domain cross-check stays the *default*) and **FE-P3** (follower-tab transaction path)
