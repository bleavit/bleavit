**The obligation is normative and predates the milestone**: 15 §4.8's Zombienet row requires *"full relay+para: e2e proposal lifecycle through the real UI data layer … against the published topology"*, and its cadence is **nightly + release**, so this drill must not become a per-commit gate. **Scope, declared 2026-08-08.** Twenty of the twenty-two `built-unwired` screens wait on *a live transport* or *a pinned chain to boot against*, and `zombienet/networks/bleavit-xcm.toml` already spawns exactly the topology that sentence describes — a four-validator `paseo-local` relay, Bleavit at para 4242, Asset Hub at para 1000, Coretime at 1005 — with every chain spec written by `tools/env/generate-relay-specs.sh`. The blocker was never the chain. It is that nothing hands those bytes to `startChainSession`. **The producer already exists and this row claimed otherwise for one hour** — F18 shipped `app/tools/dev-chain-pin.ts` in #275, 292 lines with its own suite, and it is better than the replacement that got written over the top of it: it carries the Asset Hub role, `refuseReleasePath`, and the two cross-role refusals a single role cannot make (a parachain naming the wrong relay, and two roles pinning one genesis). The mistake is worth recording because it is this session's own defect class inverted: `chain-identity.ts` describes that file in the present tense, the description was read as a promise, and `ls` was never run. **A park is a claim and it decays — so is an absence.** The remaining work is therefore narrower than declared: a **Node seam for smoldot** (nothing can spawn a worker outside a browser) and the **harness** that joins the existing pieces. **The dev pin never enters `release-sources.json`** (ruled 2026-08-07) — `releaseChainSpecs()` stays `unpinned`, `refuseReleasePath` blocks the write from one side, and `tests/screens/chain-session.test.ts` asserts it from the other. **The falsifier is half the milestone**: a drill that only boots proves that a boot happened, so the same harness runs a deliberately wrong genesis and requires `WrongChainError` (10 §3.1 `FE-BOOT-003`, terminal, no override)

re-assessed for its enlarged exposure (§3.9 preamble).
