Batch X owner for **SQ-181**. The three `P` components are deliberately **out of scope**: they are raw series needing §4.6's normalization kernel and `PriorBounds`, neither of which exists (V-43) — carried as **SQ-502**. Genesis `MetricSpec` registration is independent of both and is not a dependency in either direction. **Verified inventory, 2026-07-26 — none of the seven is a wiring job, and the reasons differ.** *Shared foundation:* `U`, `D_eff` and `K` all need per-collator authorship retained per `(epoch, day)`, and today's accumulator (`pallets/futarchy-treasury/src/lib.rs:557`) is a single live aggregate that `pay_collator_compensation` `take()`s and kills — epoch *e*'s counts are gone before *e*'s snapshot is recorded, and there is no day dimension. *Per component:* `U` additionally has **no** empty-block signal anywhere in the workspace (the 25 % weighting has no input) and **no** scheduled-slot count — and if "slots" were read as parachain blocks the ratio is identically 1, since `epoch.length` is itself denominated in them, so the denominator needs a ruling (the relay-slot reading is the only one that measures anything). `F` needs a gap *series*: `observe_dead_man` computes the gap as a local and discards it in the same block, keeping one boolean cause bit (`pallets/epoch/src/lib.rs:2221`), so no median over the window is obtainable — and neither `target` nor `Λ_max` has a 13 key. `D_eff` needs an HHI producer (none exists frame-free) plus a rollout-phase **ordinal** for §4.5's `n_cap`, which `PhaseFlags` cannot supply: it distinguishes exact-3, exact-4 and post-sudo, not Phase 5 from Phase 6+. `E` is **blocked on a value, not on code**: `collator.bond` is `genesis = false` and `[VERIFY]`-gated on the collator program before Phase-3, so the collator coverage ratio has no denominator and `E` must fail closed until it is seeded (`grd.bond` is fine — a kernel constant by 13's own exemption; the oracle pair is seeded). `H` needs an `on_finalize` sampler because `frame_system::BlockWeight` is killed at the top of every `initialize`, plus the 40 % target-utilization mapping constant. `Π` needs the whole design: zero defensive counters exist workspace-wide, and the window and bound are unspecified. **Follow the `XcmTraffic`/`ReserveProbeDaily` pattern for every new daily series** (`(EpochId, u8)` double map, the *shared* bounded `XcmTrafficEpochs` prefix index, fail-soft writer, the 2-prefix-per-call reaper) and reuse `epoch_and_day_at`. **Shipped so far:** `K` (#187), `U` (#190), `H` + `Π` (#191) — five of the six in-scope producers, `F` having been decided out of v1. `U` also removed the `pillar == COnchain` filter that made *any* S-pillar emission structurally impossible; the filter now selects on source class. **Two residuals carried by #191.** (a) **`Π` coverage is incomplete**: six surveyed sites qualify under §4.3.2 but are not instrumented, each needing a new `Config` seam in its own pallet and two sitting in `on_initialize` where a call moves that hook's benchmarked weight. Highest-value gap — `pallets/execution-guard/src/lib.rs:931` and `:1656` `MigrationHalt::put(true)` are fail-static latches that bypass `MigrationHaltSources`, so the runtime's activation-edge recorder does not see them. (b) **A defect found and not fixed, since analysed precisely (2026-07-27).** Of `note_snapshot_recorded`'s four early bails only **one** is a defect: the `active_snapshot_spec(epoch) != Some(spec_version)` bail. `active_snapshot_spec` is deliberately fail-closed on an **activation tie**, and nothing prevents the tie — `welfare_core::register_metric_spec` checks version uniqueness, the `≥ current + 2` lead, weights, sanity, source class and discipline flags, but **not** whether another registered version shares its max `activation_epoch`, so two lawful metric-track calls both activating at `current + 2` are enough. Once tied at `t`, `active_snapshot_spec(e)` is `None` for every `e ≥ t` and stays so — a later version cannot displace a joint maximum at an earlier `e` — so `SnapshotDeadline` can never advance past `t`, and **no keeper action or further registration recovers it**. (An ordinary version *mismatch* is recoverable by contrast: the core admits any registered version activated by `epoch`, and the duplicate check is keyed on `(epoch, spec_version)`, so re-recording under the canonical version still advances. Only the tie is terminal.) **Two failure modes in sequence, and the second is the dangerous one.** (1) `snapshot_overdue` fires four days after `t` closed and latches the dead-man — fail-closed, disruptive, loud. (2) Then `EpochTimings` reaps `t` after `RECENT_COHORTS` epochs, `scheduled_epoch_end` returns `None` for a reaped past epoch, and `snapshot_overdue`'s `is_some_and` reads that as **false** — so the chain reports "no snapshot overdue" **permanently**, however long snapshots have actually been missing. That is **fail-open**, and try-state catches it exactly backwards: mode 1 passes (`first_due` still equals the wedged `due_epoch`, `snapshot_due` still `Some`) while mode 2 halts a test chain. Fix is two-part — refuse the tie at registration (`AmbiguousActivation`, the invariant's proper home) **and** stop gating the *deadline advance* on the canonical version, since fail-closed is right for scoring a `W` and destructive for liveness bookkeeping. Full analysis and the owed tests: `scratchpad/SNAPSHOT-DEADLINE-DEFECT.md`. Solvency-adjacent under R-7; fix before A14 closes, after the PR queue drains (both files are contended by #187/#190/#191, and a `welfare-core` change also requires a `fuzz-gates.sh` run). **Also owed:** the `record_daily_gate` day-bound disagreement found by #187 (for a day the epoch never had, `X` reads 1, `R` refuses, `K` reads 0) belongs in 05 §4.3, not three independent runtime guards; and `Π`'s `IntegrityFailureRecorded` event needs its doc-12 §6.3 alert row, `series-inventory.toml` entry and `TelemetryApi` series before monitoring sees it. Verify: per-component tests against §4.3's formulas incl. §4.5's phase-keyed `n_cap`; a runtime test registering a spec set over all seven and observing a complete snapshot at epoch *and* day granularity; negative tests that one absent producer still fails the crank status-quo-safe; try-state over every new daily series; benchmarked weights for any new per-block accounting. **✅ closed 2026-07-27 — deliberately re-scoped, and the re-scoping is the honest part.** Four producers shipped and verified: **`K`** (#187), **`U`** (#190), **`H`** and **`Π`** (#191), each as a bounded per-`(epoch, day)` series on the shared `XcmTrafficEpochs` index with its own fail-soft writer, try-state binding in both directions, and measured weights. The other three are **not** silently dropped: **`F`** is ruled out of v1 by 05 §4.3.2 (`Λ_max` has no anchor — a median cannot see the tail the dead-man latches on, and both error directions are unsafe), keeping id 11 for a later `MetricSpec` version; **`E`** is blocked on an unseeded `[VERIFY]` `collator.bond`, so its coverage ratio has no denominator until the collator program lands; **`D_eff`** is blocked on a rollout-phase **ordinal** that `PhaseFlags` cannot supply (it distinguishes exact-3, exact-4 and post-sudo, not Phase 5 from 6+). Both are values/program gaps rather than code gaps, which is why the milestone closes rather than idling. **What the queue cost, recorded because it is the transferable part:** every one of the three review findings per PR was real, and two defects were found by *review of the branch's own weights* rather than by any gate — `record_snapshot` shipped declaring **107 reads while performing 621**, because the rebase inherited #187's and #190's walk-and-discard fixture lines but not `H`/`Π`'s, and the growth-only regression gate structurally cannot see a read that was never measured. Its declared weight is now honest at 621 reads / 630 KB PoV, inside 13's budget; giving `H`/`Π` the on-write epoch aggregate its siblings have would lower a true number rather than correct a false one, and is carried as follow-up beside SQ-503. **Open, with file:line evidence and a stated fix shape, so none needs rediscovering:** SQ-502 (the `P` pillar), SQ-503, SQ-504, SQ-505, the `SnapshotDeadline` activation-tie wedge, and SQ-181's residual — the genesis `MetricSpec` set, which these four producers unblock but do not deliver.

**Re-scoped 2026-07-14 (user-directed; see Decision log): Track A delivers production
Polkadot-SDK FRAME pallets, not frame-free models. A1–A11 are reopened ⬜.** Their logic
already exists as **frame-free functional-core models** (state struct + `fn op(&mut self)
-> Result` + typed Event/Error + `try_state`); that code is **kept as the functional
core**, relocated to `crates/<name>-core/` (`no_std`, no `frame` deps — rule 9 / 01 §5.2),
and preserved as the differential oracle (Python M3 ≡ Rust core ≡ FRAME runtime) and the
WASM-portable / auditor-consumable port. A milestone is ✅ only once its pallet ships in
full FRAME production style — the **necessary parts** per pallet:

- **`crates/<name>-core/`** — the relocated frame-free model (functional core; today's
  `pallets/<name>` logic, unchanged in behavior).
- **`pallets/<name>/src/lib.rs`** — a `#[frame_support::pallet]` shell: a `Config` trait
  (`RuntimeEvent`, `WeightInfo`, constants via `Get<…>`, `Params`/currency/asset + origin
  bounds); `#[pallet::storage]` items as `BoundedVec`/`BoundedBTreeMap` (`MaxEncodedLen`,
  bounds from 13 §4, names + SCALE shapes matching 02 byte-for-byte — rule 5);
  `#[pallet::event]` / `#[pallet::error]` mapped 1:1 from the core; `#[pallet::call]`
  extrinsics that enforce an explicit origin (`EnsureOrigin` over `pallet-origins`, one
  SafetyFilter authority-matrix row per call — 06 §3) then load storage → call the core →
  persist → deposit events, each carrying `#[pallet::weight(T::WeightInfo::…)]`;
  `#[pallet::hooks]` with the mandatory `try_state` (15 §1) and only the cursor-bounded
  cranks the spec allows (none where it says none — the ledger has no hooks, 03 §10);
  `#[pallet::genesis_config]` / `genesis_build` where the pallet has genesis state.
- **`pallets/<name>/src/mock.rs`** — a mock runtime (`construct_runtime!`: `System` + the
  pallet + its dependencies, with test `Config` impls).
- **`pallets/<name>/src/tests.rs`** — per-extrinsic × error-path × origin-misuse tests
  through the closed wrapper set, limit/boundary coverage, and a `try_state` assertion
  (15 §4.1, §1). Audit-scope-A pallets (A1, A2, A11 — R-7) add the adversarial /
  rounding-against-the-claimant / solvency suites.
- **`pallets/<name>/src/benchmarking.rs`** + **`weights.rs`** — `#[benchmarks]` for every
  extrinsic and hook, a `WeightInfo` trait, a generated `weights.rs`, and the
  `runtime-benchmarks` feature. PoV-calibrated weights land with B5; the harness + stubs
  are part of the milestone.
- **`Cargo.toml`** — `frame-support` / `frame-system` / `frame-benchmarking` on the
  `polkadot-stable2603` pins (01 §9), the `std` / `runtime-benchmarks` / `try-runtime`
  features, and the `<name>-core` dependency.

Scaffold via `/new-pallet` (already emits this shape); `test-engineer` authors the 15 §4
suites; a `spec-reviewer` pass with no blockers precedes ✅ (R-6). Per-pallet FRAME wrapping
lives here; runtime-level `construct_runtime!` / `impl_runtime_apis!` assembly is B1a/B2.
