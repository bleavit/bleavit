It deliberately **refuses** an out-of-domain rate where the runtime waives it — 03 §5.3a(5) fails open because taking value on an unparseable record is worse, and 11 §11.5 rule 5 requires the opposite of a client, so the corpus row at `1_000_000_001` perbill is asserted from both sides. SQ-171 is **two fields**: `mayOfferParMerge` (the action, true when a pair exists) and `parCopyPermitted` (the copy, true only when the decomposition left no residue), because collapsing them is how the wrong one gets used. No fee anywhere on this path, asserted by absence — `redeem_void` and every `merge*` are exempt (03 §5.3a(1)). `src/features/tx/trade-ticket.ts` is §11.5's P-1/P-2 rows: the **fee cross-check** (the two published forms of one rate, agreeing under 02 §9 rule 4's floored projection, with neither preferred on disagreement), **FE-CHAIN-005** as an **exact** quote agreement rather than a tolerance (the port reproduces the runtime's integer path and `chain-quote-agreement.json` certifies the same base unit, so slack would admit a disagreement that is a defect), a balance row against the **charge** rather than the amount, `Trading`/`Extended` **only** (D-8), and P-2's three Baseline rows each failing closed when unread — with an absent book labelled reaped rather than priced at zero. (i) The inputs were `Verified<T>`, which admits `provider`, `stale-cache` and `external-proposal`, so a ticket assembled from an operator snapshot returned an **empty** block list — read by `mayPrepareTrade` as *every precondition passed*.
