**Unblocked and part-executed 2026-08-05.** Reading its spec before building found the matrix was **25 rows by name and 12 by text** — and the first filing of that (SQ-593) was itself partly wrong, which is the more useful half: **15 §3.3 enumerates all fourteen** E1–E14 by name, and SQ-1 had already ruled §11.12 canonical with §3.3 as its index. So the row *set* was never lost; what was missing was the **facet text**, and §11.12's pointer at doc 10 was a citation defect — doc 10 carries no E-row in facet form at all. **Ruled and executed under R-1:** the fourteen facet texts are now authored into 11 §11.12 (one home, as 15 §3.3 already says), each derived from the doc-10 section it exercises — §3.1/§3.2 boot and its four `FE-BOOT-*` codes, §2.2 never-promote, §5.2's compat lattice, §6's withdrawn *history-continuous* promise, §8.3's provider health ladder, §9.3's budgets, §2.4's checkpoint bound — and the doc-10 pointer is repaired to a *reasoning* reference rather than a text-ownership claim. **`tools/ci/check-degradation-matrix.py` is the control that was missing**: it counts the rows, requires E1..E25 contiguous with no gaps or duplicates, requires V/A/F on every row (L/U/R stay genuinely optional, so nothing is padded with an em dash to satisfy a checker), and cross-checks the set against 15 §3.3 **in both directions**. Fail-closed on a parse that finds few rows — and that mattered immediately: §11.12 carries **two row formats**, and the first parser swallowed ten rows into one and reported a matrix of 15. 5 mutations, all caught. **The client-side registry landed the same session, closing it.** `DEGRADATION_RESPONSES` is a `Record<DegradationRow, …>` over a **closed** union, so a row added to the spec is a **compile error** rather than a runtime fallback — a default branch would let an unscripted degradation ship silently, which is the whole defect. The row set is bound to §11.12 by the suite, fail-closed on a thin parse. Three fields, each earning itself: `says` is the client's own voice, `blocks` is **required even when nothing is blocked** so *"blocks nothing"* is distinguishable from *"nobody wrote down what it blocks"*, and `recovery` is a three-way classification whose `none` arm is a **claim** — asserted to be exactly E6, E14, E16 and E20, the rows where no retry helps, because getting it wrong either overstates the client's power or strands a user who could have acted. A response that suggests a retry for a row it classifies unrecoverable fails the suite: INV-FE-8's habit applied to copy. 5 mutations, 0 survived — the dropped-row one caught by the exhaustive `Record` type itself.
