No store distribution ⇒ INV-FE-8/-10 stay literally true. **Landed 2026-08-06.** The assertion is made **twice, in two languages**, because the build machine and the running binary are different places: `app/tools/desktop/` before a binary exists, `app/crates/embedded-tree/` before a window does. They cannot drift because they share a **corpus read in place** (`crates/embedded-tree/fixtures/self-check-cases.json` — the single-generator discipline the vector corpus follows), and it publishes file **content** rather than digests, so neither side's hash function goes unexercised. The comparison is `packages/verify`'s own `runSelfCheck`, whose doc comment already named Tauri as an intended caller; what it needed was a **narrower parameter** (`PinnedFiles = Pick<ReleaseIdentity, 'perFileHashes'>`), because a per-commit build legitimately has no Arweave address and unresolved readiness blockers — `parseReleaseDocument` refuses both, correctly, for reasons that say nothing about whether the map describes the tree. **The gate's first version was vacuous and that was measured, not suspected:** `assertPublishable` compares digests too and **throws on the first disagreement**, so running it first made `runSelfCheck` unreachable — the witness stayed green with the self-check replaced by a hardcoded clean verdict. The self-check now runs first and its findings are the verdict, 12 §1.2's gate runs only over a tree that already matched, and the witness requires each mutation to come back as an **enumerated finding of the right kind**, which a throw cannot satisfy. **`packages/platform` imports no host SDK at all**, a decision rather than an omission: the permission 10 §10.1 grants would force either host code into the web bundle or a second build path, and the second is what this milestone forbids. So the host arrives as an injected `HostBridge`, `only-platform-touches-host-sdks` has **no real edge anywhere in the tree**, and its whole liveness proof is `tests/depcruise-witness/forbidden-external.ts` — both spellings, since `EXTERNAL` takes an alternation and a typo in either arm leaves half the rule dead. The cruise path gained `src-tauri` and `tools/desktop` with the same milestone. **The shell cannot be built without the attested release tree** (`build.rs` compiles `release-out/release.json` in and panics naming the command that produces it — asserted by its own CI negative control), and it **refuses to open a window** on any divergence: exit `70`, no flag that downgrades it, no repair path, verified end to end on all three directions against the real binary. Two configuration facts were read off the pinned Tauri sources rather than assumed, and both are gated: a configured **CSP re-serialises every embedded HTML file** at build time, so `index.html` inside the binary would no longer be the file the release signed (the release carries its own meta-CSP per 12 §5.1); and `frontendDist` accepts a **URL**, which would mean application code arriving over the network. **Direct-download-only has no citation in `docs/architecture/`** and is recorded as a scoping decision — Decision log, 2026-08-06. **Reviewed (`spec-reviewer`, 2026-08-06): 0 blockers, 3 majors, 5 minors, 5 nits; eight fixed in session.** Fixed: the shell's refusal was **free text with no code**, which 10 §9 forbids outright (*"fixed user copy + expert detail + documented recovery per code; no free-text errors"*) and for which 14 TH-38 already assigns **`FE-REL-002`** — this shell is the family's first consumer; the binary's `None`-asset branch **substituted empty bytes**, and `sha256("")` is a real digest, so a legitimately zero-byte pinned file on an unserveable key would have *verified* (now `AttestationError::UnserveableAsset`, and moved into the pure crate where it is **tested**, since `Context<Wry>` cannot be constructed in a unit test and anything decided there is decided in code no suite runs); `lattice`/`meet` **defaulted an unrecognised state to `proven`** — the one direction a fail-closed lattice must never default to, and the functions exist precisely because the type is not enough; `unknownPlatform` reported `channel: 'web'`, which claims the service worker is checking these bytes (now a distinct `unknown` channel, with `SHIPPING_CHANNELS` carrying the no-store assertion); Tauri moved to `=`-exact pins, since `tauri-codegen` decides what bytes get embedded; plus the `check:chain-literals` scan root, a mislabelled witness case, and the INV-FE-12 misattribution (the owner is app-code rule 10 — INV-FE-12's subject is the *runtime* surface). **Named residuals, none of them regressions:** (1) the refusal reaches **stderr only**, which a desktop-entry launch shows nobody — a native dialog needs `tauri-plugin-dialog` and its capability wiring, and the copy is now a constant ready to move to whatever renders it; (2) `build.rs` compiles in **whatever `release-out/release.json` is on the build machine, unverified** — it proves internal consistency, not membership of the published release, and 12 §1.4's control against CI is that CI holds no minisign keys. **It cannot be closed today**: the keyring is empty pre-ceremony (0 of the §1.4 floor of two distinct keys), so there are no signatures to verify — it becomes blocking at the first download link, and F13 owns the verifier; (3) the `app` cargo workspace is **outside the advisory gates and the 12 §1.1 SBOM** (`--locked` is covered by the new CI job; `cargo audit` on it passes locally with 17 allowed warnings, and wiring a third workspace into the release-blocking summary schema is Track O work, not F22's); (4) INV-FE-11's panel has no desktop data source, which is true on every channel today; (5) the bundle icon is a 64×64 placeholder and `tauri build` (deb/AppImage packaging, signing, notarization) is not wired — F22 ships the shell and its assertion, not a distribution pipeline. **Six spec questions the review surfaced are named in the Session log** rather than opened as SQ rows, since each asks what the *doc set* should say about a distribution channel it does not currently describe. **Bot review on PR #252 — one P2, confirmed and fixed 2026-08-06.** `desktopPlatform` marked `embedded-tree-attestation` **`proven`** on the arm where the host reports a *divergent* tree. The arm is reachable by design: the adapter returns there rather than throwing, because INV-FE-8 surfaces divergence and never repairs it and a thrown adapter is a divergence nobody can render — so every surface guarded on that capability was enabled in the one state the host said the check had failed, which is app-code rule 10 inverted. The repair is a **derivation**: `embeddedTreeCapability` is a total `switch` over `AttestationState` feeding all three constructors, so the capability cannot fall out of step with the arm and a new arm fails to compile. Its absent reason names the divergence with an exact count, capped at three paths. **The same shape had two siblings in the same function**, both fixed in the same commit: `external-navigation` was `proven()` on the desktop channel — the web adapter's argument about *browsers* copied to a shell that registers no host plugin and whose `capabilities.json` is `{}`, so the control would have done nothing when clicked, and it is a reported `HostReport` field now; and a `reported-verified` report over **zero pinned files** was believed, the exact mirror of the empty-findings refusal beside it and a comparison that proves nothing, so it is refused (no honest release reaches it — `readPerFileHashes` and the Rust `attest` both refuse an empty manifest). Mutation-proven one revert at a time, rebuilding before each run: 3 tests fail on the literal, 1 on each sibling. No spec question: the capability set is F22's own, and 10 §13.4 already routes external-link availability to FE-P11 **Status held at 🔨 pending CI, 2026-08-07.** #252 marked this ✅ on its own branch and the claim is credible — its review finding is cleared and the App job's whole step list is green locally, 48 of 48. But R-6 makes ✅ a statement that the gates passed, GitHub Actions has been in a major outage since this work began, and not one run has executed. A local run is evidence; it is not the gate. Restore ✅ when this branch has a green CI run of its own. **✅ 2026-08-07.** R-6's two conjuncts are both satisfied: the R-6 review recorded above returned no blocker, and the gate evidence is PR #261 — all **23** checks `success` on `76477e3f`, squash-merged to `main` as `34cbf7a4`.
