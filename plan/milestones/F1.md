**FE-P1 resolved 2026-08-03 (V-87)** by reading the lockfile-pinned tree, same method as V-82 — 10 §5.2 asked for "exact PAPI 2.x names/semantics" and the answer changed F4's design in four places: the surface is `(await api.getStaticApis()).compat[group][pallet][member]` and **not** the 1.x `getCompatibilityToken()`; it exists only on `getTypedApi(descriptors)`, never on `getUnsafeApi()`; `isCompatible()` defaults its threshold to `BackwardsCompatible`, so **`Partial` is not a pass** and the client must not supply its own threshold; and an absent surface yields `Incompatible` with `isCompatible: () => false`, so absence is detectable and fails closed as INV-FE-12 requires. The trap worth carrying: with no descriptors supplied at all, PAPI reports the value side as `identical` — "fully compatible" while nothing was compared. **FE-P4's artifact-size half measured 2026-08-03 (V-88)** — smoldot 3.3.2 is **2.21 MiB gz** against the ≤ 3.5 MB budget, and the measurement produced a second finding worth more than the number: the browser path is a **buffer** `WebAssembly.compile`, so 12 §5.1's `'wasm-unsafe-eval'` is what lets the light client start in Chrome at all — dropping it is a total INV-FE-1 failure that every test here would stay green through, since nothing in this repository runs under a CSP. Now a standing gate (`pnpm run check:budget`), fail-closed on a moved package layout. Per-instance memory, sync latency, the 20 blk/s anchor, proof sizes and mobile CPU still need the device lab. **FE-P5 attempted and recorded as unanswerable from here (V-89)** — smoldot's JSON-RPC dispatch lives inside the wasm, so the JS package cannot confirm the method surface; but its stated *fallback* is already shipped by F2/F4, so the gate blocks nothing either way. FE-P2 + FE-P7 launch-critical; **FE-P11** gates F20's transport. **FE-P2's routing half is answered (V-82, 2026-08-03):** traced through the lockfile-pinned tree, a typed runtime call with no explicit `at` is issued as `chainHead_v1_call` pinned to the **finalized** hash, and `chainHead.js` carries no `state_call`/`archive_*` fallback for a runtime call to be proxied through. `"best"` is opt-in — so *never pass it on the transaction path* is now an enforceable code rule rather than an open question. The **execution** half rides the B7 drills, so 10 §4.2's per-domain conservative cross-check stays the default and `FinalizedReader.crossCheckedCall` is unchanged **FE-P11's load-bearing half resolved 2026-08-04 (V-104)** against the primary specifications, and the mechanism is the answer rather than an API-by-API survey: CSP fetch directives are enforced through exactly one hook — *Should request be blocked by Content Security Policy?*, at step 2.4 of **Main Fetch** — so a capability that never enters Fetch cannot be reached by `connect-src` whatever it does. Web Share transmits through the OS sharing mechanism (governed by Permissions Policy `web-share`, not CSP), the async Clipboard API operates on the system clipboard, and File System Access on the local filesystem; none of the three specifications mentions CSP at all. 10 §12 said a negative result here **blocks §13 entirely** — it is positive. The consequence cuts both ways and is worth carrying: because CSP structurally cannot see these transports, `check:handoff-network` is not a redundant second gate but the **only** mechanical control over egress on a handoff path. FE-P11's *first* half (`navigator.share({ files })` across the browser/OS matrix) still needs a device lab, so §12's conservative assumption stands: **clipboard and file primary, Share a fallback**. **FE-P7 is now scoped exactly by F11's pipeline** rather than described: the two-pass arithmetic is fixed and tested against a recording uploader, so what the dry run still owes is the live half — ANT n-of-m controller capability, undername immutability in practice, resolver endpoints, and manifest fallback behaviour. **FE-P6's load-bearing half resolved 2026-08-05 (V-122) — and it needed no hardware.** 10 §12 filed it as a hardware test; the pinned `frame-metadata-hash-extension` settles it instead. The digest is a **compile-time** env var `substrate-wasm-builder` sets only when metadata-hash generation is enabled, and mode `Enabled` without it is `UnknownTransaction::CannotLookup`. This runtime declares `CheckMetadataHash` in its frozen `TxExtension` stack but builds with `build_using_defaults()` and no `metadata-hash` feature, so **the chain rejects every mode-1 transaction today** — the hardware test would have shown a correct device and a refusing chain. Ruled **SQ-594**, routed to new milestone **B21** with both build values derived from 02 §8 (`"VIT"`, 12). What still needs a device is narrower and now says so: whether a Ledger app blind-signs when a chain offers no digest — the outcome the mechanism exists to prevent, so not a fallback this client may rely on. **FE-P2 — the pivotal gate — resolved 2026-08-05 (V-150), positively, and it needed no chain.** PLAN had it "riding the B7 drills"; the spec's own experiment was *"smoldot docs/source + wire-level test with a lying mock peer"*, and the **source** half is analysis. Read at `npm-smoldot-v3.3.2`, the tag the lockfile pins: `chainHead_v1_call` refuses an unpinned block (`-32801`), takes the `state_root` from the header **the client pinned**, and hands it to `runtime_service::runtime_call`, which verifies a peer-supplied call proof with `decode_and_verify_proof` and then resolves every access through `call_proof.storage_value(block_state_trie_root_hash, key)`, executing the runtime in smoldot's own executor. A hostile peer can **withhold** (→ `MissingProofEntry`/`InvalidCallProof`, a failed call) but cannot forge, because the proof must hash to a root the client already accepted with the header. So `FutarchyApi` on the tx path is verified state and **client-recompute-only mode does not stand permanently**. The lying-peer half adds nothing and the reason is the FE-P5 boundary again (V-89): the lie is caught *inside* the wasm, below the JSON-RPC line our mock transport replaces — a lying-peer test at our layer would exercise our mock. Two normative consequences written into 10 §4.2, and the second was not in the question: `system_health.is_syncing` is smoldot's own `!is_near_head_of_chain_heuristic()`, the only sync-progress surface there is, so it may inform a presentation and **never** decide whether a value is verified. Our code reads it nowhere — checked, not assumed. **Still open: P3, P5, P9, P10, FE-P6's device half, and the FE-P4/FE-P7/FE-P11 halves above — every one needs a device lab, hardware, a testnet run or Arweave credentials, not analysis.** **FE-P8 resolved 2026-08-05 (V-112) — the one gate here that was pure analysis, and it produced a normative section rather than a note.** 10 §12 asked for *"max safe release age before warning — analysis vs unbonding period"*. The threat is the standard weak-subjectivity one and it is **undetectable after the fact**: a client warp-syncing from a checkpoint at era `E` trusts the authority set at `E`, and once those validators withdraw their stake they can sign an alternative finalized chain from `E` for free — everything learned through the compromised sync is compromised, *including any figure that might be used to check the sync*. The bound is therefore **derived from the relay's own constants, not chosen**: `SlashDeferDuration = 27` eras is where the deterrent lapses, `BondingDuration = 28` is where the stake leaves, at 24 h per era — verified against both the Fellowship Polkadot runtime and the Paseo one, which **agree exactly**, retiring the real risk that one number was being shipped onto a testnet with a shorter one. New **10 §2.4** states three rules: at 28 days the client **MUST NOT** present anything as `verified-finalized` (refusal, and deliberately *not* `restricted` — those modes are for a runtime whose surface is partly unknown, this is a client that cannot establish which chain it is on); at 27 days it warns above the fold; and the age is measured against the **device clock**, because that clock is untrusted but *independent of the attacker's chain*, whereas asking the sync how old its own checkpoint is asks a possibly-forged chain to certify itself. A clock set **behind** the checkpoint refuses rather than reading age zero — that is the cheapest attack on the control. Implemented in `packages/verify/src/checkpoint-age.ts`; the figures travel in the release document, so a relay amendment moves the bound rather than needing a code change (10 §5.4). **6 mutations, 0 survived**, including the two that matter most: `indeterminate` sliding onto the passing side, and the bound being hardcoded instead of read. `test:verify` 19 → 26. **F1 reopened and eight of the eleven moved, 2026-08-07 — every one from a pinned or published source, and the parked note above was wrong to say no further analysis moves it.** The pattern is the finding. Each row's *Experiment* column is a **plan**, not a statement about what the answer needs, and a milestone note that repeats it as "needs hardware" turns a plan into a blocker. **FE-P1 is now genuinely resolved (V-301) — it was recorded resolved on two of its six halves.** V-87 answered the compatibility API and V-96 the pjs-signer exports. Four remained. `PullOptions.at` defaults to **finalized**, and `watchEntries` types only `{at: "best"}`, so its one spelled option is the unsafe one. `bestBlocks$` **may skip blocks** by its own docstring, so it cannot drive ingest. `getEstimatedFees` is `TransactionPaymentApi_query_info` at the finalized block, which retires 10 §2.3's self-qualification. PAPI signs `CheckMetadataHash` as **mode 0 unconditionally**, overridable only through `customSignedExtensions`, which is the hook B21 needs. **The code assumed a weaker answer than the gate now supports, and that is the defect worth the day.** `estimateFee` took a bare `bigint` while `nonceFor` two functions below took `Finalized<bigint>` and compared block hashes. 10 §2.3 names the fee estimate **explicitly** as a value that must be `Finalized<T>`, calling it *"the one an implementer is most likely to take from a wallet or an RPC"*. It now takes `Finalized<bigint>` and `Finalized<AdmittedRate>` and returns through `meet`, so two reads at two blocks yield no estimate. **9 mutants, 0 survived**, and the first pass of two was thrown away: they died to TS6133 on an unused import, which is a compiler kill that proves nothing, so both were re-cut to compile and the block-agreement tests killed them. `test:tx` 152 → 158, `test:firewall` 34 → 35 with a new `unsourced-fee-estimate` fixture. **FE-P5 is resolved (V-303) and it corrected 10 §4.2 rather than confirming it.** V-89 named the Rust source as the way in and V-150 then used that route, so it was available. `archive_*` is absent as claimed, but *"the `chainHead` group only"* was **false**: `state_getMetadata` and `state_call` take any hash at unbounded depth, proof-verified. The real wall is `chain_getBlockHash(height)`, refused for every height but genesis and best because a light client cannot verify a full node's answer. So backfill **by height is impossible** and §9.3's blobs are **required**, not a fallback. Provenance moved too: `smol-dot/smoldot` now redirects to an archive where the tag 404s, and the live tag is `paritytech/smoldot` `5fe9121f81a58454542ac69a44c4d73f00f30283`. **FE-P3's `startFromWorker` half is resolved negative (V-302)** — `@polkadot-api/smoldot/worker` uses the bare global `postMessage`/`onmessage` of a dedicated worker, which a `SharedWorkerGlobalScope` does not have, so no browser matrix could have said otherwise. The client already types `worker: Worker` and was right. **FE-P10's two size halves are resolved positive (V-305)** — `apply_authorized_upgrade` is Operational, so the ceiling is 5,242,880 B and a ~1.89 MB image uses 36 % of it; smoldot's 1 MiB cap is **inbound only** and never binds, because substrate never sends transactions to a `Light` peer; nothing bans a peer for size. **FE-P7's n-of-m half is resolved negative (V-304), and it is the most consequential.** An ANT authorizes by **membership**, so a controller list is 1-of-m and more controllers *widen* custody — the opposite of D-16. 12 §4.2's primary option is withdrawn and the threshold ceremony is now the only path. Alongside it: `ar-io/ar-io-ant-process` was **archived 2026-06-09** and ArNS now runs as Solana programs, so doc 12's controller addresses, `setRecord` calls and FROST-compatibility claim describe a system that no longer runs. Raised as **SQ-940** — it needs a user ruling and credentials. **FE-P9 is not blocked on a testnet at all (V-306)** — its D-Bulletin triggers T1–T4 exist only in `FRONTEND_PLAN §31`, which doc 00 superseded and which is not in this repository. A trigger with no definition cannot fire. Raised as **SQ-941**; retiring the row is the cheaper answer. **FE-P4's artifact figure re-measured (V-300):** 2.21 MiB gz, and the raw and brotli totals reproduce V-88 byte-for-byte while gzip does not — so a "MB gz" budget is toolchain-dependent and must stay a bound, never an equality check. **Status: 5 of 11 fully resolved (P1, P2, P5, P8 and P10's analysable scope), 4 more half-resolved (P3, P4, P6, P11), P7 half-resolved with a launch-blocking SQ, P9 recorded as blocked on a missing definition.** F1 stays 🔨 rather than ✅ for two honest reasons: SQ-940 is open, launch-blocking and was raised **by this milestone**, and no CI run exists for this branch yet, which is what R-6's gate conjunct needs. What genuinely remains needs a device lab, a live chain, hardware, or ar.io credentials. **A twelfth gate exists as of 2026-08-07 (F24): `[VERIFY — FE-P12]`** — whether a conforming archive node answers `Metadata_metadata_at_version` at arbitrary depth. 10 §8.5.1 declined to rest on *"an archive node retains historical state by definition"*, which is an operational expectation rather than a specification guarantee, so the claim is tagged rather than assumed and its consumer fails closed — the producer refuses any block it cannot decode instead of emitting it raw. It has an owner row in 10 §12 and it blocks nothing. Distinct from FE-P5, which asks the same question of the **light client**. Raised by the R-6 re-review, which caught that the tag had been minted with no §12 row and no milestone counting it.
