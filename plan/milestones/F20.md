D-21. Closed action vocabulary; no bytes-typed field; limits only narrow. **A capsule MUST carry a labelled book `kind`** (inherited from SQ-571): S21 exports the union of the S2/S3/S4 reads, and those now span both ledger domains, so an unlabelled capsule could put an external book's prices beside a governance market's with nothing distinguishing them — exporting exactly the endorsement 16 §1 says Bleavit does not sell. **Moved ahead of F7** by the handoff-first ruling — the format layer is now upstream of the screens, and S21/S22 moved into F7 with them. **Inbound core landed 2026-08-04 (31 tests, 2 mutations caught):** `packages/intents` — `bleavit.intent.v1`, the `FE-HANDOFF-*` family and the narrow-only clamp. This is the subsystem's attack surface, so the suite is about what the parser **refuses**; a handoff parser that accepts every well-formed document is trivially green and worthless. **The rule most easily got backwards is the asymmetry** 10 §13.2 mandates: an unknown key at the *top level* is tolerated (a producer annotation no consumer reads) while one inside `action`/`limits` is refused (`FE-HANDOFF-004`) — because there it is a *proposed semantic* and "precisely where an encoded call would be placed". Both halves are asserted on one document, so neither can pass for the wrong reason. Also pinned: **`FE-HANDOFF-009` stays retired** and the family is `001..013` *with the gap* — a reused code makes two failures indistinguishable in every record written before and after; a **newer** runtime is refused while an **older** one is admitted and rebuilt (an intent's version never selects an encoding); sizing is **collateral for a prepare, a ppm fraction for a close** and each refuses the other's field; amounts survive past 2⁵³ as decimal strings (the V-74 trap); a deadline is compared against **B′, the chain clock**; and every limit narrows only — a ceiling takes the minimum, a floor the maximum, with **asked and encoded both retained** so the difference is shown rather than silently applied. **`receipts` landed 2026-08-04** (`bleavit.receipt.v1`, 18 tests, 4 mutations all caught) — and the package exists for **the outbound half of 10 §13's third rule**, which is the half that breaks by writing the obvious code. *"Not outbound either, because a receipt containing call bytes teaches a naive tool to echo them back."* The natural source for a receipt is the `TxPreparation`, and 11 §11.4 rule 3 *requires* that object to carry `scaleHex` for the payload review — so spreading it in is one line that produces a document looking **more** complete and puts ready-to-submit bytes in a tool's context window, which a helpful assistant offers back next time, unrebuilt against current state. `buildReceipt` therefore **refuses** a bytes-shaped field rather than dropping it, since a silent drop leaves the caller believing it was exported until someone adds it to the projection *"so the export works"*. **My first scan was one level deep and the nested test is what caught it**: `Finalized<T>` is a wrapper, so every real payload sits at `outcome.value` — one level below where the obvious check looks, and exactly where an encoded call would travel. Two smaller repairs of the same shape: `assert.throws` does not return the error in `node:test`, so a `const error = assert.throws(...)` assertion chain was checking `undefined`; and the *nothing-that-could-pass-for-authentication* scan was a substring match that flagged `refuseUnverifiedExport` on the `verif` in *Unverified* — loosening it would have let `verifySignature` through, so it now matches the **leading verb** and carries a negative control. **Two placement defects fixed while wiring it.** `RECEIPT_DOMAIN_TAG` sat in `contexts`, contradicting that file's own stated rule (*"a tag is not a shared convention; it is the name of one document type"*) — the context exporter had no business emitting it; the tag and the cross-format separation test moved to `receipts`. And `ChainBinding` was declared in `intents`, the inbound package, while 10 §13.1 states the binding once for **all three** formats — its two copies would never meet in a call site, so a drift would have been invisible to the compiler rather than caught by it; it now lives in `handoff-envelope` beside the other §13.1 conventions. **`llm-handoff` landed 2026-08-04** (17 tests, 5 mutations all caught) — the 10 §13.4 transports, whose load-bearing rule is *"a capsule that does not fit falls back to clipboard or file automatically and is **never truncated**"*. A truncated capsule is the worst artifact this subsystem could emit: valid JSON up to the cut, still carrying a `schema` string, so a tool answers about the half it received and the user acts on amputated data — and **nothing downstream can detect it**, because the only check is the digest and nobody re-imports a capsule they pasted into an assistant. So truncation is **unreachable rather than avoided**: `chooseTransport` returns a discriminated union whose URL variant is built only when the whole thing fits, and no exported function takes a capsule and returns a URL string — which is the shape a caller would need in order to cut one down. Length is measured on the **encoded** URL, since every `\"` becomes `%22` and a capsule of JSON punctuation triples; the first fixture for that test was simply too short to demonstrate it and passed for the wrong reason until both halves were asserted. `maxUrlChars` is **per vendor with no default** — the limit is the minimum of user agent, OS and the vendor's own front end, and only the last is knowable from here — so an undeclared one **disables that vendor's URL transport** rather than selecting a number (R-2). `TOOL_VENDORS` ships **empty and the suite asserts it**: naming a vendor is a D-21 decision with a disclosure obligation, and with none seated **file and clipboard are the entire outbound surface**, which is exactly FE-P11's conservative posture reached from the other direction. `disclosure()` takes an **id, never a name**, because 10 §13.4 forbids a tool-supplied label in the confirm flow (*"Bleavit Official Assistant"* is the phishing primitive it names) — an unknown id returns `undefined` rather than falling back to the id, which would put attacker-chosen text on screen through the back door. **And `check:handoff-network` was fixed rather than worked around.** It matched raw text, so a module *documenting why it makes no network request* tripped its own gate on the word `fetch` — the same tokenizer hole this repo already paid for in `check-chain-literals`. It now blanks comments through the pinned TypeScript scanner, **comments only**: a comment is provably inert while a string is not, since `window['fet' + 'ch']` spells a banned identifier without writing it. The witness gained **two controls in opposite directions** and both were mutation-proven — a commented primitive must not be reported, and one inside a **string** must still be, because widening the blanking to string bodies looks like the same tidy-up, voids the gate, and every pre-existing assertion stays green through it (they all name their primitives in code). **The exporter and `schemas/` landed 2026-08-04, closing the row** (21 + 13 tests; 9 mutations on the exporter, 6 on the schema gate). **`buildCapsule` checks scope in BOTH directions, and the second is the one that lies.** The filter-only implementation cannot leak, so it looks safe — and it emits a capsule announcing `positions` and carrying none, which reads to every tool and every human as *this user holds no positions*: a false claim about the chain, made by the document whose only job is to carry true ones. So data outside the consented scope is **refused** (`FE-HANDOFF-012`, which until now was *defined and unreachable* — 0 emitting call sites) rather than dropped, and a consented scope with no read supplied is refused too. What makes the second rule implementable is the distinction `local-index` already needed for holes: **an empty array is data and an absent key is not.** A book's `kind` is **checked against its id band, never derived** — deriving it would export a label the user never saw on screen, trusting it would let a hosted book leave the app dressed as a governance market — and positions are keyed **by domain**, so rule 2's merged total has nowhere to live rather than being a rule to remember. Ids are parsed as `bigint`: the first test of that passed under a deliberately `Number`-corrupted parse and proved nothing (`bookId` is echoed verbatim, so no assertion depended on the value the bit test saw); the case with teeth is `2^63 - 1`, the **largest primary id**, which rounds *up to* the boundary as a double and is classified `service`. **The `FE-HANDOFF-*` family had two homes and their copy for 013 already disagreed.** `receipts` could not import the inbound parser across the §10.1 firewall, so it declared its own union and its own sentence — two answers to what one user-facing code says, in packages that never meet in a call site, so the compiler could not see it. The family moved to `handoff-envelope` (the same argument that put `ChainBinding` there) and gained the **`recovery` 10 §13.3 requires per code and nothing carried**: a refusal without one is a dead end dressed as an explanation, and unlike copy and detail it cannot be composed at the call site. **`app/schemas/` is generated from the parser's own declarations and byte-compared**, because the specific way a hand-written schema breaks is not a missing field — JSON Schema's `additionalProperties` defaults to **true**, so omitting it on `action` publishes the *opposite* of 10 §13.2's asymmetry to the one audience that is writing producers. The generator also fails when the parser declares a field the schema does not publish, which is the direction that shrinks the format to whatever was written down. `schemas:check` is only a determinism gate, so the **differential** suite is what makes the schema true — and it found a real defect on its first run: the schema published `limits` with everything optional while the parser **requires** a direction-matching monetary limit (a prepare states `maxCost`, a close `minProceeds`, each refusing the other). *"There is no safe default for money"* is a property of the **file**, so the schema was obliged to carry it; a producer following the published version would have emitted `"limits": {}` and been refused at the user, and a proceeds floor on a purchase is worse, sitting on the confirm screen looking like protection while binding nothing. The validator **throws on any keyword it does not implement**, with a negative control per keyword, because one that skipped an unknown keyword would make every assertion weaker than it reads while staying green

Epic IDs from 11 §11.13. FE-P1…P11 prototype gates from 10 §12 (+FE-P10/FE-P11, 11 §11.13).
Rooted at **`app/`** (10 §10.1, amended 2026-08-03); the `frontend/` placeholder is retired.

**Phase grouping** (2026-08-03). **Phase 0** = F19, the spec batch and its two proofs. **Phase 1**
= F0, F2–F6, F20, F21, F7, F10, F11, F22 — web + PWA canonical plus a **direct-download** desktop
Tauri build; no app store, no iOS, no Android, no Product target, therefore **no INV-FE-8/-10
amendment needed**, since store re-signing is the only thing that makes those texts false.
**Phase 2** = F7b, F8, F9, F12, F14, F16–F18 + mobile shells. **Phase 3** = the store question
(scope INV-FE-8/-10 to the canonical channel, add INV-FE-16 channel honesty) + the Product target,
which ships fail-closed read-only until PROD-1/PROD-2 pass.

**Handoff-first navigation** (user ruling, 2026-08-03 — 11 §11.2). The client's two *primary*
surfaces are **prepare a capsule** (S21) and **review/confirm/sign** (§11.3–§11.4 + S22); the
analytical depth and the whole FE-14/FE-15 set sit behind **Advanced**. This reorders Phase 1 —
the handoff packages and the Skill set (F20/F21) now precede the screens (F7) instead of trailing
them — and it is a **presentation change only**: every screen in the 11 §11.2 inventory still
ships, still works with no external tool present, and the no-infrastructure certification run
still executes with the handoff surfaces disabled. Demoting a surface is permitted; removing one
would falsify INV-FE-4 and the 15 §2.1 reading that admits the handoff at all. **Two consequences
are not free and are tracked, not assumed:** SQ-552 (the missing 09 §1.2 ↔ 11 §11.5 precondition
diff) now blocks a *primary* surface rather than a deferrable one, and doc 14's TH-74 residual was
re-assessed for its enlarged exposure (§3.9 preamble).
