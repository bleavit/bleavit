**Pipeline landed 2026-08-04 (66 tests; every gate mutation-proven; three adversarial Codex reviews at `gpt-5.6-luna`/`max` found 25 defects in it, all fixed — see the Current focus).** Vite **8.1.4** (the 01 §9 pin) with `base: './'` — load-bearing, since an absolute base makes every asset request leave the release directory and resolve to some other transaction's file on a path gateway, which is the one failure class where the app keeps working and stops being the app that was published. Seven ordered steps in `app/tools/release/build.mjs`, and **the order is the design**: the CSP substitution and SRI injection precede the service worker's baked hash map (which pins `index.html`), and `release.json` is written last (it pins `sw.js`, which the map substitution rewrote) — either backwards and the release ships a map refusing its own files, fail-closed *at the user*. **The `connect-src` allowlist is derived, never authored** (12 §5.1): §6.2 bootnode manifests projected from libp2p multiaddrs, the baked gateway set, release-listed providers/RPC — with an **absent** section refused while an **empty** one is 10 §8.1's opt-in posture, because a deletion must not read as the launch state. 15 §4.8's no-growth diff against a committed incumbent is the only mechanical form D-21 can take: nothing distinguishes an ar.io gateway from a vendor endpoint dressed as one, so the control is that an addition costs a second, reviewable file. **The worker bakes its hashes and fetches its cache name** — the map cannot depend on a fetch, and the name cannot be baked, because 12 §1.2 only learns the manifest TXID after uploading the tree the worker is part of; the fetched field needs no trust because it *names a cache and does not authorize a byte*, and it fails closed (absent ⇒ no install) rather than to a constant two releases would share. An unknown same-origin path is **refused, not forwarded**, since a worker that forwards what it does not recognise verifies only the paths an attacker did not invent; `release.json` is the single exemption, and only because its detached minisign signatures are stronger than a hash the worker could have learned only from the same response. **SRI is emitted only where a browser enforces it** and a skipped `rel=manifest` is *reported* — a decorative `integrity` is worse than none, because a reader counts it. The **determinism check reports rather than rewrites** (a normalizer that edits makes two environments agree by erasing the evidence they disagreed), and the **SBOM is read from the lockfile, not the installed tree** — the tree describes the machine, the lockfile the recipe, and their disagreeing *is* the failure an SBOM exists to expose — with no timestamp and no serialNumber, which would make it the one file differing between two builds of one commit. Also landed here: **the 10 §5.4 no-literal gate** (`check:chain-literals` + witness) and the **`MockSigner` release-exclusion assertion** over emitted chunks, the one 10 §10.1 rule dependency-cruiser cannot answer because it is about the bundle rather than the import graph. **Hardened after review:** the worker refuses a non-2xx body (a `404` carrying attacker HTML is a response the browser *renders*) and **re-verifies its own cache on read** (`caches` is same-origin storage any script can write, so a forged entry would otherwise be served as verified forever); the activate message requires an explicit `pinned` boolean, since a missing one defaulted to *not pinned* and overrode the user's own statement; the literal gate was rewritten on the **TypeScript AST**, which removed a whole class of tokenizer holes (`const open = "/*"`, `/[//]/`, template interpolation) and added constant folding for `1n << 63n`, `0x10000` and `2 ** 63` — the first of which app-code rule 8 names outright; `release.json` gained `releaseTxid` (the consumer required it and the producer never emitted it, while the test compared the producer to a list beside the producer); the two-pass driver now refuses a document that does not describe its tree digest-for-digest and binds the sibling TXID into the final manifest rather than re-uploading its bytes; and the SRI injector parses single-quoted and unquoted attributes and matches `rel` **token-wise**. Two suites were made real rather than the code changed: `worker-runtime.test.js` loads the **built `dist/sw.js`** into a `vm` and drives it, because a suite over pure policy stayed green with the worker's digest check deleted; and the allowlist gate is its own exported call, because asserting that the *diff function* reports an addition stays green with the `throw` removed. **Remaining:** the live Arweave adapter — `arweave.mjs` is a pure driver over an injected uploader and the Turbo-SDK half is **prototype gate FE-P7** (F1), whose `[VERIFY]` R-2 forbids resolving by assumption; and the ten **readiness blockers** `release.json` names (no seated bootnode operator, no gateway set chosen, no production genesis/chain-spec hash, no paraId, no keyring, version still `0.0.0`), each of which `--production` refuses on. Signing, attestation and the two-environment byte-identical proof are F13

(scope INV-FE-8/-10 to the canonical channel, add INV-FE-16 channel honesty) + the Product target,
which ships fail-closed read-only until PROD-1/PROD-2 pass.

**Handoff-first navigation** (user ruling, 2026-08-03 — 11 §11.2). The client's two *primary*
surfaces are **prepare a capsule** (S21) and **review/confirm/sign** (§11.3–§11.4 + S22); the
analytical depth and the whole FE-14/FE-15 set sit behind **Advanced**. This reorders Phase 1 —
the handoff packages and the Skill set (F20/F21) now precede the screens (F7) instead of trailing
them — and it is a **presentation change only**: every screen in the 11 §11.2 inventory still
ships, still works with no external tool present, and the no-infrastructure certification run
still executes with the handoff surfaces disabled. Demoting a surface is permitted; removing one
would falsify INV-FE-4 and the 15 §2.1 reading that admits the handoff at all. **Two consequences
are not free and are tracked, not assumed:** SQ-552 (the missing 09 §1.2 ↔ 11 §11.5 precondition
diff) now blocks a *primary* surface rather than a deferrable one, and doc 14's TH-74 residual was
re-assessed for its enlarged exposure (§3.9 preamble).
