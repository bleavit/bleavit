Corpus rejected by class, one code each. Under handoff-first this carries the analytical load the screens used to: it is where market explanation, visualization and strategy live, so its prompt quality is a **product** surface, not a sample. **Landed 2026-08-04** (16 examples + 2 generated instruction files + 1 release assertion; 8 mutations, all caught). **Two artifacts are generated, for the same reason.** The **vendor instruction files** are assembled from `SKILL.md` + `reference/`, because the identical safety rules must reach a directory-shaped Agent Skill, a ChatGPT instruction **text box with no filesystem**, and a plain prompt — three hand-written copies agree on day one and diverge at the first amendment, *invisibly*, since nobody diffs a ChatGPT instruction box against a repository, and a stale copy is a producer operating under the previous version of the safety argument. The generator additionally **fails on a surviving pointer** to a file the inlined reader cannot open, because an instruction that cannot be followed teaches the reader that instructions here are optional. The **examples** carry their expected verdict in the *filename* (`refused-FE-HANDOFF-004--foreign-key-inside-action.json`) and every one is run through the **real parser**: a published example that no longer does what it says is worse than none, since somebody debugging against a stale corpus concludes the client is wrong, and the natural next move — loosen the document until it passes — is exactly what `reference/safety.md` rule 7 exists to prevent. The label is in the filename rather than a manifest because a filename cannot drift from itself. **Coverage is asserted over the nine codes an inbound document can cause, and the exclusions are named**: `-011` needs live chain state at a refreshed block and `-012`/`-013` are export-side, so a corpus claiming them would be describing something it does not contain — the checker says so rather than letting *"we cover the family"* quietly become *"we cover the easy ones"*. **One scope call, made rather than deferred:** the skill and `schemas/` are now **copied into the release tree** (F11's pipeline, before anything is hashed, so the worker pins them). A skill nobody can obtain from the client they are running is not delivered, and the documented route would otherwise depend on fetching from a code host — the shape of dependency D-21 removes, even though 10 §13.5's convenience-only status means no invariant would have been falsified. The **ordering** is the part a bare copy step gets wrong, and both directions are mutation-proven: files copied in *after* the map is baked are same-origin paths the worker refuses, fail-closed at the user for no reason

**Phase grouping** (2026-08-03). **Phase 0** = F19, the spec batch and its two proofs. **Phase 1**
= F0, F2–F6, F20, F21, F7, F10, F11, F22 — web + PWA canonical plus a **direct-download** desktop

**Phase 2** = F7b, F8, F9, F12, F14, F16–F18 + mobile shells. **Phase 3** = the store question
(scope INV-FE-8/-10 to the canonical channel, add INV-FE-16 channel honesty) + the Product target,
which ships fail-closed read-only until PROD-1/PROD-2 pass.

**Handoff-first navigation** (user ruling, 2026-08-03 — 11 §11.2). The client's two *primary*
surfaces are **prepare a capsule** (S21) and **review/confirm/sign** (§11.3–§11.4 + S22); the
analytical depth and the whole FE-14/FE-15 set sit behind **Advanced**. This reorders Phase 1 —
the handoff packages and the Skill set (F20/F21) now precede the screens (F7) instead of trailing
them — and it is a **presentation change only**: every screen in the 11 §11.2 inventory still
ships, still works with no external tool present, and the no-infrastructure certification run
still executes with the handoff surfaces disabled. Demoting a surface is permitted; removing one
would falsify INV-FE-4 and the 15 §2.1 reading that admits the handoff at all. **Two consequences
are not free and are tracked, not assumed:** SQ-552 (the missing 09 §1.2 ↔ 11 §11.5 precondition
diff) now blocks a *primary* surface rather than a deferrable one, and doc 14's TH-74 residual was
re-assessed for its enlarged exposure (§3.9 preamble).
