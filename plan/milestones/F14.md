DB-2. **SQ-557 ruled 2026-08-06 — the budget numbers are re-derived and this milestone is unblocked.** 10 §9's load model was sized against 196 concurrently-observing books where the chain admits **31** primary (`epoch.slots·6 + 1`, 13 §5 item 4's own figure) plus up to **128** hosted, and it omitted `Traded` entirely although 02 §5 freezes the ingest set as `Traded` + `Observed` — at the runtime-pinned **93 fills/block** (70 primary + 23 external) that stream is ~160.7 MB/day, ~6.3× the sample stream, and it drains the desktop events share in 6.7 h. All **59** published cells are now re-derived in CI by `tools/ci/check-frontend-budgets.py` from 13 §1/§3.1/§4/§5 plus the runtime's pin, so the targets this milestone measures against cannot silently rot again. **The measurement half landed 2026-08-06 and takes §9.4 from one enforced row to five of thirteen**: initial JS and smoldot were already gated (re-verified wired *and* bound), and F14 adds release-shipped fallback metadata plus chain specs (`app/tools/check-artifact-budget.ts`) and **first meaningful render** (`app/tools/render-budget/check.ts` — Lighthouse 12.8.2 over the built release tree on §9.4's own reference profiles, median of 3; measured desktop **0.40 s** and mobile **1.80 s** FCP against 1.5 s / 3 s p50 targets). Every threshold is read from its published cell and nowhere else, **including §9.4's reference-hardware sentence** — its 4× desktop throttle and its Moto-G-class device are values, not prose, and Lighthouse's desktop preset is 1× so that override *is* the reference machine (V-179). Both new gates carry witness legs (5 artifact cases, 1 render case), plus 8 hand-run render mutations and 17 new mutation tests in `tools/ci/tests` (48 in that file, 262 in the suite). **PR #254's review round corrected both new gates, and neither defect was a wrong number (2026-08-06).** Codex filed two P1s and both are this milestone's own defect class — a gate measuring something other than what it claims — so `check-frontend-budgets.py` proving both gates carried their published cells proved nothing about either. **The render gate compared a three-run median against the p95 column**, which tests the wrong statistic: samples of 2 s, 2 s and 20 s have a 2 s median and pass a 6 s p95 threshold while a third of the sample sits over three times above it. It now gates the sample's **p95 tail** against p95 and its median against p50; at three runs the nearest-rank p95 is the slowest run, so the comparison errs toward refusing (`app/tools/render-budget/statistic.ts`, boundary at nineteen samples, not twenty). **The chain-spec gate weighed source paths under `REPO_ROOT`** and nothing copied those into the bundle — `connect-src.ts` opens them at build time for bootnode multiaddrs and `build.ts` never emitted them — so a release could pin a hash, name a file, be weighed, pass and ship no chain spec for a browser to boot from. `build.ts` now emits declared specs into `dist/chain-specs/` before hashing, so the service worker pins them, and the gate measures the emitted tree: declaration ⇔ emission in **both** directions plus every pinned role matched by SHA-256, the comparison the client itself makes at boot. The empty case still requires the readiness blocker to stand and now requires the emitted tree to carry none either. Found while binding the roles: §9.4 budgets **three** specs and the format pins **two** — the Asset Hub spec has no pin slot though 11 §11.9.1 boots a light client against it (**SQ-720**, now a mechanically expiring readiness blocker). New `app/tests/budgets` suite (18 tests, mutation-proved: five reverts, each caught by exactly the intended case), the artifact witness grew 5 → 8 cases plus a positive control, and `check-frontend-budgets.py` binds the published run count (60 cells, 4 new mutation tests). **Not ✅ — eight rows stay unenforced, each on an artifact this repository does not have rather than on work this milestone declined.** *First verified current-state render*, *ingest throughput*, *per-refresh proof traffic* and *finalized-head refresh work* all need a chain the client can boot against, and it can boot against none: `release-sources.json` pins no chain-spec hash, no genesis and no para id (four standing readiness blockers), and `app/fixtures/chainhead/` is 222 transcripts at **one pinned block**, so there is no second head for a refresh to be measured across. *IndexedDB growth* was blocked on a quota manager with no module. **That sentence went stale and is corrected here (2026-08-09):** `packages/local-index/src/quota.ts` is the §9.2 quota manager, and it computes `budgetedDays` — days the tier's share admits **at the measured rate** — which is §9.2's *"computed from the measured ingest rate; there is no fixed '90 days' promise"* as a number rather than as a sentence. What still blocks the row is the measurement apparatus, not the code under it. A row asserting a false absence is the same debt as one asserting false completion, and it is worse for being believed: it invites the next session to rebuild what exists. *Memory desktop*, *memory mobile* and *mobile CPU* need the physical device lab §9.4 names and a Playwright probe that is not installed. Six of §9.4's rows carry `[VERIFY]`/FE-P3/FE-P4 tags and five of those six are in this blocked set; the sixth is smoldot, measured under V-88. The chain-spec row is measurable-when-declarable rather than blocked: no chain-spec bytes are committed for any chain, so its gate requires the readiness blocker to still stand and **fails the moment a spec hash is pinned with nothing to weigh**
