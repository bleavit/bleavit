**Raised 2026-08-06 by the R-6 re-review of F9, and it answers the half of SQ-614 that F23 does not**: F23 owns §8's *screens*, this owns §8's *wire*. It exists so F9's Spec column can name its exclusions with an owner instead of citing §8.2 whole — a citation with unnamed exclusions is what makes a narrowing unfalsifiable. **All three were blocked on spec silence, and all three silences were this session's to break** (2026-08-07). The park read R-2's ban on *fabricating* a value as a ban on *deciding* one, which R-1 delegates to the session — so SQ-612, SQ-613 and SQ-771 are ruled in the new **10 §8.5**, each derived from a constraint §8.2/§8.4 already imposes rather than selected: the `archive_v1_*` group because §8.2's *"reproducible byte-identically by anyone"* is a promise to **second producers**, who can only hold a producer to it against a versioned contract, and the legacy `state_*`/`chain_*` pair fixes neither pagination nor truncation (the `chainHead_v1_*` sibling the browser client speaks is corroboration, **not** the derivation — §4.2 constrains that client and does not reach a producer running against an archive node; stated the other way round until 2026-08-07); a document the **reader** pins by block hash while the document itself states heights, since §6.3 refuses a provider range carrying a hash; completeness **established** rather than inferred, because the interface specification is silent on early termination (V-343); an indexer serving §8.2's own document restricted to a range, so it is not a second format — on canonical serialization alone, **not** on `FE-PROV-004`, which §8.4 scopes to two independent *snapshots* and which therefore never diffs a snapshot against an indexer; and `unprobed` as a state before the ladder that serves nothing. **§8.5.3's probe driver is built and green** — `packages/providers/src/probe.ts`, 15 tests, and two mutants (drop the wrong-chain check, drop the disabled-source filter) each killed by exactly the test that names them. It contributes one property neither `probeDue` nor `afterProbe` could: a `disabled` source is **never contacted**, because the request is itself §8.1's disclosure and `afterProbe` only discards the answer after it has already been sent. **The consequence, stated rather than discovered later**: with no probe driver a source accepted from §8.1's list stays `unprobed`, so `runSamplingRound` — gated on `canServeReads` since 2026-08-06 — cannot run in production at all. The snapshot import is deliberately **not** gated on the probe (`canSupplyPinnedImport`, SQ-773), so the file half of §8 works today with zero infrastructure, which is what INV-FE-4 requires of it **All three artifacts are built (2026-08-07) and F24 stays 🔨 pending the R-6 re-review, because the first review returned 2 blockers and R-6 needs a review that returns none.** Both blockers were reproduced against the real artifacts before being accepted, and both were in the specification written that morning rather than in the code under it. **B-1: §8.5.1 contradicted §6.3.** It said a snapshot pins its range by block hash; §6.3 states the opposite as fact and *refuses* a provider range carrying one, and the shipped `SnapshotRange` is two numbers. The hash now pins the **reader**, so two producers do not race a reorg, and the document still states heights. **B-2: a wrong-chain answer GAINED the source read eligibility.** Reproduced against the built code: `unprobed` cannot serve, a wrong-chain probe returned `failed`, `afterProbe` correctly declined to ratchet on one failure and returned `failing`, and `canServeReads` correctly lets `failing` serve — so a source that had just proved it serves another chain went from not-serving to serving. Every function was right alone. `ProbeOutcome` gains a `disqualified` arm that disables at once, on §8.3's own precedent that *"auto-disable on sampling mismatch"* is uncounted. The test that catches it asserts at the **round** level; asserting the outcome kind passed throughout. Six further majors fixed and four new rulings made (11 E10's re-probe contradiction, the screens a page owes, `GET /chain` for every endpoint-bearing provider, and §8.1's disclosure naming the ten-minute heartbeat — that last one changed normative copy and broke **no** test, so its binding test was added with it). Three findings filed rather than ruled: **SQ-982, SQ-983, SQ-984**. **Second round, 2026-08-07 — the six review majors, and the first of them made the route unusable.** `readRange` and the reference server both ran `admitSnapshot` over every page, so §8.4's conservation replay — zero start, non-negativity at each step — refused **every span that did not reach back to genesis**, and the server answered `500` to conforming requests. §8.5.2 had already ruled that a page does not owe the replay; the code never caught up, so M2/M3/M4/M6 were code lagging a spec that was already right rather than open questions. **Being precise about the ruling changed the answer twice.** §8.4 names its three internal-consistency screens in one phrase, which reads as taking all three: **monotone coverage stays** (internal to the document, satisfiable mid-history, and load-bearing here because `readRange` builds a caller's coverage from the union of what the pages carried). And the derived-row check does **not** drop for the replay's reason — reading `checkDerivedRows` showed it compares `balances` against the fold of the document's *own* ops, a self-check that survives a restriction untouched. Chasing that forced the ruling that had been missed: **what a page's `balances` mean.** §8.5.2 assigns this route to §8.4's 1-in-16-page sampling, which re-verifies rows *against the chain*, so they must be state at the page's last block — and `optional/indexer/README.md` documented the exact opposite as an operator rule. **That inversion exposed a live defect in the composition**: `samplingPages` feeds `balances` into a chain comparison, so a folded balance is a mid-history subtotal held against a current holding — disagreeing on every honest page and auto-disabling the operator that served it (§8.3's *"auto-disable on sampling mismatch"* is uncounted and immediate). Unreachable only because the *other* defect masked it: mid-history pages were refused before they could be sampled, and on a genesis-anchored page fold and state coincide. Two defects, each hiding the other; fixing either alone ships the other. New `admitIndexerPage` shares `screenDocument` with `admitSnapshot` and returns a deliberately **unbranded** `AdmittedPage`, so a page can never reach `mintSnapshotRows` — verified: `ADMITTED` is a non-exported `unique symbol`. `RangeOutcome.failed` split into `unreachable` (nothing arrived, no code — `FE-PROV-003`'s fixed remedy tells the user to check a download that does not exist) and `rejected` (a document arrived and failed a screen it owes, carrying `FE-PROV-003`). M5: `ProviderCannotServeError` told callers to advance the ladder from a data read, which §8.5.2 forbids. M4: `archive-read.ts` led with the §4.2 derivation, which does not reach a producer running against an archive node — §8.2's reproduce-by-anyone promise does. Composed, **every honest row mismatches**, and §8.4's *"any mismatch"* rule auto-disables the operator that served it. Each function was right about its own half. Fixed by injecting the whole projection — `reference` and `claimed` must come from **one** function because they must come from one metadata view, and two seams could be filled from two runtime versions. **B-2: `foldedSlice`'s remaining scope was overstated.** It folds only the movements inside the span it was handed, so it equals the holdings at the page's last block **only when the page is the whole history** — page two of even a splits-only history disagrees. The README said *"the genesis-anchored case"*, which is reassuring and wrong. **The referential half of the replay should not have dropped.** §8.5.2's argument reaches non-negativity and nothing else, and the replay's *"does this document declare the vault it moves"* and *"does that vault have this branch"* checks are as internal as monotone coverage. Dropping the replay whole left `ops` — the field layer-3 actually ingests — with **no referential check**, and sampling is no compensating control for it because sampling projects `balances` and never reads a movement. Now split: the fold and the declaration checks run for both callers, only non-negativity is snapshot-only. **`FE-PROV-003`'s fixed copy was false for a page** — *"This snapshot was rejected and nothing was imported"*, with remedies telling a user to check a download and compare a publisher's hash, for bytes that had no download and no publisher. The same defect that deleted the `incomplete-check` cause on 2026-08-06, arriving from the other side.
