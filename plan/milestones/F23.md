**Answers SQ-614, which asked which milestone owns §8's ten unconsumed obligations — this one does.** F9 owns the mechanisms and `tools/snapshot`; every one of them exists, is wired to the ones beside it and is tested, and each is still a function nobody calls, which is the state that looks finished in a status table and is not. The split is where the 10 §8 obligations actually divide: F9's half is checkable without a screen (does the format admit this file, does the ladder disable on a mismatch, does the mint label the row), and this half is only checkable with one (does a user *see* the origin, the gap, the guarantee and the eviction before they agree to it). **INV-FE-3's last clause is the load-bearing one and it is a screen obligation by construction**: *"any actionable provider-supplied object triggers a direct chain fetch before the action is enabled"* needs an action surface to attach to, and until one exists the invariant has no place to hold. Two rows here are refusals rather than displays and should be built as such: the all-down state is §8.1's ordinary posture with an explainer and **not** an incident banner (`fleetState` already distinguishes *never enabled any* from *all of them are off*), and the guarantee copy must ship with its unflattering half or the client is claiming a guarantee §8.4 declines to make. Depends on F7b for the surfaces these attach to and on F8 for the store the mint's rows are written into. Not blocked by SQ-612/SQ-613 — those are the archive adapter and the indexer wire format, neither of which any screen here needs (they are **F24**). **It gained the two §8.4 chain readers on 2026-08-06**, after the R-6 re-review found F9's row overstating what landed: `chainSpotCheck` imposes the ordering and performs the comparison, and **nothing in the repository turns `System.Events` into `SnapshotOp`s**, so every caller of `BlockMovementRead` is a test closure and the same is true of `ChainRead`. They belong here rather than in F9 because they are chain reads composed against a light client this package may not open (10 §4.1) — the same composition INV-FE-3's actionable-object fetch already needs — and rather than in F24 because they read **this device's own chain**, not a provider's wire. Until they exist, §8.4's re-derivation cannot reach a chain in production, which is the state that looks finished in a status table and is not. **`BlockMovementRead` carries a stated contract as of 2026-08-06, and it is an obligation of this row rather than a note about it.** §8.4's walk takes the **side** of every out-of-reach answer from the reader and stops on `below-window`, so the reader — not the walk — is now what the screen's correctness rests on, and the failure direction flipped with the delegation: the old inference failed toward **refusal**, and a wrong reader fails toward **admission**, returning a document with `compared: 0`, no finding and the blind-spot disclosure that an honest deep-history pass is indistinguishable from. Four things the implementation MUST satisfy: **(1)** the blocks it serves are **one contiguous interval**, with no hole, because the walk's early stop is justified only by that; **(2)** the interval sits at **this device's head**, and its top is the head; **(3)** the side is derived from **this device's own head and pinned floor** and never from the document, which the signature already enforces (a block number is all it receives) and which it must not undo by consulting anything else — `below-window` only below the floor, `above-window` only above the head; **(4)** it does not throw for a block inside its own window, since a throw aborts §8.4's whole pass rather than one block. **F9 ships the executable form**: `checkBlockMovementRead` in `@bleavit/providers/testing`, which sweeps the declared window with two blocks of margin at each edge and reports every violation, including the three conditions `chainSpotCheck` throws on and a re-ask for determinism. Wire the production reader to it in this row's suite; it is a test this row inherits rather than a paragraph it has to re-derive. `ChainRead` has no equivalent yet and should get one on the same argument. **`SpotCheckReport.reach` became a named deliverable of this row on 2026-08-07**, after F9's R-6 review found that the field has no consumer anywhere — which makes F9's *admit rather than refuse* choice circular, since the justification for admitting is that the limit is **disclosed**. **The collapse is at the badge and it is measured** (`app/packages/ui/src/badge.tsx`): a `provider` status carries exactly two per-row channels, the id and `sampled`, so a row from an honest deep-history snapshot (`window-floor`, `compared: 0`), a row from a document ahead of this device's head (`above-window-only`, `compared: 0`) and a row from a pass that spent its whole ceiling above that head (`ceiling`, `compared: 0`) all render byte-identically as *unverified — X* with no spot-check clause. `SpotCheckReach` exists so those three stop collapsing, and it collapses again one layer up. **What each arm must say:** `whole-document` — every covered block inside reach was compared, and it is the **only** arm a screen may read as *fully re-derived*; `window-floor` — the walk left the bottom of this device's window, the remainder is **permanently** unreachable here, and the second-producer diff is the only cross-check there will ever be; `above-window-only` — nothing was compared because the document sits ahead of this device's head, which is **transient** and closes on sync, so it must never be told as the permanent one; `ceiling` — the mandated set is genuinely unfinished, this is a disclosure rather than a refusal (SQ-811), and the rows are not badged `sampled` however many blocks agreed. **A fifth situation the type cannot express, and the screen must:** `spotCheckSnapshot` rewrites `whole-document` only when `outOfReach > 0`, and `checkCoverage` admits an empty `coverage` array — so a document covering no blocks ends at `whole-document` with `compared: 0`, the arm whose own description requires at least one comparison. The reading is therefore a total function of the arm **and** the counts, five readings over four arms. **The surface landed 2026-08-07 on `track-f/f23-provider-surface`** as seven modules in `app/src/features/analysis/src/` — the first consumers `@bleavit/providers` has ever had, since nothing in `app/src` imported that package at all. `spot-check-reach.tsx` (the five readings, the counts rendered on **every** arm so `compared: 0` is never shown bare, and `wouldBadgeSampled` bound to `mintSnapshotRows`' own expression by a parse of both files rather than a restatement); `provider-panel.tsx` (§8.3's ladder with its required reasons, `fleetState`'s three arms, `failing` rendered **beside** `serving` so a fleet of timed-out sources cannot read as *N serving*, and `NO_PROBE_DRIVER` stating that this release drives no probe at all); `provider-suggestions.tsx` (§8.1's list, empty with its reason rather than a blank region, and an accept interstitial that **derives** the disclosure and renders it above the control); `snapshot-import.tsx` (streamed progress, the eviction preview with **no confirm control at all** on the infeasible arm, and every `ImportOutcome` arm including both refusals when the chain is what disagreed); `snapshot-crosscheck.tsx` (`no-overlap` as its own non-agreement, and a `disagree` arm with no control that picks a side); `coverage-view.tsx` (§6.3's holes, §9.2's downsampled labels, the migration discard, and **distinct sources named** rather than gaps counted); `provider-action.tsx` (INV-FE-3's actionable-object fetch, structural: `onAct` takes `Finalized<T>`, so the provider-supplied value has no path to the action). **28** suite tests in `app/tests/analysis/provider-surface.test.ts`, **27 mutants, 0 survived** (7 first written in forms `tsc` rejected — every one an orphaned import or parameter — and re-run as forms that compile). *(This cell read **36** and the file carried **27**; The status cell read ⬜ over seven landed modules, a suite and a mutation round, and is now 🔨.)* **The R-6 review of this row and F25 landed 2026-08-07 — 1 blocker, 2 majors, 11 minors; the blocker, the first major and two minors are cleared on `integration/track-f-v2`.** The **blocker** was `coverage-view.tsx` rendering a `checked` edge as *"both are checked against the chain"*: §6.3 defines that arm as *"all three checks **can** run"*, the verdict lives in `CoverageVerification`, and `CoveredHistory` carries none (V-340) — so the same range read as *checked against the chain* here and as *"Ranges this client could not check"* on F25's boot surface, every range in fact verdicting `unchecked` because no genesis is pinned (V-260). The column now states what the edge **records** and `EDGE_IS_NOT_A_VERDICT` says beside it that the answer carries no verdict; whether a history query must instead carry one is **SQ-980**, filed and not settled. **The `checked` branch had no fixture** — every coverage fixture used an `unverifiable` edge including on a `self` range, a combination §6.3 does not describe — so `self` ranges now carry a `checked` edge and the note is asserted both ways. **Major 1** was `SAMPLING_GUARANTEE` saying *"two independent sources"* where §8.4/§2.3 say *"two independent snapshot producers"*, which names a cross-check `FE-PROV-004` does not implement, with the `tests/providers` clause table paired against the substituted rendering (V-342) — the second time that table was scoped around its own drift. Copy fixed, pair re-pointed, and this row's check gained the **constant → document** direction it lacked. **Minor A**: the badge assertion `badges.size === 1` could not fail — three byte-identical arguments to a pure switch — and now derives its statuses from `mintSnapshotRows`' own output (V-341). **Minor B**: `distinctSources` now delegates to `boundarySet`, so §6.3's boundary set has one implementation and the human phrasing one home. **Remaining on this row, and it is most of the row:** the **two §8.4 chain readers** are unwritten, so `chainSpotCheck` and `chainRowCheck` still have no production producer and the executable contract `checkBlockMovementRead` still has nothing to be wired to; the **layer-3 write** of the minted rows is unwritten (the mint returns rows and `local-index` owns the database, and nothing joins them); and §6.3's coverage rendering exists as a component with **no history query calling it**.
