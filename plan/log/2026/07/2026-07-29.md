## **E1 — PR #195 review round 3: a hole in the custody return itself**

Three more findings, and the first is the most consequential spec defect of the session because it **would have recreated the leak E1 exists to close**. **08 §8 step 5(b) scoped the custody return to complete LONG+SHORT / YES+NO sets**, on the reasoning that a set is worth exactly one branch-USDC. True of a set, false of the book's inventory: after any asymmetric walk the book holds complete sets **plus an unmatched residual leg**, because delivery removes single legs while revenue recycling mints pairs. At an interior `0 < s < 1` that leg redeems for `floor(a·s)`/`floor(a·(1−s))` — strictly positive — and 04 §2 classifies whatever Sweep leaves as worthless and lets reap discard it. So the set-only return would have sent that value to ledger residue and on to `INSURANCE`. Not an edge case: the residual leg is the same inventory whose value makes realized cost `b·[ln 2 − H(p)]` rather than the whole seed, so discarding it drives realized POL cost toward the full commitment — the ≈1.79M USDC/yr error §10.5 quantifies. **Corrected in 08 §8(5b), 04 §2 + §10 + §11, 02 §5/§6 and 15 I-33: every *realizable* position returns — pair call where a pair exists, then unmatched legs individually, leaving only provably zero-payout positions for reap.** **(2)** Four more 02 metadata rows (ExecutionGuard, Epoch, Welfare, FutarchyTreasury) still claimed `= 17` while the Constitution row said 16-in-force — my round-2 fix was partial and left the table self-contradictory. **(3)** The v17 entry claimed no storage-item changes, which is impossible: `sweep_redemption_fees` needs `RedemptionFeesAccrued` and `sweep_revenue` needs the durable swept marker.
