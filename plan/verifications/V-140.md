## Item

**`finalize` was exported from the `chain-client` barrel — the transaction path could mint `Finalized<T>` from any value, and the fixture asserting otherwise tested the side door**

## Spec ref

10 §2.1, §10.1–§10.2; 15 §2 INV-FE-1

## Status

**confirmed by compilation and fixed 2026-08-05**

## Result

Found while migrating `tests/receipts`/`tests/contexts` into `check:types`: the suites could not build a `Finalized<T>` fixture, which is the property the brand exists for — so the question was how production code *does* build one. `index.ts` carried `export * from './provenance.js'`, and `provenance.ts`'s own doc comment claimed the opposite (*"not exported from the package root … see the package `exports` map"*); the `exports` map restricts nothing of the sort. **Measured, not reasoned:** a file in `packages/transaction-builder/src/` calling `finalize({free: 999_999_999n}, {blockHash, blockNumber})` compiled clean (exit 0), with two controls — a deliberate type error in the same file failed, proving the probe was compiled at all, and the same value as an object literal was rejected, proving the brand itself works. `transaction-builder` and `signing` both depend on `@bleavit/chain-client`, so the transaction path held the capability. **Neither sibling control could see it**: `check:casts` looks for `as Finalized<T>` and there is no assertion, and dependency-cruiser looks for a forbidden edge and reaching `chain-client` is exactly what those packages may do. **This is the third instance of one defect class and the first two are why it is worth naming:** `isFinalized` asserted a brand it could not check (V-81) and `selfRange` minted `origin: 'self'` from three plain numbers — both caught, while the primary mint site stayed open, though `Finalized<T>` decides what may be *signed* where `origin` decides only what renders. The corpus made it worse than an oversight: `deep-import-past-exports.ts` exists to prove `finalize` is unreachable, has always passed, and tests a deep path past the `exports` map — a locked window beside an open door, its comment even citing a `./testing` export the package did not have. Repaired by explicit barrel exports (types plus `meet`/`hasFinalizedStatus`/`readmitFromLeader`, all of which need an existing `Finalized<T>` or return no brand), a new `@bleavit/chain-client/testing` subpath following the `signing/testing` and `local-index/testing` precedent, and the rule `no-finalized-minting-outside-chain-client`. **Four controls, each mutation-proven:** the barrel now fails with **TS2724** (measured — not the TS2305 I would have guessed, because `Finalized` is still exported and is offered as the near-miss), pinned by a new corpus fixture; the deep path still fails TS2307; the subpath fails dependency-cruiser from production code (mutation applied to `transaction-builder/src/index.ts`, rule fired, tree restored); and a hand-rolled re-implementation needs `as Finalized<T>`, which `check:casts` catches (mutation applied, gate fired). The witness gained its own line, separately rather than inferred from the two sibling subpaths, since `WORKSPACE_SUBPATH` is parameterised by specifier *and* dist path.
