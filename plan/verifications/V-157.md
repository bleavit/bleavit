## Item

**`only-chain-client-opens-a-chain-connection` could not see the scoped spelling of a provider — `@polkadot-api/ws-provider` was reachable past a CI-fatal rule**

## Spec ref

10 §2.1, §4.1, §10.1; app-code rule 13

## Status

**fixed 2026-08-05**

## Result

Found while costing F18's next step, which needs a hashing primitive that lives in `@polkadot-api/substrate-bindings`. The rule's matcher was `EXTERNAL('polkadot-api|smoldot')`, whose bare arm is `^(polkadot-api|smoldot)(/|$)` — **anchored at `^`, so it cannot match a specifier beginning with `@`**. PAPI's providers are separately published, separately installable scoped packages (`@polkadot-api/ws-provider`, `@polkadot-api/sm-provider`, `@polkadot-api/smoldot`), all three already in this repo's pnpm store as transitive dependencies. **Measured, not reasoned**: adding both scoped specifiers to the witness produced `witness-could-not-resolve` and nothing else — neither `witness-external-package-matcher` nor `witness-polkadot-api-non-signer-matcher` fired. That single surviving rule is the trap, because it fires *because the package is not installed there*, and declaring the dependency — exactly what a package does in order to use one — is what makes it resolvable and silences it. So a package could have added `@polkadot-api/ws-provider` to its own `package.json`, opened a WS provider, and passed both firewall gates: `tsc -b` resolves a declared dependency, and the rule could not match. What it still could **not** do is mint `Finalized<T>`, which is separately guarded — so this is a hole in the connection rule, not in the provenance one. **Third instance of V-86/V-92's class in these same matchers**, which is why the repair is a **wildcard with a named exception** rather than a list: an enumeration of provider packages goes stale the first time PAPI publishes another, and goes stale silently. The exception is `@polkadot-api/descriptors`, which is not external at all — it is this workspace's `packages/papi-descriptors` under its generated name, carrying type data and able to construct nothing — and it is verified by a negative control rather than assumed. `POLKADOT_API_NON_SIGNER` needed the same scoped arms, since `packages/signing` is exempted from the connection rule *by path* and that pattern is then the whole of what stops it reaching a provider. **The residual drift this closes is subtler than the hole**: the witness already imported `EXTERNAL` from production *"rather than restated"*, but passed its own copy of the **argument** — so the pattern could not drift and the package list could. Both now share `CHAIN_SDK_PACKAGES`.
