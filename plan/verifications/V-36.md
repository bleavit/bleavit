## Item

**First real execution of the committed Zombienet environment (G1)** — the B7 definitions had never been run end-to-end

## Spec ref

15 §4.7; 02 §11

## Status

verified 2026-07-18

## Result

Four executable-infrastructure facts established against the pinned stack: (1) the zndsl grammar accepts no `#` comments and requires `Creds: config` — all 9 committed drills were unparseable as authored; repaired, all 9 now parse. (2) Every Zombienet timeout (toml `[settings] timeout`, DSL `within N seconds`) is 32-bit signed milliseconds — values > 2,147,483 s silently overflow (the 6,000,000 s network timeout had collapsed to a 1 ms watchdog); drill 09's soak wait split into three ≤ 2,000,000 s steps. (3) substrate-wasm-builder resolves workspaces by walking up from `OUT_DIR`, so the Paseo-CSG build under an in-repo `CARGO_TARGET_DIR` ran `cargo metadata` over the Bleavit workspace and panicked (the release.yml dry-run failure, reproduced + fixed via `WASM_BUILD_WORKSPACE_HINT`). (4) paseo-local builds `ValidatorGroups` only at session boundaries (600-block sessions, `num_cores` genesis 0), so no injected para could ever be scheduled inside an assertion window — fixed by the CSG `fast-runtime` build + `num_cores = 3` genesis seed; after the fixes drills 01/02/03 pass 10/10 against the real node/keeper binaries
