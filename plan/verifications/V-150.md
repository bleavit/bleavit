## Item

**FE-P2, the pivotal prototype gate, was recorded as needing a chain and did not — the answer was in the pinned dependency's source all along**

## Spec ref

10 §4.2, §12; 02 §3

## Status

**resolved 2026-08-05, positive**

## Result

The milestone note said the execution half "rides the B7 drills", so it read as blocked on a testnet; 10 §12's experiment column actually says *"smoldot docs/source + wire-level test with a lying mock peer"*, and nobody had done the source half. Done now, against `npm-smoldot-v3.3.2` — the tag matching the lockfile-pinned package, so it describes the smoldot this release ships rather than whatever is current. The chain of custody is short and mechanical: the JSON-RPC handler refuses an unpinned block, reads `state_trie_root_hash` off the pinned block's **own header**, and passes it into `runtime_call`; that fetches a call proof from a peer, runs `decode_and_verify_proof`, and resolves every storage access through `call_proof.storage_value(block_state_trie_root_hash, key)` while executing the runtime locally. Forgery is therefore impossible without breaking the state root; withholding is possible and fails closed. Combined with V-82 (a typed call with no explicit `at` targets the **finalized** hash), both conjuncts of the [VERIFY] hold. **Three things are worth carrying beyond the verdict.** (a) *A milestone note that says "needs hardware" is a claim, and V-147 is the standing warning about exactly this* — it had gone unchallenged, and the cost was a pivotal gate sitting open. (b) The lying-peer experiment is **not** additionally informative here and would have produced false confidence: our mock transport *replaces* smoldot, so the lie would be caught by nothing at our layer — the same boundary V-89 hit for FE-P5, and the second time this repo has met it. (c) A second finding fell out that the question did not ask for: `system_health.is_syncing` is `!is_near_head_of_chain_heuristic()` — a heuristic by the API's own name, with no exact "blocks behind" figure anywhere in a light client — so it may never gate a correctness decision. Our code reads it nowhere, verified by grep rather than assumed. **The cross-check stays**, with its rationale changed from "conservative pending FE-P2" to defence against misreading an aggregate API's semantics, which proof verification does not address; dropping a working control because one of its threats retired is the loosening this repo keeps naming.
