## Item

**Serde shape of the USDC XCM `Location` in a genesis patch** — the new chain-spec USDC gate compares the asset id structurally, so a wrong shape would reject valid specs

## Spec ref

02 §8

## Status

verified 2026-07-21

## Result

`staging-xcm 24.0.0` carries **zero** `#[serde(...)]` attributes anywhere in its `v5` module: `Location` and `Junctions` both use plain derives, so the encoding is externally tagged with unrenamed fields — `{parents, interior: {X3: [{Parachain}, {PalletInstance}, {GeneralIndex}]}}`, exactly the shape pinned in `validate-chain-spec.py`. No generated dev spec exists in-tree to confirm against a real artifact, but the gate also cross-checks the pinned Location against the patch's own `foreignAssets.assets` USDC row, so any drift fails loudly rather than passing silently
