## Item

**How does the pinned PAPI type the `AccountId` argument of `account_positions()` /`service_positions()`, and what does the `ConditionalLedger.Positions` key codec yield for the same account?**

## Spec ref

02 §3, §7.4, §8; 10 §10.1

## Status

**measured 2026-08-07** (`getTypedCodecs`, offline, against the committed descriptors)

## Result

**The two spellings differ and only one of them fails loudly.** `futarchy_primitives::AccountId` is `pub type AccountId = [u8; 32]`, so PAPI types the runtime-API argument as fixed-size binary: its codec takes **hex** and its decoder returns hex. `ConditionalLedger.Positions`' second key is a real `AccountId32`, so **that** codec decodes to an **SS58 string** in this chain's own prefix (7777, 02 §8). Handing the SS58 string to the API codec does **not** throw — measured, it produced **25 bytes**, a well-formed argument naming an account nobody holds, which `account_positions()` answers with an empty portfolio and S4 renders as *this account holds nothing*. Two further facts were measured on the same surfaces and both are relied on: `apis.X.Y` and `constants.X.Y` are **Proxies that throw** on a name the runtime does not declare (so an `=== undefined` guard around either is dead code, the shape `decodeStorage` already records for `query`); and a per-position key codec's `dec` **ignores trailing bytes**, which is why `screen-composition.ts` decodes a `PositionId` out of a storage key and then **re-encodes** it to learn how many bytes it occupied rather than slicing at a constant offset. The runtime's own fixture is what makes that non-optional: it publishes `Proposal{4242, Accept, Long}` at 11 bytes and `Baseline{9, Short}` at 6.
