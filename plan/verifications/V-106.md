## Result

The check that mattered was the deprecation one, because upstream *is* retiring this family: the same runtime marks `teleport_assets` and `reserve_transfer_assets` deprecated ("uses `WeightLimit::Unlimited`, please migrate to `limited_teleport_assets` or `transfer_assets`"), and `transfer_assets` (call 11) carries a byte-identical signature. So the row is correct today and is one upstream release from being a citation of a call that is gone. **The artifact chain is closed rather than asserted:** `paseo-network/runtimes` **v2.4.2** publishes `asset-hub-paseo_runtime.compressed.wasm`, whose srtool digest's `sha256` (`0x1b9f1149…f6db`) matches the download byte-for-byte, and whose `core_version` (`asset-hub-paseo`, spec **2004002**, tx 16, state 1) matches what both live operators report — so the pinned artifact and the chain the surfaces were verified on are the same runtime.
