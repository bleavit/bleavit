## Item

**A pallet-binding ingest filter was bound to a pallet that does not exist, and the suite proved it correct against its own constant**

## Spec ref

11 §11.8.6; 02 §6; `runtime/bleavit-runtime/src/lib.rs` `construct_runtime!`

## Status

**measured 2026-08-06**

## Result

`registry-filing.ts` shipped `REGISTRY_PALLET = 'Registry'` and `screens.test.ts` built every fixture from that same constant, so the two agreed with each other and neither agreed with the chain. Measured against the recorded runtime metadata (`app/fixtures/chain-feed/2/runtime-info.json`, 45 pallets): the registry pallets are **`IncidentRegistry`** (index 56) and **`MilestoneRegistry`** (`pallet_registry::<Instance1>`, 57); there is no `Registry`. The filter therefore rejected **every** real window event and §11.8.6's countdown adjustments could never fire — and the failure direction is the module's own: an extension that never arrives leaves the base deadline on screen, telling a challenger they are out of time while the window is open. **V-120 is not wrong**, and that is the point: it verified the check's *shape* — binds a pallet, in both directions — which still holds. Nothing asked whether the name existed, because a constant plus a fixture derived from it is a closed loop. Three durable lessons. **Break the loop, don't fix the value:** the instances are now a required argument and the module holds no chain identifier, so there is nothing left to be wrong. **The oracle must be the frozen artifact:** the suite reads `tools/release/surface-manifest.json`, which `surface:check` byte-binds to `CRITICAL_SURFACE` and `test:mock-runtime` binds to real metadata — and it supplies the *field lists* too, so the wrong-pallet fixture is the event the chain really emits. **An absence assertion must strip comments first:** the first version reported the prose explaining why a name is absent as the name being present, which is the tokenizer hole every version of `check:chain-literals` had to close.
