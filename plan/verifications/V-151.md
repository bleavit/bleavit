## Result

F18's note ended *"Remaining: the S12/S13 screens over this model, and the second light-client connection to Asset Hub"*. The screens exist: `funding-screens.tsx` (198 lines) exports `DepositForm`, `DepositTracker` and `WithdrawForm`, the feature barrel re-exports all three, and `tests/screens` drives them six times. What is actually outstanding is the Asset Hub connection alone. **The instructive part is not the staleness but which record survived it.** `routes.tsx` declares each screen's state as data — `built-unwired`, `milestone: 'F18'`, `waitingOn: 'a second Asset Hub light-client connection'` — and `screens.test.ts` *checks that claim in both directions*: a `built-unwired` entry naming a component that does not exist fails as a false promise, and a `not-built` entry whose component does exist fails too. So the routing record could not drift, and it did not; the hand-written prose beside it could, and did. This is V-147's class a second time in two days, and it suggests the repair rather than just the fix: **a milestone note should cite the machine-checked artifact rather than restate it**, because a restatement is a copy and the copy is what rots. Found by opening F18 to work it and checking the note before believing it — which is the habit V-147 asked for, now paying twice.
