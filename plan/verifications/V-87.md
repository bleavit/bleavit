## Item

**FE-P1 (10 §5.2): PAPI 2.1.8's compatibility surface, names and semantics**

## Spec ref

10 §5.2, §3.2, §5.1; INV-FE-12

## Status

verified 2026-08-03 by pinned-source reading; enum ordering pinned executably

## Result

10 §5.2 left the compat API as `[VERIFY exact PAPI 2.x names/semantics — FE-P1]`. Answered from the lockfile-pinned tree, same method as V-82. **(1)** The surface is `(await api.getStaticApis()).compat[group][pallet][member]` over groups `tx`/`constants`/`apis`/`view`/`query`/`event` (`types-BJAMtGIT.d.ts:775–791`) — there is **no** `getCompatibilityToken()`; that was the 1.x shape, and looking for it is how a reader concludes the API is missing. **(2)** `compat` is typed `Safe extends true ? {…} : unknown`, so it exists on `getTypedApi(descriptors)` and **not** on `getUnsafeApi()`, whose own docstring says it \"does not provide any runtime compatibility checks protection\". **(3)** `isCompatible(from = CompatibilityLevel.BackwardsCompatible)` — `compatibility/compatibility.js:27` defines `getIsApiCompatible(currentLevel) => (target = BackwardsCompatible) => currentLevel >= target`, so **`Partial` reports `false` by default**. The client must therefore not pass its own threshold; doing so is a second opinion about safety with no basis, and passing `Partial` would silently widen what counts as signable. **(4)** A surface absent from the runtime yields the `inOutIncompat` singleton (`if (!dest.entry)`) — `Incompatible`, `isCompatible: () => false` — so absence is *detectable* and fails closed, which is what INV-FE-12 and the 10 §5.2 classifier need. **The trap, and why the probe takes a `compat` object rather than a client:** when no descriptors are supplied at all the helper reports the **value side as `identical`** (`value: user ? incompatible : identical`), which reads as \"fully compatible\" while nothing was compared. **(5)** Storage, runtime APIs and view fns carry `args`/`value` and **no top-level `level`**; PAPI computes their verdict as `min(args.level, value.level)`, and a consumer reading `helper.level` on those gets `undefined`. The numeric enum (`Incompatible 0 < Partial 1 < BackwardsCompatible 2 < Identical 3`) is now pinned **executably** — `tests/descriptors` imports PAPI's real enum and asserts both the naming and the ordering, because the ordering is what `isCompatible` compares and a renumbering would turn `Partial` into a pass. **Not verified:** that these structural shapes still match PAPI's, since nothing constructs a `TypedApi` until F6 wires `createClient` — the same exposure `topology.ts` closes with an assignability binding, and the same fix applies when the client lands.
