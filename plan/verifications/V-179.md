## Item

**Lighthouse 12.8.2's own presets, read rather than assumed — and the audit §9.4's row name points at computes nothing**

## Spec ref

10 §9.4; `app/tools/render-budget/check.ts`

## Status

**measured 2026-08-06** against the installed 12.8.2

## Result

Four readings, each of which changes what the gate had to do. (1) `first-meaningful-paint` is still **present** in the default config and reports `scoreDisplayMode: notApplicable` with `numericValue: undefined`; a gate named after §9.4's row would therefore have compared `undefined` against 1,500 ms and passed forever. **First Contentful Paint** is gated instead, and §9.4's enforcement cell now says so. (2) The **desktop** preset's own `cpuSlowdownMultiplier` is **1**, not 4 — §9.4 asks for a mid-2023 laptop at 4× throttle, so that override is the whole of the reference machine and is now a bound constant re-read out of every report. (3) The **mobile** preset genuinely is §9.4's device: user agent `moto g power (2022)`, 412 × 823 at DPR 1.75, Slow 4G, `cpuSlowdownMultiplier: 4` — taken unmodified, and checked per run rather than trusted, because upstream has moved this preset before. (4) Lighthouse **refuses** `formFactor: 'desktop'` unless `screenEmulation` is supplied with it, since the default emulation is mobile: a profile that named only the form factor would not have run at all. Spread over four 3-run passes: desktop 401–410 ms, mobile 1,803–1,809 ms
