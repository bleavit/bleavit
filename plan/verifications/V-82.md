**FE-P2 (pivotal): PAPI 2.1.8 routes typed runtime calls through `chainHead_v1_call` pinned to the *finalized* hash by default**

## Spec ref

10 §4.2, §2.1, §11; 11 §11.13

## Status

## Result

10 §4.2 flags this `[VERIFY]` as **pivotal** because the answer decides whether every `FutarchyApi` result on the transaction path must be re-derived from direct storage reads. Traced end to end through the installed, lockfile-pinned tree (the same method V-41 used for the `try-runtime-cli` keep-alive): **(1)** `polkadot-api/dist/src/runtime-call.js:16` defaults the caller's block to `null` (`const at = _at ?? null`); **(2)** line 30 hands it to `chainHead.call$(at, callName, …)`; **(3)** `observable-client/dist/chainHead/chainHead.js:224` defines `call$` as `withOptionalHash$(…)`; **(4)** `enhancers/optionalHash.js:5` puts `null` in `dynamicBlocks` alongside `"best"`/`"finalized"`; **(5)** line 12 resolves every dynamic block that is not literally `"best"` to **`finalized$`**; **(6)** `substrate-client/dist/methods.js:25` builds the wire name as `chainHead_v1_call`. And **(7)** `chainHead.js` contains **zero** occurrences of `state_call` or `archive_*`, so there is no peer-proxy path for a runtime call to fall back to — the concern FE-P2 names explicitly (*"any call proxied to a peer unverified MUST be excluded"*). smoldot executes `chainHead_v1_call` locally against proof-backed storage, so the composition carries the same verification as a storage read. **Two consequences, and one is a standing rule rather than a finding:** `at: "best"` is opt-in and yields a best-block result, which 10 §2.1 classifies `verified-best` (display-only) — so the client must never pass `"best"` on the transaction path, and that is enforceable in code rather than hoped for; and `getRuntimeContext$(at)` resolves by the same rule, so codecs and metadata come from the same block as the result. **What is NOT yet verified, and why the conservative mode stays in force:** this is a static reading of what the library does, not an execution of the deployed composition against a live chain. 10 §4.2 makes the per-domain cross-check the *default* until FE-P2 resolves; the routing half is now answered, the execution half rides the B7 zombienet drills, and `FinalizedReader.crossCheckedCall` remains the transaction path's entry point unchanged. The residual risk is no longer "does PAPI pin to finalized" but "does the deployed stack behave as its pinned source says".
