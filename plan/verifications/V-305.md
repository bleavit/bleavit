## Item

**FE-P10: no size ceiling in any pinned source refuses a multi-megabyte upgrade extrinsic**

## Spec ref

11 §11.8.4; 10 §12

## Status

**resolved 2026-08-07 from pinned Rust sources, both sides**

## Result

FE-P10 asks about transaction-pool and gossip size limits, peer banning on oversized transactions, and mobile memory. The first two are readable and both come back positive. **Our own ceiling.** `runtime/bleavit-runtime/src/configs.rs` builds `RuntimeBlockLength` with `max_length(5 * 1024 * 1024)` and applies `NORMAL_DISPATCH_RATIO` of 75 percent to the Normal class only. So Operational and Mandatory get **5,242,880 B** and Normal gets 3,932,160 B. `system.apply_authorized_upgrade` is `DispatchClass::Operational` in the pinned frame-system 48.0.0, and so is the execution-guard's own apply path, so the binding ceiling is the larger one. `check_weight` enforces it against the **cumulative** block, so a nearly full block eats the headroom. **The payload.** The measured `bleavit_runtime.compact.compressed.wasm` is about 1,894,119 B, which agrees within 0.4 percent with two committed fixtures and with V-136. Encoded as a call it is about 1,894,125 B and as a signed extrinsic about 1,894,266 B, which is **36 percent** of the Operational ceiling. The published bound `MaxRuntimeCodeBytes` is 4,194,304 B and still fits, with 1,048,570 B spare. Normal class would be short by exactly 262,144 B, which is why the Operational class is load-bearing. **The peer side.** `sc-network-transactions` caps a transactions notification at `MAX_RESPONSE_SIZE`, 16,777,216 B. smoldot's own `notifications_protocol_max_notification_size` is 1,048,576 B but applies to **inbound** notifications only, and a substrate node never sends transactions to a `Light`-role peer, so it never binds. smoldot performs no byte check on the outbound path at all. **No peer banning on size.** An oversized inbound notification closes the substream with no reputation change, and size alone triggers no reputation event on the substrate side. **Still open:** mobile memory, because the payload crosses the JSON-RPC boundary as a hex string through a Worker copy; local `validate_transaction` cost over that argument; and whether a peer opens a transactions substream to a light client at all, which no constant answers.
