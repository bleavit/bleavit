## Item

Which pallet holds the authorized upgrade hash 11 §11.8.4 step 1 reads

## Spec ref

11 §11.8.4; 02 §7.6

## Status

✅ Corrected

## Result

**Doc 11 named a pallet that does not have it.** §11.8.4 step 1 said the hash is read *"from `parachain-system` storage"*. Decoded the runtime's own metadata (release build, `extract-metadata.py` against a booted node): `ParachainSystem` exposes **31** storage items and none is `AuthorizedUpgrade`. The authorize/apply pair lives in **`frame_system`** on the pinned SDK line, so the item is `System.AuthorizedUpgrade` with value `Option<CodeUpgradeAuthorization { code_hash: H256, check_version: bool }>`. Same defect class as V-169's `REGISTRY_PALLET = 'Registry'` — a client read bound to a pallet that cannot answer it, which returns nothing and reads as *no upgrade authorized*. Frozen in 02 §7.6 and corrected in doc 11 at contract v28
