## Item

**The S3 reader minted its own `verified-finalized` status for nine values, four of which it had never read**

## Spec ref

`app/src/features/tx/src/market-reads.ts`; 10 §2.1/§2.2/§2.3; 11 §11.4 rule 4

## Status

**measured 2026-08-06, fixed**

## Result

`readMarketTrade` defined a local `finalized<T>(value)` helper returning a hand-written status object at the reader's pin. `Finalized<T>`'s brand is a non-exported `unique symbol` in `packages/chain-client`, so the helper produced a plain `Verified<T>` and the module was **asserting** finality rather than establishing it. Counted: **nine** call sites. Five wrapped a value genuinely derived from a read made in that function (`marketOpen`, the chain charge, `maxTrade`, `tradingEnabled`, `ledgerFrozen`) and are correct in substance but unprovable in type. Two wrapped **caller-supplied inputs the chain was never asked about** — the book id and the epoch, both of which the screen renders with a provenance badge. Two — `minTrade` and `maxTrade` — took the **payload** of a caller-supplied `Verified<TradeBounds>` and discarded its status, which is a promotion: a `provider` bounds read went in and a finalized-looking `MinTrade` came out, on a value 11 §11.5 P-1 reads. **Why no gate saw it.** `check:casts` matches `as Finalized<…>` and there was no assertion; `check-render-provenance`'s rule B matches an object literal whose `status` initializer is a `.status` **access**, and this one wrote the status out longhand; dependency-cruiser's `no-finalized-minting-outside-chain-client` matches the `@bleavit/chain-client/testing` import, which was never made. What exposed it was #250 changing the *consumer* type to `Finalized<T>`, at which point `tsc` refused the assignment. **The same shape exists in `funding-reads.ts`** (`finalizedAt`), and it is not a defect there only because `DepositInputs`/`WithdrawInputs` declare `Verified<T>` leaves — S12/S13 are not precondition-bearing in the §11.4 rule 4 sense. Recorded rather than changed, so a later milestone that tightens those types knows where to look. **Root cause and fix:** 10 §2.2 admits values computed purely from finalized reads, and the barrel exported that for two reads (`meet`) and for none for one — so the unary case had no sanctioned spelling. `derive(read, compute)` adds it; it grants nothing, since `meet(a, a, …)` is the same function, and a test asserts that identity.
