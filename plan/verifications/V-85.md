## Item

**A chainHead operation event arriving before its `started` response was dropped, hanging the read forever**

## Spec ref

10 §4.2

## Status

found + fixed 2026-08-03 by the recorded-transcript provider (F3)

## Result

The `started` response and the operation's own follow-subscription events are separate messages; `await`ing the former yields to the microtask queue, so `operationStorageDone` can be delivered **before** the handler waiting for it is registered. The transport dropped it and the promise never settled. Worth recording for the failure mode as much as the bug: a hung read is indistinguishable on screen from a slow chain, so it produces a bug report about the network. Fixed with a bounded orphan buffer drained at registration — bounded because the buffer is filled by the node, and an unbounded map there is remote-controlled memory growth against the 10 §9.4 budget. **Found only because the test double is a *provider* at the wire rather than an adapter written to the transport's own interface**; a double built to match the interface would have called the methods in the order the implementation expected.
