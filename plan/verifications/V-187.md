## Item

**Four of the client's eleven `execute` reason codes were names `pallet_execution_guard::Error<T>` has never declared — and three more were the wrong real name**

## Spec ref

`pallets/execution-guard/src/lib.rs:871–892` (the enum) and `:1944–2200` (`do_execute`); 11 §11.5 P-12

## Status

**measured against the pallet, 2026-08-06**

## Result

The review named four: `NotQueued` (the guard returns `NotFound` for a missing entry and `Cancelled` for a cancelled one — two errors, one client code), `VersionMismatch` (`StaleQueue`), `MeterExceeded` (`MetersBlocked`), and `GateSuspended` standing in for the `delay_once` arm's `GuardianHold`. Reading `do_execute` end to end found **three more of the same shape, all real names attached to the wrong check**: row 2's past-grace arm reported `NotMature` where the guard raises `GraceExpired`; row 7's ⊆-declared arm reported `CapabilityDenied` where the guard's item-11 loop raises `BadDomainDeclaration`; and all four of row 14's bounds reported `BadPreimage` where the guard raises `TooManyCalls`, `PayloadTooLarge`, `SafetyFilter` and — for the weight ceiling, which reads oddly and is what the code says — `CapabilityDenied`. **Nothing could have caught any of them.** `tsc` cannot: a union member and its use site move together, so a renamed code compiles. `check-dispatch-mirror.py` cannot: it binds two documents and neither names a code. **Two gates now do**, and they make different claims — `check-execute-error-codes.py` binds the union to the error **enum**, and a suite test binds every emitted code to `do_execute`'s **body**, which is strictly stronger since `QueueFull` is a real variant `execute` never returns
