## Item

**`CoreKeys` declared three storage-key functions no reader called, and no test could have seen it**

## Spec ref

`app/src/features/tx/src/core-screen-reads.ts`; 02 §7.1/§7.4/§7.8; 10 §4.2

## Status

**measured 2026-08-06**

## Result

The four core-screen readers take an injected `CoreKeys`, one function per surface, because `packages/chain-client` is the only package permitted to encode a storage key. Three of the ten — `queuePrefix`, `welfareSnapshotsPrefix`, `recentCohortSummaries` — served surfaces that are **paired with a runtime-API result** and therefore named to `crossCheckedCall`, which resolves the prefix itself (10 §4.2). Nothing called them. That is worse than dead code in this position: an implementer must write three functions whose output nothing consumes, so one of them can disagree with the prefix the cross-check actually used and stay wrong forever — the read returns nothing, and an empty map is indistinguishable from a real empty one. They are removed, and the surface is now asserted **exhaustively** by a counting `CoreKeys` that fails when any declared member is not reached by a reader, so the next addition cannot be dead on arrival. The general shape is the one this repository keeps finding under a different name: a control with no path that exercises it reports success indistinguishably from one that works.
