## Item

**Then what does the extra handle cost, since it is not sync state?** (the half SQ-1013 called *"unmeasured"*, and the half that decides which §9.4 row moves)

## Spec ref

10 §4.1, §9.4

## Status

**verified 2026-08-08 — it is CPU, and the budget row it touches is not the one the question named**

## Result

The same pinned file, two paragraphs on: *"Smoldot tries to distribute CPU resources equally between all active `Chain` objects of the same client."* The cost of a probe handle is therefore a **share of one core for as long as it lives**, not memory and not a second warp sync — one probed chain halves the reader's share, two thirds it. SQ-1013 asked whether §9.4's **memory** line had to name it; the answer is that the memory line is right as it stands and the **mobile CPU** row is the one that was silent. That row now names the line, and the obligation it carries is that a probe handle is released when its verdict is produced rather than held for the session — which is what makes §9.4's steady-state figure the no-probe figure. Only the measured share stays open, under FE-P4, alongside the other memory/CPU rows
