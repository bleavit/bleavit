## Item

**N7 THIRD FIX ROUND — the resource domain was too narrow, and the extension undercharged itself**

## Spec ref

05 §4.3; 15 §4.5; 16 §8.5

## Status

verified 2026-08-02 (compliance re-review open)

## Result

PR #221's automated review found two P1 defects, both real. **(1) Classification.** `is_external_client_call` treated only the `ExternalClient` authority leaves plus `crank_observe` as external, so `Market::buy`/`sell`/`sweep_revenue`/`reap` against a hosted book — and every `ServiceLedger` and `QuestionService` crank — were reserved against `PrimaryUsed`. Hosted **volume** is by far the largest term, so the partition left open the exact channel it exists to close. The resource domain is now specified in 16 §8.5 as distinct from the authority domain (rules 1–3 + the emergency/governance exception) and implemented as: `ExternalClient` leaves; the whole `ServiceLedger` instance and `QuestionService` pallet; any market call naming a `BookKind::External` book, over an **exhaustive** match so a later market call fails to compile rather than defaulting to primary. Emergency/governance authority is excluded in every pallet, so a saturated client quota cannot block a Bleavit pause or freeze (R-7). **(2) Weight.** The extension declared `reads_writes(2, 2)` against an enumerated worst case of **8 reads / 2 writes** across validate/prepare/post-dispatch (1 book-kind + 2 `BlockWeight` + 2 `Number` + 3 `BlockResourceUsage`); the same figure sizes the XCM adapter's reservation, so undercharging both understated the block and handed the external side unpaid quota. The enumeration ships as a table in the doc comment. **(3) A wrapper laundered hosted work into the primary quota — not a review finding; found by asking the bot's question one level up, and proven live before any code was written.** `Utility::batch([Market::buy(hosted), …])` classified **PRIMARY**, so hosted trades took the 75 % primary budget instead of the 25 % client quota *and* moved `H` — a strictly larger bypass than (1), reachable from any signed account. Both possible classifications of a wrapper are unsafe, because the partition reserves against exactly one side per top-level dispatch: primary launders hosted volume into `H`, external hides primary leaves from `H` and overstates health. So the shape is **refused** — a resource-accounting refusal, not an authority one; the same calls sent separately remain admissible and a wrapper with no hosted leaf is unaffected. The walk covers the closed 06 §3.3 wrapper set at every depth under the projection's own nesting budget and **fails closed on depth overrun**. **Anti-vacuity, run explicitly for both:** reverting the classifier to its pre-fix body makes the new `n7_hosted_domain_work_is_external_whoever_signs_it` fail at `Market(Call::buy { market: 9223372036854775809 })` — the `SERVICE_ID_BASE + 1` id also confirming the disjoint band; and a temporary probe asserting the batch was external failed with "classified PRIMARY" before the refusal existed. Both fixes were then restored and re-verified.
