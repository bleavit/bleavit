## Item

**`surface-manifest.json` — the frozen 222-entry critical surface — had drifted from the runtime on 8 entries**

## Spec ref

02 §6, §13; 10 §5.4

## Status

verified 2026-08-03, corrected

## Result

Found by the first execution of a layout comparison against a live runtime. Four `ConditionalLedger` redemption events (`ScalarRedeemed`, `ScalarPairRedeemed`, `GateRedeemed`, `BaselineRedeemed`) lacked the trailing `fee: Balance` that **contract v17** added; both `RegistryEpochClosed` rows lacked the trailing `spec_version` that **contract v14** added; and both `Attestor` rows recorded `cause_hash` as `primitive_types::H256([u8;32])` when `futarchy_primitives::H256` is `pub type H256 = [u8; 32]`. The **runtime is correct in all eight** — each matches the change 02 §13's own version history describes — and the manifest simply never followed. It matters because 10 §5.4 generates the app's `CRITICAL_SURFACE` from this file, so a client built from it would have expected the wrong shape for four redemption events. **Why nothing caught it:** `tools/release/record-chainhead-fixtures.py` already carries the layout-comparison capability; it had never been *run*, because no release has ever been produced (`git tag` is empty). The capability existed, the execution did not — the same shape of gap as the stale blob, an artifact internally consistent with every consumer and never compared back to the source that moved. Corrected by naming the eight explicitly (never by pattern, so a ninth cannot ride along) and asserting zero other entries drifted; diff is 26 insertions / 2 deletions, `tools/release/tests` 87 green.
