## Item

**FE-P4 (artifact-size half): smoldot 3.3.2 is 2.23 MiB gzipped, and `'wasm-unsafe-eval'` is load-bearing rather than defensive**

## Spec ref

10 §9.3, §4.1; 12 §5.1; INV-FE-1

## Status

measured 2026-08-03 from the lockfile-pinned package

## Result

10 §9.3 budgets *"smoldot WASM (worker, lazy) ≤ 3.5 MB gz **[VERIFY artifact size — FE-P4]**"*. Measured from `smoldot@3.3.2` as installed: the bytecode ships as **four JavaScript modules carrying zlib-compressed, base64-encoded string literals** — not as a `.wasm` file — totalling 3,082,260 B raw, **2,333,920 B gzip (2.23 MiB)** and 2,312,719 B brotli. **Within budget, with 1.31 MiB of headroom.** Two consequences the number alone does not give. **(1) The CSP directive is necessary, not cautious.** The browser path is `WebAssembly.compile(zlibInflate(trustedBase64Decode(wasmBase64)))` (`dist/mjs/bytecode-browser.js:34`) — a **buffer** compile, not `instantiateStreaming` from a URL. Chrome-family CSP requires `'wasm-unsafe-eval'` in `script-src` for buffer-based compilation, so 12 §5.1's `script-src 'self' 'wasm-unsafe-eval'` is what lets the light client start at all in the majority browser. Dropping it would produce `FE-BOOT-004` on every Chrome load — a total INV-FE-1 failure — **while leaving every test in this repository green**, because nothing here executes under a CSP. That is worth a release gate of its own (F13's CSP-diff leg) rather than a comment. **(2) "Lazy" means a dynamic `import()` of a JS chunk**, not a `fetch` of a wasm asset, so the load is governed by `script-src` and never by the §5.1 `connect-src` allowlist — which also means the bundler must not be allowed to inline those four modules into the entry chunk, or the §9.3 lazy-load line becomes false without any budget number changing. **Still open in FE-P4:** per-instance memory (the §9.4 mobile budget's named 2 × ≤ 120 MB line), real sync latency, the 20 blk/s ingest anchor, measured proof sizes and mobile CPU — all of which need the device lab the gate names, and none of which this measurement touches.
