## Item

**A NUL byte reached source through the *Edit* tool, and the tell was `grep` returning nothing**

## Spec ref

`app/packages/providers/src/snapshot.ts`; app-code rule 14

## Status

**measured 2026-08-06**

## Result

The fourth instance, and the first found by the sweep rather than by a failing assertion — the previous three were caught because a test claiming the separator was a *space* passed anyway. Writing `` `${SNAPSHOT_FORMAT}\0` `` into a template literal puts the resolved byte on disk, and the symptom was `grep -n preimageOfSerialized <file>` printing **nothing** for a function that was plainly there: git and grep classify the whole file as binary the moment it holds a NUL, so the tool reports no matches rather than an error, which reads as *the symbol does not exist*. Two durable lessons. **The editor is not safer than the shell** — rule 14 previously said to prefer the Write tool over shell interpolation, and that advice is now known to be insufficient rather than wrong. **The repair is structural**: the separator is written as a byte into the `Uint8Array` (`preimage[tag.length] = 0`), never into a string, which is the same device `handoff-envelope` already used (`String.fromCharCode(0)`) and the reason that module's comment exists. Sweep the tree before claiming it is clean; it is four lines of Python.
