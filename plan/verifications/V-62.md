## Item

**What `broker.renew` actually charges** — SQ-538 published a coretime runway on the reading that the renewal price compounds at the per-period cap without bound. That is a claim about someone else's code, so it was checked against that code rather than carried.

## Spec ref

08 §10.1; 09 §4; SQ-538, SQ-541

## Status

complete (2026-07-31, E7)

## Result

**Source: `pallet-broker` 0.28.0** — not a recollection and not the Wiki: it is the version this workspace's own `Cargo.lock` pins, so the evidence is re-checkable from the repo. `dispatchable_impls.rs::do_renew` lines 209–211: `let price_cap = cmp::max(record.price + config.renewal_bump * record.price, end_price); let price = Self::sale_price(&sale, now).min(price_cap);`. `utility_impls.rs::sale_price` = `leadin_factor_at(through) * end_price`, `through` clamped to \[0,1\] by `.min(sale.leadin_length)`. `adapt_price.rs::CenterTargetPrice::leadin_factor_at` = two linear phases, `100 − 180t` for `t ≤ ½` and `19 − 18t` above, pinned by that file's own `leadin_price_bound_check` at (0,100) (¼,55) (½,10) (¾,5.5) (1,1) — the reference model asserts the same five points. `ensure_cores_for_sale` (same file, 635–643) is the `SoldOut` risk of renewing late. **Result: the SQ-538 reading was wrong.** The `min` clamps the ratchet to the open market, so it saturates rather than compounding; the `max` is a floor stopping a renewer underpaying the market, not an escalator; and the paid price tracks `end_price` **down** as well as up. **What is NOT verified and stays `[VERIFY]`:** `renewal_bump`, `interlude_length` and `leadin_length` are live Coretime-chain `ConfigRecord` values set by relay governance, and the coretime runtime is not in this dependency tree — every published figure is bracketed against Kusama's 3 %, never asserted as Polkadot's.
