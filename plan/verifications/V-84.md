## Item

**The read interface let the *transport* choose the block a value was labelled with**

## Spec ref

10 §2.1, §4.2; INV-FE-2

## Status

found + fixed 2026-08-03 (F3)

## Result

`storage(key, type)` took no block: the transport read at whatever it considered current, and `FinalizedReader` labelled the result with the pin it was holding. The `#assertStillPinned()` guard looked like it prevented this and did not — it ran **before** the read, so a head that advanced in between produced a value read at N+1 carrying a `verified-finalized` status for N. Nothing about the value can detect that; it is individually valid and its provenance is a lie, which is the precise thing `Finalized<T>` exists to make impossible. Fixed by passing the block explicitly (`storage(at, …)` / `call(at, …)`), so "read at the block I pinned" is unbypassable rather than checked around, and the transport fails rather than substituting. The regression test asserts **on the wire**, because the returned value cannot distinguish the two. Note the converse was also wrong to want: a reader that died whenever the head moved would have a useful life of one block time — pinning exists so it does not.
