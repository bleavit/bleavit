## Item

**PAPI renders a decoded account in the CHAIN's SS58 prefix, so an SS58-keyed watched set would have matched nothing — silently, forever**

## Spec ref

10 §6.5; 02 §6

## Status

**measured 2026-08-06**

## Result

The ingest loop's decision is `watched.has(account)` — a **string** comparison. PAPI decodes `AccountId32` to an SS58 string in **this chain's** prefix: Alice supplied to the encoder as the generic-format `5GrwvaEF5zXb26Fz9rcQpDWS57CtERHpNehXCPcNoHGKutQY` (prefix 42) comes back out of the decoder as `fvJdNW3p1BT1RfWzfZegj9tbVTUAXWf6Zf5kD9sJukyeafVR8` (prefix **7777**, the value 02 §8 freezes). Same 32-byte public key; the two strings share nothing. **This row read 22622 until 2026-08-06** — a number copied from five pre-existing `app/` comments, all of them wrong; the address quoted beside it was always the 7777 encoding, and 22622 renders the same key as `fgw8ys7FygTp2jenWCJoYZ8xYrT18A6ipP3WciH8ZiPyExE4G` (measured, `AccountId(prefix).dec()`). The finding is unchanged — it never depended on which prefix, only on it not being 42. So a watched set built from addresses a user pasted, or from any other chain's rendering, would match **no event ever**, and the symptom is an **empty transaction history** — indistinguishable from a user who has never transacted. Nothing throws, nothing logs, the app looks correct. That is 10 §6.5's silent-narrow failure in its purest form, and it would have shipped: the extractor's obvious implementation is to return what the decoder gave it. **Resolved by making the canonical form the only form that leaves the module** — a branded `AccountKey`, the 32-byte public key as `0x` hex, which is what `packages/local-index` already compares against (its suites use `0x` + 32 bytes, so the mismatch was on the producer side). `accountKey(address)` is exported so a watched set is built through the **same** function, since two conversions written separately is exactly how a prefix mismatch survives review. It also refuses a valid address whose public key is not 32 bytes — V-163's trap reached from the watched-set side, where the consequence is again an empty history rather than an error.
