## Item

**Does anything a history query returns record whether a range was compared against the chain — and what verdict does every range in this build actually reach?**

## Spec ref

10 §6.3, §2.2; 15 §2 INV-FE-15

## Status

**measured 2026-08-07** (R-6 review of F23/F25, on `integration/track-f-v2`)

## Result

**No, and `unchecked`.** `CoveredResult<T>` declares exactly `data`, `span`, `ranges`, `holes`, and `CoveredHistory<T>` adds `downsampled` and `chartDiscard` — no verdict field anywhere. The verdicts are `RangeVerdict` (`ok` | `invalid` | `unchecked`) inside `CoverageVerification`, which only `verifyRanges` returns and which only the **boot** path consumes; no history read calls it. And the verdict every range reaches today is `unchecked`: no genesis is pinned (V-260), so `index-boot.ts` passes `cannotObserve`, `observe` returns `undefined` for every range and `verifyRanges` keeps them all in `unchecked`. So `coverage-view.tsx`'s *"both are checked against the chain"* described a comparison that had not run, on ranges F25's own surface simultaneously lists under *"Ranges this client could not check"*. Repaired as a capability statement; the shape question is SQ-980
