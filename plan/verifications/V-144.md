## Item

**A doc change and the mutation test anchored to its text landed on *different branches of one stack*, so three PRs were each independently red**

## Spec ref

09 §1.2; 11 §11.5; 15 §4.8

## Status

**fixed 2026-08-05, measured per branch**

## Result

V-143's repair split 11 §11.5 row 12 in two, which shifted every row below it — *Batch bounds* 13 → 14. `tools/ci/tests/test_check_dispatch_mirror.py` is the **mutation suite** for `check-dispatch-mirror.py`: it edits doc 11's text and requires the checker to catch the edit, so its anchors are literal quotations of the row numbering. The doc edit went onto `split/2-core-packages` and the anchor update onto `split/5-docs-and-tooling`, four commits later — so `split/2`, `split/3` and `split/4` each carried a doc the anchors no longer matched, and every one of them failed `tools/ci/tests` with `'| 13. Batch bounds |' not found`. **Nothing local could see it**: the working tree is the *top* of the stack, where both halves are present, so the suite passed on every branch I actually had checked out. Measured by building a detached worktree at each branch tip and running the job's own legs there — `main` consistent at 13/13, `split/2`–`/4` split 14/13, `split/5` and above consistent at 14/14. Repaired by moving the anchor hunk down to the commit carrying the doc change, so the two travel together, and the stack rebased onto it. **The general rule this yields: in a stacked split, a change and everything that quotes it must land in the same slice — the reviewable unit is the branch, and CI checks each branch alone.** Also recorded because the *first* diagnosis was wrong: the suite passing locally and on `main` reads as a flake, and it is not one.
