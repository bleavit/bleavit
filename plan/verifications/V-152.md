## Item

**The Stop-hook escape I wrote for F1 never engaged: the hook matches `> **PARKED:**` and I wrote `> **PARKED: …**`**

## Spec ref

AGENTS.md R-5; CLAUDE.md · Hooks

## Status

**fixed 2026-08-05**

## Result

`guard-track-goal.sh` stands down only on `re.search(r"^>\s*\*\*PARKED:\*\*", focus)` — the bold must close immediately after the colon. The line I added opened the bold at `**PARKED:` and closed it two lines later, so the regex never matched, the hook kept blocking, and **I reported F1 as parked in a state where nothing had actually been parked**. The record was true and the mechanism was inert. **The class is the one this repository keeps naming, inverted**: not a check that cannot fail, but an *escape that cannot fire* — and it is harder to notice, because the failure mode of a silent escape is that the guard keeps working, which looks exactly like correct behaviour. Nothing caught it and nothing could: the marker is prose in a document no checker parses for this, and the only signal was the hook firing a second time, which reads as *more work to do* rather than *your escape is malformed*. Fixed by closing the bold at the colon, verified by replicating the hook's own extraction and regex against the file rather than by re-triggering the hook and inferring. **The general repair is the one V-149 argued**: a marker whose exact spelling is load-bearing should be matched leniently or checked mechanically, since the writer and the reader of that string are in different files and different languages.
