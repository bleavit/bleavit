## Item

**PLAN.md said an F8 component *did not exist* when it was built, exported and tested — and the read it staged for the next session is impossible as described**

## Spec ref

10 §6.5, §4.4; 02 §5–§7.2

## Status

**corrected 2026-08-05, measured**

## Result

Two corrections to one milestone row, both of which would have cost a session. (a) F8's note named the `fut-ingest` single-writer lock as *not existing* — `src/ingest-lock.ts` exists, is exported from the barrel, has its own suite, and local-index runs **92 green**. A stale *absent* is worse than a stale *present*: it sends the next session to rebuild something, and the rebuild's tests pass. (b) The same note staged the scan→ingest account mapping as *"a careful read of 02 §6's frozen per-pallet table"*, and **that read cannot be done from §6**: the section freezes event **names**, giving field lists only for the events it bolds, so **31 of the ingest set carry no field list at all** (8 ledger, 11 epoch, 10 registry, 2 system) and `pallet-market`/`pallet-oracle` delegate wholly to §5 and §7.2. Counted, not estimated. A second measurement redirects the design: PAPI decodes `AccountId32` to a plain SS58 **string** (`AccountId(42).dec(…)` ⇒ `typeof 'string'`), so no walk over a *decoded* event can separate an account from any other string — the discrimination has to come from **metadata type ids**, which also handles `Vec<AccountId>`/`BoundedVec` fields that a hand-written table gets wrong, and is the only form that cannot drift from the runtime. The general point: a milestone note is read as fact by the next session, so *"does not exist"* and *"just read table X"* are claims that need the same verification as code.
