## Item

**The negative-compilation corpus could not tell a rejected import from a missing file**

## Spec ref

10 §10.2; 15 §4.8; INV-FE-3/FE-5

## Status

found + fixed 2026-08-03 (F6)

## Result

The corpus asserted only *"did not compile"* and *"produced diagnostics"*. It never read **why**. So the two fixtures F6 added — one proving a `provider` read cannot satisfy a precondition, one proving a forged `GatePassed` cannot reach a signer — **passed while proving nothing**: both failed with `TS2307, module not found`, because `tests/firewall/package.json` did not depend on the packages they were testing. For a corpus whose entire purpose is demonstrating rejection, that is the difference between a control and a decoration. The subtlety that makes a blanket ban wrong: `TS2307` is the *intended* proof for three existing fixtures, because 10 §10.2 makes module resolution the **primary** gate — a forbidden package edge is supposed to be unresolvable. The same diagnostic is the proof in one file and the vacuum in another. Fixed by declaring the expected error in each fixture's own first line (`// expect-error: TSxxxx — why`) and asserting the compiler produced it; every one of the nine is now pinned to a specific code (TS2307 ×3, TS2322 ×3, TS2305, TS2345, TS2741). Three mutations caught: a fixture failing with `TS2307` instead of its declared error, a fixture with no declaration, and a declaration the fixture does not produce.
