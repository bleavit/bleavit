## Item

**Does any test prove that `execute` refuses a mandate past `failed_at + EXECUTION_RETRY_WINDOW`, and how should 13 §2's new key be classified?**

## Spec ref

13 §2; 09 §1.2(1); 05 §2.1 T18/T23; 15 §4.6 / I-22

## Status

**measured 2026-08-07** (3 mutants, 0 survived)

## Result

**No such test existed, and the missing half was the direction nobody reports.** A repository-wide sweep for `GraceExpired` found three production sites and exactly one test site: `ordered_check_1_rejects_cancelled_immature_and_expired_entries` (`pallets/execution-guard/src/tests.rs`), which never stamps `failed_at` and so exercises only the `None` arm against `grace_end`. `t22_expiry_is_closed_during_retry_window_and_terminal_after_it` covers the **complementary** dispatch well — `expire_failed_execution` refuses with `RetryWindowOpen` at exactly `failed_at + RETRY_WINDOW` and succeeds one block later — so the retry clock was pinned for the call that *retires* a mandate and unpinned for the call a user signs. **The new test pins four blocks**, and the mock's own shape is what made the fourth reachable: `Grace` defaults to 10 blocks against a 43,200-block retry window, so direction 2 needs `Grace::set(RETRY_WINDOW * 2)` and cannot be observed at the default. Direction 1 admits `execute` at exactly `failed_at + RETRY_WINDOW`, which is 43,190 blocks **after** `grace_end`, then refuses it one block later. Direction 2 widens grace past the retry window, admits the boundary block, and refuses `failed_at + RETRY_WINDOW + 1` **while asserting `now <= grace_end` still holds** — the state that offers a user a signature the runtime rejects, and the one a client reading only `grace_end` reports as live. **Classification ruled `dispatch-limit` with `ExecutionGuard::GraceExpired`.** `param-bounds` is wrong because the value is a kernel constant (`futarchy_primitives::kernel::EXECUTION_RETRY_WINDOW_BLOCKS = 3 * BLOCKS_PER_DAY`), not an amendable `Params` key, and it is absent from `genesis-keys.json`. `value` is wrong for the reason that decides the class: unlike `grd.bond`, this key **does** gate a dispatch path with a Module error, and `value` would exempt it from ever needing a marked test. **One mechanical constraint corrected the entry's shape:** the checker rejects a `genesis` field on any non-13 §1 key (`check-limit-coverage.py`, the `manifest non-§1 key ... must not declare genesis` branch), and this key is extracted from §2, so the entry states the absence of genesis seeding in its `reason` and declares no `genesis` field. **Mutation evidence: 3 mutants, 0 survived.** Reverting the `Some(failed_at)` arm to plain `grace_end` fails at the direction-1 boundary; narrowing `<=` to `<` fails at the same assertion; deleting the retry arm outright fails at the direction-1 refusal. The non-monotone assertion was then isolated into a throwaway single-block test and **independently kills the first mutant**, so the direction that matters is not carried by its neighbours. The marker is load-bearing too: deleting `// limit-coverage: EXECUTION_RETRY_WINDOW` turns the gate red with `dispatch-limit key 'EXECUTION_RETRY_WINDOW' has zero attached test markers`.
