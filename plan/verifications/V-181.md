## Item

**A `process.exit()` inside a `try` skips its `finally`, and the render gate leaked a browser on every failure path**

## Spec ref

`app/tools/render-budget/check.ts`

## Status

**measured 2026-08-06** while mutation-proving the gate

## Result

Found by counting processes after a mutation run, not by reading the code: eight mutations, eight refusals, **eight orphaned Chrome process trees**. The gate launched Chrome, entered `try`, and every refusal called a `fail()` that exited the process directly — so `finally { chrome.kill(); server.close(); }` never ran. A green run could never show this, because the happy path returns normally. Repaired by making both refusal classes **throw** and moving the single `process.exit(1)` outside `main()`, so every path unwinds through the cleanup; re-measured at **0** leftover processes. Worth recording beyond this file: the same shape hides in any gate that exits while holding a child process or a bound port, and CI never reports it because the runner is discarded either way
