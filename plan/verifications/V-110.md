## Item

**A types-only package satisfies the 10 §10.2 compile firewall, so "module resolution cannot see it" is not true in general**

## Spec ref

10 §10.2

## Status

**verified 2026-08-04 by `--traceResolution`**

## Result

The general statement of V-109's first half, recorded separately because it is not about JSX. 10 §10.2 grounds the primary firewall in module resolution and says an isolated `node_modules` layout is what makes an undeclared import unresolvable. It does for **runtime** packages: `react` is reachable from no project but `packages/ui`. It does **not** for anything with a `@types/…` counterpart declared at the workspace root, because TypeScript resolves the *types* and stops — the runtime package never has to exist. Any external package whose types are hoisted is therefore invisible to the primary gate from every compilation unit. dependency-cruiser still catches the ordinary case (a written `import`), so the exposure is specifically **compiler-injected** imports; `check-handoff-emitted` covers those on the one path where an external import is categorically forbidden. Not generalised further: outside the handoff trust domain an external import is permitted, so there is nothing there for a gate to say
