## Item

**Relay finality-stagnation persistence window** (SQ-283) — the alert must not fire on ordinary GRANDPA lag

## Spec ref

12 §6.3; 05 §4.8

## Status

**`[VERIFY]` — deliberately unresolved 2026-07-21**

## Result

Cannot be resolved here and was **not** invented (R-2): the correct value is a function of observed healthy relay finality behaviour, which requires telemetry from a real relay this worktree has no access to. A conservative default of **1,800 s** ships, chosen so it sits orders of magnitude above healthy GRANDPA lag (seconds) while remaining far inside the ~8 h dead-man horizon (`DEAD_MAN_RELAY_BLOCKS` 4,800 × 6 s), so operators are paged well before the on-chain protective trigger engages. Single-homed as `DEFAULT_STAGNATION_WINDOW_SECONDS`, overridable via `--stagnation-window`, marked `[VERIFY]` in the 12 §6.3 row, the alert rule and the exporter, with a test pinning all three to the same literal. **Ops must calibrate it against observed healthy relay behaviour before production**
