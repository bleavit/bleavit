## Item

**The `Finalized<T>` assertion gate scanned lines, so it survived only by being a `.mjs` file outside its own scope — and it caught my repair attempt**

## Spec ref

10 §2.1; 15 §4.8

## Status

**fixed 2026-08-05, witnessed**

## Result

Converting the tools to TypeScript put `check-finalized-casts` inside the set it scans, and it failed immediately — on its **own diagnostic strings**, which contain the phrases it forbids. The tempting repair is a self-exemption, and it is the wrong one: the file that would become unscannable is the file that defines the control, so a mint added there would be the only mint nothing could see. Rewritten to walk the TypeScript AST instead, which is the repair `check-chain-literals` already reached by the same route — a comment body and a string body simply are not `AsExpression` or `TypePredicate` nodes, so the tokenizer-hole class disappears rather than being enumerated. It is also **stricter than the regexes were**: `as unknown as` split across lines is now caught (it is an assertion whose operand is an assertion to `unknown`, however spelled), and so are `as Readonly<Finalized<T>>`, `as Finalized<T>[]` and `as Finalized<T> | undefined` — each of which mints exactly as effectively and none of which the old pattern saw. A rewritten detection engine observed only through a green run is an engine nobody has seen fire, so `check:casts:witness` was added: seven declared expectations across all three mint mechanisms plus negative controls (a comment and a string carrying the banned phrases) that must produce **nothing**, wired into `pnpm test` and into `ci.yml`. It proved itself on the spot — it rejected an `as unknown as` I wrote in `check-foreign-feed.ts` while typing that file, and the honest fix was to stop restating PAPI's metadata type and use `ReturnType<typeof unifyMetadata>`, which then exposed dead logic: the deprecation guard compared against a `"NotDeprecated"` tag that **does not exist** in `deprecationInfo`, so it was always true and filtered nothing.
