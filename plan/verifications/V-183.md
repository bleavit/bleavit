## Result

The same local `finalized<T>` helper V-182 found in `market-reads.ts`, in a file `audit/provenance-mints` could not reach because it lives on this stack. Four call sites, and they split two ways. **The account is the worse one and it reached a rendered surface**: `who` is the *key* both frozen maps are read at, never a value either returned, and it renders through `<Identifier>` in the panel's own subject line — so a string the chain was never asked for carried a finalized badge at the reader's pin. 10 §5 forecloses it in as many words, listing *"a selected account"* among the chosen values that *"can never be represented as verified"*. It is now a caller-supplied `Verified<string>` passed through unchanged, the treatment `market-reads.ts` gives `bookId` and `funding-screens.tsx` gives `destination`. **The three balances split by failure path.** An *absent* record is a real zero and stays badged — the chain answered, and its answer is that the account holds nothing — so it is `derive`d from the read. An *undecodable* one was contributing `0n` under the same badge, defended by a comment arguing that the `undecodable` row beside it said the figure was not to be believed. 10 §2.2 settles that against the argument (*"only to values read through smoldot with storage proofs checked, or computed client-side purely from such values"*), and INV-FE-9 attaches the label to **the datum**, so an explanation living in a sibling array never reaches the field a user is reading. The figure is now absent and the screen renders a refusal in its place — the ruling `audit/provenance-mints` took for `funding-reads.ts`, applied to the same shape one screen over.
