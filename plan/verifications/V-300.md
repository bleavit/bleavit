## Item

**FE-P4: the smoldot artifact size, re-measured — and only the gzip figure moved**

## Spec ref

10 §9.3, §9.4, §12

## Status

**re-measured 2026-08-07** from the lockfile-pinned package

## Result

V-88 recorded 2,333,920 B gzip for `smoldot@3.3.2`. The same four bytecode modules now compress to **2,320,965 B**, which is 12,955 B less. The **raw** total is 3,082,260 B and the **brotli** total is 2,312,719 B. Both reproduce V-88 byte for byte. Identical input plus identical brotli plus different gzip means the DEFLATE implementation moved, not the dependency. This box runs node v22.18.0 with zlib 1.3.1-470d3a2. **The finding is a rule, not a number.** A "MB gz" budget cell is toolchain-dependent at about half a percent, so `check:budget` must stay a bound and must never become an equality check against a recorded byte count. An equality check would fail on a node upgrade while nothing shipped had changed. The tool's own header comment still said 2.23 MiB and now says 2.21 MiB, which is what the gate has printed since the toolchain moved. Headroom against the ≤ 3.5 MB budget is 1.12 MiB.
