## Item

**A private brand is not a boundary when its minting function is public**

## Spec ref

10 §2.2, §6.3

## Status

**found by Codex review, confirmed and fixed 2026-08-05**

## Result

`selfRange` mints `origin: 'self'` — the one origin `isVerifiedAt` treats as light-client verified — from three plain numbers, and it was exported through the package barrel. So `providers`, the package that backfills from operator endpoints, indexers and snapshots, held the ability to relabel any of it as verified: §2.2's silent promotion arriving through the front door, past a `unique symbol` that only ever stopped the object literal. The module comment claimed the brand made a forged range *"a type error rather than a naming convention"*, which was an overclaim and is now replaced with what actually holds. Repair follows the `@bleavit/signing/testing` precedent: `selfRange` leaves the barrel (an explicit re-export list, since `export *` would re-admit it on the next reformat), moves behind `@bleavit/local-index/testing`, and a `no-range-minting-outside-ingest` dependency-cruiser rule fails production code that imports it — **witnessed separately** from the signing subpath, because `WORKSPACE_SUBPATH` takes a specifier *and* a dist path and a typo in either would leave the rule vacuous with the existing witness still green. Mutation: `providers` importing the minter is an error, exit 1
