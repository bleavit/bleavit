## Item

**Two more halves of one change split across branches — and the sweep that found them is the only thing that could have**

## Spec ref

15 §4.8

## Status

**fixed 2026-08-05, measured per branch**

## Result

Repairing V-144 by hand would have left the stack red, so every branch tip was re-verified in a detached worktree with the job's own legs — and that found two further instances. (a) `app/package.json` on `split/3-screens` defines `test:ui`, `test:screens`, `check:above-fold` and two witness pairs whose **`ci.yml` steps were four commits later** in `split/5`; `split/4` added `check:chain-literals`, `release:build/check`, `signers:audit` and `test:release` the same way. `test_every_app_script_is_wired_into_ci_or_exempt` is exactly the gate for this and it fired — on the branch, never on my working tree, which is the *top* of the stack where both halves are present. (b) Moving those steps then failed differently: `split/3`/`split/4` carry the **line-anchored** matcher `^\s*pnpm run (…)`, which structurally cannot see the second half of `pnpm run check:no-html-sinks && pnpm run check:no-html-sinks:witness` — so a correctly wired witness leg reported as unwired. That regex repair was itself sitting in `split/5`, downstream of the first `&&` step it has to parse. **The rule: a script, the CI step that runs it, the code it tests and any checker change it needs all belong in one slice** — CI grades each branch alone, and a working tree at the top of a stack can never reproduce that.
