## Item

**A test fake that grants the property under test — the `mode` argument was untested for free**

## Spec ref

10 §6.5, §4.4

## Status

**found and fixed 2026-08-05 by mutation**

## Result

The `fut-ingest` lock's suite used a Web Locks stand-in tracking **name occupancy only**, so `mode: 'shared'` and `mode: 'exclusive'` behaved identically and a mutation swapping them **survived**. Nothing about the suite looked wrong: every test passed, the exclusive mode was written in the source, and the assertion *"a second holder gets busy"* held — because the fake made *any* second holder conflict. The fake was granting the exact semantics the module depends on. Rewritten to model the real rule (shared holders coexist; exclusive conflicts with any holder, and any request conflicts with an exclusive one), after which the mutation dies. Recorded because the failure mode generalises past this module: **a stand-in built from what the caller needs, rather than from what the real API guarantees, tests the caller against itself** — and it is invisible in review, since the fake looks simpler and the tests look thorough
