## Item

**`requests.find(...)` inspected the first storage request per transcript, so a suite asserted the corpus contained no hashed key while two sat in the files it was reading**

## Spec ref

02 §11; 10 §4.1; 15 §4.8

## Status

**fixed 2026-08-05**

## Result

V-156 concluded that `app/fixtures/chainhead/` records prefix-only keys and therefore could not certify hasher application. The conclusion was right about coverage and **wrong about the facts**: 65 of 67 key items are 32-byte prefixes, and **two are not** — `ForeignAssets.{Asset,Metadata}(usdcLocation)`, single-entry `value` reads whose keys are 58 bytes: prefix + `blake2_128` + the concat'd 10-byte Location. Two files record a *second* `chainHead_v1_storage` request, and both the measurement script and the suite took `requests.find(…)` — the first match — so the second request was invisible to every check. The suite then **asserted** the false statement (*"every recorded key is a 32-byte PREFIX"*) and passed, which is this repo's recurring shape: a control that cannot fail. It was found only because building the composition root required the USDC `Location` and asking *where does the client legitimately get it* meant opening the transcript by hand. **Nothing built on the wrong belief is wasted, and the correction strengthens it**: the Rust fixture is still the right oracle, because between them the two recorded keys exercise one hasher, one key type, one arity and one pallet — no `Twox64Concat`, no multi-key map, no tuple key, no instance disambiguation. What they add is a **third independent producer**. The client rebuilds both recorded keys byte-for-byte, and the Location the live recorder hashed is the same pre-image the runtime publishes for `ForeignAssets.Account` — the 02 §8 pinned `USDC_LOCATION_ENCODED`. A live node, a compiled runtime and the client, none of which saw the others. The suite now counts both classes and pins the split (65 / 2, named files), so the corpus can be neither over-claimed nor under-claimed as it changes. **The general lesson is about `find` in a verification context**: it answers *"is there one?"* and reads as *"here is the one"*, and every helper here that summarises a fixture must enumerate.
