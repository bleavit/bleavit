## Item

**§11.8.1's "never HTML" is not enforceable by a type, and the client had no gate for it**

## Spec ref

11 §11.8.1; 10 §13.2

## Status

**verified 2026-08-05 by building the gate and mutating a real sink into a shipped component**

## Result

Evidence is bytes an **adversary chose**, rendered inside the console operated by the system's most privileged actors, and 10 §13.2's imported documents are the same shape from another direction. §11.8.1 requires evidence *"rendered as text/structured data only, never HTML"* — but `AdmittedEvidence.text` is a `string`, and `dangerouslySetInnerHTML={{ __html: text }}` typechecks perfectly, the same shape as `check-render-provenance`'s rule A. So it is a **source** gate: `check:no-html-sinks` (+ `:witness`) fails on `dangerouslySetInnerHTML`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `eval` and `new Function` anywhere in app source. Two narrowings, both deliberate: the sink list is **closed** rather than a pattern, because *"anything ending in HTML"* fires on `escapeHtml`/`parseHtml`/`htmlLang` and gets switched off within a week; and it runs on the **AST**, so a sink named in a comment or a string body — including in the gate's own header — is simply not a property access. Confirmed live by mutating `EvidencePanel` to use `dangerouslySetInnerHTML`: the gate fires **and** the escaping test fails, which is the belt-and-braces the two are meant to be. App source is otherwise clean: 0 sinks. The other half of §11.8.1 is the **re-hash before rendering**, whose hash function is a *required* argument — an optional one is a digest check that defaults off, the `FE-HANDOFF-010` defect exactly — and whose **unavailable** and **hash-mismatch** arms are kept distinct, because 07 adjudicates unobtainable evidence as *absent* and a blank panel would let a reader conclude none was filed
