## Item

pnpm reproducibility for the 12 §1.1 build recipe — does pnpm's content-addressed store leak absolute paths into sourcemaps?

## Spec ref

12 §1.1; 15 §4.8

## Status

complete (2026-08-03)

## Result

**PASS.** Two Vite 8 / pnpm 10.23 builds at different absolute path depths with **separate stores** produced a byte-identical tree (`c5360712cc2505fe…`) and **zero** absolute paths in `dist/`. pnpm's virtual store lives inside the project at `node_modules/.pnpm`, so emitted sources are relative. **Caveat that became a recipe pin:** those relative paths encode the store layout (`../../node_modules/.pnpm/<pkg>@<ver>/…`), so a hoisted install yields identical app bytes and a *different* sourcemap — `node-linker` is therefore part of the pinned recipe, not left to default. 12 §1.1 amended `npm ci` → `pnpm install --frozen-lockfile` on this evidence
