## Item

**FE-P5: metadata at depth is retrievable, and 10 §4.2's stated reason for saying otherwise was wrong**

## Spec ref

10 §4.2, §9.3, §12

## Status

**resolved 2026-08-07 from smoldot's Rust source at the pinned tag**

## Result

V-89 recorded this gate unanswerable from the JS package and named the Rust source as the way in. V-150 then used that route for FE-P2. Applying it here settles FE-P5 and corrects the section. **Provenance first, because it moved.** `smol-dot/smoldot` now redirects to `paritytech/smoldot-archive`, where the tag no longer resolves, so V-150's recorded URL form returns 404 today. The live repository is `paritytech/smoldot`, and `npm-smoldot-v3.3.2` is commit `5fe9121f81a58454542ac69a44c4d73f00f30283`, dated 2026-07-24. Tag, package version, `repository` field and changelog date all agree with the lockfile pin. Two independent probes found the redirect, so it is corroborated rather than assumed. **The verdict is structurally bounded, and not where the question assumed.** `archive_*` is genuinely absent. But *"smoldot exposes the `chainHead` group only"* was **false**: smoldot implements 63 of its 88 declared methods, and the other 25 answer `-32000 Not implemented in smoldot yet`. `state_getMetadata` and `state_call` accept **any** block hash at unbounded depth. Each resolves over the network, checks the header by hash, fetches `:code` under a storage proof against that header's own state root, then executes locally. No pin and no subscription are involved. `chainHead_v1_*` cannot serve depth at all and answers `-32801 unknown or unpinned block`. **The wall is hash acquisition.** `chain_getBlockHash(height)` returns `null` for every height except genesis and best, and smoldot states the reason: *"there is absolutely no way to verify the answer of the full node"*. So backfill by height is impossible. Backfill by walking `parentHash` from a trusted hash costs one round trip per block. **Two traps.** `rpc_methods` returns the raw macro name list, all 88, so it over-reports and is not a capability set. `state_getMetadata` requires `Metadata` API version `1..=2` while `state_call("Metadata_metadata_at_version", …)` does not. **Consequence:** §9.3's shipped blobs are required rather than optional, and §4.2 is corrected. The remaining probe is peer retention, which is a property of our own nodes.
