## Item

**The Bash tool's sandbox disables git and `gh` in this repository — and git fails *fatally*, not with a warning**

## Spec ref

— (environment; AGENTS.md R-13)

## Status

**measured 2026-08-06, after `/sandbox` was enabled mid-session**

## Result

Recorded because both symptoms read as repository or credential damage and neither is. **git:** the sandbox bind-mounts `/dev/null` over every `.git/**/config.worktree` (visible in `/proc/self/mountinfo` as `devtmpfs /null … ro`, and as a `crw-rw-rw- nobody nogroup 1, 3` entry in `ls`) and then denies reading it. This repo sets `extensions.worktreeConfig = true` in `.git/config`, so git **must** read that file, and the result is `fatal: unknown error occurred while reading the configuration files` — every command, in every worktree *and* in the main checkout, with the three `warning: unable to access …` lines above it being the only clue. **`gh`:** `~/.config/gh/hosts.yml` is 84 bytes and holds the *username*; the token is in the system keyring behind D-Bus, which the sandbox blocks, so `gh auth status` reports *"The token in default is invalid"* and every API call is HTTP 401. That reads as an expired login and is not — network is fine, measured at HTTP 200 from an unauthenticated `api.github.com` fetch in the same shell. **The fix is to turn the sandbox off (`/sandbox`); there is no in-session workaround**, because the only lever that would bypass it is the Bash tool's `dangerouslyDisableSandbox`, which R-13 forbids by name. Consequence for this session: PR #245 could not be read or merged and nothing could be committed, so the F9 work below sits uncommitted in the working tree.
