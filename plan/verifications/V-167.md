## Item

**A workspace dependency declared at `app/`'s root is hoisted, and that voids the firewall corpus's central fixture**

## Spec ref

`app/tests/firewall/fixtures/forbidden-package-edge.ts`; 10 §10.1

## Status

**measured 2026-08-06** while giving `app/tools/snapshot/build.ts` access to `@bleavit/providers`

## Result

Recorded because the failure is *a green gate going red for a correct-looking reason*, and the tempting repair is to edit the fixture. `app/tools/**` resolves bare specifiers from the app root, which declares no workspace dependency at all, so a tool needing one has to get it from somewhere. Adding `@bleavit/providers` to the root `devDependencies` makes pnpm link it into `app/node_modules/@bleavit/`, at which point it is resolvable from **every** directory — including `tests/firewall`, whose `forbidden-package-edge.ts` proves 10 §10.1's CI-fatal edge precisely by being **unresolvable** (`TS2307`). It failed as `TS2305, no exported member 'anything'`, which is the corpus's own *failed for the wrong reason* check (V-91) firing correctly. **The fix is to scope the dependency**: `app/tools/snapshot/` is its own private workspace package, so the link lands in `tools/snapshot/node_modules/` and the root stays empty — the same shape every `tests/*` suite already uses, and the reason they are workspace members rather than bare directories. Anything under `app/tools/` that later needs a workspace package must do the same — and `pnpm-workspace.yaml` **already said so**, in the comment above `tools/verify-release`: *"a member here rather than a root devDependency … the root is reachable from every package by the parent-directory walk"*. The rule was written down and I re-derived it by breaking the gate, which is the more useful half of this row: the reasoning existed, the consequence did not, and the fixture is what supplied it.
