## Item

chainHead storage: is `discardedItems` distinguishable from an empty result?

## Spec ref

10 §4.2; 15 §2 (INV-FE-1)

## Status

complete (2026-08-03)

## Result

**NO — a refused query read as an empty one.** The node may answer `result: 'started'` *and* discard the requested keys; for a one-key read that is `discardedItems: 1`, `operationStorageDone` with no items, and a resolved `[]`. Verified against the pinned `@polkadot-api/substrate-client@0.7.0`, which raises `OperationLimitError` on `result === "limitReached" || discardedItems === inputs.length` — the same condition, so this is the reference implementation's own reading and not a strictness of ours. Now refuses any nonzero discard: stricter than PAPI on *partial* discards, because a short `descendantsValues` witness would turn the FE-P2 cross-check into a verdict about node load.
