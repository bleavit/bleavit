## Item

**F8's ingestion loop: three failures that only *order and continuity* can produce**

## Spec ref

10 §6.3, §6.5

## Status

**verified 2026-08-05 by mutation, one of which I had to write twice**

## Result

The decision layer was complete; the loop that drives it was not, and its own risks are invisible to any unit test of the pure functions. (1) **Coverage must advance only after the write lands.** The tempting shape advances per scan and writes in the background — a crash then leaves coverage claiming blocks whose rows were never stored, and coverage is *the structure the client consults to decide it need not re-fetch*, so `isVerifiedAt` answers `true` for a block with no data behind it, permanently and invisibly. (2) **A skipped block is a hole, never a span.** Subscriptions drop; on resume the naive `addRange(selfRange(first, latest))` claims every block in between as self-ingested — 10 §6.3's forbidden promotion, arrived at by a *reconnect* instead of a merge. The loop adds one single-block range per block and lets `addRange` join only genuine adjacency, so a gap survives because no range was ever created over it. (3) **A failed body fetch fails the block.** Writing the events and advancing anyway records the block as ingested while the user's own transactions from it are missing, and a *filtered* history is indistinguishable from an empty one. A fetched body whose extrinsic count disagrees with the scan is refused for the same reason `attributedExtrinsics` refuses a bad index — from the other side. **9 mutations, 0 survived — but the first attempt at rule 1's mutation was a no-op** (it computed the early coverage and discarded it), which is worth recording: a mutation that does not change behaviour reports *survived* and reads exactly like an untested control
