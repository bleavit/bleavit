## Item

**A workspace *subpath* export is recorded as a bare specifier too, so INV-FE-5's new rule shipped vacuous**

## Spec ref

10 §10.1; INV-FE-5

## Status

found + fixed 2026-08-03 (F6)

## Result

V-86 one layer in, and worth its own row because the first fix did not generalise on its own. `@bleavit/signing/testing` resolves at build time through the package's `exports` map, but enhanced-resolve does not follow it — so dependency-cruiser records `@bleavit/signing/testing` verbatim with `couldNotResolve: true`, exactly as it does for an uninstalled external package. The new `no-test-signer-in-the-bundle` rule, written against the resolved `packages/signing/dist/testing` path, therefore **could not fire**, and it reported success for it. Caught by refusing to accept a new rule's green run without watching it fail — the same discipline that found V-86 four hours earlier. Fixed with a `WORKSPACE_SUBPATH()` matcher beside `EXTERNAL()` in `app/tools/depcruise-external.cjs`, plus a permanent witness importing the production matcher. **The general statement now lives in one place:** dependency-cruiser records *any* specifier it cannot resolve verbatim, so a rule must always match both the specifier a source file writes and the path it would resolve to.
