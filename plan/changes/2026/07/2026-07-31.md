# Unplanned changes — 2026-07-31

## Added `rust-analyzer` to `rust-toolchain.toml`'s…

Added `rust-analyzer` to `rust-toolchain.toml`'s `components` (user-reported VS Code dialog).

The extension ships its own rust-analyzer binary built against a newer rustc than the pinned `1.89.0`, so its proc-macro server refused this workspace; listing the component makes the extension run `rustup run 1.89.0 rust-analyzer` instead, which matches the pin exactly (verified locally: `rust-analyzer 1.89.0 (2948388 2025-08-04)`). **No CI effect** — every workflow uses `dtolnay/rust-toolchain@1.89.0` with an explicit `components: rustfmt, clippy` input, which ignores `rust-toolchain.toml`; the cost is a one-off ~30 MB component fetch for contributors resolving the toolchain through bare `rustup`. `fuzz/rust-toolchain.toml` (nightly-2025-11-24) is deliberately untouched: it is *newer* than the bundled server, so it does not trip the same check. No spec, no runtime code, and no milestone status touched.
