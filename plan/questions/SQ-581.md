## Question

**`surface-manifest.json` covers under half of the metadata constants 02 §9 declares frozen, and two of the gaps are the ones 11 §11.5 explicitly requires.** Filed first as "02 does not freeze `Market::Fee` / `ConditionalLedger::RedemptionFee`" — **that diagnosis was wrong and is corrected here**. 02 §9's *Frozen metadata-constant names* table declares **65** constants; the manifest carries **39**, and **36 declared names have no manifest entry**. Since the manifest generates `CRITICAL_SURFACE`, none of those is probed by 10 §5.2, so a rename moves them with the classifier still reporting **`full`**. **Do not take 36 as the drift count**: at least the four per-pallet `INTEGRATION_CONTRACT_VERSION` rows are a naming artifact (the manifest carries one `constant.identity.contract_version`), and 10 manifest entries absent from this table are legitimately declared elsewhere in 02 (`System.SS58Prefix` in §8; the `QuestionService.*` and `ClientRegistry.ClientBond` v22/v23 additions). The residue is still large and includes **`Market.Fee`** and **`ConditionalLedger.RedemptionFee`** (both named by 11 §11.5 as constants the client MUST read and cross-check), plus **`Market.Kappa1e9`** and **`Market.ObsInterval`**, which app-code rule 7 classifies as tunables `packages/protocol` must take from chain rather than compile in. The client reads them happily today — they are in the runtime metadata, verified in the committed `chain-feed/2/metadata.scale` — which is what makes the silent-loss-on-rename the whole failure mode. **Ruling needed:** reconcile the manifest against 02 §9 (likely **no contract bump** — 02 already declares them), then add the gate that would have caught it. **That gate is now cheap and exact**: 02 §9's table has the header `Pallet` / `Constant name` / `Type` / `Value source`, so the check is a set diff against the manifest's constant entries — no prose heuristic, unlike the doc-sweep probe that first surfaced this. Distinct from SQ-580, where 02 mentions Multisig zero times. **Note against the F6 work:** P-1's fee clause first cited `constant.market.min_trade` — a different constant that happens to exist — because the right one was not citable; the type accepted it and the clause read plausibly. Corrected to omit the fee cross-check rather than half-state it

## Status

open **Attempted end-to-end 2026-08-04; specified, not shipped.** All **36** declared-but-absent constants were resolved against the committed runtime metadata via `scale_metadata.surface_layout` — **every one exists**, so all 36 are genuine manifest omissions and the earlier "some are naming artifacts" caveat was wrong: the per-pallet `INTEGRATION_CONTRACT_VERSION` constants really are separate metadata entries. Entries were generated with derived layouts and **`check-chain-feed.py` accepted all of them** (256 frozen surface entries verified against the real metadata), and `CRITICAL_SURFACE` regenerated to 256 probed — which made `Market::Fee` citable and let P-1's fee cross-check be restored with both halves. **No contract bump is required**, as predicted. **What blocks it is the recorded feed**: `tests/mock-runtime` and `tests/descriptors` assert *bidirectionally* that every frozen surface entry has a chainHead fixture, and the 36 new constants have none. Hand-writing those fixtures is precisely what app-code rule 12 forbids ("never fix a red drift gate by editing the artifact it is comparing"), so the change was **reverted** and the tree left green. The fix is therefore: add the 36 entries, **regenerate the chainhead feed from a booted runtime** (`tools/release/record-chainhead-fixtures.py`), regenerate `critical-surface.ts`, restore P-1's fee clause. **Corrected after checking rather than assuming**: a constant's fixture is *not* content-free. All 39 are distinct — each carries a `metadata_presence` record with the surface id and the **expected vs actual layout**, which is precisely what `surface_layout` derives, so the completeness gate is meaningful and not over-strict. The node is needed only for the shared `chainHead_v1_header`, but **re-recording pins a new block, so all 222 fixtures change** — which is why this is a regeneration cycle rather than an incremental add, and why the attempt was reverted rather than patched.
