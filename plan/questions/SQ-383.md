## Question

**Does the 08 §4.2 NAV-floor gate bind the post-sudo arming writer?** 06 §3.2's PhaseFlags writer map says bits 0–4 are written by bootstrap sudo via `constitution.set_phase_flag` "and by phase-advancement upgrades thereafter (09 §5.2)". SQ-180's gate lives inside the dispatchable, so a phase-advancement **migration** that writes `PhaseFlags` directly bypasses it entirely — after sudo removal the minimum-viable-NAV floor would stop binding at exactly the point the chain is most autonomous. Either the migration path must carry the same check, or 08 §4.2 should say the gate is bootstrap-only and explain why that is safe.

## Status

**resolved 2026-07-24 (A13)** — 08 §4.2 binds every writer of the arming bits, not only the dispatchable. `transition_phase_four` now calls `PhaseArmingGate::ensure_armable(Param)` before any write; an under-floor transition rolls back inside the existing `with_storage_layer` (bits unchanged, sudo key retained, cap raises reverted, bridge left `Scheduled` for a funded retry) and notes the loud halt marker. Pinned by `sq383_phase_four_transition_refuses_below_the_param_nav_floor`; both funded-transition regressions now fund NAV above the PARAM floor first.
