## Question

**Ten of §8's obligations are screen-level and no milestone owns them, so a mechanism with no consumer reads as a completed one.** F9 owns `packages/providers` and `tools/snapshot`, and after 2026-08-06 every §8 mechanism exists, is wired to the ones beside it, and is tested. What has no owner is the half that puts them in front of a user: the provider settings surface that renders the §8.3 ladder and its reasons, the all-providers-down explainer as a rendered state, the §8.1 suggestion list with its accept interstitial, the §8.4 eviction preview as a screen, the import progress and refusal surfaces, the two-snapshot diff UI §8.4 says the client *"supports and recommends"*, the `SAMPLING_GUARANTEE` disclosure §8.4 makes normative UI copy, the coverage/hole rendering §6.3 requires of every history query, the layer-3 write of the minted rows, and **INV-FE-3's actionable-object chain fetch** — *"any actionable provider-supplied object triggers a direct chain fetch before the action is enabled"*, which needs an action surface to attach to. Each is currently a function nobody calls, which is the state that looks finished from PLAN.md and is not. The question is which milestone owns them — F-track screens, a new one, or F9 extended — and it must be answered explicitly rather than by the row staying open.

## Status

**RULED 2026-08-06 — a new milestone owns them: F23** (Track F table). The question asked which milestone, and answering it by leaving the row open was the failure mode it described. The split is where the obligations divide rather than where the code sits: F9 keeps what is checkable without a screen (the format admits or refuses a file, the ladder disables on a mismatch, the mint labels a row), F23 takes what is only checkable with one (a user sees the origin, the gap, the guarantee, and the eviction before agreeing to it). **F9's *Spec* column is narrowed to match** — it read `10 §8` unqualified, and a milestone whose spec claim is a whole section cannot discharge it by exporting functions nobody calls. INV-FE-3's actionable-object chain fetch goes to F23 because it needs an action surface to attach to
