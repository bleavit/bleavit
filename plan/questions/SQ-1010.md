## Question

**`createClient` is unowned, and every milestone named as its owner has closed.** `app/packages/descriptors/src/probe.ts` states that *"nothing constructs a `TypedApi` until F6 wires `createClient`"*; F6's row is the tx machine, signers and preconditions and never mentions it. PLAN.md separately records that *"where `createClient` goes is an F3/F7 boot-sequence decision"*. **F3, F4, F6 and F7 are all ✅**, so the decision was deferred to rows that then closed without taking it — which is why four milestones each name it as somebody else's business and none carries it as open work. This is the owner half of SQ-1005: that row says the classifier has no producer, and this one says why nobody built one. It is now load-bearing — F14's four budget rows, F17's screen registration, F18's deposit leg and `implementedScreens()` all sit behind it. **The design constraint is already recorded and must be honored by whoever takes it:** `light-client.ts` excludes `createClient` *on purpose*, because putting metadata compatibility underneath the read layer would make the app **fail to construct a client** instead of booting into `ReadOnlyIncompatible` and saying why. So the client is built above the read layer, and an incompatible runtime is a boot state the user is told about rather than a crash.
