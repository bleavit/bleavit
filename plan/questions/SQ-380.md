## Question

**The 07 §8 reserve probe is inert in production and its health flag is a one-way latch (critical; blocks SQ-205).** Two independent gaps compose into a trap. (a) `RuntimeProbeDispatch = ()` outside `runtime-benchmarks` (`runtime/bleavit-runtime/src/configs.rs`), so `ProbeDispatch::live()` is false and **no probe is ever sent**. (b) `XcmConfig::ResponseHandler = PolkadotXcm` (`runtime/bleavit-runtime/src/configs.rs:754`) rather than `bleavit_xcm::probe::ProbeAwareResponseHandler`, and no production type implements `bleavit_xcm::probe::ProbeSink` (the only impl is `runtime/bleavit-xcm/src/mock.rs:341`), so **`pallet_oracle::Pallet::reserve_probe_result` has zero production callers** and no probe *pass* can ever be recorded. But `crank_reserve_probe` commits `pending_since` regardless of `live()`, so its timeout folds still count fails: any signed keeper drives `ReserveUnhealthy` in ~`res.fail_threshold` probe intervals, and `res.recover_threshold` consecutive passes — the only exit — are unreachable. Today this is latent because the flag reaches nothing but `welfare_current().reserve_flag`; it becomes a chain-killer the moment SQ-205's sink is bound, since 08 §1.2 zeroes `spendable_nav` while the flag is set. Fix is B4's unfinished production binding: wire the response handler + a real `ProbeSink`, and bind `ProbeDispatch` to `XcmProbeDispatcher` (both impls already exist in `runtime/bleavit-xcm`), with the live-XCM admissibility re-verified as V-6 did. **A cheaper partial fix exists and was deliberately not taken**: gating `crank_reserve_probe`'s state advance on `T::ProbeDispatch::live()` would turn the latch into a no-op and make SQ-205's sink safe to bind live *today*, in files this branch already edits — the SQ-205 compliance review argued for exactly that. It was declined because it decides **SQ-385** (whether a structurally-absent probe scores as a fail per 07 §8's literal text, or advances no state at all) by implementation rather than by ruling, and either reading changes observable behaviour on a solvency path (R-1, R-7). Resolve SQ-385 first; if reading (b) wins, the `live()` gate plus binding the sink closes SQ-205 immediately.

## Status

**resolved 2026-07-24 (stale — verified against HEAD)** — every claim is false at HEAD: `configs.rs` binds `RuntimeProbeDispatch = XcmProbeDispatcher<…>` in production, `XcmConfig::ResponseHandler = ProbeAwareResponseHandler<PolkadotXcm, RuntimeOracleProbeSink>`, and that sink calls `Oracle::reserve_probe_result`, so probe passes are reachable and the latch has an exit. The `ReserveProbeArmed` design added to 07 §8 also removes the pre-arm fail accrual the row described. Live Asset Hub calibration remains separately tracked by the release manifest's `treasury.reserve_probe_unverified` blocker, which is ops evidence, not a code gap.
