## Question

**`static_check` slashed a false footprint *after* the refundable domain/ask arms, so a culpable false declaration escaped the T4 slash by co-occurring with a refundable fault.** A proposal that was both domain-inadmissible (nested `authorize_upgrade` in `utility.batch_all`, which `domains_admissible` refunds — SQ-308) **and** declared a false resource footprint hit the `Refund(ProcessHold)` at the domain arm and never reached the `declared_matches_footprint` slash, so the proposer kept the bond despite a verified false declaration (05 §2.1 T4). Fixed by evaluating the footprint-equality `SlashAll(ConstitutionViolation)` **before** the domain/ask refunds in `configs.rs`, so a false declaration is slashed first and the refundable arms are reached only once the declaration is known truthful. Honest proposals are unaffected: a domain-inadmissible payload whose declared footprint matches still refunds.

## Status

**RESOLVED 2026-07-22.** Reorder in `RuntimeConstitutionAccess::static_check`; regression `false_footprint_is_slashed_even_when_also_domain_inadmissible` returns `Refund(ProcessHold)` pre-fix and `SlashAll` after, and the SQ-308 honest-refund / eligible tests stay green.
