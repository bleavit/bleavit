## Question

**The A-pillar milestone component is unfed end-to-end — no target field *and* no consumer.** (a) `MetricSpec` carries no milestone target (`crates/welfare-core/src/lib.rs:152-171`), so the MilestoneRegistry cannot normalize points or bind a frozen target for a measurement epoch; `milestone_target` is an `EpochContext` **trait method** whose production adapter returns 0 (`runtime/bleavit-runtime/src/configs.rs:3920-3925`). (b) Even with a target, nothing consumes the result: `configs.rs:3661` pulls `Aggregates` for the default (Incident) instance only, the Milestone instance's aggregate is read nowhere in the runtime, and the push seam is a deliberate no-op (`WelfarePullSink`). Add the target to an authoritative versioned metric-spec surface **and** wire the Milestone aggregate to its welfare consumer — neither half is independently verifiable, which is why they are one row. 05 §4.3's MetricSpec field list and its `register_spec` rejection rule were amended in batch B3 to name `target`, so the schema home is now settled; the code is not. *(Absorbed SQ-292, 2026-07-20 — same job. The row's original "so milestone filing/close rejects" was **false** — close silently recorded an aggregate of 0.0 — which batch B3 fixed to a real fail-closed rejection, SQ-291.)*

## Status

**resolved 2026-07-25 (contract v14)** — both halves, which is why it was one row. (a) `MetricSpec` gains the trailing `target` field, validated at `register_metric_spec` (a milestone component with no positive target is refused, and `try_state` re-checks it as a static property of the stored record), so the divisor is frozen per version exactly as I-16 requires. (b) `EpochContext::milestone_target(epoch, spec_version)` is a real read of that frozen field instead of the constant 0 it returned since B1b, keyed by version because two cohorts measuring one epoch under different specs normalize against different divisors — which is the same fact SQ-141 re-keys the aggregate for. The benchmark seam narrowed rather than disappeared: it now falls back only when no spec is registered, so a benchmark that does register one measures against its real target. **The consumer half moved further than the row asked:** with the milestone component now identifiable in a frozen spec, `cohort_exposure(Milestone, ·)` is determinable for the first time and no longer returns the `ExposureUnavailable` stub SQ-296 left it at — it folds the escrow of exactly the cohorts whose frozen spec carries the component (07 §7's component-scoped set), and still returns `None` rather than `Some(0)` when none does, because an undeterminable exposure must refuse the filing, not price it at the floor.
