## Question

**The E3 fee handler adds unweighted storage work to every USDC-paying extrinsic — and the same investigation found the USDC fee path is inert at genesis.** Raised as **P1** by the #196 round-4 Codex review. `UsdcFeesToMain::handle_credit` (`runtime/bleavit-runtime/src/configs.rs:374-390`) resolves the credit into `MAIN`'s asset account **and** mutates `FutarchyTreasury::PendingMainCredit`, inside `pallet_asset_tx_payment`'s `ChargeAssetTxPayment` extension, while `type WeightInfo = ()` leaves the extension charging the SDK's own reference-runtime measurement. The SDK weight is also the exact post-dispatch weight, so there is no later correction: roughly two reads and two writes per USDC-paid extrinsic go uncharged, and a block filled with such calls can exceed its declared execution/PoV budget. Understatement is the one direction 15 §4.5 forbids. The runtime-registry comment claiming these costs are "carried by the extrinsic base weight" was true before E3 and is now stale — the base extrinsic weight is a measured constant that cannot know about a runtime's custom `HandleCredit`. **Practical severity is bounded by a second finding, which is the more interesting one:** `fee.vit_usdc` is **not** a genesis-seeded key (absent from `constitution_core::genesis_params()` and from `tools/limit-coverage/genesis-keys.json`), and `LiveFeeConversion` fails closed without it — so on a genesis chain the entire USDC fee path is **inert** and this handler is unreachable until governance sets a rate. The defect is real but latent, and it arms exactly when that rate is set

## Status

**resolved 2026-07-30.** Fixed by benchmarking `pallet_asset_tx_payment` **in this runtime** and binding `type WeightInfo` to the generated artifact. The prior attempt aborted on `test_run`'s `.unwrap()` and I had guessed at why; this time the error was **instrumented** rather than inferred — `test_run` is not benchmark-gated, so a plain runtime test drives the extension in the same `development` genesis the bencher builds. It reported `Invalid(Payment)` for *bare* and for *rate-only*, and `OK` once the caller held USDC: the fixture needed exactly two preconditions, the governed rate and a funded payer, and neither is a genesis given. Both now live in `AssetTxBenchmarkHelper::setup_balances_and_pool`, and `create_asset_id_parameter` returns `usdc_location()` because `LiveFeeConversion` rejects every other asset — the stock synthetic id would have measured the conversion's **`Err` arm**, a cheap early return, and weighted the paying path with it. **What the measurement showed is worse than the estimate in this row.** The SDK's `()` charged 5 reads / **2 writes** / **3,675 B** estimated proof; the real path measures 5 reads / **4 writes** / **7,404 B** — a **2.01x PoV understatement**, +3,729 B on *every* USDC-paid extrinsic, against a 3,932,160 B normal-class budget. The row's "roughly two reads and two writes" was right on writes and silent on the dimension that actually bounds a parachain block. The measured storage lines are exactly the E3 seams: `Constitution::Params` r:1 (the rate), `ForeignAssets::Asset` r:1 w:1 + `ForeignAssets::Account` r:2 w:2 (withdraw plus the resolve into `MAIN`), `FutarchyTreasury::PendingMainCredit` r:1 w:1 (recognition). **The spec was also wrong, and that is the durable half:** 15 §4.5 mandated benchmarks "for every call and hook" — a transaction extension is neither, so the surface this defect lived on was outside the mandate's scope entirely. Amended under R-1 (see the Decision log): the mandate now names extensions, and a new normative bullet states why an understatement here is worse than for a call (the post-dispatch refund is **self-referential** — it subtracts the same `WeightInfo` function it charged, so on the charged path it is identically zero — and the weight is charged per *extrinsic* rather than per feature-user, so the error scales with block occupancy) and requires upstream fixtures to be re-pointed when this runtime narrows their admissible inputs. Verification: three fixtures generated at the committed 50x20 fidelity, the all-32-pallet drift gate, and a named runtime test (`the_usdc_fee_extension_benchmark_fixture_measures_the_paying_path`) that pins **both** preconditions plus the assertion that the benchmarked path really moves custody and NAV — so a future break surfaces as a named test failure rather than as an unexplained weights-pipeline abort
