## Question

**Does §8.4 authorise disabling a *source* on the strength of a file whose association with that source nothing verifies?** `bleavit.snapshot.v1` carries a content pin and a chain binding and **no publisher identity** — no signature, no key, no operator field — so the only link between a file and a provider is the `Provider` the caller passed to the importer. The consequence is a live path: an `unprobed` provider plus one spot-check disagreement reaches `disabled(auto, …)` at `app/packages/providers/src/import.ts`, and §8.4 makes re-enabling an explicit user action. A third party can therefore hand a user a forged *"snapshot from X"*, and importing it switches X off — a denial-of-service on an honest operator that costs the attacker one file and needs no access to X at all. **Filed separately from SQ-630 rather than folded into it, deliberately**: SQ-630 asks whether a mismatch is file-scoped or source-scoped and is answerable from §8.4's own text, whereas this asks whether the *attribution* the source-scoped reading depends on exists in the format at all — and the answer changes 10 §8.2's format (a publisher identity a consumer can check) rather than only §8.4's scoping sentence, so folding them would hide a format change inside a scoping ruling. A ruling should say whether an unattributed file may disable a source, and if not, whether the format gains an identity or the disable is dropped
