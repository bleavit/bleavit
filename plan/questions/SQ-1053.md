## Question

**CI compiles the `runtime-benchmarks` feature everywhere and executes its tests nowhere, and two crates are already failing inside that blind spot.** `tools/ci/rust-workspace-gates.sh` *builds* `bleavit-runtime` with the feature and *tests* only `try-runtime`; `tools/ci/runtime-profile-gates.sh` uses it for `clippy --lib` and `cargo check`, neither of which compiles a `#[cfg(test)]` module. So any test written under that feature runs in no gate at all. TR7 found this the hard way: the guard it wrote against a benchmark helper that silently declines — the one failure mode the growth-only weight-regression gate structurally **cannot** see, because a decline produces a *cheaper* weight — was itself uncompiled by every gate and could have rotted into a build error unnoticed. TR7 added `cargo test -p bleavit-runtime --features runtime-benchmarks --locked tests_trading_rewards`, and the scope is the question rather than the fix. **Two independent blockers stop it widening, and neither is TR7's:** (1) unscoped, `bleavit-runtime` fails **71** tests deterministically — identical failing set across two runs, all conditional on the feature alone, and no trading-rewards test among them. `RuntimeMetricInputs::onchain_components` has carried a `#[cfg(feature = "runtime-benchmarks")]` branch fabricating welfare metric components since A14 (2026-07-26, PR #177/#191) — but **that explains only 8 of the 71**, all in `tests_welfare_inputs`, and **the other 63 have no identified cause**. The 8 was measured, by neutralizing the fabrication under `cfg(test)` and re-running to 71 → 63, after the scoped re-review refused the fix round's claim that one cause accounted for all of them; (2) `cargo test -p pallet-oracle --features runtime-benchmarks` fails `bench_report` on its own fixture assertion, **found independently by #299's security review the same day** and reproduced at `615c9ba8` in a pristine worktree. Two sessions discovering the same hole in one day at two different layers is the argument for a row rather than two honest footnotes. **The decision owed is whether the fabrication is a legitimate measurement artifact** — a `runtime-benchmarks` runtime is never shipped, which is the same reasoning #299 used to justify its `BenchmarkRecomputeEngine` — **or a defect that makes the profile untestable.** If the former, the gate can only ever be a list of opted-in modules and that list needs an owner; if the latter, both crates need repair before the feature can be tested as a whole. Raised by TR7's fix round, which was told to report the failing set rather than fix unrelated crates.
