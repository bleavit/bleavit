## Question

**`app/package.json` carried `0.0.0`, which `build.ts` refuses, and nothing stated what the first release should publish.** The value is not cosmetic: 12 §1.2 mints an immutable per-release undername `vX-Y-Z_futarchy` from it, §1.4's notes list it, the tagged Arweave sibling carries `App-Release: <version>`, and it feeds the SBOM — a published identifier that cannot be revised, fixed by the undername shape to three components

## Status

**resolved 2026-08-07 (R-1)** — 12 §1.2 now states the scheme: the version tracks **the rollout phase the release is built for**, `0.MINOR.PATCH` through Phases 0–2 and `1.0.0` at Phase 3 mainnet, with the first release publishing **`0.1.0`** (the smallest legal value above the refused `0.0.0`). Tracking `INTEGRATION_CONTRACT_VERSION` is ruled out because 02 §13 rule 8 makes that a *Bleavit runtime* fact while §1.6's expedited lane ships a client release with zero app-code delta, so a client-only release would move a number it does not own. Plain semver over the client's own surface is ruled out because its major component means *"a dependent's code breaks"* and this client is an application with no dependents — the convention would arrive without its referent
