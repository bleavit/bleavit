## Question

**`buy` is one weight for three book kinds, and its benchmark only ever measured one of them.** `fn buy()` seeds `seeded_decision::<T>(1)` and the harness has **no Baseline helper at all**, so the Baseline wrapper's ledger path has never been measured — the dispatch has always charged Decision-book weight for a Baseline buy. Pre-existing, but **SQ-519 widens it**: `buy_baseline` now performs two additional `do_transfer` calls to segregate the fee legs, and the regenerated `pallet_market.rs` shows *no* change in reads/writes/proof precisely because the fixture cannot see them. The #196 GitHub review rates this **P1** and pins the `sweep_revenue` half precisely: on a `Voided` vault the fee account holds accrued buy fees on **both** branches, so `withdraw_fees` runs **two** full `do_redeem_void` operations while the settled fixture measures a single winning-branch redemption — the committed weight omits the second outright. Same shape as the spec audit's `sweep_revenue` note — that fixture measures the settled decision path while `Voided` is strictly heavier, and after SQ-519 its Baseline arm is unmeasured too. 15 §4.5 requires every production-dispatched call to fit its class **at its worst component arguments**, and an unmeasured heavier path understates, which is the one direction weights must never err. Not a solvency defect: understated weight costs block space, not backing

## Status

**resolved 2026-07-29 (milestone E4) — both worst cases now measured at 50x20, and the measurement corrected the review's mechanism on one of them.** `buy`: re-pointing the fixture at a Baseline book moves every block-bounding dimension sharply **down** — proof_size 108,804 -> 16,632 (-84.7 %), reads 77 -> 29, writes 67 -> 19, ref_time -55 % — so the decision book is the worst case by a wide margin and the committed weight was never wrong. That also explains the symptom that raised the row: SQ-519's two extra fee-segregation transfers were real but sit three orders of magnitude below the fixture that sets the weight, which is why its regeneration showed no storage change. `sweep_revenue`: the `Voided` terminal **is** heavier, but the cost lands **entirely in execution time** — ref_time 773,310,000 -> 857,390,000 (+10.9 %) while reads (72), writes (55) and estimated PoV (72,866) are *identical* on both terminals, because both walk the same fixed instrument universe and only the work over it differs. The #196 review described the committed weight as omitting the second `do_redeem_void` "outright"; that is true of ref_time and false of the block-bounding dimensions, which the settled fixture already covered. Fixture switched to `Voided`, weights regenerated, and the ack re-pinned to carry `ref_time` with that reconciliation. `seeded_baseline` and `settle_baseline_and_latch` are retained `#[allow(dead_code)]` as the comparison arm — a fixture selects one kind, so the losing kind's builder is dead by construction, and deleting it is precisely what left the Baseline path unmeasured across three book kinds in the first place. Gates: `--changed` exit 0 (fmt, clippy `-D warnings`, 411 runtime + 90 market tests), weight regression / storage bounds / generated-weight purity all exit 0, and `regenerate-weights.py --check` reports PASS on storage dimensions with only ref_time jitter (<= 3.4 %). **Superseded working note, kept because the reasoning order was right:** the worst cases were derived from `market-core` before being measured, and both derivations held — the value of measuring was in the *mechanism*, not the verdict
