## Question

**Is `decision_stats()` meant to be servable before the decision boundary?** 02 §3 says "exactly as `decide()` would read them **now**", and 02 §9 lists the `dec.*` keys as backing "decision previews". B2's view returns `None` for the whole Trade phase (the full-window TWAP has no checkpoint at a future boundary) and at the boundary itself while registered windows are still unsealed (the crank syncs the clock and seals first, then decides — the view reads immediately). Conservative, but it makes the preview unavailable exactly where 02 §9 implies it is wanted. Also: `backing_complete` requires live baseline TWAPs even though `decide` may legally use the 05 §5.3 previous-settled-baseline carry, so a decidable proposal can read `None`. Should a preview read a different window, or is `None`-until-sealed the contract?

## Status

**resolved 2026-07-24 (code).** Finalized-only timing remains unchanged. `backing_complete` now accepts the exact `decide()` fallback: live Baseline full/trailing windows when the Baseline is decision-grade, otherwise the previous sealed carry — but only after the live Baseline window is registered, sealed, and failed decision-grade; a missing or unsealed window keeps the view `None`. All non-Baseline inputs and gate/depth/prize requirements remain fail-closed. The runtime regression covers the missing-window, unsealed-window, and sealed-failed-grade+carry states. No contract or network change.
