## Question

**§4.5 "SCALE decoding of payload batches" — model type vs runtime type.** The S2 `payload_scale_decode` target fuzzes the frame-free `execution_guard_core::Payload` (over the model `origins_core::RuntimeCall`); the production preimage-decode boundary is `pallet_execution_guard::RuntimeBatch<Runtime>` over the aggregate `frame_system::RuntimeCall`, which the nightly `fuzz/` workspace deliberately does not link (frame-dependency + the separate-workspace **stable2606**-pin isolation; corrected from "stable2603"/"cannot link" at ratification). Does §4.5 require fuzzing the runtime type specifically (⇒ a runtime-linked target, in tension with the isolation rationale), or is model-type fuzzing + the SQ-225 depth-limit hardening + its runtime regression test a sufficient discharge?
