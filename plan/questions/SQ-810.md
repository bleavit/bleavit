## Question

**§8.4's `FE-PROV-003` cause list contains neither outcome of the spot re-derivation the bullet above it mandates.** The table gives that code three causes — a content-hash pin mismatch, malformed encoding, or a failed internal-consistency check (monotone coverage, event↔derived-row agreement, conservation replay) — and every one is a **file** screen. The bullet directly above them mandates a fourth thing: *"deterministic spot re-derivation for the covered blocks that fall inside light-client-reachable depth"*, which is a comparison against the chain and can end two ways the list does not carry. A re-derivation that **disagrees with the chain** is not among the three, and `FE-PROV-002` does not obviously reach it either, being scoped to *"a §8.4 **sampling round**"* — snapshots get screens and indexers get sampling, by that same section's own division. A re-derivation that **cannot finish** is in neither list. §10.4 forbids free text and requires fixed copy per code, so a mechanism with no code has nowhere to go: F9 currently files a disagreement under `FE-PROV-003` with a per-cause remedy **and** disables the source under `FE-PROV-002`, which is two codes for one event chosen by this implementation rather than by the specification. **Is the three-cause list exhaustive, and which code carries each re-derivation outcome?** Distinct from SQ-630, which asks which *subject* a mismatch attaches to (the file or the source) and takes the code assignment as given; this asks whether the assignment exists
