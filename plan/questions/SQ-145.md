## Question

**CODE/META referendum binding is unavailable before ratification passes.** 09 §1.1(4) says queue admission binds a submitted referendum reference and execute later checks pass, but A8's enqueue seam carries only a `requires_ratification` bool and A11 exposes the referendum index only through `Ratifications`, which is written when ratification has already passed. The runtime therefore cannot freeze a pending referendum id without inventing it and conservatively refuses CODE/META enqueue until pass, removing the intended during-timelock consent window. Should proposal/queue state gain a submitted-referendum binding, or should the enqueue seam carry the id?

## Status

**resolved 2026-07-23 (B18)** — bounded `PendingRatifications` storage plus proposer-only `epoch.bind_ratification` freezes the exact live ratify-track preimage before or after queue admission, carries it into `ratify_ref`, rejects mismatches and consumes it only when the exact payload/index passes. A proposal with no submitted referendum may still queue unbound; it remains retryable under D-5.
