## Question

**Do §8.4's import quotas govern the `GET /range` walk, or only the file import?** §8.4 gives *"import quotas … streamed"* with a 400 MB / 4 M-row ceiling, and the word *import* reads as the snapshot-file path. The walk retains every page it admits and had **no bound of any kind** until 2026-08-07 — the derived page ceiling bounds round trips, not size, so a conforming server may answer each of them with a 400 MB page. The fail-closed reading is in force: `readRange` now meters bytes and rows against the same two constants and stops with a `quota-reached` outcome, leaving the rest of the span as holes. What is unruled is whether a *live walk* should share a *file import's* budget at all, given that the two have different memory shapes and a walk can be resumed by span where an import cannot.
