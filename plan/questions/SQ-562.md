## Question

**05 §5.6's `ManipFloor̂` adds a share count to a USDC amount, overstating attacker cost 1.928× — and high is the *unsafe* direction for a lower bound.** `C_disp = Σ b·ln( ((p̄+δc)(1−p̄)) / ((1−p̄−δc)p̄) )` is algebraically `b·(logit(p̄+δc) − logit(p̄))`, which [04](docs/architecture/04-markets-and-pricing.md) §3 states on one line is the **displacement** `Δ`, in *shares* — while the **cost** of the same move is `b·ln((1−p)/(1−p′))`, in *USDC*. 04 §3's own V3 vector prints both for one move (4,054.65 shares vs 2,231.44 USDC), so they are neither equal nor proportional. `C_hold` is USDC, so the sum was dimensionally incoherent. At Bleavit's own PARAM pair (`b` = 10,000/book, δ = 0.0375, p̄ = 0.5) it read **3,005.64** against a true cash cost of **1,559.23**. Because the quantity is a **lower bound on attacker cost**, overstating it makes manipulation look more expensive than it is and **delays §5.6's own escape clause**, which fires when the published floor reads below `3·InCapPrize`. The reference model reproduced the error faithfully; `simulation/.../engine.py::_signed_manip_floor` was already correct via `lmsr.displacement_cost` — so two implementations disagreed by 1.928× and nothing compared them

## Status

**resolved 2026-08-01.** 05 §5.6 now states the cash form with the buy-side price made explicit (`p̄*` = the pre-move price of the outcome the attacker buys, so one δc move costs the same expression on both books), carries the correction as a normative record with the worked numbers, and names 04 §3's `cost`/`displacement` pair so the two cannot be confused again. `manip_floor_hat` now calls `lmsr.displacement_cost`. The durable half is the **cross-check test** (`test_manip_floor_hat_is_cash_cost_and_matches_the_simulation`): it pins the corrected value, asserts the superseded expression really was >1.9× high, and re-derives the simulation's two-sided legs to prove the two implementations now agree. No vector-corpus change (`manip_floor_hat` feeds no vector row) and no contract surface moves
