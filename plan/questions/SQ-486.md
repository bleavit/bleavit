## Question

**`sec.flow_cap` adoption is the one A13 value the error direction makes unsafe, and it is deliberately not taken here.** SQ-173 adopted the published `sec.prize.*` calibration because its absence *blocked* every PARAM/CODE/META proposal — a live defect. `sec.flow_cap` is the opposite shape: unseeded, `sec_flow_cap_1e9()` clamps to the kernel floor **×7**, which 13 §1 row 88 names as the tightest admissible ceiling, so the chain is currently at its most conservative setting and nothing is blocked. The Phase-0 artifact publishes **×16** (0.995 quantile over 4,303 samples; `publication_evidence.flow_cap`), and 13's `[VERIFY — Phase-0 calibration; sim-gated]` tag is exactly the request that evidence answers. But the direction matters: `sec.flow_cap` bounds how much contest capital counts toward `L̂` in step 9's `AttackCost̂`, so raising it **widens** measured attack cost and makes the sizing gate *easier* to pass — the direction in which an error admits an under-secured payload. Every other value adopted in this batch errs toward refusal. Recommendation: adopt ×16 (it is the calibrated value the spec asks for, and ×7 rejects honest exactly-grade proposals per row 88's own note), but as an explicit user/values decision rather than an implementation choice, per R-1.

## Status

**resolved 2026-07-25 — adopted at ×16, and the row's own recommendation was framed backwards.** This row said ×7 was "the conservative reading" and asked for a user decision. Checking the artifact inverts that: the 15 §4.9 security criterion was met **at the ×16 calibration** — `all_decidable_harm_false_pass_lt_1pct: true` across all four classes, `sub_3p_brackets_clean: true`, `violations: []` — from the 0.995 quantile of min-book 04 §7a contest capital over decision-pair depth `2b` (15.637 over 4,303 samples, rounded up). Meanwhile 13 §1 says of the ×7 kernel min that "below ×7 the ceiling could reject honest exactly-grade proposals". So shipping ×7 was shipping a value the simulation never validated, at a known liveness hazard — **conservatism there buys no validated safety**. Adopted ×16, anchored in published evidence per the amended R-2. The **unsafe direction is upward** (a higher ceiling counts more contest capital into step 9's `L̂`, easing the gate), so the row also gains a **×32 max** — one governed Δ ×2 step above the calibration, beyond which the ceiling stops binding on observed flow and the `C_hold` wash bound goes vacuous; R-2 now requires an unsafe direction to be bounded. Seeded kernel-bounded at genesis; the consumer's `.max(SEC_FLOW_CAP_FLOOR_1E9)` clamp stays as defence in depth. **Stale artifact corrected in passing:** the limit-coverage registry classified the key `diagnostic` because "13 §1 explicitly marks sec.flow_cap diagnostic-only in v1; it never gates dispatch" — made false by the SQ-231 amendment, which put the ceiling inside step 9's `L̂`. Reclassified `param-bounds`; the `diagnostic` class is now empty.
