## Question

**`ParamView.value`'s unit for Perbill/Percent/Fixed keys.** 02 §4 says "SCALE-encoded per-key scalar, unit per 13"; 13 §1's `mkt.fee` row reads `Type: Perbill | Unit: bps | Default: 30`, and genesis stores `Perbill(3_000_000)`. So `params()[mkt.fee].value` is 3,000,000 while the `Market::Fee` metadata constant is 30 — and 02 §9 binds the FE to **both** for the same purpose ("quote display, buy/sell cost recompute"). A client trusting 13's "bps" unit computes a 300× fee (it fails closed via 11 §11.5's cross-check → `FE-CHAIN-005`, but trading blocks). Which unit does `ParamView.value` carry?

## Status

resolved 2026-07-21 (batch C, contract v6) — 02 §4 now defines `ParamView.value`/`.min`/`.max` as the **raw inner scalar of the stored `ParamValue`** (`Fixed` on the 1e9 grid, `Perbill` in parts per billion, `Percent` as integer percent, integer/balance variants native) — explicitly *not* the human unit printed in 13's Unit column, which 13 now says so too. The canonical `Perbill`→bps conversion (**divide by 100,000**, floored as shipped) is stated, and 02 §9 / 11 §11.5 P-1 bind fee recomputation to the frozen `Market::Fee` bps projection cross-checked against the raw parameter. **The row's "300×" is false** — raw 3,000,000 misread as bps instead of 30 is **100,000×**. No production code needed; the raw-view/bps-constant split already ships.
