## Question

04 §7 clamp-widening index `k`: is "k missed intervals" in `(1±κ)^k` the **total** number of 10-block intervals elapsed since the previous recorded observation (model: `elapsed // obs_interval`, so a 60-block gap → k=6), or elapsed-minus-the-on-time-interval (k=5)? Backward weighting and staleness are unaffected; only the clamp width differs.

## Status

**resolved 2026-07-20 (B4 ratification).** 04 §7 now pins `k = max(1, ⌊Δblocks / mkt.obs_interval⌋)` — the *total* elapsed whole intervals including the one ending at the record block, so a 60-block gap gives k = 6, not 5. Rust (`crates/market-core/src/lib.rs:1551`) and the reference model (`twap.py:43`) already agree and are test-pinned at `^10`; the doc was the only ambiguous party. The Rust-only inward rounding of the widened bounds was folded in as a normative I-13 requirement.
