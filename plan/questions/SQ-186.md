## Question

**Formula-valued Params rows need a runtime representation.** In particular, `prop.bond`'s TREASURY Ask slope cannot be represented by the scalar Params registry without duplicating a kernel formula outside the named key.

## Status

**resolved 2026-07-25 (contract v13)** — history: **RULED 2026-07-21 (batch X)**, code owed. Verified: only the intercept is represented (`prop.bond.trs`); the 50-bps slope is an undeclared kernel component, and 13 offers no slope bounds fit for a mutable parameter. **Ruled: the slope is a kernel constant `K`**, exposed as pallet metadata, with the base left META-governed; 13's governance metadata for that row applies to the **base only** and must say so. Adding a governed `prop.bond.trs_bps` was refused: with no economic bounds to bind it, governance could walk the surcharge toward zero and weaken intake pricing (R-7). **PARTIAL 2026-07-21 (batch X) — blocked on a contract bump for the metadata half.** Verified: the kernel constant already exists — `kernel::TREASURY_BOND_ASK_BPS = 50` (`crates/futarchy-primitives/src/lib.rs`), consumed by `required_proposal_bond` (`runtime/bleavit-runtime/src/configs.rs`); the "explicit kernel constant" deliverable is already met. Landed here (no 02): 13 §1's `prop.bond` row now states the `+ 0.5%·Ask` surcharge is the kernel constant, **not** part of the `Params` row, and the Default/min/max/Δ columns govern the class **base only**. **Still owed and NOT done here:** exposing the slope as a frozen **pallet metadata constant** (e.g. `TreasuryBondAskBps`) so the frontend can bind it without a hardcode (X-11h). That requires **adding a name to 02 §9's frozen metadata-constant list → `INTEGRATION_CONTRACT_VERSION` bump (v7→v8) + joint sign-off** (02 §13(2)), so it must ride the separate contract-bump PR, not this one. Row stays open on that residual. **resolved 2026-07-25 — decided and done as contract v13.** The residual was never a design question, only a sign-off one, and the sign-off is the user's on both sides (02 §13(2)), so it was taken rather than escalated. `Epoch::TreasuryBondAskBps` now exposes `kernel::TREASURY_BOND_ASK_BPS = 50` on 02 §9's frozen metadata-constant list, so the frontend can compute a TREASURY bond from the live class base without hardcoding the slope — the hardcode being exactly what the exposure exists to prevent, which is why the regression asserts the **real runtime metadata** rather than the Rust constant. Purely **additive**: a new name, no existing name/type/shape/value touched, so `transaction_version` is unchanged (02 §13 rule 7). `INTEGRATION_CONTRACT_VERSION` 12 → **13** across primitives, the five 02 references, the version-history entry, the release surface manifest and its test, all four Rust assertions, and the derived design pack — whose `prop.bond` row now names the metadata constant and says not to hardcode the slope. 13 §1's existing statement that the surcharge is kernel-owned and governs the class **base only** needed no change; it was already correct.
