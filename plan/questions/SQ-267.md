## Question

**Which suites constitute "reference model ≡ pallets on shared vectors" (09 §7.1)?** The shared corpus carries decision/welfare/treasury/twap scenario families (and `lmsr_maker_example`) that **no Rust suite consumes anywhere** — only kernel (LMSR/MPFR) + ledger families have differential consumers. 15 §4.4 requires "decision engine and ledger vs the … reference model driven by shared JSON scenario vectors" and grid-exact welfare reproduction, so the Phase-0 exit criterion is not fully attestable today. The G0 checker therefore enumerates corpus families in its report and caps criterion A at `pass-partial` while any family is unbound. Who owns the missing differential suites (A7/A8-adjacent test debt), and is Phase-0 exit satisfiable without pallet-side replay of the treasury/twap families (no stated Rust-side obligation in 15 §4.4)?

## Status

**resolved 2026-07-20 (triage sweep — code-verified + delegated ruling).** All **14** corpus families carry true-equivalence Rust differential consumers that replay through production code paths with pinned cardinality. `CORPUS_FAMILY_BINDINGS` (`tools/phase-gates/check-phase0-exit.py:55-70`) is cross-checked against the live corpus with drift as a hard error, every binding is non-`None`, and `test_actual_vector_corpus_family_inventory_has_not_drifted` asserts `unattested == []` against the real `vectors.json`; the `pass-partial` branch is retained deliberately as a regression latch. **Ruling on the sub-question**: crate-level consumers (`futarchy-treasury-core`, `market-core`) satisfy 15 §4.4 for the treasury/twap families — §4.4 obliges agreement with the reference model over shared vectors, not a pallet-level replay; the ledger families additionally carry a pallet-level sweep consumer where the spec does demand one.
