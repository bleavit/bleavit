## Question

**The ar.io platform moved from AO to Solana, so doc 12's name-control machinery describes a system that no longer runs.** FE-P7 resolved the n-of-m half negative (V-304), and the archive notice on `ar-io/ar-io-ant-process` carries the larger finding: *"The AR.IO smart contracts have migrated from AO to Solana."* Data upload is unaffected, because bundles still go to Arweave through Turbo. Name control is what moved. Doc 12 now needs three things re-derived rather than carried over. (1) What a "controller share" is, and what signature scheme the current program verifies, which decides whether the FROST-ed25519 ceremony of §4.2 still applies or becomes a platform-native threshold account holding the ANT. (2) What §1.4 item 5's *"one ANT `setRecord`"* is now, and what §2.2's signer registry records as a controller address. (3) Whether FE-P7's four remaining halves — two-pass manifest flow, undername immutability, resolver endpoints, manifest fallback — still describe the same operations. **Ruling needed:** does 12 §4.2 adopt the platform-native threshold path, or keep an application-level ceremony? The answer sets the §6.5 Phase-3 ceremony and D-16's launch block, so it is not deferrable past F11.

## Status

**open — raised by F1 (FE-P7).** The negative n-of-m result is already applied across 00, 10, 12 and 14, so the conservative position holds: single-key custody stays prohibited and launch still blocks. What is open is which threshold mechanism the current platform admits. Needs the user, because it depends on an external commitment and on credentials.
