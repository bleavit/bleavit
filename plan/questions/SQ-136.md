## Question

15 §5 requires artifacts "published … and mirrored content-addressed (Arweave)" before a release is publishable, but CI holds no keys (12/O1) — the ordering is circular if "mirrored" must precede publication. B8 implements a two-step: the tag release is created **prerelease** with notes stating it is not canonical until an operator attaches mirror evidence (JSON mapping each SHA-256 → Arweave TXID; documented in `tools/release/README.md`); the manifest carries `mirror.status: pending`. Open: who records the TXIDs, where the evidence lives on-chain/off-chain, and whether "publishable" in 15 §5 means the prerelease or the post-mirror promotion (O1 interplay).

## Status

**resolved 2026-07-20 (B5 ratification; ordering fixed in 15 §5).** The circularity was real because §5's "published … and mirrored" is a conjunction that never fixed an order. It does now: (a) CI publishes the artifact set as a **prerelease** whose notes state it is not canonical and whose manifest records the mirror duty outstanding; (b) an operator attaches mirror evidence mapping every content digest to its Arweave TXID; (c) the release is promoted to canonical. **"Publishable" in the gating rule is step (a)** — what a runtime release must clear to ship at all — while canonical status, which frontend releases and §1.4 repoints depend on, requires (c). The mutable-host independence §5 asserts is therefore preserved by (c), not by (a). Ratified as shipped: the pipeline creates a visible prerelease and every manifest carries `mirror.status: pending` unconditionally.
