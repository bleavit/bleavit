## Question

07 §7 resolves a challenged filing "by `recompute_proof` where the spec permits, else terminal escalation into §5.4". A6 models the OracleResolution **verdict** via `resolve_challenge`(ResolutionAuthority) but has **no permissionless `recompute_proof`** mechanical path (07 §9 — deterministic recomputation + evidence retrieval). Confirm the recompute path is B-track (keeper/B9), and constrain ResolutionAuthority to the verdict only.

## Status

resolved 2026-07-20 (batch B3) as a *question*, but **ratification refused** — the work moves to successor rows, not a doc sentence. Every clause failed verification. (1) "No permissionless `recompute_proof`" is **false for the oracle**: it exists, is `ensure_signed`, evidence-bound (`hash_evidence(proof) == round.evidence_hash` → `EvidenceMismatch`) and settles via `SettlePath::Recomputed` (`pallets/oracle/src/lib.rs:628-636`; `crates/oracle-core/src/lib.rs:770-802`). The real gap is the **registry**, which has no recompute path at all. (2) "`uphold` is the verdict, not a free authority choice" is **not true of the code**: registry `resolve_challenge(epoch, filing_id, uphold: bool)` checks only that the filing is `Challenged` — no evidence binding, no recompute — and directly decides who is slashed (`crates/registry-core/src/lib.rs:441-463`), unlike the oracle's `adjudicate`, which grid-bounds the value and requires `round >= round_cap` plus a live challenger. (3) "Deferred to B-track (keeper/B9)" is **stale**: B9 shipped with zero recompute references. Refused rather than doc-trued toward the code, on the SQ-79 test — the shipped path is the *less* constrained one, so ratifying it would be an active choice against R-7. Split → **SQ-294** (constrain registry terminal resolution), **SQ-295** (07 §5.4's admissible-call list undercounts), **SQ-296** (registry escalation + §6 re-bond unimplemented).
