## Question

`sec.prize.{param,code,meta}` are `[VERIFY]`/sim-gated (13 §1 row 84). While undefined, how must a conforming implementation treat a PARAM/CODE/META proposal whose capability-envelope prize proxy is 0/unset — hard-reject under 05 §5.6's "undefined proxy ⇒ MUST NOT pass sizing", or pass with `prize=0`? The reference model currently passes (the `adopt` vector), contradicting the conservative-default reading; the reject-on-undefined behavior is modelable without inventing the `[VERIFY]` numbers. *(S4 2026-07-18: the simulation carries an explicit undefined-proxy ⇒ never-adopts negative control; the reference-model/pallet representation question stands.)*

## Status

**resolved 2026-07-21 (batch X)** — **fixed in code.** Verification confirmed the two-sided conformance gap but broke one row claim: the `honest_param_adopt` vector now supplies a nonzero envelope, so it no longer demonstrates the defect (the reference-model *unit* test still did). Fix: `decide_engine` returns a terminal `Ok(Reject(SecuritySizing))` when a required prize proxy is absent instead of `Err(BadDecisionInput)`, so the proposal actually resolves — T10 resolves the reject vault, closes and dequeues the proposal, releases its resource lock and refunds the bond in full. The reference model now preserves `None` as *undefined*, distinct from an explicit numeric zero, and the differential corpus gained an absent-proxy case so the two sides can no longer drift silently. Tests: `undefined_prize_proxy_is_a_terminal_security_sizing_rejection`, `sq40_undefined_prize_proxy_takes_t10_and_refunds_the_full_bond` (both failed pre-fix with `BadDecisionInput`).
