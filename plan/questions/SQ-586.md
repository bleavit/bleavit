## Question

**Nothing derives 02 §6's event obligations from the runtime, and event entries do not pin SCALE discriminants.** Two findings of one shape from the contract-v24 adversarial review, both about the event surface being checked by *agreement* rather than *derivation*. (i) §6 sets criteria (a)–(c) for which events are canonical-frontend ingest, and no gate applies them to the runtime source — so a pallet that gains an event meeting those criteria is never noticed, and the manifest stays green describing an incomplete set. This is the event-side twin of SQ-582, which was exactly this defect for *storage* and was closed by parsing `#[pallet::storage]` from in-repo sources; the same instrument fits `#[pallet::event]`. (ii) `surface_layout` renders an event as its **field list only**, discarding the variant `index` — so inserting a new event *before* an existing one shifts the SCALE discriminants of everything after it while every committed field layout stays byte-identical. A client decoding by discriminant then mis-attributes events with no gate firing. The full `RuntimeEvent` expansion did carry indices, which is why this surfaced while reviewing the `System.Events` elision; but the hole predates it and is not created by it. **Both are implementation work with no ruling needed**
