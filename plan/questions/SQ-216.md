## Question

**02 §9's Status column is implementation status inside the versioned §2-§12 range.** 02 §13(2) bumps `INTEGRATION_CONTRACT_VERSION` on "any change to §2-§12", so flipping a row from "Next wiring" to "Wired" would nominally require a version bump for a status edit — and R-4 says status belongs in PLAN.md, not the spec. Should the column be dropped from 02 (status tracked in PLAN.md), or is it explicitly exempt from §13(2)?

## Status

resolved 2026-07-21 (batch C, contract v6) — **the Status column and the "Wired"/"Next wiring" definitions are deleted from 02 §9.** Every row was wired, so the column carried only stale implementation prose inside a range whose every textual change is versioned by §13(2) — the exact R-4 violation the row identifies. No §13(2) exemption was created: an exemption would have preserved the duplication and weakened the otherwise simple "any §2–§12 change bumps" rule. Status lives in PLAN.md.
