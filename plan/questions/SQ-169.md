## Question

**No `FailedExecuted → Rejected` edge for a failed T23 re-validation.** 05 §2.1 T23 requires "full dispatch re-validation repeats" but defines no rejection edge when it fails (e.g. attestation revoked during the retry window). The S1 model disables T23 in that case and lets T22 fire at retry expiry (status-quo).

## Status

**closed 2026-07-21 (batch D) — no gap.** A failed T23 re-validation is an *errored attempt with no transition*, which the exhaustive-table rule already specifies; T22 then fires at retry expiry. Adding `FailedExecuted → Rejected` would make a transient guard failure terminal and discard the reserved retry window — strictly less conservative. No amendment.
