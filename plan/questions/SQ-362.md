## Question

**05 §2.1's T4 taxonomy does not name the domain-admissibility failure SQ-308 introduced.** The refund arm enumerates "a call the classifier cannot re-derive while its footprint is otherwise admissible", but not the SQ-308 case: a call the classifier **can** re-derive, into a domain the execution guard's `enqueue` refuses, while the declared footprint matches and the class capability check passes. The implementation disposes it as `Refund(ProcessHold)` on the strength of the section's governing principle ("confiscation requires a verified culpable act"; "the refund arm is the default and the two slash arms are the enumerated exceptions") — the payload's only fault is a classifier projection artifact on `utility.batch_all`, a wrapper 05 §1.4 explicitly blesses. Should the refund arm gain this case explicitly?

## Status

**resolved 2026-07-24 (ratified as implemented)** — 05 §2.1's T4 refund arm now names the SQ-308 case explicitly: a call the classifier **can** re-derive but whose projected domain `enqueue` refuses, while the declared footprint matches and the class capability check passes. Pinning it in text stops the disposition drifting back to a slash: the payload's only fault is a classifier projection artifact on a wrapper §1.4 blesses, and the section's governing principle is that confiscation requires a verified culpable act.
