## Question

**`WrongBranch` is dead metadata.** Declared in the core and FRAME error enums and mapped between them (`crates/conditional-ledger-core/src/lib.rs:192-205`, `pallets/conditional-ledger/src/lib.rs:400-466`), produced by no path — settled redemption derives the winning branch internally before building the position key (`conditional-ledger-core:870-943`), and the differential suite deliberately excludes it for want of an honest witness (`tests/differential_vectors.rs:430-447`). Batch D struck the corresponding `NotWinningPosition` from 03 §8. Remove the variant and the two stale differential comments. Worth pairing with a full reconciliation of 03 §8 against the reachable pallet error surface, which has drifted in both directions.

## Status

**resolved 2026-07-21 (batch X)** — **fixed in code.** `WrongBranch` removed from the core and FRAME error enums and from the mapping between them; the two stale differential comments are gone. 03 §8 (batch D) had already made this normative: "Implementations MUST NOT expose an unreachable wrong-branch error variant." Verified that **02 does not enumerate the ledger error enum**, so no contract bump is owed — but the removal does shift FRAME error indices (`TryStateViolation` 12→11 … `InflowCapExceeded` 19→18), which is recorded here deliberately because it is a metadata change downstream decoders see. New test `metadata_exposes_exact_reachable_error_surface` decodes V15/V16 metadata and pins the ordered error surface, so a future dead variant fails CI rather than shipping.
