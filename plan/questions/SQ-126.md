## Question

No spec text defines the off-chain keeper's parameter-sourcing obligation: must it track live `Constitution.Params` values (`mkt.obs_interval`, `dec.window`, `res.probe_*`), or may it ship normative defaults with operator overrides (as the reference implementation does, dynamic `ParamValue` decoding being unspecified for clients)?

## Status

**resolved 2026-07-20 (B5 ratification; resolved by adding text, not by citing it).** Verification refuted the row's premise that 01 §4.2 / 12 §6.1 already carry the obligation — both are role/funding tables and say nothing about parameter sourcing, so the shipped behaviour was simply unspecified. 12 §6.1 now states it: live `Constitution.Params` tracking is **mandatory** for every 13 row governing a crank's due-time or admissibility, under the shipped precedence **override > live > documented default**, with compiled-in defaults required to equal their 13 genesis value. Rows with no safe default are **live-or-nothing** (the keeper skips rather than guesses) — the shipped instance is `ops.ct_quote_ttl`, so it is five keys, not the four the row lists. The honest limit is recorded too: a keeper cannot distinguish "row absent" from "read failed", so both fall back identically and staleness is detected through keeper liveness series, not the chain.
