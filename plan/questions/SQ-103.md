## Question

**(bot P1) Values referenda track collapse + track-config code home.** Stock `pallet-referenda` selects the track from the proposal origin (`track_for`), so the five 06 §2.1 tracks that all produce `ConstitutionalValues` (metric/constitution/entrenched/guardian/ratify) cannot be discriminated — collapsing them onto one track ID would let an entrenched-scope action (e.g. lowering the entrenched-class `att.bond`) enact at a weaker track's threshold. **B1a fix:** the single shared `ConstitutionalValues` track now uses the **strongest (entrenched) thresholds** — 80% approval, 20%→10% support, 50,000-VIT deposit, 4-epoch-equivalent (7 d/28 d/7 d, 28 d enactment) — so **no values action can enact below its required bar** (over-strict but G-1-safe); `OracleResolution` keeps its own track (60% / 10%→3% / 7 d). Two residuals: (a) true six-track discrimination with per-track *scope* needs per-track enactment origins + per-call track-`EnsureOrigin`s (can't be expressed in stock referenda with one shared origin — the 06 §2.3 [VERIFY] family) = a **values-layer milestone**; (b) the track-config plumbing (`SubmissionDeposit`/`UndecidingTimeout`/`MaxQueued`/`AlarmInterval`/`max_deciding`) has no 13 code home (13 marks track values "track config" — neither K nor `Params`).
