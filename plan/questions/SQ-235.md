## Question

**`claim_assets` recovery is undispatchable in the shipped runtime — both routes.** 09 §6.1's trapped-assets row mandates self-scoped Signed reclaim for self-keyed traps and a TREASURY-class call for protocol-keyed traps, and B4's library classifier (`bleavit-xcm`) admits self-scoped Signed `claim_assets` — but the runtime's own classifier puts every `PolkadotXcm.claim_assets` in the Treasury domain (`classifier.rs`), and `pallet_xcm`'s `ExecuteXcmOrigin` is wired with the empty converter (`EnsureXcmOrigin<RuntimeOrigin, ()>`), so a `FutarchyTreasury`-origin dispatch fails `BadOrigin` and Signed dispatch is filtered before it. Every trapped asset is currently unrecoverable pending wiring: which milestone owns the origin-converter + classifier reconciliation? RB-XCM documents the gap and directs operators to record traps, not to attempt claims. Related: SQ-129 (drill routing).

## Status

**resolved 2026-07-24 (B15 merge verification).** The row's remaining documentation claim was stale: merged B15 (`ba27dfa`) already updated RB-XCM with the live Signed self-claim and TREASURY protocol-claim routes, their exact ownership constraints, and the remote-origin inbound `ClaimAsset` route. `tools/deploy/check-runbooks.py` binds the current runbook; no further runbook edit is required.
