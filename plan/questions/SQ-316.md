## Question

**The 09 §6.1 TREASURY-class trap recovery is unreachable through proposal screening.** 09 §6.1 mandates that protocol-keyed AssetTrap entries are reclaimed via a TREASURY-class call, and batch D added the matching 06 §3.2 row; B10 proved the *dispatcher* works (`runtime/bleavit-runtime/src/tests.rs:2856-2885`) but that test bypasses the lifecycle. The exhaustive resource-footprint matcher has no `pallet_xcm.claim_assets` arm (`runtime/bleavit-runtime/src/classifier.rs:98-167`), so screening treats the payload as unclassifiable and cancels it (`configs.rs:3163-3217`); `derived_treasury_ask` additionally accepts only treasury-pallet leaves (`configs.rs:2860-2897`). Needs a canonical resource-domain family for trap recovery (05 §1.4 row), Treasury-domain re-derivation inside belief execution while keeping the Public base-filter treatment for Signed self-recovery, an ask derivation that accepts a zero-outflow leaf, and an end-to-end submit→screen→qualify→queue→execute test.

## Status

**RESOLVED 2026-07-21** (batch X wave 2), jointly with **SQ-244** — one ruling, one patch. Verification **broke one claim**: Treasury-domain re-derivation is *not* necessary — direct Treasury dispatch already works while the leaf stays Public. The real class-safety requirement is an explicit Treasury-only rule inside belief execution, because otherwise adding the admission arms would let PARAM/CODE/META payloads inherit the generic Public allowance (I-8 class confusion). Implementation: keep the base projection Public (a Signed self-keyed reclaim is 09 §6.1's ordinary path); add a `PolkadotXcm::claim_assets` arm to `RuntimeCapabilities::leaf_enabled` requiring `ProposalClass::Treasury` + the Treasury-spend capability; add the singleton `0x0A` footprint arm and the zero-outflow ask arm; and add one submit→screen→qualify→queue→execute regression plus negative PARAM/CODE/META and mismatched-resource tests. **Implemented:** the ruling's class-safety concern was confirmed empirically — before the fix `RuntimeCapabilities::call_enabled(ProposalClass::Param, claim_assets)` returned **true** via the generic Public fallback, exactly the I-8 class confusion predicted. The new `leaf_enabled` arm requires `ProposalClass::Treasury` **and** the Treasury-spend capability; the base call-filter projection stays Public so a Signed self-keyed reclaim needs no governance. Covered by the same 5 tests as SQ-244.
