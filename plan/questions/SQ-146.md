## Status

**RESOLVED 2026-07-22 (B16).** Confirmed inert: every `BlockedMeters` writer was a test/mock (the sole non-test write was the try-state roundtrip helper), no production writer exists. Retired through this runtime's first storage-versioned cleanup — the `ExecutionGuard::BlockedMeters` `StorageValue` + `StoredBlockedMeters` + the `execution-guard-core` `blocked_meters` field + its two vacuous (always-empty) checks were removed, and the orphaned key is cleared by `migrations.rs::RetireB16State` (execution-guard `StorageVersion` 0→1). Behaviour-preserving: the removed execute-time check was over an always-empty set; real §1.2(7) admission (`code.spacing` + the dispatched calls' own meters) is unchanged. `QueuedExecutionView.meters_clear` is now unconditionally `true` (it always was, given the empty set). **Residual split to SQ-461:** the fuller ruling's live `meter_admission`-over-`preview_batch_admission` execute check + a live `meters_clear` view is a functional change spanning the core/execute/view/differential surfaces and was deliberately deferred from the first-migration session (R-7); it is a refinement, not a lost-enforcement defect.
