## Question

θ⁻ floor semantics: 05 §4.1 says θ⁻ floors are "kernel-entrenched: tightening is CONSTITUTIONAL-class; **loosening** requires the entrenched 80% values path" (implying θ⁻ can be set below its launch default), but 13 (entrenched-floors row, L124) says the welfare-gate knees are "**tighten-only from genesis and can never be amended below launch values**." A7's `WelfareParams::validate` hard-rejects θS_lo<0.90 / θC_lo<0.85 (following 13).

## Status

**resolved 2026-07-21 (batch D), split.** Doc half done: 05 §4.1 now pins "loosening" as *un-tightening only* — the entrenched path may walk a raised knee back down to, never below, the launch value — so 05 and 13 read as one rule. Verification found the code half is **not** what the row claimed: both knees are `ParamClass::Const`, so authorization is class-based with no direction test — the constitution track can lower a previously tightened knee and the entrenched track has no authority at all. Raised as **SQ-313** (batch X).
