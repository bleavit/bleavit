## Question

**09 §3.2(1)'s ledger/market inflow-freeze mechanism is unspecified for the no-cursor case (spec-reviewer minor).** §3.2(1) says the playbook freezes the execution queue AND ledger/market inflows, but the runtime's `MigrationHalt` gates only the execution queue; `playbook_calls(Migration)` constructs no `ledger/market.set_frozen`, so a genuine cursor relies on the FRAME MBM lockdown for the inflow freeze and drill 06's source-less staged halt freezes no inflows. Is the MBM lockdown accepted as the §3.2(1) inflow-freeze mechanism (making the explicit ledger/market freeze wording redundant), or must `MigrationHalt` independently gate ledger/market inflows for the no-cursor case?

## Status

**RECONCILED 2026-07-20 (G1, spec-reviewer-verified).** 09 §3.2(1) ruled: for a genuine cursor the FRAME MBM lockdown (`MultiBlockMigrator = Migrations`) IS the ledger/market inflow-freeze; `MigrationHalt` is the automatic execution-queue halt-source bridge. A source-less staged halt (SQ-274 drill) has no half-migrated layout, so it gates the execution queue only — no separate guardian-dispatchable ledger/market freeze exists.
