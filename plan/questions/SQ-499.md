## Question

**Three permissionless cranks each reserve ~389 KB of proof for a payout that fires once per epoch.** SQ-490 replaced the A13 collator-compensation weight with a real benchmark, and its declared PoV is the generator's **estimated** 389,037 B (the recorded proof was 17,874 B — the estimator charges each of the 120 payees' `ForeignAssets::Account` keys as an independent maximum-depth trie path and ignores their shared asset prefix). Declaring the estimate is the correct conservative call, because under-declaring PoV yields blocks that exceed their proof budget at execution while over-declaring only costs capacity — and a sparse benchmark trie under-represents production path depth, so `pov_mode = Measured` would be optimistic about exactly the wrong thing. But the cost is real and now quantified: `decide` sits at **19.0 %** of the 3,932,160 B normal-class budget and `settle_cohort(12)` at **23.9 %**, so roughly four cranks fill a block's proof budget, and the payout they are being charged for happens on one crossing per epoch. **The remedy already exists in the spec for a different call:** 15 §4.5 requires a payload-executing extrinsic to pre-charge its worst case and refund actuals via post-dispatch info. Applying the same pattern to `tick`, `decide` and `settle_cohort` — return `DispatchResultWithPostInfo` and refund `collator_compensation()` on every path that did not cross an epoch — recovers the capacity without under-declaring anything. Cost: three dispatchables change return type, and every early-return/error path in them has to carry the refund, so the refund must be derived in one place rather than repeated (a missed path silently overcharges, which is safe, while a wrongly-applied refund undercharges, which is not).

## Status

**✅ resolved 2026-07-26 (batch X)** — implemented. The three cranks return `DispatchResultWithPostInfo` and refund `collator_compensation()` on every path that did not pay. The pre-charge is unchanged (13 §5's pinned ceilings read `get_dispatch_info()` and did not move); this is post-dispatch only. Each pre-charge now lives in exactly one place — `tick_weight`/`decide_weight`/`settle_cohort_weight`, used by both the `#[pallet::weight]` attribute and the body — because a second copy that drifts would under-refund, which is the unsafe direction. Early `?` exits *before* the payout decision keep `actual_weight: None` and so pay the full charge: that is the safe direction and is commented at each call site so a later reader does not \"fix\" it. Verified by three tests asserting the exact refund, its absence on a crossing, and its presence on an error path
