## Question

**Nothing pins the registry's non-tracking of `orc.window`/`wt.quorum`.** 07 §7 now ratifies that the registry holds the 72 h / quorum-2 kernel floors while the oracle tracks live META raises (SQ-74), but `tools/limit-coverage/registry.toml:428-433` binds `orc.window` solely to `Oracle::WindowClosed`, and no test asserts that amending `orc.window` leaves a registry filing's window at 43,200. A future refactor pointing the registry at live `Params` would pass every gate silently. Add a registry-side negative test and widen the registry.toml reason string to name both consumers.

## Status

resolved 2026-07-20 (batch B3) — fixed in the same session. `registry_windows_do_not_track_a_raised_orc_window` and `registry_quorum_does_not_track_a_raised_wt_quorum` amend the live params upward and assert the registry still pins `REG_WINDOW_BLOCKS` (43,200) and `WT_QUORUM`, so a future refactor pointing it at live `Params` now fails a test instead of passing silently. `tools/limit-coverage/registry.toml` reason strings name both consumers and record the deliberate non-tracking.
