## Question

**The registry challenge row names neither the epoch nor the filing it challenges.** `challenge_filing(epoch, filing_id, evidence_hash)` takes both, and `ChallengeFilingInputs` carries neither — so `windowOpen` and `challengeBond` are per-filing reads with nowhere to say **which** filing they were read for. Found by the F17 evidence sweep, which fixed six sibling instances where the missing subject was a field: `EpochClosure`, `RegistrationReading`, `RerunState`, `FrozenSpecVersions`, `FilingOccupancy` and `AllowanceMeter` all now name what they were read about. This one is not a field — the row models a challenge without modelling its target, so it is a workflow to implement rather than a type to extend, and the same evidence-subject discipline must land with it. Deliberately kept out of #287, which had already been through four review rounds. A challenge is **bonded**, so the failure mode is a user losing money to a transaction naming a filing the client never read.
