## Question

**`quote()`'s failure representation is unspecified.** 02 §3/§4 give `quote()` a total return (`QuoteView`, not `Option`), so a missing/closed/overflowing/out-of-domain book needs a sentinel. B2 returns `cost: 0, fee: 0, p_after_1e9: 0` with `within_domain: false` — a **zero charge for a buy**, i.e. the anti-maker-adverse direction if a client ever renders it as a price, with `within_domain` overloaded to mean both "domain exceeded" and "not evaluable". Is the zero sentinel intended, should it be `Balance::MAX`, or should `QuoteView` gain an explicit evaluability field?

## Status

resolved 2026-07-21 (batch C, contract v6) — `QuoteView` gains a trailing **`evaluable: bool`**. `evaluable = true` for any successfully computed quote *regardless of* `within_domain`; `false` for a missing, closed, trade-inadmissible, inventory-invalid or overflowing book, in which case every price-like field is non-renderable and non-actionable. `within_domain` keeps its single meaning: the post-trade domain predicate. **Two corrections:** the row's claim that an out-of-domain book gets the sentinel is false — `market-core` computes a real quote and sets `within_domain` independently, so only a computation error yields zeros; and `Balance::MAX` was **rejected** as the sentinel because the same view covers sells, where that value is adverse in the opposite direction.
