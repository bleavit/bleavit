## Question

**Does 10 §6.3's *"every history query"* bind a read that is not a layer-3 read?** §6.3's rule opens *"Holes are first-class states. Every history query returns data plus the coverage it came from — a `CoveredResult<T>`, never bare rows"*, and the section it opens is titled *Layer 3 — gap-tolerant local index*. §9.1 makes the chain-wide trade tape deliberately **not** layer 3: *"a chain-wide trade tape is a bounded windowed read, never a retained table"*, so it has no ranges, no origins and no `RangeEdge` — there is no coverage to return. Yet the same read can answer a caller's window with fewer fills than the chain produced, because a block the scan stream never delivered (a reconnect, a paused tab, a subscription that resumed late) is skipped by the same statement that skips a block outside the window — and INV-FE-15's *"gaps are first-class and visible, never silently spliced"* carries no layer scoping at all. **F8 implements the conservative reading**: `readTradeTape` returns the blocks it observed and the gaps beside the fills, in its own vocabulary (`TapeSpan`, never `Hole` or `CoverageRange`), because borrowing §6.3's words would answer this question in code. **Ruling needed:** does a non-layer-3 read owe a coverage statement, and if so in what shape?

## Status

**open — raised by the fifth R-6 review of F8.** No unsafe direction while it stands: the shipped read discloses more than a ruling can require, and a ruling that scopes §6.3 strictly makes the disclosure optional rather than wrong. Filed to **B7**
