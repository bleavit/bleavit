## Question

Which surface answers `OracleDeadlock`'s `contains_key(target)` in `TxPreparation.requires`? §11.8.2 binds `OracleDeadlock` and `VoidInFlight` to the same frozen item (`Epoch.PendingOracleVoids`) under different predicates — per-cohort and non-empty — and `rows.ts` declares **one** clause for both (`key: 'trigger-pending-void'`). `clauseCoverageId` keys on `row/key`, so one passing result certifies both readings, and a client that evaluated only the non-emptiness would satisfy the gate while VOIDing a cohort whose latch was never read. The client side is now closed by type (`TriggerSubject` carries the cohort), but the *declaration* still cannot distinguish the two; should the row carry two clauses, or should the predicate travel with the clause?
