## Question

The guard emits `Enqueued`/`Rejected`/`UpgradeApplied`/`PreimageUnpinned` events absent from the frozen 02 §6 guard row (`Rejected`/`UpgradeApplied` are referenced by 09 §1.5; `Enqueued`/`PreimageUnpinned` are local observability). Reconcile 02 §6 (append + joint sign-off) at a future contract touch, or drop the non-09 ones.

## Status

resolved 2026-07-21 (batch C, contract v6) — the guard row in 02 §6 gains all five shipped lifecycle variants: `Enqueued`, `Rejected`, `UpgradeApplied`, `PreimageUnpinned`, `UpgradeAborted`. **The true drift was six events, not four.** `PreimageUnpinned` is contracted (not dropped as the row offered) because INV-FE-4 requires the frontend to read the committed payload bytes, so it must learn when the preimage stops being pinned. `PendingOutflowSyncFailed { queued, fail_static }` is explicitly named in §6 as a deliberately off-contract operations alarm owned by 12 §6.3 — the first application of the new §6 inclusion rule (SQ-193).
