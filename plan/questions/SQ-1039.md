## Question

**12 §1.5's expedited lane is undecidable from the published tree, and `diff-scope` allowlisted a path the build never emits.** §1.5 states its admissible delta over source paths (`packages/descriptors/**`) and checks it over the built tree, while §1.1 gives every chunk a content-hash-only name — so a descriptor refresh renames its own chunk and every chunk that imports it, up to the entry and `index.html`. The tool allowlisted `assets/descriptors/`, which exists only in its own fixtures, so the check looked decidable and authorized nothing. Ruled 2026-08-09 under R-1: the allowlist entry is removed, the lane is unavailable, and `diff-scope` refuses any candidate whose built-tree delta reaches app assets — the safe direction, since skipping a soak on a false premise is the only unsafe error here. **What remains is a choice, not a defect:** give descriptors a built path stable across refreshes, or have `release.json` carry a signed declaration of which built files are descriptor-derived. The second needs no bundler change but makes the candidate declare its own scope, so it is only as strong as §1.5's two delta-scope attestations; the first is self-evidencing and costs a named chunk, which §1.1 deliberately avoids. **A second blocker sits behind the first, found while implementing this ruling: `sw.js` bakes the per-file SHA-256 map (12 §5.2), so a descriptor refresh changes it too — under a fixed name, arriving as `changed` rather than as a rename.** So a stable descriptor path is necessary and not sufficient, and any answer must cover the service worker as well. The fixture that idealizes the lane's odds holds `sw.js` constant and the tool still refuses.
