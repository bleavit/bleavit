## Question

**`void_cohort` overwrites the recorded decisions of Measuring cohort members, destroying decision history.** 07 §10 says "decisions already made stand" and the amended 05 §2.1/§7(4) pin cohort VOID as a cohort/vault-only transition. But `void_affected_proposals` returns the cohort's members (all post-decision) *plus* the epoch's still-pre-Executed proposals (`crates/epoch-core/src/lib.rs:1215-1244`), and the loop then sets `state = Rejected(ProcessHold)`, overwrites `decision`, and pushes `ProposalForceRejected` for **every** entry (`:1270-1280`) before `push_summary` archives it (`:1293`). A pallet test pins the overwritten archive (`pallets/epoch/src/tests.rs:1342-1351`). Fix: split the affected set — Measuring members keep `state`/`decision` and take vault VOID + the cohort-level `CohortVoided` outcome with no per-proposal event; only pre-Executed proposals take T20.

## Status

**resolved 2026-07-21 (batch X)** — **spec reconciled, then fixed in code; partition corrected after review.** Verification found the row's premise only half true: docs 03 §2.3 and 07 §10 back preservation, but **05 contradicted itself** — §2.1 (batch D) mandated preserving decisions while §7(4) mandated overwriting them for every affected proposal. **Ruled for preservation** and amended 05 §7(4): the archive is the only durable record of what the market concluded, so overwriting a completed `Adopt` with `Reject(ProcessHold)` records a rejection the market never produced (R-7/G-1). **Review corrected the first implementation**: partitioning on `decision.is_some()` was wrong, because T9 sets `Some(Adopt)` on entry to `Queued` and the ordinary T13 rerun path never clears it — so a reopened rerun would have archived its **stale first-round Adopt**, reproducing the same truth defect. The partition is now **cohort membership** (`Measuring` or beyond), which matches §7(4)'s own wording, matches T20's "any non-terminal pre-Executed" scope, and fixes the rerun case structurally. Test: `sq314_void_cohort_preserves_decided_outcomes_and_rejects_only_undecided` plus a rerun-window regression. The residual question — what a *decided but pre-Executed* proposal should record — is raised as **SQ-319**.
