## Question

**11 §11.8.5 names `welfare.snapshot(epoch)`; the runtime's call is `Welfare.record_snapshot(epoch, spec_version)`.** The section's whole precondition is *"epoch boundary passed and snapshot for `epoch` not yet taken"* — keyed on the epoch alone — while `Welfare.Snapshots` is keyed `(epoch, spec_version)` and `pallets/welfare/src/lib.rs:1226` takes both. The consequence is not a naming nit: across a MetricSpec amendment a **second admissible version** needs its own record, and a client implementing §11.8.5 literally refuses a lawful crank because some *other* version already has one for that epoch — on the crank whose overdue state engages the dead-man rule (05). Client posture: `snapshotCrankState` takes the version and keys *already taken* on the pair, and the S18 console renders the version so an operator can tell a genuine no-op from this.

## Status

**resolved 2026-08-07 (contract v29).** The call is `Welfare.record_snapshot(epoch, spec_version)` and `Welfare.Snapshots` is keyed on the **pair**. The consequence is the point: across a MetricSpec amendment a client keyed on the epoch alone refuses a lawful crank because another version already recorded one — on the crank whose overdue state engages the dead-man rule
