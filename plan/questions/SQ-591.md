## Question

**OPEN — `check-client-surface-obligations.py` is sound but not complete: an obligation stated in prose that never names its item is invisible to it.** The gate exists because `check-chain-feed.py`, `surface:check` and `test:mock-runtime` all verify that what *is* declared agrees with the runtime and none asks whether what is *required* was ever declared. It closes that direction by extracting `Pallet.Item` references from docs 10/11 and keeping those whose prefix is a real `construct_runtime!` pallet — and the restriction is load-bearing, since an earlier unrestricted prose sweep reported every capitalised dotted pair and had to be thrown away (a gate that noisy is switched off rather than fixed). **The residual hole is the same one the v24 human sweep had**, because both work from names: 11 §11.3 mandated the proxy delegation read as *"proxies supported as call wrappers under the same precondition system"* and named no storage at all, so neither the sweep nor the gate had anything to match, and SQ-590 survived eleven days behind a gate built specifically to prevent it. Adding `Proxy.Proxies` to §11.3 fixes **that instance**; nothing prevents the next obligation from being written the same way. **What this is not:** it is not an argument for the noisy sweep, and it is not a claim that the gate is wrong — it is sound, and unsoundness would be the worse failure. **Candidate directions, none costed yet:** (a) require every normative client obligation in 10/11 to name its surface, enforced by a shape check on the mandating sentence rather than on the whole document; (b) derive the obligation set from the *client code* instead — every `SurfaceId` a package cites must be frozen, which inverts the direction again and is mechanical, though it cannot see an obligation nobody implemented; (c) accept the gap explicitly and require a spec-question row whenever a client read is added without a §7 home. (b) is the cheapest and covers the case that actually hurts (a shipped client reading an unfrozen surface); it does **not** cover the case SQ-590 was (an obligation nobody had implemented yet), so it is a complement rather than a replacement **Milestone-sized instance found 2026-08-05 (V-114): 11 §11.8 states F17's entire read surface in prose and enumerates nothing**, so this gate is blind to four operator consoles. The surfaces themselves are frozen (02 §7.2/§7.4) and probed, so nothing is unsafe — but the gate built to prevent the SQ-580 class cannot see the largest remaining client surface, which is the completeness gap this row already names. A fix that only enumerated §11.8 would leave the method gap; the row stays open for the method.
