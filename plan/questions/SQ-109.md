## Question

**Ratify two B3 genesis-economics rulings** made under the session's standing delegation (both conservative, both spec-pinned in the amended 08 §2.1): (a) founding-team vesting = the **0%-at-cliff** single-schedule curve (not the conventional 25% catch-up — see the 2026-07-16 Decision-log row for why catch-up is unsafe at genesis); (b) **unvested VIT cannot pay transaction fees** (strict "nothing spendable before the cliff"; founding-team accounts pay fees in USDC per 08 §9 — a reviewed-then-removed fee carve-out adapter is preserved in git history if the ruling is reversed).

## Status

**resolved 2026-07-20 (B5 ratification; both rulings ratified, one mechanism corrected).** (a) Ratified as shipped: the 0%-at-cliff single schedule is in `genesis.rs` (`begin = BLOCKS_PER_YEAR`, `liquid = 0`), pinned by `team_vesting_curve_is_cliffed_and_never_faster_than_the_ideal_curve`, and enforced on the production side by the allocations template plus the validator's exact-equality `TEAM_VESTING_SCHEDULE` pin. (b) Ratified in outcome, **refuted in mechanism** — the row credits a strict lock, but `UnvestedFundsAllowedWithdrawReasons = TRANSACTION_PAYMENT` literally *permits* fee payment; the strictness is emergent from `FungibleAdapter`, whose `fungible` API has no withdraw-reason concept. 08 §2.1 now binds the **adapter** (no fee path may exempt a vesting lock; the exemption set is inert and is not authorization), so an adapter swap is a spec violation rather than a silent regression; the runtime test driving the real fee path is the standing guard. The row's "preserved in git history" claim is also inaccurate: pickaxe over all refs finds no adapter code — only the `7354d5c` commit message records the decision.
