## Question

**Shared Baseline semantics across late rerun windows are incomplete.** Pin which frozen window a rerun uses when its original epoch's shared Baseline has later proposal windows or an already-sealed boundary.

## Status

**resolved 2026-07-20 (B1 tail; verified against `pallet-market`, then documented).** Shipped behaviour is fully determined — the spec simply never described the mechanism. The shared Baseline book stores **one window per distinct boundary triple** (`DecisionWindows: MarketId → BoundedVec<TwapWindow, 8>`) with **per-proposal ownership layered on top** (`DecisionWindowOwners: MarketId → BoundedVec<(ProposalId, start, trailing_start, end)>`), so sharing is by *identity of boundaries*, not by epoch: coinciding epoch-e proposals share one window and hold separate owner rows. Answering the row directly: a rerun **registers its own new window** from the fresh `decide_at` (`force_rerun_markets` recomputes `start`/`trailing_start` and calls `register_decision_window(baseline, pid, …)`), never reusing or mutating its pre-rerun window; an **already-sealed** earlier window is *not* an obstacle — it stays a distinct entry, and `consume_decision_windows` consumes **every** window a proposal owns at once ("including an earlier sealed extension attempt"), requiring all of them to be sealed first; and a rerun **cannot** read another proposal's boundaries, because every match is on the exact triple the reader owns. Eviction is reference-counted — a window and its checkpoints drop only once the *last* Baseline-sharing owner has consumed them. The capacity edge is handled, not open: the 8-distinct-boundary ceiling (13 §4 `TwapCheckpoints`) is checked **before any mutation** and fails closed with a regression test (`ninth_twap_checkpoint_boundary_is_rejected_without_mutating_full_ring`), and `shift_decision_window` shifts a dead-man deadline **in place** precisely to avoid a transient ninth boundary on a shared Baseline. Spec trued: 04 §8.4 gained a normative five-point paragraph pinning all of it. No code change.
