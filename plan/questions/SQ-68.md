## Question

The 07 §4 quorum machinery has `WindowAcknowledged`/`WindowExtended`, but those names are frozen in 02 §7.2 for the **oracle** (A5/#52 froze them there), not in the 02 §6 **registry** row. A6 emits neither (state is read from `Filings`). Should 02 §6 gain *registry*-shaped `WindowAcknowledged{epoch,filing_id,watchtower}` / `WindowExtended{epoch,filing_id,new_deadline}` (append-only + contract bump + joint sign-off) for FE/keeper observability, or stay event-less?

## Status

resolved 2026-07-21 (batch C, contract v6) — **ruled eventful, and implemented.** `registry-core` already computed `WindowAcknowledged`/`WindowExtended` and the FRAME shell **discarded** them; both instances now map them to public variants, and 02 §6 freezes the registry-shaped fields (`epoch`, `filing_id`, `watchtower` / `new_deadline`) — distinct from the identically named oracle events frozen in §7.2, which are untouched. Ruled eventful rather than event-less because 11 §11.8.6 must display acknowledger identity, and `Filings` carries only a *count* (individual acknowledgers live in a separate dedup map).
