## Question

**The four occupancy keys are refused in both directions, so their 13 §1 registry rows are unexercisable.** SQ-303 screened the class-floor family by value; the occupancy family — `epoch.slots`, `mkt.obs_interval`, `dec.window`, `epoch.length` — kept the unconditional refusal it inherited from A13's temporary brake, because 13 §5 items 1–4 state their envelopes as prose derivations with no literal to compare a re-derivation against. Two consequences, both narrow and both real. (a) No value of these four keys is admissible through `constitution.set_param` today, so the §1 bounds / max-Δ / cooldown rows — which do still run, and run *before* the screen, so their limit-coverage bindings stay honest — gate an entry nobody can reach. (b) `epoch.length` is declared governable over 14–42 d and 06 §2.4 reasons from that range; that is a statement about the declared registry, not a live capability. (b) costs the SQ-234 entrenchment guarantee nothing — it is sized against `kernel::PRODUCTION_MAX_EPOCH_LENGTH_BLOCKS` precisely so it never depends on the key moving. **The fix is not the artifact verifier**: SQ-303 established that no artifact can move a compile-time bound, so it could not deliver the property here either. It is single-homing items 1–4's envelopes as constants, the way SQ-303 single-homed 08 §4.1's floors into `CLASS_NAV_FLOOR_USDC` — after which the identical value test applies and the refusal narrows to exactly the unsafe values. Item 4 (the keeper-crank observation budget) is the cheapest start: it already names its four assumed values in the spec text.
