## Question

`MarketCreated { …, epoch, … }` (frozen 02 §5): for a decision/gate book `pallet-market` holds only the `ProposalId`, not the proposal's owning epoch, so A3's internal `create_market` emits `epoch = 0` for non-Baseline books (and hardcodes the vault `MetricSpecVersion = 0`). Both belong to the epoch/welfare context. Should `create_market` gain `epoch`/`spec` params (the epoch pallet provides them at book creation), or is decision-market `epoch` defined as 0?

## Status

**resolved 2026-07-24 (SQ-64 implementation).** The vault-spec premise was stale; the actual frozen-surface defect is fixed. `pallet-market::create_market` now requires an explicit epoch, emits that value for decision/gate books, rejects a Baseline epoch mismatch before mutation, and production `RuntimeMarketAccess::open_markets` plus benchmark/runtime fixtures pass `proposal.epoch`. Pallet and runtime regressions pin event fidelity and atomic mismatch refusal; the exhaustive Rust gate is green.
