## Question

The attestor challenge-resolution surface is unenumerated. 06 §7 says a challenge resolves "by a `ratify`-track adjudication referendum," but §2.1 (ratify-track scope), §2.2 (ratify `Contains` filter) and §3.2 (authority matrix) enumerate only `execution_guard.ratify` + `guardian.ratify_action` — no attestor resolution call. `pallet-attestor` (A10) implements `attestor.resolve_challenge(attestation_id, upheld)` behind an injected `RatifyOrigin` seam; its name, origin and §3.2 matrix row are unspecified. Separately, 06 §8's event shorthand `AttestationSubmitted/Challenged/ChallengeResolved` does not distribute a shared prefix cleanly, and the pallet additionally emits `MembersSet`/`AttestorEjected` (not in the §8 list). Both need pinning when the attestor surface is frozen at B2 (rides with SQ-2/SQ-26's 02 §7 attestor-row amendment, one contract bump).

## Status

resolved 2026-07-21 (batch C, contract v6) — 06 §2.1/§2.2/§3.2 now admit `attestor.resolve_challenge(attestation_id, attestation_upheld)` on the ratify track (the shipped call already enforces `RatifyOrigin`, wired to the Ratify track in the runtime), 06 §8 carries the five exact shipped names, and 02 §6 gains a `pallet-attestor` row freezing them. **The row's `Challenged` shorthand was wrong** — the shipped name is `AttestationChallenged`. No production code needed.
