## Question

A6's reap archive-delay gate needs a tunable, but 13 has only `ledger.archive_delay` (no `reg.archive_delay`); the registry's `Config::ArchiveDelay` is a `Get` the runtime sources at B1a. Add a `reg.archive_delay` key to 13 §1 (+ 07 §14), or reuse `ledger.archive_delay`? Also: 07 §7 anchors reap at "cohort settlement + archive delay" while the code anchors at close-block + delay (ledger `sweep_dust` precedent) — coincide iff the delay ≥ the close→last-consuming-cohort settlement span.

## Status

**resolved 2026-07-24 (contract v12).** The ruling did not require a new `reg.archive_delay` tunable: the runtime now derives both registry instances' `ArchiveDelay` as `max(live Params[ledger.archive], 21 × BLOCKS_PER_DAY)`, independently preserving the §11 money-deadline floor. The pallet exposes this value as the frozen metadata constant named by 02 §9; contract v12 and its 00/02 history record the binding. Runtime metadata/floor regressions and full registry/runtime verification are green. No network drill applies.
