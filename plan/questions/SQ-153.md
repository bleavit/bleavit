## Question

**The 06 §3.3 closed-wrapper table has stable2603/metadata representation drift.** It omits the present `utility.if_else` and `utility.dispatch_as_fallible` variants (S5 pins both fail-closed per the milestone brief), while `pallet_xcm.execute` semantically holds `VersionedXcm<RuntimeCall>` but SCALE metadata's `DoubleEncoded<T>` skips `T`, so registry traversal sees opaque bytes rather than a path to the runtime-call type. Should 06 add the utility rows and explicitly define XCM's semantic-carrier exception to the metadata tripwire? (`sudo_as` remains separately tracked by SQ-99.)

## Status

**resolved 2026-07-21 (batch D)** — 06 §3.3 gains `utility.if_else`, `utility.dispatch_as_fallible` and `pallet_xcm.execute` (all denied), plus a normative definition of **carrier** covering metadata-opaque *semantic* carriers, so the CI exhaustiveness rule binds them. Ripple: 09, 14 TH-30. ("stable2603" in the row was stale — the runtime is stable2606.)
