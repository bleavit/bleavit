## Question

**Does §8.3's health ladder gate a snapshot *import* at all?** §8.3's subject is reads a client issues to a provider, and a snapshot is not one: it arrives out of band, the user already holds the bytes, and what admits it is the content pin plus §8.4's screens plus the chain re-derivation — no step of which asks the endpoint anything. So a literal reading makes provider health irrelevant to an import, and the `Provider` on the import request is only the label its rows carry. §8.4 pulls the other way by binding a re-derivation mismatch to the **source** (`FE-PROV-002`, the question SQ-630 asks), which only means something if health governs this path. F9 splits the difference deliberately and says so: `disabled` refuses (`FE-PROV-002`'s fixed recovery tells the user the source *"has been switched off"*, and minting fresh rows under its label contradicts that — and re-enabling is an explicit user act, so the gate is satisfiable), while `unprobed` does not, because no probe driver exists or can exist until SQ-771 and SQ-613 are ruled, and a gate nothing can satisfy is a dead feature wearing a control's clothes. A ruling should say which of the two subjects §8.3 has, and whether an import is a read
