## Question

**The 12 §5.2 out-of-band monitor reads its credentials from inside the bytes they sign, and its document schema has no producer.** Two findings from the F13 Codex round, one document apart. `attestation_monitor.py` takes `release_signatures` and `attestations` out of the served `release.json` (line 703) while verifying them against `sha256(release_json_bytes)` (line 397) — the same bytes — so a signature transaction id written into the document invalidates the signature over it. 12 §1.4 gate 4 now publishes both id sets in the release notes and `verify-release compare` takes them as `--signature` and `--attestation` (ruled 2026-08-09), which closes the CLI half. The monitor half is open: it is unattended and cannot be handed flags, so it needs a machine-readable index of the credential transactions **addressed independently of `release.json`**. Separately its schema is `bleavit.release.provisional.v1` with a `files` map that no producer emits, so the §5.2 monitor is unfillable in a second way. Both belong to O1's provisional `release.json` field names rather than to F13.
