## Question

**PB-MIGRATION checkpoint state-root semantics.** 09 §1.2 requires the parent block/state-root audit anchor, but the runtime host exposes the current transactional storage root while `frame_system` exposes the parent block hash; the exact pre-dispatch parent-state root is not named as a runtime-readable source. Is the checkpoint `(System::parent_hash, current pre-dispatch storage_root)` as implemented, or must the executive persist the parent header state root separately?

## Status

**resolved 2026-07-21 (batch X)** — **fixed in code** (rides **SQ-127**'s anchor patch, as its disposition predicted). Execute-time storage-root computation is deleted outright — the anchor is captured at application, so no state root is computed at execute. The checkpoint/pending equality try-state assertion is replaced by the specified **one-way lifetime invariant**. Test: `sq_144_try_state_enforces_only_the_anchor_lifetime_direction` pins authorization-without-anchor and rejects orphan anchors.
