## Question

**08 §5.4(a) contradicts §5.3's scaling rule.** The normative CODE worked example takes `P = 693,147` against `P_ref(CODE) = 341,589` — a ratio of ≈2.03 — yet seeds the **unscaled** floor `b = 60,000` for its POL-depth term (`2 × 60,000 × ln 2 = 83,178`); §5.3 requires `b = 60,000 × 2.03 ≈ 121,760`, giving depth ≈168,800. §5.4(b) already carries a "Normative-seeding form" companion showing both readings, so (a) is the unfixed twin. Restating (a) with the scaled form raises its margin, so the identity is not at risk — this is a correctness-of-the-worked-example defect, not a security one.

## Status

**resolved 2026-07-21 (batch D)** — 08 §5.4(a) restated with §5.3's normative scaled seeding (`b ≈ 121,751`, depth 168,783, L̂ 1,555,077, AttackCost̂ 2,332,616, margin **12.2 %** vs the old 6.0 %), matching (b)'s existing companion; the floor-depth arithmetic is retained as an explicitly labelled conservative lower bound. **Scope note:** this closes the doc-internal contradiction only — the runtime seeds the flat `pol.b` floor and has no on-chain `P` for CODE, which is **SQ-300**'s code scope, not a conformance claim by this batch.
