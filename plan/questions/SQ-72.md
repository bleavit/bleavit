## Question

07 §7 `close_epoch` **pushes** the aggregate via `note_external_component`; 07 §2 says welfare **reads** closed records at snapshot. A6 does both (push at close + records readable until archive-gated reap). Which is normative? Determines whether the reap timing must key on welfare-consumption rather than a block delay.

## Status

resolved 2026-07-20 (batch B3): **pull is normative.** 07 contradicted itself — §7's trust boundary already said "`pallet-welfare` reads its *closed* records at snapshot time" while §7's `close_epoch` row said the aggregate is "hand[ed] to `pallet-welfare::note_external_component`". The row now says close_epoch computes and **stores** it, plus a normative *Consumption model* note: welfare pulls and the registry MUST NOT acquire a write endpoint (a push inverts the dependency and puts the relative ordering of two independently keeper-cranked calls on the settlement path). The code already implements the pull reading — the push is a deliberate no-op (`runtime/bleavit-runtime/src/configs.rs:3892-3900`, `WelfarePullSink`), so "A6 does both" was true only of the pallet's trait surface. **Reap made normative rather than incidental:** records MUST outlive the §11 money deadline and every consuming cohort's settlement, and the archive delay MUST pin that floor independently — today the registry borrows the *ledger's* `ledger.archive` (90 d min vs the 21 d worst case: safe, but only by reusing another component's key). **New:** the Milestone instance's aggregate is written but read by nothing in the runtime → **SQ-292** (X).
