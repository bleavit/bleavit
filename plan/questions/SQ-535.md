## Question

**The 02 §9 `Epoch::PhaseOffsets` list publishes a decision-window fraction that is only true at the genesis registry.** Found by the new `reference-model` `lifecycle` module, which put 05 §3.1's phase schedule into Python and could not reproduce 13 §3.1's table with one formula. Every entry in `phase_offsets::ORDERED` scales with `epoch.length` by construction — that is what the list is *for*, and 13 §3.1 says so — except `DECIDE_WINDOW_NUM = 15`. 05 §3.1 anchors the decision window **absolutely** to Trade close (`[18/21·L − dec.window, 18/21·L)`; "`dec.window` and `dec.trailing` remain absolute block-count parameters"), and 13 §5's own in-flight table classifies `dec.window` as **live**-consumed via `decide_at − dec.window`, so the absolute reading is unambiguously the governing one. The fraction coincides with it at `(epoch.length, dec.window) = (302,400, 43,200)` and, executably, at **exactly one** of the 19,201 lawful `epoch.length` values — the default. At `epoch.length = 604,800` the fraction gives `[432,000, 518,400)` against the governing `[475,200, 518,400)`; at `dec.window = 86,400` it gives a 43,200-block window against the governing 86,400. **Not a live defect:** the only current consumer, the keeper's `phase_boundary`, uses `ordered[5]`/`ordered[6]` and never reads index 4, taking the window from the absolute `dec.window` instead — so nothing today renders it wrong. It is latent and points at the frontend, which 02 §9 entitles to read the list as phase offsets and which does not exist yet. **The doc half is fixed**; the contract half is this row

## Status

**open (batch X).** 13 §3.1's table row is corrected under R-1 — it now states the absolute derivation and why the `15/21` was a default-registry rendering — and `reference-model` pins both readings so the divergence cannot widen unnoticed. What remains needs a ruling and is **not** a doc change: `ORDERED` is a frozen 02 §9 metadata surface, so dropping the entry (7 → 6) is an `INTEGRATION_CONTRACT_VERSION` bump with joint sign-off plus keeper index shifts. Three dispositions: drop it; keep it and add a normative 02 §9 sentence that the DecideWindow entry is advisory-at-default and clients MUST derive the window from `dec.window`; or keep it and re-specify the window as a true fraction, which would make `dec.window` redundant and contradict 13 §5 item 4 — so that third is recorded to be refused, not chosen. Cheapest correct move is the second, folded into whichever bump lands next
