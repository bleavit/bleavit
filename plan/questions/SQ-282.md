## Question

**Drill-04 dead-man does not engage on a relay *finality* stall — the `observe_dead_man` relay-parent-**jump** detector vs 05 §4.8's "no parachain block finalizes" (first-execution finding).** Drill 04's first-ever run (on the SQ-128 fast-timing runtime, `DEAD_MAN_RELAY_BLOCKS` compressed 4,800→48) reached the 48-relay-block stall in ~8 min, but `assert-dead-man engaged` **failed** ("dead-man did not pause the epoch clock and execution queue"). Root cause is a detector/scenario mismatch, **not** timing: the parachain kept producing throughout the stall (liveness `dead-man-pre-fault,2` passed), so `data.relay_parent_number` advanced smoothly and `observe_dead_man` (`pallets/epoch/src/lib.rs:1521`) saw no ≥-threshold jump. The B10 detector fires on a relay-**parent** jump between consecutive parachain blocks (a parachain **outage / catch-up** signal), whereas a relay-**finality** stall keeps the relay producing and the parachain follows the unfinalized best — exactly the open 05 §4.8 `F`-signal `[VERIFY]` ("exact accessible validation-data fields on stable2606"): `PersistedValidationData` exposes `relay_parent_number` but not the relay's finalized-head number, so the runtime cannot compute best-over-finalized on-chain. Options: (a) the drill induces a parachain outage (pause **collators**, not relay validators) so a genuine relay-parent jump fires the detector — but that tests catch-up, not finality; (b) extend the detector with a relay finalized-head input **if** the relay state proof exposes it (audit-scope-A, closes the 05 §4.8 [VERIFY]); (c) accept the detector as an outage/catch-up backstop and re-scope 05 §4.8's "no parachain block finalizes" wording. The `DEAD_MAN 4,800→48` compression is proven correct and independent of this.

## Status

**RESOLVED 2026-07-20 (G1, decide-yourself ruling; spec-reviewer-verified).** SDK verification (three checks over the stable2606 pin) is definitive: the parachain runtime **cannot** observe the relay GRANDPA finalized head — `PersistedValidationData` carries only `parent_head`/`relay_parent_number`/`relay_parent_storage_root`/`max_pov_size`, no `well_known_keys` finality key exists, and `cumulus_pallet_parachain_system` surfaces only the relay best/anchor. So option (b) (a finalized-head detector input) is impossible on the pin; a pure relay *finality* stall is not on-chain-detectable. Resolution = (c)+(a): the 05 §4.6 `F`-signal `[VERIFY]` is closed (accessible field = `relay_parent_number`; `F` is inclusion/liveness, not GRANDPA-finality — the detector code was already `relay_parent_gap`-based and correct), 05 §4.8 trigger 1 + 13 §2 + 14 TH-37 re-scoped to the observable relay-parent-gap semantics with the finality-stall residual honestly assigned to an off-chain monitor (SQ-283) + XCM-isolation bound, and **drill 04 re-pointed** to a real relay-parent-gap collator outage (pause all collators → relay best advances ≥ 48 → catch-up jump engages the on-chain dead-man). First execution proved the mechanism (bit 6 + `incident_active` latch, relay parent 108); the acute queue-freeze is transient under the compressed catch-up so the drill asserts the durable engaged flag (the acute freeze stays unit-tested, `pallets/epoch` `dead_man_pauses_phase_and_rejects_submission`). Spec-review: 0 blocker; the finality-lag-alert pointer defect is SQ-283
