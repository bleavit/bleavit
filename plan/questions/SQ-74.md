## Question

Is the registry's challenge window the **fixed** 43,200-block kernel floor (A6's `kernel::ORC_WINDOW_BLOCKS`, per 07 §7 "frozen constant") or does it track the META-raisable `orc.window` (07 §5 "MAY be raised via META to ≤ 120 h")? Same for the registry's `WT_QUORUM` (kernel floor vs live).

## Status

resolved 2026-07-20 (batch B3): **ratified the kernel floors.** 07 §7 gained a normative *Fixed windows and quorum* note — the registry pins 72 h and `wt.quorum = 2` as fixed constants and does **not** track META raises of `orc.window` (≤ 120 h) or `wt.quorum`, which the §5 oracle game does track. Divergence verified: `crates/registry-core/src/lib.rs:22` (`REG_WINDOW_BLOCKS` = `kernel::ORC_WINDOW_BLOCKS` = 43,200 = exactly 72 h at 6 s blocks) and `:33`/`:376` (`WT_QUORUM` const) vs `crates/oracle-core/src/lib.rs:492` (`params.window`) and `:694` (`params.watchtower_quorum`). Rationale ratified: registry filings hold settlement only (§12) and must clear the §11 money deadline, so a longer window buys no dispute quality while pushing closure toward it. **Residual:** `tools/limit-coverage/registry.toml:428-433` binds `orc.window` to the oracle consumer only, and nothing pins the registry's *non*-tracking → **SQ-290** (X, test coverage).
