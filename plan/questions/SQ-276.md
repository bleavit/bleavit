## Question

**02 §11/15 §4.7 state no rule for admissible drill-environment overrides.** The only normative text is 02 §11's "genesis overrides matching the release" (which the Bleavit para spec honors — `constitution.phaseFlags` only). The G1 session had to invent the operative reading for the *relay side*: Paseo-host configuration (`scheduler_params.num_cores`) and the Paseo tree's own local-profile `fast-runtime` feature are admissible in the local drill environment, while the Bleavit runtime and every 13-owned value must match the release byte-for-byte. Ratify that reading (the 2026-07-18 Decision-log row documents exactly what was toggled and why), or amend 02 §11/15 §4.7 to state the rule explicitly.

## Status

**RATIFIED 2026-07-20 (G1):** relay-host/local-profile overrides (`num_cores`, `fast-runtime`) are admissible drill-env overrides, extended to genesis-**state** staging of drill preconditions against the byte-identical release runtime — the drill-06 `MigrationHalt` flag and the guardian seat-bond funding reallocation, alongside the existing `phaseFlags`/guardian-membership overrides. The Bleavit runtime Wasm and every 13-owned value stay byte-exact (the reallocation preserves the 08 §2.1 1B-supply/150M-ops/200M-founding totals). 02 §11's "genesis overrides matching the release" governs the Bleavit para spec
