## Question

**`phase3.tvl_cap` makes Phase 4 unreachable: the arming gate reads a NAV floor 2.31× the cap that bounds NAV.** 09 §5.2 caps *all* local USDC issuance at 2,000,000; 08 §1.2 makes every positive NAV term local USDC; the Phase-3→4 transition observes the 08 §4.1 PARAM floor of 4,620,989 *before* it may raise the cap. Every escape closes in the spec itself — genesis seeds twelve 0.01-USDC protocol-account floors (0.12 USDC total, and those *consume* issuance headroom rather than create an off-cap NAV term), the try-state ProtocolAccounts exemption bypasses only the per-account meter, and §5.2 forbids a raise at Phase ≤ 3. Derived minimum caps, which no document states: **Phase 4 = 4,620,989**, Phase 5 = 25,000,000 (its funding target dominates the 7,393,600 treasury floor), Phase 6 = 21,256,533. Both cap values carry `[VERIFY]`, so this is a lower bound rather than a proposed value. **Ruling needed:** which value does 09 §7.2's raise schedule adopt, and should §7.1's Phase-4 row state the dependency?
