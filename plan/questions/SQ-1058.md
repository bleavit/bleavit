## Question

The transaction-builder root exports `gate(prep, at, live, compat, results)`. Every input is a
caller-constructible plain object; agreement between fabricated values reaches the cast to the only
`GatePassed` brand. The real raw-signing test fixture demonstrates this without any finalized read.
This contradicts the module and INV-FE-2 claim that the gate proof is constructible only after one
proof-backed refresh. Exposure is latent because the current application composition registers no
transaction screen or production signer call site.

## Status

**resolved 2026-08-12.** The caller-controlled evaluator was removed from the production API.
Public `refreshAndGate(prep, connection)` accepts exactly two arguments, opens one fresh finalized
pin and observes the connection's finalized runtime, but deliberately returns `FE-TX-004` until a
closed metadata-derived evaluator owns every key, decoder, compatibility decision and predicate.
It therefore has no port through which a genuine irrelevant read, `derive` callback, fabricated
verdict or off-pin result can become signing evidence. The explicit-value evaluator remains only
for state-machine tests behind `@bleavit/transaction-builder/testing`; the package root withholds
it and production dependency rules reject both that subpath and relative imports of its underlying
module. Negative compilation covers the removed callback type, old third argument, plain transport
and former mint, while named-rule probes keep both production firewalls non-vacuous. Signing is
intentionally unavailable until the closed evaluator lands; that is INV-FE-12's safe staging state,
not a claim that the full §11.4 read table is implemented.
