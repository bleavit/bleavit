## Question

06 §3.3's two-check model — "(b) `BaseCallFilter` **denies governance-privileged calls unless dispatched with their matching custom origin** — enforced again by each pallet's `EnsureOrigin`" — cannot be realized inside a `Contains<RuntimeCall>`, which is origin-blind. The implemented split (A4): the **origin-less** base filter denies the nobody row, the dangerous wrappers, and bare governance leaves (a signed submitter carries no matching custom origin); the **origin-aware** re-check (`SafetyFilter::validate(Some(origin), …)`, already applied by `execution-guard-core` at execute, I-11) plus each pallet's `EnsureOrigin` runs at the governance dispatch boundary (guard; scheduler per §3.4), which then dispatches via `dispatch_bypass_filter`. This is safe/conservative and matches the guard core, but 06 §3.3's `impl Contains` reference block (`_ => static_domain_allowed(c)`) reads ambiguously — the A4 Codex adversarial review reads it as *allowing* bare governance leaves at the base filter (origin enforced solely by `EnsureOrigin`), and warns that naïvely setting `BaseCallFilter = SafetyFilter` on the enactment path would `BadOrigin`-reject every custom-origin call and stall governance. Should 06 §3.3 be clarified to state explicitly that (i) the origin-less `BaseCallFilter` denies bare governance-privileged leaves and (ii) governance/scheduler enactment bypasses it and re-validates origin-aware — pinning the B1a wiring? Code is internally consistent under the conservative reading; this is a spec-clarity + B1a-wiring item, not a current safety defect.

## Status

**resolved 2026-07-21 (batch D)** — and the row's own premise was **false**: the stock scheduler does *not* bypass `BaseCallFilter` (it uses ordinary filtered dispatch), which is exactly why the runtime carries a closed bare-values-enactment admission set (`classifier.rs:988-1043`). 06 §3.3/§3.4 + 01 now state the real two-path enforcement: origin-aware `contains_for` + bypass on the belief side, origin-blind closed-set admission + `EnsureOrigin` on the values side.
