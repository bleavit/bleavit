## Question

The canonical `limited_reserve_transfer_assets` exit is public and uses the general
`HealthTrackingRouter`. Every locally accepted send increments the numerator of
`X = accepted / (accepted + failed + probe_timeouts)`, with no per-account/window cap and before
remote execution is known. After real failures lower `X`, a user with a position that benefits from
higher `C_onchain` can pay for repeated deliverable Asset Hub exits and drive `X` back toward one.
That moves daily gate and settlement inputs upward through an ordinary XCM outcome, which I-24
forbids. Existing tests prove the call is public and router success increments the counter, but no
joined adversarial test covers the path.
