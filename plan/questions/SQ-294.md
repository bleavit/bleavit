## Question

**Registry terminal resolution is an unconstrained binary authority choice.** `resolve_challenge(epoch, filing_id, uphold)` gates only on `T::ResolutionAuthority` plus the filing being `Challenged`; it binds no evidence, admits no recompute proof, and decides the slash directly (`crates/registry-core/src/lib.rs:441-463`; `pallets/registry/src/lib.rs:605-614`). The oracle's counterpart *is* constrained — grid-bounded value, `round >= round_cap`, live challenger required (`crates/oracle-core/src/lib.rs:821-854`). 07 §7 says a registry counter-round closes "by `recompute_proof` where the spec permits, else by … terminal escalation into §5 step 4"; the code does neither. Constrain the call (evidence/recompute binding) or specify the discretion normatively.

## Status

**resolved 2026-07-25 (batch X) — and the row's "or" was right to collapse: BOTH stated paths are structurally unavailable.** (a) `recompute_proof` cannot apply — §9 defines evidence as raw data *plus recomputation instructions under the frozen `formula_ref`*, and a registry filing is a bonded claim about an off-chain fact with no `formula_ref`; there is nothing to recompute, so the zero occurrences in the registry are correct rather than missing work. (b) Escalation into §5 step 4 keys on a `(component, epoch)` game, and **`I` is not a `MetricId`** — it is a scalar multiplier on `C_attested`/`C_settlement` (05 §4.4), which is why SQ-296 prices it against every consuming cohort — so an Incident filing has no component to open a game on. The path is not implementable, not merely unimplemented. **Ruled: the counter-round is terminal and closes on an `OracleResolution` verdict** (which is what the code always did and what §7 never said), **with the discretion bound by three normative constraints** rather than removed: the caller MUST restate the challenge's committed `evidence_hash` (a commitment binding, not a proof — `MaxEvidenceLen = 32` means no preimage exists on-chain; its job is to stop a mis-parameterised verdict from silently slashing an unrelated party's bond, since `(epoch, filing_id)` are two integers); the counter-round window MUST have elapsed (`Challenged{window_end}` was **stored and read nowhere** — `crank_close` did `let _ = window_end`, so a verdict could land in the same block as the challenge); and the forfeit is the **stored** bond (I-28). Also fixed: `_ => WindowOpen` conflated "still `Filed`" with "already terminal", which now reports `AlreadyFinal`. 07 §7 gains the missing `resolve_challenge` Calls row plus the terminal-resolution note; the false `recompute_proof` promises in the pallet docs are gone. The authority is deliberately **not** removed: `crank_close` never auto-resolves a `Challenged` filing, so stranding it would wedge `close_epoch`, the aggregate and the welfare input — and the failure direction is not neutral, since welfare's pull-side default reads a missing aggregate as the *favourable* "no incidents" value. Two regressions, both verified to fail under mutation of each constraint.
