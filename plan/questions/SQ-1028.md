## Question

**Which INV-FE-9 provenance status does an observed genesis hash carry, and does a plain-DOM render escape the no-unlabeled-rendering obligation?** The terminal screen writes `error.observed` — a value the chain supplied through `chainSpec_v1_genesisHash` — as raw `textContent`, unlabeled. None of INV-FE-9's six statuses fits: it is not finalized-verified, not best-head, not derived-local, not provider, not stale-cache, not external-proposal. `check-render-provenance.ts` cannot see it by construction, since it gates `.value` accesses on `Verified<T>`, so a plain-DOM surface sits outside every mechanical control. Pre-existing, and raised now because this is the first shipped surface rendering a sourced value outside the typed component system.
