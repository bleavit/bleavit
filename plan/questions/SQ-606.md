## Question

**10 §7's database name `futarchy@<paraGenesisHash-prefix8>` does not say whether "prefix8" is 8 hex characters or 8 bytes, and it names a persisted database.** The two readings differ — `futarchy@a1a1a1a1` against `futarchy@a1a1a1a1a1a1a1a1` — and this is the one identifier in the client that **cannot be changed later without orphaning every user's stored index**: a client that reads the other spelling opens an empty database, re-backfills from nothing, and reports no error, because an absent database and a fresh one are the same state. The section's own reason for the suffix is what makes the ambiguity matter: a single shared database would let a client that connected to Paseo yesterday and Polkadot today read yesterday's rows as today's chain, and nothing downstream could notice — the rows are well-formed and the ids collide because both chains number their proposals from one. F8 ships **8 hex characters** (`chainTag`, 32 bits of the hash), which is the reading *"prefix8"* takes in the same document's other prefix language and is ample against accidental collision while being useless against a deliberate one — which is not a threat here, since the name is local. **Ruling needed:** fix the spelling in §7 so it can never be re-read

## Status

**open — raised while implementing F8's store.** Low stakes today (no user has a stored index) and permanently high stakes after the first release, which is the argument for ruling it before F-launch rather than after. Filed to **B7**
