## Question

**Deferred: `QueuedExecutionView.meters_clear` is not yet a live rate-meter preview.** After SQ-146 retired the inert `BlockedMeters` set, `meters_clear` is unconditionally `true` (its always-true value under the empty set). SQ-146's fuller ruling calls for a read-only `meter_admission(&RuntimeBatch)` on `BatchDispatcher` implemented over the existing runtime `preview_batch_admission`, an execute-time 09 §1.2(7) check returning `MetersBlocked` **without** setting `failed_at`, and the same preview computing `meters_clear`. Deferred from the first-migration session (B16, R-7) because it is a functional change spanning the frame-free core, the execute path, the view (needs per-item preimage decode) and the differential surfaces — a view-hint refinement, not a lost-enforcement defect (real §1.2(7) admission is unchanged).

## Status

**resolved 2026-07-25 — and it was not a view-hint refinement.** Verified first: 09 §1.2(7) requires treasury-outflow, issuance *and* `code.spacing` to admit the batch at step (7), with contention leaving the proposal queued to "retry within grace". Only `code.spacing` was checked there; treasury/issuance contention surfaced instead as a mid-batch dispatch failure at step (12), whose atomic rollback **records the T18 failure** — moving the proposal onto the shorter `failed_at + RETRY_WINDOW` clock, so a transient meter could spend a retry budget the spec grants against `grace_end`. That is an enforcement/behaviour gap, not a hint gap; the row's "no lost enforcement" reading was right only about *whether* the meters bind, not *where*. Fix: defaulted `BatchDispatcher::meter_admission`, implemented in the runtime over the existing `preview_batch_admission` machinery, consulted at step (7) **before any dispatch** (so the storage layer rolls back whole and no `failed_at` is written), and single-homing `meters_clear` in `Pallet::queue_view` — fail-closed, since an unfetchable/undecodable payload must not be published as meter-clear. Two narrowings are load-bearing and both are pinned by tests: (i) the leg excludes `code.spacing`, which the guard must own because it alone knows the D-9 expedited exemption — a spacing-blind preview would have refused exactly the emergency CODE payload the exemption exists for; (ii) only `MeterExhausted`/`IssuanceCapExceeded` block, because the first draft flattened *every* treasury error into `MetersBlocked` and was caught by `execute_under_constitution_dead_man_reports_freeze_active_and_preserves_queue` — `fund_budget_line` carries no meter at all, so its `InsufficientFunds` was being reported as meter contention and preempting the (10) freeze check. Non-meter refusals stay with step (12), where the bounded retry window is the right treatment for a defect that will not improve by waiting. 09 §1.2 gained the normative note stating both directions; 11's mirror row now points the FE at `meters_clear`. **No 02 surface change, so no contract bump** — the field's documented semantics were already "rate meters would admit execution now"; the implementation was non-conformant. Four tests fail under mutation of either leg. **Connector P1 on #170, valid and fixed:** the preview simulates only four treasury calls, so a batch whose earlier leaf moves the meter *base* — `[sweep_insurance, spend]`, funding the spend from the sweep — judged the later leaf against a **stale** NAV. Harmless while the preview only gated queue admission; wiring it into step (7) turned it into a liveness regression that would strand an adopted proposal for its whole grace window over a batch the ordered atomic dispatch would complete. Fixed structurally rather than by simulating one more call (each unmodelled call is a latent repeat): the preview now returns **no verdict** the moment it meets a `FutarchyTreasury` leaf outside the four it models, and step (7) fails **open** on that. The boundary is provable, not guessed — `nav()` is a pure function of treasury state, so `FutarchyTreasury` leaves are exactly the set that can move a meter base. Safety is unchanged because the meters bind on the dispatched calls at step (12) regardless. 09 §1.2 carries the rule normatively
