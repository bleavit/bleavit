## Question

**`RederiveBudgets` is a normative screening obligation with no implementation, and B4 made it the sole safety rider for the frozen NAV floors.** 13 §5 item 6 says the classifier tags the trigger keys with a `RederiveBudgets` obligation "checked at screening"; the identifier occurs nowhere in `crates/`, `pallets/`, `runtime/` or `tools/` (the similarly-named `rederive_call` is the unrelated execution-guard payload re-derivation). B4 extended the trigger set from 4 keys to 10 and made 08 §4.1's *Freeze and re-derivation* paragraph lean on it, so it now stands between a one-META `pol.budget_epoch` cut and a §4.2 gate arming below the true floor. Impact is deferred only because SQ-180 leaves §4.2 unwired — this is therefore a **dependency of SQ-180**, not an independent row. *(**Both halves of that sentence are stale as of 2026-07-25.** SQ-180 resolved 2026-07-21 and the §4.2 arming gate is live — `TreasuryPhaseArmingGate` → `ensure_nav_floor`, consulted before any `set_phase_flag` write — so the impact is **not** deferred and this row is independent and load-bearing, which is presumably why the temporary brake shipped. Two further corrections: 13 §5 no longer contains the string `RederiveBudgets` or "checked at screening" at all, so the row's quotation of it is dangling — and so is 08 §4.1's cross-reference, which still cites a term 13 no longer defines; and the trigger set is **12** keys today, not 10, after SQ-305 added `pol.b_baseline`.)* Implement the screening check, or de-normativize the obligation and rely on the paired-CODE-proposal control 08 §4.1 now states.

## Status

**✅ resolved 2026-07-26 (batch X)** — the obligation is now **enforced by value, not by direction**, and the row's own framing ("implement the screening check, or de-normativize") turned out to admit a third answer that is better than either. `constitution.set_param` re-derives 08 §4.1's per-class floors from the *proposed* parameter set and refuses exactly when one would exceed the frozen literal, rounding the derived floor **up** so the error direction is against the proposal. Verified: the derivation reproduces the published table, with every literal sitting 0.39–30.07 USDC **above** the exact value — conservative, which is what makes `derived <= frozen` the right test rather than an equality. **Why this beats the artifact/verifier the row lists as owed:** 08 §4.1 states outright that "no governance artifact can move" a compile-time floor, so a verifier could never have delivered the safety property — only the paired CODE proposal can — and the direction test refused the values change *even after* that CODE landed, so the six keys were frozen in fact rather than screened. A value test admits them precisely when the literals have become right, with no artifact schema, pairing record or execution ordering. **Two over-rejections removed**, each against 13 §5 item 6's own words: `ledger.archive` ("can only move downward … remains safe") and `pol.b_baseline` ("moves no frozen literal") are no longer screened at all. **A third was claimed here and was false**: an earlier version of this row said `epoch.length` had stopped being frozen in its safe direction. It had not — `is_occupancy_input` classifies it unconditionally and always did — and the Codex review of #184 caught the claim after merge. All four occupancy keys stay fail-closed in **both** directions, because items 1–4 have no single literal to compare a re-derivation against. That residue is now **SQ-501**, which also carries the consequence the false claim was reaching for: 06 §2.4 reasons from `epoch.length` being governable over 14–42 d, and that range is today declared rather than exercisable. Frozen floors single-homed into `futarchy_primitives::kernel::CLASS_NAV_FLOOR_USDC` so the treasury and the constitution screen cannot drift
