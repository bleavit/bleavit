## Question

**`FE-IDX-002` is declared and defined nowhere.** 10 §9.4's error taxonomy lists `FE-IDX-001..002`, and the same paragraph requires *"fixed user copy + expert detail + documented recovery per code; no free-text errors"*. `FE-IDX-001` has all three (10 §7, 11 E9, 14 TH-58). **`FE-IDX-002` appears in exactly one place in 00–16 — that range — and has no trigger, no copy and no recovery.** This is the shape SQ-552 and `FE-HANDOFF-010` both had: a code that exists as a range endpoint and emits nowhere, which no green run distinguishes from one that never fires. The local index has an obvious second failure class needing a code — a **per-range** invalidation, where §6.3's *"corruption of one range invalidates that range, not the index"* means the user loses a span of history without the whole-database rebuild `FE-IDX-001` describes — and F8 now implements exactly that (`verifyRanges`, `checkIndexAtBoot`), reporting it with no code because none is defined. **Ruling needed:** define `FE-IDX-002` with its trigger, copy and recovery, or retire it from the range the way `FE-HANDOFF-009` was retired (with the gap kept, since a reused code makes two failures indistinguishable in every record on either side of the reuse)

## Status

**open — raised while implementing F8's per-range invalidation.** The per-range drop is the natural referent and F8's boot path is its emitter, so the cheapest resolution is a definition rather than a retirement. Not ruled here because the taxonomy is a UX surface with fixed copy, and inventing copy for a code is exactly what §9.4 forbids. Filed to **B7**
