## Question

A7's `EpochNotFinalized` guard admits a snapshot/daily-gate crank only for a **strictly past** epoch (`epoch < CurrentEpoch`; 05 §4.6 winsorizes over *finalized* values). This imposes a B1a epoch-tick ordering — the clock must advance to `e+1` **before** `Snapshot(e)` is recorded, so `Snapshot(e−1)` exists when epoch-`e` normalization is frozen at epoch open (05 §4.6) — and admits daily gate flags at **whole-epoch** granularity, not live per-day, so a mid-epoch guardian `suspend_on_gate` reaction (05 §4.7/06) would need a current-day/slot seam A7 does not expose.

## Status

**resolved 2026-07-20 (triage sweep — code-verified).** The increment-then-record obligation holds structurally and is pinned: neither pallet declares a snapshot-writing hook, the tick persists the incremented index before returning (`pallets/epoch/src/lib.rs:2088`), and welfare's clock IS that storage item (`configs.rs:3744` → `pallets/epoch/src/lib.rs:277-281`), so `record_snapshot(e)` is admissible only after a tick moved the clock past `e` (runtime tests `tests.rs:3342-3368` and `:3161-3173`). The row's second clause — a mid-epoch day-elapsed seam — was explicitly conditional ("if live within-epoch daily recording is wanted") and remains unrequested; `record_daily_gate` keeps whole-epoch granularity.
