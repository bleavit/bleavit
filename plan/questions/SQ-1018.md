## Question

§11.8.2's propose-flow precondition list is closed at "allowance remaining for the power" plus the activation trigger, while `guardian_core::check_and_consume` enforces more: `SuspendOnGate`'s gate-breach flag (06 §5.2, unnamed in 11), `PauseIntake.until` and `ActivatePlaybook.expiry` within `[now, now + HOLD_MAX_BLOCKS]` (`DurationTooLong`), `DelayOnce`/`ForceRerun` proposal status (`NotRerunnable`) and the already-rerun set (`AlreadyRerun`). Every input is a frozen surface — `HOLD_MAX_BLOCKS` is `Guardian.PlaybookFreezeWindowBlocks`, and `RuntimeGuardianStatus::status` reads nothing but `Epoch.Proposals` — so the fail-closed reading is implementable rather than an obligation with no surface. Should the propose row carry these the way §11.5's `execute` row carries the guard's fourteen? Implemented fail-closed and declared as O-4 clauses pending the ruling. A related bound is **not** implementable and stays open: `TooManyPending` (`pending.len() < 64`) has no frozen constant, so a client can read the count and not the cap
