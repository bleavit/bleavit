## Question

**Oracle value-at-risk snapshot is absent.** 07 §6.1 requires the reporter merit bond to use a value-at-risk frozen at `Snapshot(m)`; the live vault/treasury state is mutable and cannot substitute safely. A8 returns `Balance::MAX` whenever a relevant cohort exposure exists, pricing such reports out rather than under-bonding them.

## Status

**resolved 2026-07-25 (A12)** — and the row's own premise needed correcting. `StakeAtRisk` now returns the real 07 §6.1 quantity: `Σ CohortEscrow(k)` over the cohorts whose frozen MetricSpec consumes the component for measurement epoch `m`, summed from each cohort's vault escrow — bounded at ≤ `MAX_NON_TERMINAL_COHORTS_BOUND` cohorts × 5 proposals. The `Balance::MAX` sentinel is gone, so exposure-bearing reports are priced instead of overflowing `round_bond`'s checked multiplication (the accidental fail-closed that masked SQ-293). **The row asked for a new frozen snapshot store; none was needed, and building one would have been wrong.** 07 §6.1 contained a self-contradiction: its `CohortEscrow` line read escrow "at the block `Snapshot(m)` finalizes", while the same section's *Per-game freezing* paragraph binds `B_1` — and therefore the `StakeAtRisk` inside it — **once, at round-1 creation**, storing it with the game. `oracle_core` already implements the latter. The `Snapshot(m)` reading is also **circular** for an attested component: that snapshot *consumes* the oracle's settled value for `(c, m)`, so it cannot be the input that prices the game producing it. Amended under R-1: escrow is read at round-1 creation, which is equally deterministic, equally immune to later escrow movement, and actually implementable. This unblocks **SQ-296** and through it SQ-294/SQ-295.
