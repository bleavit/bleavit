## Question

**§8.2 promises snapshots are *"reproducible byte-identically by anyone from `tools/snapshot` against an archive node"*, and no document says what `tools/snapshot` consumes.** That promise is to **independent producers** — a second person must be able to write a reader, feed the tool, and obtain the same pin — and a producer input format that exists only as a TypeScript parser in this repository is not a format somebody outside it can write against. §8.2 already treats the *published* format's canonical rules as normative for exactly this reason (a second producer that cannot reconstruct the same bytes cannot cross-check the first). F9 publishes the boundary as a generated schema (`app/schemas/bleavit.archive-export.v1.schema.json`) so the gap is at least documented, but where that format's normative home belongs — doc 10 §8.2, a new subsection, or explicitly nowhere because it is tooling — is 10's to say. Bound up with SQ-612: the format's shape and the read interface that fills it are the same question asked from two ends.
