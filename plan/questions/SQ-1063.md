## Question

Both app build jobs use the same mutable runner image and `actions/setup-node@v7`; the second job's
declared isolation is chiefly a checkout-path change. No workflow runs the required digest-pinned
container, and runtime release tooling also records an unpinned build image. A compromise or drift
in the common runner/action can therefore produce identical injected output and preserve the green
tree-hash comparison.

## Status

**resolved 2026-08-12.** Third-party workflow actions are full-SHA pinned and
mechanically checked. App reproducibility uses distinct digest-pinned Node/Debian
images; runtime primary/recovery builds run through one digest-pinned OCI wrapper
with a read-only source and build-info v3 environment identity. Genuine artifact
regeneration follows the clean source commit; historical v2 evidence is not
relabeled.
