## Question

**SQ-608's provenance-blind *"downsampled"* label now sits beside a §9.2 `MUST`, which makes the same gap load-bearing rather than cosmetic.** SQ-608 records that §9.2's label has no source while §7 keys chart rows per source, so one span can be coarse for one source and raw for another. §9.2 also states: *"Raw depth is the tier that moves with hosted occupancy, so a client **MUST** present it as measured-and-current rather than as a promise."* F8 implements the `MUST` by measuring depth per tier from the stored rows — which is per source in the rows and **not** per source in the label, so a surface reading the label and a surface reading the rows can disagree about the same span while both are correct. **Ruling needed with SQ-608, not separately:** either key the label by source, or state that a surface presenting measured depth must read the rows and that the label is a span-level summary only

## Status

**open — raised by the R-6 re-review of F8.** The label remains the pessimistic one (it never claims more resolution than is stored); the measured-depth report is per tier and exact. Filed to **B7**
