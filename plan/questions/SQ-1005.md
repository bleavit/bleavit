## Question

**10 §5.2's compatibility classifier has no producer for either chain, so the compat lattice has never run.** `probeCriticalSurface` is defined once and called **zero** times in `app/src`, because it takes a `CompatSurface` only PAPI's typed client produces, and `createClient` is constructed nowhere in the client. `classifyForeign` has the same gap on the foreign side, which is where it surfaced: `readDepositInputs` requires `assetHubCompatible` and nothing supplies it. This is not a defect in F4, whose row correctly calls the three-mode classifier a pure function over probe results by design — until F18 gave `startLightClient` its first caller there was no client to build. What makes it urgent is that `check-client-surface-obligations.py`'s stated rationale is *"10 §5.2's classifier probes exactly the frozen set, so an unfrozen read is one the compat lattice cannot fail on"* — the gate enforces the freeze and the consumer the freeze exists for is absent.
