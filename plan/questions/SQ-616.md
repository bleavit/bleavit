## Question

**RULED AND EXECUTED 2026-08-06 — contract v28 freezes `Guardian.PendingActions` and `Guardian.Approvals` in 02 §7.4, and doc 11 §11.8.2 now spells all four items it reads.** **11 §11.8.2 calls the guardian pending-action items *"frozen in 02"* and 02 §7 freezes only membership and allowances.** The console *"reads guardian storage (membership ≤ 7, per-power allowances, pending actions — item names frozen in [02](../../docs/architecture/02-integration-contract.md))"*, and 02 §7 carries exactly two guardian rows — the manifest cites *"02 §7.4 guardian membership"* and *"02 §7.4 guardian allowances"* against §7.4's prose line, and nothing else. `Guardian.PendingActions`, its per-member approval set and its expiry are absent, so S15's **central** read — the list the whole console is built around — has no contract surface, and the same lattice blindness as SQ-601 applies. The trigger condition §11.8.2 makes part of the propose precondition row is a second instance: the five triggers read five *different* frozen items, but which trigger a playbook requires is a property of the playbook registration, which 02 does not freeze either. Client posture: `UNREADABLE['O-3']`/`['O-4']` declare both `blocking`.
