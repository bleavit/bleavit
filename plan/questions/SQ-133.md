## Question

**02 §12 `updated_at` (offset 108) writer-(a) semantics.** 02 §12 calls it "block number of last update", but the writer-(a) field enumeration (spec_version target, pending_authorized_at, URGENT_UPGRADE, clear-pending) excludes it — a guard write would leave it stale. **B6 ruling (needs ratification):** guard writes bump `updated_at` to the current block (plain-meaning reading; harmless to stranded readers — `manifest_txid` is untouched). If instead the field is writer-(b)-only manifest freshness, revert the two adapter sites.

## Status

**resolved 2026-07-20 (batch B2 · ratified).** The plain reading stands and **no 02 change was needed**, so no contract bump: 02 §12's row-108 gloss ("block number of last update") is unqualified, and the per-writer parentheticals enumerate the fields each writer sets *purposefully* rather than granting exclusive title to an offset. The clarifying sentence went into **09 §2.3**, which is where 12 §106 routes write authority and which is outside the versioned surface. Verified harmless before ratifying: offset 108 has exactly one consumer — a bare gauge in `tools/monitoring/chain_alerts_exporter.py:416` — no alert rule references it, the 12 §6.3 repoint-lag alert derives from `manifest_txid` divergence instead, and the field appears in no view type and no runtime API. Row correction: there are **three** guard write sites, not "the two adapter sites" — authorization, applied detection, and the SQ-131 abort cleanup.
