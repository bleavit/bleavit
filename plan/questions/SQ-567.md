## Question

**Genesis-preopened HRMP channels make a parachain's first candidate unbuildable.** No topology in this repository declaring `hrmp_channels` had ever produced a parachain block; every topology without them passes. Cause, proven from source: genesis preopening queues DMP notifications stamped `sent_at = 0`, and cumulus's partial-processing cursor falls back to `{ sent_at: LastRelayChainBlockNumber, reverse_idx: 0 }` — which on the first candidate is `{0, 0}`, because `LastRelayChainBlockNumber` is written in `on_finalize` and no block has finalized — so the reverse scan in `drop_processed_messages` matches the last block-0 message and drains all of them. The runtime rebuilds an empty MQC head against the relay's non-zero one and traps at `cumulus-pallet-parachain-system-0.29.0/src/lib.rs:1362`. The sentinel conflates *nothing processed yet* with *all block-0 messages processed*. Identical across the five cumulus versions cached here (0.22.1…0.29.0); older ones were not checked and the partial-DMP cursor may simply be newer than all of them
