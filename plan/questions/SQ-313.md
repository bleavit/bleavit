## Question

**θS⁻/θC⁻ have no directional authorization — the constitution track can loosen a knee the entrenched track should own.** 05 §4.1 (as amended by batch D) and 13's entrenched-floors row agree: *raising* a knee is CONSTITUTIONAL-class, *lowering* one requires the entrenched 80 % path, and neither may go below the launch values 0.90/0.85. The code enforces only the absolute floor (`crates/welfare-core/src/lib.rs:54-75`) and registers both keys as `ParamClass::Const` (`crates/constitution-core/src/lib.rs:1554-1582`), so authorization is class-based with no comparison against the current value (`:517-528`): `ConstitutionTrack` can lower a previously tightened knee, and `EntrenchedTrack` has no authority over these rows at all. Needs a direction test at `set_param` (increase ⇒ constitution, decrease ⇒ entrenched, both floored) plus the four-case test matrix.
