## Question

**`FE-PROV-003`'s row lists three causes and the mechanism has five.** §8.4 binds the code to *"content-hash pin mismatch, malformed encoding, or a failed internal-consistency check"*. Two more causes exist and neither is in that list: a document describing **another chain** (10 §7 gives one local database per chain identity, so importing one files another network's history under this one — SQ-610's other half), and a spot re-derivation that **could not finish**, which is a statement about this device rather than about the file. §10.4 requires fixed user copy, expert detail and a documented recovery **per code**, and the recovery cannot be shared across causes: telling somebody to check their download completed is wrong advice for a snapshot of a different chain, and it is wrong twice for a check that stopped early. F9's reading keeps one code with one message and one recovery — nothing imported, nothing evicted — and selects a **fixed** remediation sentence by typed cause into the expert detail §10.4 already designates as the per-occurrence half. That is conformant on its face and it does widen a code past its own row, so 10 §8.4 should either enumerate the causes or state that the list is illustrative
