## Question

**Three `pallet-attestor` error variants are unreachable as dispatch errors, against 15 §4.1's per-error obligation.** `ChallengeStillOpen` is declared (`crates/attestor-core/src/lib.rs`; `pallets/attestor/src/lib.rs`) and mapped, but **never returned by any code path**. `QuorumMissing` is produced only by `attestor_core::require_quorum`, which has **zero callers** — the execution guard and epoch both consume the boolean `has_quorum` instead. `EjectedMemberActive` is a deliberate try-state-only invariant: core and pallet storage-corruption tests now prove it, but no dispatch can return the mapped public pallet error. Decide whether each variant represents missing enforcement, should remain core-only, or is deliberately retained in metadata. Surfaced by SQ-215/SQ-262/SQ-312 verification; not previously rowed.

## Status

**resolved 2026-07-24 (disposition)** — the row overstates 15 §4.1, which requires coverage of extrinsic **error paths**, not that every declared variant be dispatch-reachable. Each of the three is retained deliberately and now says so in code: **`ChallengeStillOpen`** is a **superseded duplicate** of the live `ChallengeOpen` that the reap path actually returns (the row missed that the live variant exists); **`QuorumMissing`**'s only producer was `require_quorum`, which had **zero callers anywhere** — production needs to *branch* on quorum so it reads the boolean — and that dead helper is deleted; **`EjectedMemberActive`** is deliberately try-state-only, signalling storage corruption, and is proven by the core and pallet corruption tests. All three stay on the SCALE surface because it is append-only. `sq342_unreachable_error_variants_are_exactly_the_documented_three` pins the set so a fourth unreachable variant is loud drift rather than silent accretion.
