## Question

**Security-prize/envelope valuation for PARAM/CODE/META is not represented on chain.** `in_cap_prize` can exactly derive TREASURY outflow, but no backing surface provides the published security prize for the other binding classes. The runtime returns `None`, blocking Adopt at decision step 9. Which pallet owns the immutable proposal-time envelope?

## Status

**resolved 2026-07-24 (A13)** — the epoch-owned `ProposalSecurityTermsOf` side map already froze the certificate at qualification; the missing half was the certified PARAM/CODE/META envelope itself, and every such proposal was unresolvable at step 9. Three `sec.prize.*` genesis rows now supply it, adopted from the Phase-0 published calibration (50,000 / 300,000 / 600,000 USDC; `designation: published`, `violations: []`) and consumed exactly as 08 §5.2 and the reference model's `in_cap_prize` specify: PARAM takes the envelope alone, CODE/META take `max(ask, envelope)` plus the `trs.cap_proposal · spendable NAV` floor for upgrade payloads (an undecodable preimage counts as an upgrade — claimant-adverse). The rows are kernel-bounded with **min = default**, so a class's proxy can only be raised; the consumer reads the **live** record only, so a chain missing the row fails closed rather than inheriting an unratified default. **The G0 drift detector caught the adoption and was honored, not bypassed:** `tools/phase-gates/check-phase0-exit.py` lexically binds the `sec.prize.*` row to 13's sim-gated Phase-0 tag, so replacing `[VERIFY]` with concrete values failed the Phase-0 gate. The row keeps its **sim-gated** marker and now reads *adopted from* the Phase-0 calibration, naming the artifact it is bound to — so a future change away from `phase0-calibration.json` still fails loudly through the same gate. **Correction (2026-07-25, R-6 round 3) — the CODE/META NAV floor is CONDITIONAL, and this session briefly shipped it unconditional in error.** Round 2's reviewer read `decision.decide`'s signature — which takes no `upgrade_payload` argument — and concluded the oracle applies the floor unconditionally; that finding was accepted and the runtime, 08 §5.2, 05 §5.6 and 13 row 87 were all changed to match. It was wrong. The oracle expresses the condition **through its caller**: `decide` passes `spendable_nav` straight through, so a caller signals "not an upgrade" by passing `spendable_nav = 0` — which is exactly what the Phase-0 simulation engine does for non-upgrade CODE/META proposals, and the published calibration the `sec.prize.*` defaults were adopted from contains **20 such cases**. Applying the floor unconditionally therefore silently invalidated the very evidence the adoption rests on. All four artifacts now agree on the conditional reading again — prose, engine, simulation and runtime — the convention is documented at the divergence source in `decision.py` so the misreading is not repeated, and the differential pin asserts **both** sides (non-upgrade 200, upgrade 500) instead of one.
