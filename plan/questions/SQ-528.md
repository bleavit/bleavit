## Question

**`FeeMultiplierUpdate = ()` pinned the transaction-fee multiplier to ZERO from block 2, so transaction weight was not priced at all.** `pallet_transaction_payment::Config::FeeMultiplierUpdate` requires `Convert<Multiplier, Multiplier>`; the pallet implements it only for `TargetedFeeAdjustment` and `ConstFeeMultiplier`, so `()` fell through to sp-runtime's blanket `impl<A, B: Default> Convert<A, B> for ()` returning `Default::default()` — and `Multiplier = FixedU128` defaults to **0**, not 1. `on_finalize` runs unconditionally, so genesis's multiplier of 1 survived exactly one block. `compute_fee_raw` multiplies only the weight term, so from block 2 a 185 Gps `settle_cohort` cost precisely what an empty call cost. **On a PoV-bound parachain that is a standing denial-of-service subsidy**, and it silently falsified every fee-derived figure in 08 §6 and §10. Invisible to the suite because the only fee test executed a single block, dispatching while the multiplier was still 1

## Status
