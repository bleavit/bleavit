## Question

**A guardian propose can still reach `ready` on a bound the client cannot read.** `guardian_core::propose_action` refuses when `pending.len() >= 64`, and the client can read the **count** (`Guardian.PendingActions` is frozen and O-3 declares it) but not the **bound**: no `constant.guardian.*` publishes it, and the surface manifest records `BoundedVec(Vec<PendingAction{…}>)` with no length. Guessing 64 from the Rust source is what R-2 forbids, and a `blocking` unreadable obligation would close the propose control outright rather than gate it. It is therefore the one enumerated input shape that stays open after the guardian class was closed — named rather than hidden, because an unenumerated shape is how the class survived its first fix. Should 02 §9 freeze the pending-action bound?
