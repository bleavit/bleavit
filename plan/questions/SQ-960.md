## Question

**Does §11.5 P-1's *"agree within the fixed-point bounds"* admit any non-zero tolerance between `quote()` and the client recompute?** P-1 states the row that way and E6 says `FE-CHAIN-005` fires *"beyond the 04 §4 bounds"*, so both normative texts describe a **band**. `trade-ticket.ts` compares the two published fields for **exact** equality, which is strictly stronger, and states why: `packages/protocol` reproduces the runtime's integer path — the same three roundings in the same order — and `crates/market-core/fixtures/chain-quote-agreement.json`, written by the runtime's own `quote()`, certifies that it lands on the same base unit. A tolerance would admit a disagreement the port is built not to have. But the direction of error is the one 15 §4.8's mirror rule names: a client refusing a trade the runtime accepts, on a rounding difference the document appears to permit. **Ruling needed:** is exact per-field agreement the rule for a client that reproduces the integer path, or does P-1 oblige a stated band — and if a band, in which of `cost` and `fee`?
