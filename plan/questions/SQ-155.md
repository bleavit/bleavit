## Question

**`unwired` exemption class vs I-22's unconditional CI sentence.** 15 §4.6 / the I-22 row admit no exemption ("a registry key without a matching test fails CI" / "every meter/bound key MUST have a test"), but 7 of the 175 13-registry keys have **no consuming dispatch surface in the deployed runtime yet** (`pol.budget_epoch` meter; the three treasury obligation sync bounds; `TwapCheckpoints` ring — a pre-existing A3/A5 gap S3 surfaced; both phase-3 caps — production `AssetTransactor = ()`, library-level bleavit-xcm coverage exists). S3 ships them as a machine-checked `unwired` class: reason + owner **B10** mandatory, owner validated against PLAN.md milestone IDs, the full list printed on every checker run (green included), `unwired` markers never satisfy coverage, and — added for the PR #88 Codex P1 — **the exemption expires mechanically: the checker fails the moment an unwired key's owner milestone (or B10 for `consumer_binding`) flips ✅ in PLAN.md**, so an exemption can never outlive the work that justifies it. The dead-man switch was reclassified out of this set at the same time: its enforcement CONSEQUENCE (queue freeze via the real SafetyFilter, epoch clock pause) is dispatch-tested; only the 4,800-relay-block detector that raises the flag remains B10. Ratify this honest-expiring-exemption reading or require red CI until B10 wires them.

## Status

**resolved 2026-07-20 (triage sweep — mechanism validated end-to-end).** The exemption class is now **empty**: `tools/limit-coverage/registry.toml` carries 0 `unwired` and 0 `consumer_binding` entries (B10 cleared the consumer bindings; B12 cleared the last unwired key). The mechanical-expiry design did exactly what it promised — no exemption outlived the milestone that justified it, and none had to be renewed. The tooling stays for future use; the general 15 §4.6 wording question rides SQ-156 and SQ-160.
