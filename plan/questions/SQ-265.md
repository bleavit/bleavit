## Question

**Normative definition of a "stalled" migration cursor (12 §6.3 Upgrades row).** `configs.rs`' tracker itself records that the semantic definition of "stalled" is open (a lawful `step` may return identical cursor bytes >900 blocks). B13's telemetry ruling (this session, decide-yourself delegation): the exported `bleavit_runtime_migration_cursor_stalled` signal is the **union** of the no-progress detector and the failure-halt/`Stuck` cursor state — a permanently failed cursor is strictly more alarming than a slow one, and RB-UPGRADE owns both; the underlying normative "stalled" semantics for PB-MIGRATION remain open.

## Status

resolved 2026-07-20 (batch B6): 12 §6.3 now defines the signal normatively as the union of the stall-halt latch, the live no-progress detector and the `Stuck` cursor, and states that the no-progress leg admits false positives by design. Row corrected — `MIGRATION_FAILURE_HALT` is not an input to the union
