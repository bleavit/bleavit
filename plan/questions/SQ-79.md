## Question

05 §4.7 daily gate-breach flags: an epoch with **no** (or incomplete) recorded daily observations reads as `(s_breached=false, c_breached=false)` — a deterministic default — so gate markets settle "no breach" on a keeper/data liveness failure (arguably against G-1 status-quo). 05 §4.7 states no daily-coverage requirement (the gate *books* carry coverage≥95/98% at decide(), A8); the day_bitmap records breach days only, so completeness is indistinguishable from no-breach.

## Status

**resolved 2026-07-21 (A12).** Prior disposition: batch **X**; **RULED 2026-07-21 (batch X)**, code owed. Verified: zero-sample and some-sample windows are *already* distinguishable without touching the 02 contract, but settlement ignores the distinction and resolves a wholly absent observation window as **no breach** — an adopt-favourable claim paid out of absent data. **Ruled: a zero-sample gate window is an unavailable gate input and VOIDs the affected cohort** (07 §10's existing fail-static path), which neither invents breach history nor pays from nothing (G-1/R-7). **Partial** coverage is deliberately *not* ruled here: it cannot be classified until an expected-day count or equivalent completeness measure is normative, and inventing one now would be a values call disguised as a bug fix. Re-verified before coding: the permissive default sat at `welfare-core::gate_breach` and `pallet-welfare::gate_outcomes`, and presence of a `GateBreachFlags` entry already distinguishes sampled from unsampled (the entry is written on the first recording whether or not it breached), so no 02 §7.4 shape changed. 05 §4.7 gained the normative zero-sample paragraph; `welfare_core::gate_window_outcomes` refuses a window whose e+1 or e+2 carries no observation (`Error::GateWindowUnsampled`), scoped to gate books only — scalar/Baseline still settle, and the 02 §4 `WelfareView` display default is untouched. Partial coverage remains deliberately unclassified and is now pinned by a test. Pre-fix behavior captured verbatim: settlement over a wholly unobserved window returned `Ok(FixedU64(1000000000))` with both gates false. Spec-reviewer (COMPLIANT, 0 blockers) noted 07 §10 supplies no *automatic* VOID for a keeper-unsampled window, so the §4.7 text was tightened to describe the actual recovery (late re-sampling; manual guardian `PB-ORACLE-VOID` for permanent loss) and the automation question was raised as **SQ-421**.
