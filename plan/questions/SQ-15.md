## Question

Is 04 §4 bullet 3's method ("range reduction to [1,2) + 64-bit polynomial iteration") normative, or only the error bounds? 64-bit internal precision appears mathematically insufficient for a ≤2-ulp worst case under any method — should the spec state a required internal/guard precision?

## Status

**resolved 2026-07-15** (user-delegated batch; see Decision log): bounds normative, method free — 04 §4 now mandates guarded internal precision (worst-case error analysis part of crate conformance; ≥32 guard bits reference config, single final rounding); 64-bit-wide intermediates declared insufficient
