## Question

**Phase-0 exit realized-cost threshold — 1× InCapPrize (profitability) or 3× (the `AttackCost̂`/`ManipFloor̂` margin)?** The V-12 15 §4.9 exit criterion scores a causal wrong-PASS flip as a security failure only when *realized* attacker cost < prize (profitable capture); a flip whose realized cost is ≥ prize but < `3·InCapPrize` is deep-pocket griefing (TM-18), recorded as a diagnostic. 05 §5.6 + 08 §5.5 mandate tightening δ/`dec.v_min`/`pol.b` whenever the `ManipFloor̂` diagnostic reads below `3·InCapPrize` (a Phase 3–4 obligation that "never gates in v1"); D-4 states `3·InCapPrize ≤ AttackCost̂`. Per the user ruling the exit uses the 1× profitability line, and 05 §5.6/08 §5.5 gained reconciling cross-references (the runtime 3× margin conservatively guards the 1× realized-profit line the sim validates directly). Confirm the 1× exit threshold, OR require realized cost ≥ 3× at exit — which reopens the 14 unprofitable thin-capture/gate-suppression griefing flips as violations and demands a `dec.v_min`/`pol.b` tightening the sim shows δ alone cannot supply. Sub-nuance: TH-6's named residual is the off-system-payoff attacker specifically, so "realized cost ≥ prize ⇒ TM-18" is an interpretation.

## Status

resolved 2026-07-20 (batch B6): the 1× profitability line ratified as the Phase-0 exit threshold in 15 §4.9.
