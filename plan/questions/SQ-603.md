## Question

**10 §6.5's *"ingested event subset"* names a subset no document states.** The whole sentence is *"Ingested event subset, per-era metadata decode discipline (…) — carried forward"*, and the phrase *carried forward* points at the superseded FRONTEND_PLAN.md rather than at any section of 00–16. Nothing anywhere enumerates which events the local index ingests. That is not a documentation gap with a cosmetic consequence: §6.5's whole cost claim — *"blocks containing none of the user's extrinsics never trigger a body fetch; worst-case overhead is proportional to the user's own activity, not chain activity"* — is a claim about a set, and both ways of getting the set wrong are silent. Attribute too narrowly and the user's history is *filtered*, which is indistinguishable from *empty*; attribute too broadly and a light client on a phone fetches a body for every block the chain produces while every "does it find my transactions" test stays green. F8 ships the only reading available: **every** event the runtime emits is ingested, and attribution is decided per event by the accounts it names (`chain-client/src/event-accounts.ts`, metadata-driven) with `System.ExtrinsicSuccess`/`ExtrinsicFailed` enumerated as correlation-only. **Ruling needed:** either state the subset in 10 §6.5, or state that there is no subset and delete the phrase — a named subset that no reader can resolve is worse than the absence of one, because an implementer will invent it

## Status

**open — raised while implementing F8's ingest loop.** The conservative direction is the one shipped (ingest everything, filter at attribution): a subset narrower than the runtime's event set can only lose history, and the cost claim survives because the *body fetch* is what §6.5 bounds and that is decided per block, not per event. Filed to **B7**. **Half-answered 2026-08-06 by SQ-557's ruling on main (#249)**, which this branch rebased onto: 10 §9.1 now rules that the index retains *\"only events attributing to the user's watched accounts\"* — §6.5's *\"proportional to the user's own activity\"* rule applied to storage as well as to body fetches — and F8 now implements it. That settles **retention**. What this row still asks is the other half and it is not the same question: which events the loop *ingests and decodes* in the first place, which is what the phrase *\"ingested event subset\"* sits in front of and what the cost claim is stated over
