## Question

**§8.2 obliges consumers to check a rule `bleavit.snapshot.v1` cannot express.** The section states three canonical-form rules — *"the movement list is in chain order — block, then extrinsic, then event"* among them — and closes *"Consumers check these on import."* `SnapshotOp` carries only `block`, so a consumer can check the block half and **cannot** check the finer half at all: the producer computes `extrinsicIndex` and `eventIndex` (`app/tools/snapshot/build.ts`) and discards them before serializing. The block half is now checked, and it was worth checking — measured, a document whose `ops` run block 13, 10, 12 was admitted, the same history in block order was also admitted, the two pins differed, and `diffSnapshots` of the pair reported `disagree` with `FE-PROV-004`, which is the exact failure §8.2's own paragraph exists to prevent. The question is whether §8.2 wants the format to carry the two indices, which is a `bleavit.snapshot.v2`, or wants the consumer obligation narrowed to the block-level consequence it can actually verify
