## Question

02 §7.2's frozen key + **value shapes** for `Rounds`/`ComponentValues`/`ReserveHealth` are narrower than the merged core: the game runs per `(component, epoch, frozen version)` (triple key, not the 02 pair — extends SQ-2), and `RoundState`/`ReserveHealth` carry extra fields (per-round ack keying, bond-schedule freezing at snapshot, §5.5 slashing, probe timing) the frozen views omit. Reconciling (amend 02 §7.2 + bump `INTEGRATION_CONTRACT_VERSION` + joint backend+frontend sign-off, or split internal fields into non-FE-read storage) is a contract change the code cannot ship unilaterally under R-1 / rule 5.

## Status

**resolved 2026-07-15 (user-delegated, R-1 — 02 amended, contract v2→v3).** The "defer to B2" reading was unworkable: A5 → B2 → B1a → A1–A11 is circular, so A5 can never reach ✅ if it waits on B2. Since there is no deployed runtime (pre-genesis) and no FE yet, the contract was made **correct now** and B2/Track-F conform to it. Amended **02 §7.2** `Rounds`/`ComponentValues` to the triple key `(MetricId, EpochId, MetricSpecVersion)` + the full `RoundState`/`ReserveHealth` field sets, **02 §4** `OracleRoundView` gains `spec_version`, **02 §13** version-history entry, **07 §13** synced, **00 D-2** records the bump, and `INTEGRATION_CONTRACT_VERSION` 2→3 in `futarchy-primitives` (+ the constitution/primitives version tests). The v2 pair key was self-contradictory (its own bound note said per-version games "append a `RoundState` per frozen version" — impossible for a one-value-per-key map), so this is an R-1 correction, not a redesign. Joint backend+frontend sign-off: the user (both sides). A drift-lock test (`round_state_fields_match_contract_02_section_7_2`) pins the shape so it can't re-diverge.
