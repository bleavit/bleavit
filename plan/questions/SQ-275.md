## Question

**`UnvestedFundsAllowedWithdrawReasons = TRANSACTION_PAYMENT` is dead code under the fungible fee adapter.** The vesting config carves fee payment out of the vesting lock (suggesting locked VIT *should* pay fees), but fees ride `pallet_asset_tx_payment` over the fungible traits, whose `reducible_balance` subtracts frozen amounts regardless of `WithdrawReasons` — observed live in the G1 drill run: the genesis-vested guardians (fully locked, `liquid = 0`) get `1010: Inability to pay some fees`. Current behavior matches B3's strict "unvested VIT pays no fees" ruling, so this is either (a) the config carve-out is a stale leftover to delete, or (b) the ruling intends locked funds to pay fees and the fee path needs a WithdrawReasons-aware adapter. Doc 08 §9's fee-path wording should settle it.

## Status

**RULED 2026-07-20 (G1):** option (a) — the carve-out is a stale leftover. The stricter "unvested VIT pays no fees" reading (B3; 08 §9 USDC fee path) stands unchanged; removing the dead `UnvestedFundsAllowedWithdrawReasons` const is a behaviorally-inert cleanup deferred to a future runtime touch (not done now, to avoid an unnecessary audit-scope edit + rebuild). Drill helpers fund usable balance
