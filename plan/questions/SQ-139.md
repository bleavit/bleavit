## Question

B8 defined the environment run-evidence contract B7 must satisfy (`bleavit.env-evidence.v1`: per-file SHA-256 inventory, release wasm hash, release commit, named passing suites — validated byte-for-byte at strict assembly so placeholder env dirs can never pass). Ratify the schema, and decide whether commit-level CI green satisfies 15 §5's "the backend's own suites ran against exactly those artifacts" or the tag pipeline must re-execute the Zombienet/Chopsticks suites against the packaged artifacts.

## Status

**resolved 2026-07-20 (B5 ratification; schema ratified and the consumer hardened to match).** 15 §5 now names the frozen fields — schema id, suite kind, release wasm hash, release commit, **tier**, named suites with results, per-file digest inventory — requires assembly to validate them **byte-for-byte** against the packaged set and to refuse evidence not binding to the release under assembly, and permits additive producer fields that consumers MUST NOT depend on. Ruling on the row's second half: commit-level CI green does **not** satisfy 15 §5, because it proves the source was tested and never that the packaged bytes were; the tag pipeline re-executes against the built artifacts. Two gaps found and closed rather than ratified: `tier` was produced but unchecked, so a `g1`-stamped file satisfied the consumer; and — caught by the adversarial review, which **empirically disproved** the first draft's claim that byte-for-byte validation stops a placeholder directory — `artifact_hashes: {}` passed vacuously, because set-equality against an empty directory is trivially satisfied. `validate_run_evidence` now requires `tier == "release"` and a **non-empty inventory** (both tested; the inventory guard mutation-checked). Honest residual: evidence emission is still blocked fail-closed by SQ-203/SQ-204, so the contract is normative but unexercised, and the spec text is written as the contract rather than as present-tense behaviour.
