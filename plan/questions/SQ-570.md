## Question

**The hosted service is inert by design, so drill 11's full lifecycle is not reachable on a release-shaped chain — and I-36's push half is therefore unwitnessed.** Found by actually running drill 11 once SQ-567/SQ-568 unblocked cross-chain drills. It fails at `register` with `polkadotXcm.ProcessXcmError` + `messageQueue.Processed { success: false }`, and that is **correct fail-closed behaviour, not a defect**: the program crosses, Bleavit's barrier **accepts** it (so the six-position template round-trips end to end, which is a positive result — drill 13 proves eight malformed programs are refused, drill 11 now proves the well-formed one is admitted to execution), and execution then fails at the admission gate. Admission is shut twice over and both locks are deliberate: `svc.client_bond` is `[VERIFY]`-tagged and **absent** from the registry, so `client_registry.admit_client` refuses `ClientBondUnset` before any hold or write, and 13 §1 says the row stays unset "until registration-abuse calibration can derive it"; and `admit_client` requires `EnsureGuardianTrack`, which has **no Root arm** (so sudo cannot forge it) while `pallet-client-registry` has **no `GenesisConfig`**, leaving no drill-reachable admission path at all. **What was rejected:** seeding `svc.client_bond` to green a drill is precisely the fabricated value R-2 forbids, and `sudo → utility.dispatch_as(GuardianTrack, …)` would forge an origin the wrapper filter denies (I-10/I-11) to reach a state no governance path produces — a drill that lies. **What shipped instead:** drill 11 reads `ClientRegistry.ClientCount` and runs the leg chain state makes reachable, so it cannot claim a lifecycle it never reached *and* upgrades itself the moment a client is admitted. The containment leg is a real assertion — a live ingress crosses the one-way channel, is refused fail-closed, pushes nothing back, and moves neither SEND term of `X` — which is I-36's **containment** half. **The open obligation is the push half:** with no report there is no outbound push, so "a failed delivery must not feed `X`" is not exercised, and the artifact records that under `i36_push_leg_unwitnessed` rather than hiding it behind a green tick. Closing it needs a calibrated `svc.client_bond` **and** an admission path a test network can drive (a `GenesisConfig` on the registry is the drill-06 `migration_halt` precedent — plain spec, no production fault-injection surface)

## Status

**open — drill re-scoped honestly and now passing 4/4; underlying witness still owed.** Batch **X**. **The containment measurement had to be redone, and the redo is the interesting part.** The first version asserted `Welfare.XcmTraffic` byte-identical across the ingress window and failed — which looked like an I-36 violation and was not. `XcmTrafficCounters` is `{accepted, failed, probe_timeouts}` and Bleavit performs its own outbound XCM, so the cell moves on its own; an assertion that fails for something outside its own claim is broken rather than strict. Rebuilt as a controlled experiment with a quiet 10-block control window: **control moved `accepted` +2, `failed` 0, `probe_timeouts` 0; the refused-ingress window moved 0/0/0.** My stated hypothesis — that the 07 §8 reserve probe was timing out with no Asset Hub to reach — was **wrong**; the background was accepted sends around the channel handshake, so a diagnosis written from the hypothesis rather than the measurement would have been confidently wrong. The control also proves the counters were live at that moment, which is what stops a zero treatment from reading as a dead instrument. A second, **attributing** check was then added because a window comparison only infers: no `polkadotXcm.Sent` in the ingress window may name the client para — immune to background traffic and aimed at I-36's actual hazard, a send toward a client whose return channel is absent. Not a blocker for N10/N11: everything reachable is proven, and what is not reachable is unreachable because the values layer deliberately has not armed the service
