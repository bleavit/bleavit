## Question

**Three files carry release key material before the ceremony and nothing binds them to each other.** `deploy/`-adjacent `app/tools/release/sources/signers.json` records who holds which key, `release-sources.json` records the `signing.keyIds` that go into `release.json`, and F13 added `keyring.json` with the public keys a signature verifies against. `tools/deploy/check-signers.py` binds `SIGNERS.md` to `signers.json` and stops there. So a key present in one file and absent or different in another is a state no gate reports, and the first run that notices is the ceremony — where the cost of a mismatch is a release that cannot be verified by the people who just signed it. All three are empty and phase-gated today, which is why this is cheap now and expensive later. Needs a ceremony-time cross-binding gate and a ruling on which file is authoritative for a key's identity.
