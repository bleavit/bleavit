## Question

**Minimum release-key signature count is unquantified.** 12 fixes ≥ 2 *attestations* (§1.4(2), §5.2(2)) but never fixes a floor for release-key *signatures* on a canonical release ("signing key IDs", plural, unquantified). The O5 attestation monitor refuses to default it: the operator config must state an explicit minimum. Should 12 (or a 13 row) fix a normative floor?

## Status

**resolved 2026-07-20 (B5 ratification; a floor is fixed rather than left to operators).** 12 §1.4 now fixes **≥ 2 valid release-key signatures from distinct active keys of the current keyring generation**, counted after excluding keys revoked in `ReleaseChannel` — the same floor as attestations, for the same reason: a canonical release must survive the loss or compromise of any single release key, and a one-signature release makes a single key a unilateral shipping authority, the concentration §2.2 exists to prevent. Deployments MAY require more, MUST still state their minimum explicitly, and MUST NOT go lower; the O5 monitor's floor moved from ≥1 to ≥2 while keeping its refusal to default. Two corrections to the row: "signing key IDs" is §1.1, not §2.1, and the monitor enforced an *explicit* minimum, never a *safe* one — an operator could lawfully configure 1.
