## Question

**(bot P1) Phase-3 real-USDC exposure caps not enforced on ledger inflows.** `phase3.tvl_cap`/`phase3.deposit_cap` (D-13) live in the constitution registry but nothing consumes them: once B4 supplies real USDC and vault creation is live, a signed user could split/credit USDC with no global or per-account cap check, removing D-13's bound on sudo-era exposure. **Scope:** 09 §5.2 enforces the caps "at every split/inflow-crediting path **and** the XCM inflow leg" — the split path is `pallet-conditional-ledger` (A2) and the inflow leg is B4; **neither is runtime-`Config` wiring** (per-account cumulative-deposit accounting is ledger storage). B1a makes **no** inflow path live (XCM fail-closed → B4; vault creation `MarketAdmin`/`MarketAuthority`-gated → fail-closed until A8 is wired), so there is nothing to guard yet.

## Status

**resolved 2026-07-20 (triage sweep — code-verified).** B10 armed both legs the row made conditional on B4/A2: `pallet-inflow-caps` owns the per-account cumulative meter and the mint-step gate (`CumulativeDeposits`, `mint_admissible`, `pallets/inflow-caps/src/lib.rs:53-129`), and B10 wired the production `AssetTransactor` plus the ledger split gate, so no inflow path goes live uncapped. The residual scope question — Signed splits only, or also MarketAuthority set minting — is tracked separately as SQ-252.
