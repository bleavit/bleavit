## Question

Frozen-event drift (pre-existing): 09 §1.5/§2.1(3) reference `UpgradeApplied` and an `applicable_at` field on `UpgradeAuthorized`, but 02 §6's frozen guard event list carries neither. The A11 pallet emits `UpgradeApplied` (the B7 drills assert it). Reconcile at the next 02 amendment batch (contract-version bump rules apply). **B6-merge extension (2026-07-17, PR #65 bot P1):** the new append-only `UpgradeAborted { code_hash }` (SQ-131 abort ruling) joins the same reconciliation batch — like `UpgradeApplied` it is emitted-but-uncontracted until 02 §6 is amended with the batch's version bump + joint sign-off; the FE meanwhile observes abort state via the ReleaseChannel raw key, which the abort clear updates.

## Status

resolved 2026-07-21 (batch C, contract v6) — folded into SQ-95's single guard-event append: `UpgradeApplied { code_hash, spec_version }` and `UpgradeAborted { code_hash }` are now frozen in 02 §6. **The `applicable_at` half of the row is stale and was refused:** 09 §2.1(3) already specifies `UpgradeAuthorized { code_hash, authorized_at }` and derives `applicable_at = authorized_at + DescriptorLeadTime`, and the pallet's public event matches 02 byte-for-byte. Adding the third field would have *recreated* a contradiction both sides had already removed, so `UpgradeAuthorized` is unchanged.
