## Question

12 §6.3's trigger cells hardcode 13/08-owned values ("> 80% of 12,000 USDC/epoch" = `keeper.budget`; "600 blocks" in the ReleaseChannel row) with no normative-value pointer — if governance amends the Param, the doc-12 trigger text (and O4's byte-bound runbook frontmatter mirroring it) goes stale. Should these cells reference the owning Param instead of a literal?

## Status

**resolved 2026-07-20 (B5 ratification; premise half-refuted, so the row splits).** The keeper half is real: `keeper.budget` is a 13 §1 PARAM row (12,000 USDC, range 6,000–60,000, ×2, cooldown 1), so a governance amendment would strand the doc text and every byte-bound runbook and rule annotation. Ratified as shipped, since the exporter *already* computes utilization against the live gauge: the cell now names the key (`> 80% of \`keeper.budget\``) and 12 §6.3 makes evaluation-against-the-live-value normative. The ReleaseChannel half is **refuted** — "600 blocks" is not 13/08-owned, it is 12 §1.4(6)'s own repoint deadline, absent from 13 entirely — so the cell keeps its literal and the new rule states the general principle: a literal is admissible in a trigger cell only when this document owns the value.
