## Question

**02 §7.5's attestor bounds have no 13 §4 row and no reap path (liveness trap).** The v4 freeze pins `Members ≤ 16` / `Attestations ≤ 256` — bounds rule 3 says must come from 13 §4, which has no attestor row — and the flat 256-entry ledger is never reaped (06 §2.2 reaps ratification records with the proposal; there is no attestation analogue). Once full, `attest` is a permanent no-op ⇒ no CODE/META proposal can reach quorum (05 §5.4 step 10) ⇒ the CODE upgrade that would fix it cannot itself qualify. Add a 13 §4 attestor bounds row and a reap-with-proposal path (a shape change 02 §7.5 must then version), or make the freeze conditional on one.

## Status

**resolved 2026-07-23 (B19).** The 13 §4 premise is disproved: rule 1 places per-pallet storage bounds with their owning pallets. The liveness defect is fixed by bounded `reap_attestation`; terminal cleanup now removes settled, closed-window records and releases any returned liability, so the frozen 16/256 bounds no longer self-lock future proposals.
