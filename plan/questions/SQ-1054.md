## Question

**Six pallet mocks do not COMPILE under `runtime-benchmarks`, so six `impl_benchmark_test_suite!` invocations have never executed — and one of them was this branch's own new pallet.** Sibling of [SQ-1053](#spec-questions) and strictly narrower: that row asks whether the *gate* should run the feature's tests, and this one records that for these crates there was nothing to run. `cargo test -p pallet-trading-rewards --features runtime-benchmarks` failed with `error[E0437]: type BenchmarkHelper is not a member of trait pallet_assets::Config` plus `error[E0576]` — both pointing at the `#[derive_impl(pallet_assets::config_preludes::TestDefaultConfig)]` line itself, not at any code a session wrote. The cause is a feature mismatch rather than a bug: `pallet_assets`'s `TestDefaultConfig` prelude emits a `BenchmarkHelper` associated type as soon as `frame-support/runtime-benchmarks` is on, while `pallet_assets::Config` only declares one when `pallet-assets/runtime-benchmarks` is on, and no crate here forwards that feature. **The fix is one line per crate** — adding `"pallet-assets/runtime-benchmarks"` to the crate's own feature list — and it was verified on `pallet-trading-rewards`, whose suite goes 91 → **97**, the six new tests being exactly `bench_enroll`, `bench_top_up_bond`, `bench_withdraw_bond`, `bench_claim_rewards`, `bench_settle_market_score` and `bench_settle_epoch`. **Only that pallet is fixed here**, because it is the one this branch adds and shipping a new pallet whose benchmark suite has never run is this branch's defect rather than inherited debt. The other five — `pallet-client-registry` (reproduced identically), `pallet-conditional-ledger`, `pallet-registry`, `pallet-market`, `pallet-question-service` — are untouched, and each may surface its own failures once it compiles, which is the work this row owns. **What makes it a question rather than a chore:** the same one-line change is what SQ-1053 would need before its scope could widen at all, so the two must be decided together, and repairing a mock may expose real benchmark defects that were never observable.
