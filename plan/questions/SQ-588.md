## Question

**RULED 2026-08-04 (R-1) — and the question's premise was wrong, which is the part that mattered.** SQ-588 asked whether to freeze `Market.MarketProtocolAccounts` for P-9. **The runtime does not use it for this.** `ledger.transfer`'s refusal is `ensure!(!T::ReservedProtocolDestinations::contains(&to), ProtocolDestination)` (`pallets/conditional-ledger/src/lib.rs:848`), i.e. `ProtocolAccounts` **or** `ServiceProtocolAccounts`; `MarketProtocolAccounts` is an ownership/refcount index for deposit exemption, and `configs.rs:3720` says so in as many words — *"Classification does not depend on this index: every canonical future/present/past address is reserved above."* Freezing it would have added a contract surface, a per-recipient storage read on every transfer, **and still not answered P-9**: the client would have evaluated a strictly narrower predicate than the runtime enforces and passed a row the chain refuses. Worth recording as method rather than as trivia — the question was raised from the pallet that *names* the concept instead of the call path that *enforces* it, and reading the enforcing line first is the whole cost of a ruling. **The ruling: neither option as posed. Add a 14th `FutarchyApi` method, `is_reserved_protocol_destination(who) -> bool`, at contract v25.** The question offered "freeze the storage item" or "publish the derivation so membership is derivable with no read"; the second is closer and still wrong for a **precondition**, because 11 §11.4 rule 2 requires every P-row to be *an exact chain read* and a client-side derivation from published constants is a computation, not a read. That is also precisely why `ConditionalLedger::ServiceIdBase` was right as a metadata constant and this is not: a constant classifies a datum the client already holds, a precondition asks the chain. The predicate is two things at once — a domain-separated byte namespace (a 16-byte prefix ++ a `B`/`F` kind byte ++ a little-endian `u64` id ++ a zero tail, `configs.rs:3641`) **and** a list of PalletId-derived singletons — so publishing it as constants means ~13 frozen entries plus a client reimplementation that can drift, while one method can do neither. It is additive, so §13 rule 2 bumps the `sp_api` version and no existing method, type, storage key, event or call index moves. **Follow-on work is tracked under F6, not here**: the API method and impl, 02 §3/§13 v25, the feed regeneration, and P-9's clause in `rows.ts` bound to the new `SurfaceId`. **The residual SQ-588 identified, which survives the correction**: `check-client-surface-obligations.py` extracts `Pallet.Item` references, so an obligation phrased as *prose* naming no surface — as P-9's is — is invisible to it. That bounds what the gate may be credited with, and it is the same blindness as SQ-587 reached by a different route
