## Question

A7's genesis-activation relaxation (genesis specs activate at epoch 1, skipping the two-epoch lead) keys on `current_epoch == 0` as the pre-launch sentinel. This requires B1a to wire `CurrentEpoch` so live welfare epochs are 1-indexed (05 §4.6 "computable from epoch 1") and epoch 0 is never a live registration clock — else a live `register_spec` at epoch 0 would inherit the genesis relaxation.

## Status

**resolved 2026-07-21 (A12).** Prior disposition: batch **X**; medium. Split by verification. The activation-relaxation reasoning is **stale**; the live residual is a **boot-at-zero failure** — the ambient epoch-zero sentinel is ambiguous between "genesis" and "unset". Replace it with explicit genesis context. Confirmed the residual is the boot-at-zero ambiguity, not the relaxation itself: `welfare-core` inferred genesis from `current_epoch == 0`, which the genesis build and a live `register_spec` against an unset clock both satisfy. `register_metric_spec` now takes an explicit `Registration::{Genesis, Live { current_epoch }}`; the genesis build passes `Genesis`, the dispatch always passes `Live`, so a live registration at a zero clock takes the `>= current + 2` lead. 05 §4.4 gained the normative paragraph. Pre-fix behavior captured verbatim: a live `register_spec` with `activation_epoch = 1` at clock 0 returned `Ok(())`.
