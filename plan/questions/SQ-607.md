## Question

**10 §7 publishes eight table names and no column lists, so the client's storage keys have no spec answer — and one of them was wrong in the direction that loses data.** The section names `meta`, `events`, `priceSamples`, `candles1h`, `proposalsArchive`, `txHistory`, `metadataCache`, `snapshotsImported` (plus §9.2's `candles4h`/`candles1d`) and states changes to them, but never a field list or a primary key for any. Two consequences met in F8 and neither is cosmetic. **(a)** Whether `priceSamples` is keyed by block or by wall-clock time is unanswerable from the document, and the two differ observably: keyed `[bookId+at]` the primary key becomes a function of the **device clock**, two observations of one book inside the same second overwrite each other silently, and replay stops being idempotent — which §6.5 requires in as many words. F8 keys it on the block. **(b)** Once a chart row carries its `origin` (§2.3's only mitigation for provider-fed data), a key without the source stores two provenances' rows on top of each other: `foldCandles` correctly refuses to merge them and the *table* merges them anyway, so the label survives and the datum under it is whichever source wrote last. F8 adds the source to the key of `priceSamples` and all three candle tables, and 10 §7's change table records both under R-1 (Decision log). **(c)** `events` carries no **proposal reference**, and §9.2 permits compacting *\"`events` for settled+reaped proposals\"* — so there is nothing to scope the delete by. The obvious implementation deletes every event in the proposal's block span, which removes other proposals' events, market trades and ledger movements alike; the R-6 review of the repair pass found exactly that, and F8 now takes the **event ids** from the caller (which already had to establish that the proposal is settled) rather than a block range. That works and is not what a schema should require of every caller. **Ruling needed:** either publish the key per table in §7, or state that keys are an implementation choice — but the second is only tenable if §7 also states that a stored row's provenance is part of its identity and whether `events` carries a proposal reference, because those are the parts an implementer gets wrong

## Status

**open — the two keys F8 needed are amended under R-1 this session; the general question is whether §7 owns keys at all.** Filed to **B7**
