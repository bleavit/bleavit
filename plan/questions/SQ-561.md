## Question

**The 07 §3 permanent ban is defeated by arithmetic: fill the retained-record store with ejections and the next ejection re-registers at full stake with a clean ladder.** `MAX_REPORTER_RECORDS = MAX_REPORTERS = 64` and the eviction rule correctly refuses to drop an ejection, so the store can reach a state where `upsert_reporter_record` returns `false`. `record_reporter_offense` then emits `ReporterRecordsFull` and **releases the seat anyway** — which it must, since G-1 forbids a full table from aborting a values-track verdict. But with no retained row, `register_reporter`'s guard (`!carried.is_some_and(|r| r.ejected)`) reads `carried == None` and passes, and §2(5)'s half-stake re-entry is skipped too, so the account returns at **full** stake with `offenses = 0`. §3's "An ejected reporter MAY NEVER re-register" is unconditional and the code is not. Cost to reach: 64 accounts × 3 adjudicated-false findings — bounded and priced, not impossible. The deeper tension is structural: permanent bans accumulate without bound, bounded state (I-20) cannot hold them all, and the spec never said which side gives

## Status

**resolved 2026-08-01.** Closed at **entry**, not at ejection: the verdict path keeps failing open (G-1 — the seat is still released and `ReporterRecordsFull` still fires), while `register_reporter` now refuses any account presenting no retained record once the store holds nothing evictable (`ReporterRecordsSaturated`). Once no ban can be recorded, an unrecorded account is indistinguishable from a dropped ban, so entry closes rather than admitting one; seated reporters are untouched, so the live set keeps serving; and the only escape is a CODE change enlarging the store — the right venue, since the size is a consensus constant whose growth is a PoV cost. The saturation predicate is defined as the exact complement of the room `upsert_reporter_record` looks for (one shared `evictable_record`), so gate and drop cannot drift. Regression test drives the **real** ejection path (`a_saturated_ban_store_closes_entry_instead_of_re_admitting_the_ejected`) and fails if either half is reverted
