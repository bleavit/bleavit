## Question

**POL opening has no epoch-budget admission/shrink-to-fit implementation.** A8 fixed paired Accept/Reject and gate seeding to use one dual-mint split per pair and makes insufficient custody fail atomically, but it does not reserve a frozen epoch budget or apply the specified shrink-to-fit allocation across simultaneous proposals.

## Status

**resolved 2026-07-21 (code; branch `fix/treasury-reserve-health`).** Re-verified first: `ensure_nav_floor`/`flag_nav_floor` did have zero production callers (`pallets/futarchy-treasury/src/lib.rs:914,929`), so the row was real. `pallet-constitution` gained a bounded `PhaseArmingGate` provider (`pallets/constitution/src/lib.rs`) consulted by `set_phase_flag` **before any write**, mapping bit 1→Param, bit 2→Treasury and bit 3→**both** Code and Meta so the higher (META) floor binds — the fail-static direction. The runtime binds it to `FutarchyTreasury::ensure_nav_floor` (`TreasuryPhaseArmingGate`, `configs.rs`); refusal is `NavFloorUnmet` with `PhaseFlags` unchanged. **Deviation from the row's wording, deliberate:** it asked for both `ensure_nav_floor` *and* `flag_nav_floor`, but 08 §4.2's "event + extrinsic error" cannot both survive one dispatch — an `Err` rolls the event back — so the hard variant is used here and `flag_nav_floor` stays the `Ok`-returning shrink-to-fit path of 08 §4.4. Disarming is deliberately never gated (gating it would strand the chain armed below its own floor). 7 constitution tests + 2 runtime tests (`tests_treasury_health.rs`), all four confirmed failing before the fix.
