## Question

**`OracleRoundView.escalated: bool` is undefined.** 02 §4 names the field without semantics. B2 reads it as "a prior round escalated the game" (`round > 1`, coherent with oracle-core incrementing `round` and clearing `challenger` on escalation); the alternative — "a challenge is live" (`challenger.is_some()`) — differs during a round-1 challenge that 07 §5.2 says will escalate at window close. Which does the FE oracle-ballot screen (11 §11.8) need?

## Status

resolved 2026-07-21 (batch C, contract v6) — 02 §4 defines `OracleRoundView.escalated` as **`round > 1`**: true iff at least one prior round advanced the game, and **false for a round-1 report even while that round has a live challenger**. The contract states explicitly that it does *not* mean "currently challenged" — a live challenge is a different fact, and a future view needing it must add a separately named field. Ratified as shipped: `views.rs` already emits exactly this meaning and a runtime test pins both arms. **The row's framing is corrected** — neither reading of one bool can satisfy 11 §11.7.5's ballot screen, which needs full dispute lineage from round storage and events.
