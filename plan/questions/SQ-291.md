## Question

**A zero or absent milestone target normalizes to aggregate 0.0 instead of rejecting.** `crates/registry-core/src/lib.rs:729-731` returns `FixedU64(0)` when `target == 0` and closes the epoch normally; neither `Registry::file` nor `Pallet::file` checks the target. Both `runtime/bleavit-runtime/src/configs.rs:3923`'s own comment ("Zero makes filing/close reject") and SQ-175's row text assert a rejection that does not happen — a fail-*adverse* fabricated measurement rather than the fail-closed refusal 07 §7's new *Milestone normalization* rule now requires of `register_spec`. Lands with, or before, SQ-175's MetricSpec field.

## Status

resolved 2026-07-20 (batch B3) — fixed in the same session. The Milestone instance now refuses instead of fabricating a measurement: `MilestoneTargetUnset` is returned at **both** entry points — `file` at the door and `close_epoch` — so no aggregate is ever derived from an undefined divisor, and state is unchanged on the failure path (G-1). Tests `a_zero_milestone_target_refuses_the_filing_at_the_door` and `a_zero_milestone_target_refuses_the_close_instead_of_recording_zero`; 07 §7's error list carries the new error. This also makes `runtime/bleavit-runtime/src/configs.rs:3923`'s long-standing "Zero makes filing/close reject" comment true for the first time.
