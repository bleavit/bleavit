## Question

**`PositionView.vault_state` has no branch-free settled representation.** 02 §2's `VaultState::ScalarSettled { winner, s }` requires a `Branch`, but a Baseline vault (03 §2.3) settles with a scalar and no branch — so B2's `account_positions` must fabricate `winner: Branch::Accept` for Baseline positions and rely on consumers ignoring a field 02 never says is meaningless. 02 §4 nonetheless binds the field ("Baseline: its epoch vault"). Pre-genesis, so appending a `BaselineSettled { s }` variant to `VaultState` is available; alternatives are making the field optional or stating normatively that `winner` is undefined for `PositionId::Baseline`.

## Status

resolved 2026-07-21 (batch C, contract v6) — `VaultState` gains a trailing branch-free **`BaselineSettled { s: FixedU64 }`** variant; proposal vaults keep `ScalarSettled { winner, s }`, and `PositionView` uses the new variant for `PositionId::Baseline`. This replaces the shipped projection that fabricated `winner: Branch::Accept` for every Baseline position — publishing a winning branch that does not exist is exactly what R-7 forbids, and "declare `winner` undefined" would still have forced every generated client to carry and special-case false data. Ledger storage was already branch-free (`BaselineState::{Open, Settled(s)}`); only the contract and its projection were lying.
