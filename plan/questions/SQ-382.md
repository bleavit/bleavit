## Question

**`PhaseFlags` bit 3 arms CODE and META together, but 08 §4.1 gives them different floors.** 02 §7.3 allocates one bit for CODE/META; 08 §4.1 sets CODE 13,862,944 and META 21,256,533 USDC. SQ-180 implemented the conservative reading — arming bit 3 requires **both** floors, so META's 21.26M binds — which is the only literal reading of §4.2 for a bit that arms both classes and is the fail-static direction. But 08 §4.1's own prose says "Below ~13.9M NAV the chain **cannot pass its own runtime upgrades**", which reads as CODE arming at 13.86M. The conservative reading therefore raises the chain's self-upgrade threshold by ~7.4M USDC above the figure the spec advertises. Is that intended, or should bit 3 be split into separate CODE and META arming bits (a 02 §7.3 change, hence a contract bump)?

## Status

**resolved 2026-07-24 (ruled — shipped behaviour ratified, no contract bump)** — 02 §7.3 allocates **one** bit to CODE/META and 09 §7.1 arms both classes at the same Phase-6 gate, so the bit is settable only when every class it arms clears its own §4.1 floor: the binding value is META's **21,256,533 USDC**. 08 §4.2's "below ~13.9M the chain cannot pass its own runtime upgrades" is a *necessary*, not sufficient, condition and is now stated as such; 09 §7.1's phase-6 row is amended to name the higher floor. Splitting bit 3 into per-class arming bits was refused — it changes a frozen 02 surface (contract bump + joint sign-off) to buy only an earlier CODE arming that the shared Phase-6 gate would never use.
