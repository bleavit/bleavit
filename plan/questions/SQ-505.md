title: **Thirteen epoch→market seam methods fully bypass their production bodies under `runtime-benchmarks`, and the stated rationale for doing so does not carry the weight accounting.** `impl pallet_epoch::MarketAccess<AccountId> for RuntimeMarketAccess` (`runtime/bleavit-runtime/src/configs.rs:3058-3863`) gates **15** methods behind `#[cfg(feature = "runtime-benchmarks")]`. Two of them still touch storage and are fine — `open_markets` creates the real conditional-ledger vault, `baseline_market` performs its `BaselineMarketOf::get` and only fabricates an id when absent (which is why `decide` declares that one market item). **Thirteen return before touching storage at all:** `extend_markets`, `force_rerun_markets`, `resume_markets`, `close_markets`, `seal_decision_window`, `twap_full`, `twap_full_at`, `twap_trailing_at`, `spot_at`, `decision_grade`, `welfare_grade`, `measured_depth`, `published_flow_per_day` — plus `is_gradeable` in the neighbouring `RuntimeBaselineGrade` impl. Concretely: `close_markets` is `return Ok(())` ahead of a loop calling `pallet_market::consume_decision_windows` **and** `close` for every proposal book plus the baseline; `decision_grade` is `return true` ahead of `Markets::get`; `welfare_grade` returns `Ok` ahead of `Markets::get` + `contest_floor_for_grade` + `decision_grade_facts_at`. **These calls are inline, not dispatched** — `pallet_market::Pallet::<Runtime>::close(epoch_signed_origin(), id)` runs that extrinsic's body inside the caller's dispatch, carrying no weight of its own. **The choice is deliberate and its reasoning is written down, which is why this is a ruling rather than a bug report.** `open_markets` states it: *"The sibling market pallet benchmarks the bounded book writes; this adapter supplies deterministic decision telemetry."* **That does not follow for weight purposes.** `pallet_market`'s own weights charge `pallet_market`'s own dispatches; they charge nothing when the same code runs inline inside `pallet_epoch::decide`. The composition that would carry the argument does not exist: `tick_weight`/`decide_weight` (`pallets/epoch/src/lib.rs:2148-2154`) add **only** `collator_compensation()` — so the repo already knows how to compose a foreign term into these weights and does not do it here. Observed consequence: `tick` declares **zero** `Market::` storage items and `decide` exactly **one** of 63 (655 reads), while `settle_cohort` declares ten including `Market::Markets (r:72 w:72)` — so a reviewer spot-checking whether epoch weights charge for market work finds that they sometimes do, which is what has kept this invisible. `decide`'s six bypasses carry no rationale comment at all. **Both cranks are permissionless**, so if the accounting gap is real it is an R-7 block-capacity surface, and neither the growth-only regression gate nor the generated-weight purity gate can see work that was never measured. **Owed before any fix: a measurement**, not an estimate — benchmark `tick`/`decide` at HEAD and again with the seam live, and quote both. If the delta is material, the cleanest resolution is the one #190 used for the same shape one layer down: **have each gated arm perform the real reads for their storage effect and fabricate only the returned values**, which keeps benchmark determinism while charging the storage — then assert the worst-case fixture inside the benchmark body so it cannot silently stop reaching the work. The alternatives are to execute the seam outright (the machinery exists: `benchmark_ensure_market_books`, `configs.rs:8690`) or to compose the corresponding `pallet_market::WeightInfo` terms the way `collator_compensation` is composed; if it is not material, the `open_markets` rationale should be restated in accounting terms and applied to the other thirteen, which today carry no justification. **Scope beyond the market seam, and the limits of the sweep (recorded 2026-07-27).** A brace-tracking pass over **every** trait impl in `configs.rs` — classifying each gated arm for storage access against a production body that has it — flags 18 arms across 7 impls, adding `present_and_quorate` (`RuntimeEpochAttestation`, whose production body does `has_quorum` **plus** a full `Attestations::get().iter().any(...)` scan), `queue_time_check`, `is_gradeable`, `oracle_deadlock` (one `contains_key`, real but negligible) and `onchain_components` (the A14 case #187/#190/#191 are already fixing). **That 18 is an upper bound, not a finding.** The detector only sees direct `::<Runtime>::` accesses, so an arm that reaches storage through a helper reads as a bypass when it is not — `cohort_exposure` is exactly that, and it is a **verified false positive**. **`cohort_exposure` is also the answer to this row.** Its gated arm walks the fold deliberately (`let _ = incident_cohort_escrow(epoch);`) under a comment recording why: both registry instances bind the same generated `WeightInfo`, so returning the fixture without walking measured Milestone at 99 reads against Incident's 119 and the 99 **overwrote** the 119, reintroducing the undercharge SQ-489 exists to remove. That is the in-repo precedent for the fix — execute the reads for their storage effect, fabricate only the values — and it is stronger than any pattern invented here. **One more instance of the same blind spot, measured (2026-07-27):** `rust-workspace-gates.sh` runs `clippy --workspace --all-targets` **without** `--all-features`, so `-D warnings` never compiles the `runtime-benchmarks`/`recovery` arms of the runtime's own test modules. Three combos exit **101 identically at `cd0e16d` and on #190's branch** — dead-code and unused-import errors in `tests_b15_recovery.rs`, `tests_migration_guard.rs` and `configs.rs`'s `TestRenewalDispatch` — and `-p bleavit-xcm --all-targets --features runtime-benchmarks` exits 101 with four more, identical at `52a431e`. Pre-existing, invisible to CI, same family as the arms below. **Personally verified as genuine full bypasses so far:** `close_markets`, `decision_grade`, `welfare_grade`, `twap_full`, `twap_full_at`, `is_gradeable`, `present_and_quorate`, `oracle_deadlock`. The remaining candidates (`extend_markets`, `force_rerun_markets`, `resume_markets`, `seal_decision_window`, `twap_trailing_at`, `spot_at`, `measured_depth`, `queue_time_check`) need the same per-arm read before any of them is asserted.
