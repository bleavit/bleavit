## Question

**Split-gate scope: Signed ledger splits only, or also MarketAuthority set minting?** 09 §5.2 says caps are "enforced at every `split`/inflow-crediting path"; B10 gates the four Signed split extrinsics (the SQ-105 reading); the trade path's MarketAuthority splits stay exempt, so `buy` can create escrow while over cap (issuance base unaffected — defense-in-depth question only).

## Status

**resolved 2026-07-20 (batch B2 · ratified).** 09 §5.2 now scopes the split-path read to the four **Signed** ledger split extrinsics and states the `MarketAuthority` trade-path exemption with its reason. The row's central safety claim ("issuance base unaffected") was **independently verified rather than accepted**: a `buy`-path split escrows collateral the trader already holds — `settle_collateral` only ever calls `Collateral::transfer`, never a mint (`pallets/conditional-ledger/src/lib.rs:1463-1487`) — and every unit of that balance entered issuance through `CappedInflows::mint_asset`, the sole production issuance path, since `pallet_assets::mint` is classified `Nobody` for all origins including sudo and genesis seeds zero USDC. No unbacked claim, no cap bypass. One correction in the *unsafe* direction, recorded for a future row: the registry seeds both `phase3.*` keys with `min = 0`, `max = u128::MAX` and no monotonicity (`crates/constitution-core/src/lib.rs:1904-1923`), so 09 §5.2's "raised only by phase gates" is procedurally stated but **unenforced**.
