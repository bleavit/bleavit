## Question

**Does a spot re-derivation count as a §8.4 sampling round, so that a mismatch auto-disables the publisher?** §8.4 gives `FE-PROV-002` to *"a §8.4 sampling round [that] finds **any** mismatch against chain state … ⇒ auto-disable"* and `FE-PROV-003` to *"a snapshot rejected at import"*, and the deterministic spot re-derivation satisfies **both** descriptions: it is a §8.4 comparison against chain state, and it happens at import. The two codes scope differently — one is about the source, the other about the file — and §8.4 never says which applies. F9 ships the conservative reading: the file is rejected (`FE-PROV-003`, `chain-disagreement` remedy) **and** the source is auto-disabled through the same `afterSampling` the live sampler uses (`FE-PROV-002`), because a publisher this device caught contradicting the chain is exactly the source §8.3's ladder exists to stop reading from, and re-enabling is the user's explicit act either way. The three other rejection causes leave the provider untouched, which is the distinction the ruling has to confirm or overturn: a damaged download, a wrong-chain document and a check this device could not finish are statements about the file or the device, not about the publisher. What 10 owes is one sentence saying whether an import refusal is file-scoped or source-scoped
