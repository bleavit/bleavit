## Question

The "TREASURY > 1% NAV" gate-market classification (05 §5.1) needs a NAV read the frame-free engine cannot do. A8 **freezes** the classification at Seed via a `treasury_gate_required` seam; B1b wires spendable NAV and `decide` keys off the deployed books (`markets.gates.is_some()`), never a live recompute. The runtime follows 04/05's explicit 1% rule through a primitives constant, but 13 does not own that threshold or say whether the META-governed classification should instead have a dedicated `Params` key; `trs.stream_threshold` is a different grant-stream concept and is not reused.

## Status

**closed 2026-07-20 (B4 ratification) — obsoleted by integration contract v5.** The question no longer has a subject: the TREASURY ask/NAV gate threshold was **deleted** on 2026-07-19 (commit `243a1f9`) when v5 made gate markets universal across every market-bearing class. `requires_gate_markets` is now a compile-time class match with no NAV read (`crates/epoch-core/src/lib.rs:45-50`); `TREASURY_GATE_NAV_BPS` and the `treasury_gate_required` seam are gone from the tree. 13 §1 explicitly records that universal gating introduces **no new parameter**, so there is no threshold for 13 to own. Docs and code already agree — no amendment made.
