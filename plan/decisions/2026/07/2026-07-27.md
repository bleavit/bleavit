# Decisions — 2026-07-27

## A14 — the measurable day set is read against the…
authorized_by: Claude (R-1 delegation, 2026-07-25); raised by #187's spec-reviewer pass
docs_touched: 05 §4.5, §4.7 (13 §4's bound row retained as the storage bound)

A14 — the measurable day set is read against the *scheduled* epoch length, and a truncated authorship window makes `D_eff` unavailable.

Two 05 amendments, both raised by #187's implementation. (1) **05 §4.7** said a day counts if "the epoch actually contained it", which is ambiguous exactly when it matters: §4.8's dead-man keeps the day index advancing while the clock is paused, so a paused epoch physically spans more days than it was scheduled to hold. Ruled **scheduled**, because the error directions are not symmetric — the scheduled reading can only *refuse* a day that elapsed, costing coverage the section already tolerates (it declares no expected-day count), whereas the elapsed reading *admits* days created by the pause itself, measured against components that were not running, manufacturing a breach out of a liveness failure the S pillar and the dead-man already price. That is the fail-destructive direction G-1 excludes. (2) **05 §4.5** gains the rule that a truncated *or empty* authorship window makes `D_eff` unavailable. It had been recorded only in 13 §4's bound row, which is a parameter table, not the owning document. The substance also corrects an earlier claim of mine: dropping an author is **not** conservative for `D_eff`, because it reads a distribution rather than a count — discarding a newly rotated high-count author makes a concentrated set look uniform and *overstates* the score. Counts (`K`, `U`) stay readable, where the drop really is pessimistic.

## A14 `U` — a boundary block belongs to the window in…
authorized_by: Claude (R-1 delegation, 2026-07-25) — implementation choices within 05 §4.3.2, no doc text changed
docs_touched: none (05 §4.3.2 already admits both partitions; recorded here because the choice is observable)

A14 `U` — a boundary block belongs to the window in which its relay slot was observed, and an epoch total is maintained on write rather than folded on read.

Two implementation rulings inside 05 §4.3.2 rather than amendments to it, recorded because both are observable and neither is forced by the spec text. (1) **Partition.** §4.3.2 fixes the *deltas* — each block contributes `relay_parent(this) − relay_parent(previous)`, with *previous* crossing the window boundary — but leaves the block→window partition to the epoch clock, so a block carrying `Epoch.tick` is conforming in either window. Recomputing it in the post-transaction hook split one block across two: the closing epoch received a denominator with no authored block and the opening one an authored block with no slot, depressing one `U` and overstating the next, both of which feed gate settlement. The window is now resolved **once**, in the parachain inherent — where the slot is observed, and where `X` and `R` are already attributed — stamped with its block number, and a capture that cannot be attributed to *this* block is dropped rather than guessed. Residual, documented not hidden: a block carrying `tick` and `record_snapshot(closing)` sees the slot but not yet the authored count, one block in `epoch.length`, understating. (2) **Aggregate.** The epoch value is a `BlockProductionEpoch` total written in the same index-gated step as the day slot, not a 256-key fold at read time: charging the fold would cost `record_snapshot` up to 256 reads and ~645 KB of proof for a three-field sum, about six times the call's entire PoV footprint, against one read/write on a per-block path that already carries `Mandatory` benchmarked weight. `try_state` binds the total to the field-wise sum of its day slots in both directions.
