# Decisions — 2026-07-29

## SQ-517 ruled: the two Track-E revenue cranks freeze…
authorized_by: Claude (R-1 delegation, 2026-07-25); raised independently three times — the Track E spec audit, my own reading of 06 §6.3, and the #196 round-3 Codex review at P1
docs_touched: 06 §6.3; 03 §5.4 + L-7; 04 §2

SQ-517 ruled: the two Track-E revenue cranks freeze with the rest of the value-moving surface — and L-7 makes this a proof, not a preference.

06 §6.3's Effect bullet enumerates the frozen set, and that enumeration was written before Track E existed, so the two Signed permissionless cranks it added (`ledger.sweep_redemption_fees`, `market.sweep_revenue`) fell outside it by omission rather than by decision. Each fails under a freeze for its own reason. **`sweep_redemption_fees`:** 03's L-7 bounds the accrual at `RedemptionFeesAccrued ≤ balance(sovereign) − TotalEscrowed − held_deposits − min_balance`, while the I-4 drift flag — the sole admission condition for `PB-LEDGER-FREEZE` — asserts exactly `TotalEscrowed + held_deposits > balance(sovereign)`. The bound is therefore **negative precisely under the state that authorizes a freeze**: there is no surplus to sweep, "moves surplus, never escrow" is a theorem about the healthy state rather than a property of the crank, and `Preservation::Preserve` does not rescue it because it protects `min_balance` and is indifferent to escrow. L-7 is restated as the conditional it always was, with its condition named. **`sweep_revenue`:** its fee leg redeems through the ledger's *internal* path, which carries no `Frozen` check, so under a freeze it collects the protocol's own claim out of a possibly-short sovereign at the moment every claimant's `redeem` is refused — and G-1 forbids resolving that ambiguity in the direction that pays. **Why this does not collide with the settlement carve-out**, which is the part the enumeration alone cannot settle: neither crank effects a terminal transition, each is idempotent or counter-based and retryable indefinitely, and its value stays fully collateralized in place — so freezing them **strands nothing** and costs only an NAV-recognition delay bounded by the freeze's own ≤ 28-day ceiling, the same delay 04 §2 already bounds for an unswept book. `reap` is delayed transitively (it requires the swept marker) and inertly (it discards only worthless residue). `sweep_dust*` is deliberately **left live and unchanged**: it is the terminal-vault cleanup the carve-out covers, its residue is a liability transfer to INSURANCE rather than a treasury payout, and it already sits behind a one-year archive delay. Implementation detail made normative because it is observable: `sweep_revenue`'s guard sits **after** its idempotence early-return, so a freeze never retroactively changes what an already-swept book answers.

## SQ-519 ruled: the Baseline buy-side fee routes to…
authorized_by: Claude (R-1 delegation, 2026-07-25); found independently by the round-2 Codex review and the spec audit
docs_touched: 04 §6.1; 08 §10.2

SQ-519 ruled: the Baseline buy-side fee routes to `MAIN`, and it was never a spec gap.

I had it filed as a judgement call. It is not — 08 §10.2's `ρ` derivation already states "Baseline books realize 1.0 on **both sides**", so the spec's own revenue arithmetic *already counted* that fee as realized income funding the recurring cost base. The code simply did not deliver it, which makes this a defect rather than an open question. The parenthetical justifying the row was also wrong on its face — "their fee is retained as plain USDC" describes the **sell** side; the buy side is a complete LONG+SHORT set — so 08 §10.2 now names both mechanisms and 04 §6.1 carries the normative buy-side rule. **Two properties are load-bearing and are written into 04 §6.1 rather than left to the implementation.** *Segregation, not accounting:* the fee must leave LMSR inventory when charged, because by settlement that inventory may no longer cover the accrual — a book whose bought leg traders drew down would have nothing left to remit, so no sweep-time computation from a running total is realizable. *Ordering:* segregation happens **before** the buyer's leg is paid, so a book that cannot fund `amount` with the fee set aside fails the trade (G-1) instead of silently financing itself out of fee revenue. Realization at Sweep is uncharged because 03 §5.3a deducts only from a **non-protocol** claimant, so the protocol's own fee realization is not charged its own fee.

## 15 §4.3's rate-coverage clause named the wrong leg…
authorized_by: Claude (R-1 delegation, 2026-07-25); found while resolving the doc-15 test-regime row
docs_touched: 15 §4.3

15 §4.3's rate-coverage clause named the wrong leg load-bearing, and its own stated reason proved the opposite.

The clause (written 2026-07-29 with E1) read: "the **zero**-rate leg is the load-bearing half for I-2/PT-2 — a widening of the charged set into `redeem` passes a zero-rate suite silently." Those two halves contradict each other. At `ledger.redeem_fee = 0` every fee computation yields 0 **whatever the charged set contains**, so a widening into the exempt `redeem` par leg is exactly what a zero-rate suite *cannot* see; the **non-zero** leg is the one that catches it. Corrected to name the non-zero leg, with the inversion recorded inline so the next reader sees it was deliberate rather than re-inverting it. The two-leg *obligation* is unchanged and still binds — both legs are required, and 03 §11's parallel sentence was already correct and needed no edit. Worth noting how it was caught: not by review of the text, but by implementing against it — the code comment PT-2 already carried (written from 03 §11) stated the correct reading, so the spec and its own implementation disagreed in a file nobody diffed against the other.

## E1 — `INSURANCE` gains a derived target size and…
authorized_by: user (work order); R-1
docs_touched: 08 §1.1, §1.2, §10.6; 03 §7 R-5

E1 — `INSURANCE` gains a derived target size and automatic above-target overflow.

An inflow-only reserve outside NAV with no ceiling is a value sink. The ceiling is **derived, not chosen**: `T_ins` = cumulative unreclaimed swept ledger residue + `min_balance`, because 03 §5.4 keeps swept claims live through the Merkle-archived claims procedure, so the residue is exactly the contingent liability the reserve backs. Balance above `T_ins` overflows to `MAIN` **in the same transaction as the inflow** — no governance act, no slot. Bond slashes keep their full deterrent effect (the offender still forfeits) while the value becomes spendable. `sweep_insurance` remains the only way *below* target. Explicitly ruled: `INSURANCE` is **not** an operating buffer for quiet epochs — a reserve sized to a liability cannot also be a buffer sized to an expense

The work order proposed charging the whole terminal-redemption family including `redeem`; it also offered the alternative of exempting the mirror leg, and that branch is taken. `redeem` of winning branch-USDC is the **par leg** every D-3 wrapper buy leaves with the buyer; charging it would falsify G-3 (01 §2), D-3 (00), 04 §6.2, I-2(b), I-5 and PT-2 simultaneously, and would buy a factor of about two on an instrument 08 §10.4 shows is not decisive at any rate. `redeem_void` is exempt (VOID is protocol failure; charging inverts G-1) and every `merge*` is exempt (they are what make a complete set worth exactly one branch-USDC; a fee there opens a spread around par). **Necessity over reusing `mkt.fee`** (R-2 step 1): the two price different acts on different bases with different elasticities — turnover through the book versus settlement of held capital — and evidence that one is mis-set must be actionable without moving the other. **Value derived, not picked** (R-2 step 2): `ledger.redeem_fee ≤ mkt.fee` is exit-neutrality, and the default sits at the bound. **System effects** (R-2 step 3): unsafe direction is upward; max-Δ 10 bps and cooldown 1 mirror `mkt.fee`; the coupling is screened jointly at the amendment boundary like `gate.v_min` ↔ `dec.v_min` and asserted in try-state

## E1 — two corrections to §5.3a, both found by the…
authorized_by: user (work order); R-1; found by `reference-model/` per R-2
docs_touched: 03 §5.3a(2), (2a), (3); 15 I-5, I-32, PT-7

E1 — two corrections to §5.3a, both found by the reference model *before* any Rust was written.

This is the spec-first loop (R-2) doing the job it exists for, so both are recorded rather than quietly fixed. **(a) The pair calls now charge what their legs would charge.** The first draft charged `fee(a)` on `redeem_scalar_pair`/`redeem_baseline_pair`, which **falsifies the very guarantee the atomic pair call exists to provide** — that the pair never pays less than leg-by-leg redemption of the same holdings (I-5, PT-7, 03 §7 R-1). Witness at defaults, `a = 20,000`, `s = 0.70005`, 30 bps: pair `20,000 − 60 = 19,940`; leg-by-leg `(14,001 − 43) + 5,999 = 19,957`, the SHORT leg falling under the waiver. A waiver applied per **call** interacts with a fee applied to a **combined** base, and fragmentation becomes the rational strategy — the exact anti-claimant inversion the charged-set ruling was written to prevent. Fix: `fee_pair(a) = fee(floor(a·s)) + fee(floor(a·(1−s)))`, each leg applying its own waiver, gross payout still exactly `a`. Identical fee functions on identical bases plus `floor(a·s) + floor(a·(1−s)) ≤ a` make `net_pair ≥ net_legs` hold for every `a`, `s` and rate; both sides of the witness now read 19,957. **(b) The waiver tests the net, not the gross.** The rationale claimed the waiver stops a gross in `[min_balance, min_balance + fee]` being pushed below `min_balance` — but `ledger.min_split` and `min_balance` are **both** 10⁴, so a gross-based test at exactly 10,000 charges 30 and nets 9,970, landing on the `BelowMinimum` path the waiver was said to remove. Fix: waive exactly when `g − ceil(g·rate) < ledger.min_split`. Neither correction touches conservation — both were guarantee/liveness defects, not solvency ones — and both regression witnesses are now named vectors
