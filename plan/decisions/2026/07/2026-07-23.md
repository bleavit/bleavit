docs_touched: 00; 02 §7.2/§13; 07 §§5–6/§11; 15 I-18/I-29; derived design kit; PLAN A12

The oracle's `counter_report` is a reporter-signed consent boundary: a keeper never creates the next reporter bond. `challenger` is durable for the game and the same challenger must fund each later challenge; if the reporter misses consent, `ChallengerDefault` settles the current counter-value and routes the reporter stack 40/60 to the challenger/INSURANCE. Because `SettledComponent.path` is a frontend-readable SCALE enum, 02 is amended and `INTEGRATION_CONTRACT_VERSION` moves **10→11**; 00, runtime assertions and the derived design pack are synchronized. This is pre-genesis, so no storage migration or transaction-version change is needed.

A12 custody kernel is split at the first safe boundary; no protocol semantics were amended.

The oracle now has a real runtime custody adapter for reporter/watchtower registration stakes, a dedicated sovereign account, atomic insufficient-funds rollback, stake-liability `try_state`, and explicit reduction of the stored stake on the existing slash paths. Round-bond custody is intentionally not enabled: the current core auto-adds the next reporter contribution in `crank_round_close`, erases challenger identity between rounds, and has no signed `counter_report`; the spec also leaves ejection disposition and late-verdict bond ownership underdefined. Frozen `StakeAtRisk`, consenting escalation, d20 bond-retention, registry value-scaling/versioning and daily source stores therefore remain one follow-on kernel/successor rather than being invented piecemeal.

## SQ-340 / B19 bond-consent ruling — option (a).

`attestor.set_members` is the sole values-elected seating surface, so it atomically holds the live `att.bond` from each newly seated nominee; a missing balance fails the entire values enactment and leaves the old roster/custody untouched. Continuing seats adjust the hold to the live value, departing seats release only after their independent liability rows and records are gone, and there is no permissionless pre-bond state that an attacker could starve. ## PR handoff does not wait on redundant CI.
authorized_by: User, explicit standing instruction after merging PR #139, 2026-07-23
docs_touched: AGENTS.md R-12/session protocol; PLAN.md

Once a PR's significant implementation state has sufficient local verification or a green CI run, agents mark it ready for review and continue with the next logical work. A later documentation-only/status-only commit such as the final `PLAN.md` closure does not require waiting for an identical exhaustive rerun. This does not waive gates for meaningful code/build/workflow/dependency/generated-artifact/test changes and does not permit ignoring an observed failure. CI, when polled, is read no more than once every five minutes.
