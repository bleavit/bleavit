## `app/`'s tests and tools move to TypeScript.
authorized_by: User (explicit instruction, 2026-08-05)
docs_touched: no `docs/architecture/` change

User instruction, and the motive it shares with the artifact normalization recorded above: keep the diff a human reads made of things a human wrote. **No hand-written JavaScript** — Node 22.18 runs `.ts` directly by stripping types and `erasableSyntaxOnly` was already set, so the suites need no build step and no transpiler enters the dependency graph. But **stripping is not checking**: it deletes the annotations and runs whatever is left, so a suite full of wrong types executes exactly as before. `tsconfig.tests.json` + `check:types` is therefore the actual control, and its `include` grows **one slice at a time** — adding every directory at once would leave ~1,500 errors sitting red, and a gate that cannot be switched on is a gate nobody switches on; the pressure would then be to silence errors with `any`, which reproduces the untyped tree with extra ceremony

## Generated artifacts are normalized at their generator,…
authorized_by: User (explicit instruction, 2026-08-05)
docs_touched: `.gitattributes` (new); no `docs/architecture/` change

Generated artifacts are normalized at their generator, not by hand: compact chainHead transcripts and prettier-normalized PAPI `.d.ts`.

Both apply the same discipline — **one normalization site, shared by generate and check** — because two formatters that could disagree is a drift source rather than a fix for one. `deterministic_json` emits compact separators (`sort_keys` still carries determinism); `descriptors:generate` now runs through `check-descriptor-drift.ts --update`, so the drift gate's claim becomes `committed == normalize(papi generate)`, which still binds the tree to the generator and still fails a hand-edit. **Only `.d.ts` is normalized, never the emitted `.js`** — a declaration file has no runtime semantics so a formatter cannot change behaviour there, while the generated JavaScript executes. `.gitattributes` marks the generated trees `linguist-generated`, with `-diff` only on PAPI output and chainHead fixtures; generated weights and lockfiles keep textual diffs because the weight-regression gate and supply-chain review are people reading exactly those lines. Landed **on `main` first, deliberately**: a reformat of files that already exist upstream shows as a full rewrite inside a feature branch and inflates the very PR it was meant to shrink — measured at +26k on #234 before this was extracted

## `pallet_execution_guard::apply_authorized_upgrade`…
authorized_by: Me, under R-1/R-7; no `docs/architecture/` change and no 02 surface moves, so no contract bump — the spec gap the fix exposed is raised as SQ-596
docs_touched: none (runtime only): `pallets/execution-guard/src/lib.rs`, `runtime/bleavit-runtime/src/pov_budgets.rs`

`pallet_execution_guard::apply_authorized_upgrade` moves to `DispatchClass::Operational`, matching the `frame_system` call it forwards to.

The class is not a label here: `CheckWeight::check_block_length` measures the encoded extrinsic against the *class's* `BlockLength` ceiling, and this is the one call carrying a whole runtime image as a single argument. Declaring no class made it `Normal`, whose ceiling is this runtime's 75 % slice — **3,932,160 B** against the **4,194,304 B** the same pallet publishes as the frozen 02 §9 constant `MaxRuntimeCodeBytes`. Three alternatives were considered and refused: lowering the constant breaks a frozen contract surface and its derivation from `pallet_preimage::MAX_SIZE`; deleting the duplicate call removes a genuinely better error surface and would be a call-index removal; and leaving it is R-7's forbidden reading — a bound the chain publishes and cannot honour. **Side effects checked rather than assumed:** `OperationalFeeMultiplier` scales only the *priority* virtual tip and not the fee, so nobody pays more; the N7 `ResourcePartition` stops partitioning the call, which is correct and already written down there (*FRAME owns the Operational and Mandatory budgets… those classes still enter the primary accumulator through the residual fold*); the guard's rule that payload calls must be `Normal` is about calls *inside* a proposal and this is not one; and dispatch class is absent from SCALE metadata, so no chain-feed, descriptor or surface artifact moves. **No `spec_version` bump**: no chain is live, and the feed's directory identity is being regenerated concurrently by the Track F stack. The relation is now pinned by `upgrade_apply_paths_can_carry_max_runtime_code_bytes`, which derives both sides and was watched failing before the fix.
