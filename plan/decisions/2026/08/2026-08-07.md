## 10 §4.2's opening claim was false and is corrected: smoldot implements the legacy read group, and the bound on depth is hash acquisition (R-1 spec change; F1, FE-P5, V-303).

## 10 §2.3 stops qualifying its own fee rule, and `estimateFee` takes a read instead of a number (R-1 spec change; F1, FE-P1, V-301).
authorized_by: Claude (R-1; no 02 change, no contract bump)
docs_touched: `10` §2.3, §12; `11` §11.3; `app/packages/transaction-builder/src/fees.ts`

§2.3 required the fee estimate to be `Finalized<T>` and then softened itself: *"FE-P1 leaves the exact PAPI fee-estimation surface open, so until it resolves the conservative reading is in force"*. FE-P1's fee half resolves, and it resolves in the direction that removes the excuse: PAPI answers `getEstimatedFees` from `TransactionPaymentApi_query_info` at the **finalized** block, so a conforming figure is obtainable. The qualifier is withdrawn and three implementer traps are written in, each a way to hold the right API and still get an unsourced number — `TxOptions.at` does not move the fee call, `partial_fee` excludes the tip, and `partial_fee` is native-denominated under `ChargeAssetTxPayment`. **The code assumed the weaker answer.** `estimateFee` took a bare `bigint` while `nonceFor` beside it took `Finalized<bigint>` and compared block hashes. It now takes `Finalized<bigint>` and `Finalized<AdmittedRate>` and returns through `meet`, so a fee and a rate read at different blocks yield no estimate.

## 10 §8.5.2 — which screens a `/range` page owes, and what its `balances` hold (F24; closes SQ-983).
authorized_by: Claude (R-1 delegation, 2026-07-25)
docs_touched: `docs/architecture/10-frontend-architecture.md` (§8.5.2, §9.1's schema row)

§8.5.2 already said a page *"does not owe the conservation replay"* and pointed at §8.4's phrase for the rest — *"monotone coverage, event↔derived-row agreement, conservation-identity replay"* — which read as a block takes all three away. **Two of the three drop, and for two different reasons; collapsing them into one is what a first draft of this ruling got wrong.** The **replay** drops because non-negativity from a zero start is meaningless for a page that opens mid-history. The **derived-row agreement** drops only as a consequence of the second half of this ruling, since it compares `balances` against the fold of the document's *own* movements and is otherwise a self-check that survives a restriction untouched. **Monotone coverage stays** — it is internal to the document, a mid-history page satisfies it, and it is load-bearing precisely here, because a client builds its coverage from the union of the lists the pages carried and a page whose movements sit outside its own coverage hands back blocks that coverage does not claim. **A page's `balances` are read from state at its last block, not folded**: §8.5.1 already has a producer read balances independently, and §8.5.2 already assigns this route to §8.4's 1-in-16-page sampling, which re-verifies rows *against the chain* — a folded balance would disagree with a current holding on every honest page and turn the one live control §8.4 gives an indexer into a generator of false mismatches that auto-disable honest operators. **The code was doing the opposite of all of this**: `readRange` and the reference server both ran `admitSnapshot`, so every span not reaching genesis was answered `500`, and `optional/indexer/README.md` documented the folded obligation as a rule. New `admitIndexerPage` entry point, deliberately **not** branded `AdmittedSnapshot` so a page can never reach `mintSnapshotRows`. No `INTEGRATION_CONTRACT_VERSION` bump: 02 owns none of the client↔provider wire

## 10 §6.3's `RangeEdge` becomes a discriminated union, and every range still carries one (R-1 spec change; user ruling).
authorized_by: User ruling (2026-08-07), implemented by Claude
docs_touched: `docs/architecture/10-frontend-architecture.md` §6.3 + the design-kit verbatim copy

§6.3's three per-range integrity checks were given a `RangeEdge` by F8 so they would have something to read (SQ-605). `packages/providers/src/mint.ts` is the only production producer of `snapshot` and `indexer` ranges and it **cannot honestly fill two of the three fields**: `bleavit.snapshot.v1` carries no block hash anywhere, and its `binding.specVersion` is a producer claim `admitSnapshot` deliberately declines to compare, because §6.4 gives snapshots deep history predating the runtime — writing it into the edge would make `verifyRange` invalidate every deep snapshot at the first boot after an upgrade. The indexer arm has no binding at all. Filling either from the client's own reads is worse: `verifyRange` would compare the chain against itself, a check that cannot fail. **Ruled:** a `checked` arm carrying all three facts for a range this client's own ingest produced, and an `unverifiable` arm that keeps `genesisHash` and **names the reason the other two are absent**. `edge` is **not** optional and nothing is defaulted — the same shape §8.4 uses for the depth blind spot, and INV-FE-15's *absent with an explanation, never silently spliced*. The genesis binding therefore still runs on provider ranges, which is the check that catches another network's history filed under this chain's ids; past it the verdict is **`unchecked`, never `ok`**, and `verifyRanges` now reports such a range in its `unchecked` set — a range in neither list read to a caller as one that passed. An `unverifiable` edge carrying a hash, a spec version or no reason is refused, as is an edge with no arm (guessing `checked` for a pre-union record is how a provider range would acquire the arm the checks may run over). **SQ-605's open half is untouched and still open**: it asks whether the client can re-perform the checks at the depths its *own* ranges describe, which this ruling neither settles nor worsens. SQ-610 (whether §8 wants a chain binding at all) is likewise cited and left open — this ruling consumes the genesis binding admission already performs and asks §8 for nothing new. No new spec question was needed. 11 mutants, 0 survived
