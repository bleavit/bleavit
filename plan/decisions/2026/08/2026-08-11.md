## The exhaustive Rust gate is a CI artifact, not a local…
authorized_by: Session, under R-3. No spec text changed and no gate was weakened — the script is untouched and CI still runs it exhaustively
docs_touched: none (AGENTS.md · *Quality gates*)

The exhaustive Rust gate is a CI artifact, not a local one, and this session paid nine hours to establish it.

`tools/ci/rust-workspace-gates.sh` with no arguments took **9 h 17 m** here against **61 min** for the identical script in CI, and the gap is environment rather than scope — `ci.yml:49` runs the same file. Three differences account for it, and two are one-line fixes. CI restores a warm cargo cache through `Swatinem/rust-cache@v2`, so its hour is mostly fingerprint checking. CI sets **`CARGO_INCREMENTAL=0`** and this workstation did not, leaving **23 GB of a 72 GB debug tree** as incremental bookkeeping that pays off across edits and buys nothing in a one-shot gate. And the dev profile keeps full debuginfo with no `mold` or `lld` installed, so the serial link tail dominates — the load average was **4.03 on 32 cores** while the gate ran. Ruled for practice rather than for the script: **run the two feature-gated legs locally, not the whole file.** That is the honest response to the opposite lesson this branch taught three times, where `runtime-benchmarks` and `try-runtime` tests stayed invisible to every unfeatured command. `CARGO_INCREMENTAL=0` and `CARGO_PROFILE_DEV_DEBUG=line-tables-only` join AGENTS.md's local-prerequisites block. **One near-miss is recorded because it would have been a plausible wrong conclusion:** the branch's own CI Rust job read 31 minutes against main's 61, which looks like the new TR7 leg costing nothing. It measures nothing at all — `set -euo pipefail` aborted that job at the try-runtime leg, so it never reached the new one. A faster failed run is not a faster run

## The 2026-08-02 weight-noise rule now has a per-function…
authorized_by: Session, applying the 2026-08-02 Decision log rule to a case it did not cover. No spec text changed and no D-n moves
docs_touched: none (`runtime/bleavit-runtime/src/weights/pallet_market.rs`, `pallet_futarchy_treasury.rs`)

The 2026-08-02 weight-noise rule now has a per-function form, because this is the first regeneration that was part real and part noise.

That entry established: regenerate whenever pallet code moves, but commit the result only where a fidelity-stable dimension moved, or a routine regeneration launders machine noise into figures the specification publishes as economics. It was applied at **file** granularity, because `pallet_market` and `pallet_conditional_ledger` were noise end to end and reverting each whole file was lossless. **TR4 and TR6 broke that assumption**: `pallet_market::buy` and `sell` genuinely gained the score observer's storage (+3r/+2w and +2r/+1w), `pallet_futarchy_treasury` genuinely gained `fund_trading_rewards`, and `note_collator_block`'s proof term genuinely moved 6,328 → 6,361 with the trie — while the other **23** functions in those two files moved ref_time and nothing else. Reverting the files would have discarded real measurements; keeping them whole moved `crank_observe` 141,590,000 → 136,580,000 and failed four `sustainability.py` pins, including SQ-527's published 2.829× A-1 crossover. Ruled: **revert per function, not per file** — each reverted body is its previous generator output verbatim, so the 15 §4.5 purity gate still sees only generated text, and the header keeps the new date because the file genuinely was regenerated. Classification is mechanical rather than judged: a function is noise if reads, writes, the proof term and every component term are unchanged. **The evidence that this set is noise is its sign, not its size** — ref_time moved in *both* directions across the 23, from −7.13 % to +6.83 %, on the same host at the same 50×20 fidelity. **The safety argument is the stronger half:** 17 of the 23 were *decreases*, and a decrease committed on noise understates a weight in precisely the direction the growth-only regression gate cannot see, which is SQ-490's class. After the revert the reference model passed 703/703 with **no** pin edited — the published economics never moved, which is what the rule is for

## 15 §4.5 gates `unsound` RustSec advisories instead of…
authorized_by: R-1 (spec rulings delegated 2026-07-25); 15 is not 02, so `INTEGRATION_CONTRACT_VERSION` is unchanged
docs_touched: `docs/architecture/15-invariants-and-testing.md` §4.5 (the advisory-sources parenthetical + one new normative paragraph). 15 §4.5 gates `unsound` RustSec advisories instead of preserving their informational classification (SQ-1048).

Dependabot reported GHSA-wrw7-89jp-8q8g (`glib` 0.18.5, RUSTSEC-2024-0429) against `app/Cargo.lock` at **medium** severity while `tools/ci/supply-chain-gates.sh` was green — and structurally would have stayed green: leg 2 (`cargo-audit`) classifies `unsound` as an allowed warning, exactly as §4.5 required, and leg 3 (`check-ghsa-only.py`) skips every RustSec-carried finding by contract. The two normative sources disagree on whether an `unsound` advisory is a vulnerability, and the section had ruled for RustSec's answer. Amended to rule for **exposure** instead, and a fourth cargo leg implements it. `unmaintained` deliberately stays informational — it names no defect and no mechanism, GHSA raises no record for it, and this tree carries about thirty. Waiver keys gain the **workspace** (clause 4 applied to the triage rather than to the audit), and every entry declares an `exposure`: `unreachable`, `constrained` (the affected function **is** called, so its call sites are cited) or `triggerable`, which is refused at load time. The three-state field is forced by evidence rather than taste — `parity-db` genuinely calls one of `memmap2`'s six affected functions, so a yes/no field would have compelled either a false "no" or a red gate with no admissible answer.
